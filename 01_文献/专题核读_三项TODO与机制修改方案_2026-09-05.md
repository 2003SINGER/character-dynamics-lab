## 2. 四篇论文究竟能借什么

页码均指本地 PDF 从 1 起的页序；文件名不替代实际出版年。

### 2.1 FAtiMA-PSI：直接支持“连续状态 + 非线性响应”

原文：[Creating Adaptive Affective Autonomous NPCs](PDF/2012_FAtiMA_Creating_Adaptive_Affective_Autonomous_NPCs.pdf)；[作者公开版本](https://www.macs.hw.ac.uk/~ruth/Papers/agents-affect/JAAMAS-final.pdf)，[规范 DOI](https://doi.org/10.1007/s10458-010-9161-2)。本次核读摘要、§4 方法与 §5–6 原型/评价边界，视觉检查 PDF p.22 的公式。

**paper evidence：** p.17 Eq.(1) 用加法和裁剪更新驱力；p.18–19 用不同权重和衰减表达人物差异。p.21–22 Eq.(6–8) 以 `Str(L)=(10-L)^2` 计算满足需求的效用差，再结合紧迫性与预期能力。p.23 用当前意图效用与 selection threshold 限制目标切换。这些是该系统的模型设计，并非各系数的普遍心理测量结果。

**inference from paper：** 可以先保留 S 加减，在 S/P 的消费函数中加入非线性；也可以让 P 调制敏感度、恢复速度、启动/切换门槛。论文没有规定本项目的 68/13.5/2.5 分区。p.27 明确未单独评价该架构相对 FAtiMA/PSI 的技术改进，游戏反馈不能证明每个公式成立。

### 2.2 Temporal Causal Network：每个节点自己的时间尺度与阈值

原文：[Temporal Causal Network Model for Appraisal Process in Emotion](PDF/2018_Temporal_Causal_Network_Appraisal_Process.pdf)；[DOI](https://doi.org/10.5220/0006867403470356)。核读 §2–6，视觉检查 p.6 / 印刷 p.352 的参数表；本轮在线 PDF 端返回 403，具体证据来自本地原文。

**paper evidence：** §3 / PDF p.4 写出 `Y(t+Δt)=Y(t)+ηY[cY(ωX1,Y X1(t),…)-Y(t)]Δt`。连接权重、组合函数与变化速率各有职责；§4.1–4.2 / p.5–6 用 logistic 的阈值与陡峭度控制某些加工环节的激活，参数表中各状态使用不同速率/函数。§5 的五种条件是设定输入后的模拟演示。

**inference from paper：** 支持“数值持续维护，输入到后续模块时产生阶段性作用”，也支持把字段之间的影响声明为显式依赖。它不支持所有更新互不影响，更没有验证统一分界或本项目行为预测优势。

### 2.3 Two Sides of Appraisal：P/S 调节加工方式，X 与持续状态不可混为一项

原文：[Two Sides of Appraisal](PDF/2004_Two_Sides_of_Appraisal_Cognitive_Architecture.pdf)；[AAAI 来源条目](https://m.aaai.org/Library/Symposia/Spring/2004/ss04-02-013.php)。核读结构、state/trait 调制、结果及局限，视觉检查 p.4 Fig.2-4。

**paper evidence：** p.2–4 描述 traits/states 对处理容量、线索排序和响应动态的影响；Current State Modulator 将新评价与上轮情绪结合，trait 影响增长、衰减、最大强度。该版本 appraisal 本身使用线性加权函数。p.5–6 区分程序验证与心理有效性，并报告经验数据不足、参数反复调试和模型脆弱性。

**inference from paper：** 支持 P 作为算子参数以及当前状态反馈到后续解释；不能把“所有输入函数都必须分阶段”归因给该论文。它也提醒我们：增加一批分区和特殊规则可能引入模型自己的现象。

### 2.4 Hierarchical State Space：保留线性对照，显式表达跨状态影响

原文：[A hierarchical state space approach to affective dynamics](PDF/2010_Hierarchical_State_Space_Affective_Dynamics.pdf)；[作者公开版本](https://www.ppw.kuleuven.be/okp/_pdf/Lodewyckx2011AHSSA.pdf)。实际期刊卷期是 *Journal of Mathematical Psychology* 55 (2011), 68–83；文件名前缀为 2010，对应在线发表年份。本次针对 p.1–3 的问题/方程和 p.12 的讨论核读；未重验其完整推断附录。

**paper evidence：** p.3 / 印刷 p.70 Eq.(1)、(5) 区分潜在状态转移与观测生成；转移矩阵同时含自身滞后与跨变量作用。论文分析亲子冲突互动中的生理与行为观测；其讨论承认线性和 Gaussian 误差是假设，可能不适合突变等数据。

**inference from paper：** 工程可拆分与机制上相互影响并不矛盾；线性模型应是阶段模型的对照。这里的 observation equation 是测量潜在状态的统计模型，不等于本项目 W→O 的角色可知边界；也不能据此将心理状态归入统一正态区间。

## 3. 第一项修改：把分段做成可替换响应策略

### 保留用户给出的宽度

用用户近似比例直接得到五段（边界由右侧区间接收，终点 1 包含）：

| 区间 | 宽度 | 用户阶段 |
|---|---:|---|
| `[0,0.025)` | 2.5% | 低侧异常 |
| `[0.025,0.16)` | 13.5% | 低侧独特 |
| `[0.16,0.84)` | 68% | 正常 |
| `[0.84,0.975)` | 13.5% | 高侧独特 |
| `[0.975,1]` | 2.5% | 高侧异常 |

“68%”在此首先是轴上的区间宽度；不代表真实人物 68% 的时间落在其中。上下两侧要分别保留，不能把高度自控和极低自控仅压成同一个“极端”标签。日志可使用 `low_extreme / low_distinctive / typical / high_distinctive / high_extreme`，每字段另外显示有含义的名字。疲劳为 0 的解释应是充分恢复，而不是临床异常。

精确逆映射对应 `Φ(-2)≈0.02275`、`Φ(-1)≈0.15866`、`Φ(1)≈0.84134`、`Φ(2)≈0.97725`；用户给出的 0.025/0.16/0.84/0.975 是近似分界。两套都可配置，但同一次实验须固定其中一套。实际求 `Φ⁻¹` 时需处理 0/1 的无穷端点；直接区间判定则无须求逆函数。将 u 当作计算坐标不等于已经用人群数据校准出了真实百分位。

### 候选实现 A：状态仍加减，后续函数切换斜率

继续 `s_next=clip(s+Δs)`。在实际消费 s 的位置配置 `ResponseProfile`，声明字段、分界、各段参数、用途与版本。以高侧响应为例：

```text
h(s) = a0*s + a1*max(0,s-0.84) + a2*max(0,s-0.975)
```

这在阈值两侧连续，但斜率不同：普通疲劳平缓提高恢复倾向，较高疲劳加速提高，极高疲劳进一步改变权重。低侧需要另设分支；不要用绝对偏离把方向抹掉。这里的系数需要比较后确定。

### 候选实现 B：阶段改变具体加工策略

若只换斜率仍不足以表达用户的“质变”，在 D 或具体 updater 中用阶段选择不同策略，例如极端疲劳下对高认知负荷行动增加强惩罚、降低任务切换容忍度，恢复后再回到原策略。该规则影响人物侧偏好/加工；只有明确的物理失能才改变 W 的合法动作。

阶段最好由连续状态派生，不额外保存同义状态。若出现边界反复跨越导致动作抖动，可比较带滞回的版本：如 0.84 进入高疲劳、低于 0.78 才退出。后两阈值只是工程试验值；滞回需要保存 prior regime，它就成为新的历史状态，必须单列消融。

**推荐：** 保留用户 68% 划分作为命名配置 `user_band_v0`；先只给 `fatigue → recovery response` 接入。P 先固定并只调一个门槛或增益，之后再测试某一 P 自身的五段映射。状态存储层不强制所有消费者调用同一个分段器；每个函数可选 identity / 分段 / 平滑 / 阶段策略。

### 验收与研究界限

固定输入扫描整条响应曲线；比较线性、上述分段、平滑非线性，检查斜率、方向、边界跳跃和饱和。需要查看 π(A) 而不仅是同 seed 的一次采样。多步干预中保持外部条件可比，分别做固定输入回放与自主轨迹；自主选择导致世界分叉属于结果，不能再称后续 W 完全相同。

自己写规则再观察它产生阶段变化，只证明实现生效。是否改善未来行为预测，要在独立数据与强 summary/raw-history 基线上比较留出 NLL、校准、成本。分界和超参数只在开发集调整。只有复杂度增加却无稳定收益，就保留较简单的响应函数。

## 4. 第二项修改：拆职责与写入权限，不切断必要心理关系

**当前代码事实：** `Inc/appraisal.h:11` 的 X 仍是九个状态 delta；`Src/state.cpp:21` 单函数处理全部字段；`Src/decision.cpp:182` 根据原始 `WorldOutcome` 写 commitment；`Src/simulation.cpp:140` 收敛了循环，但还未提供可注入的算子实现。低耦合完成了一部分。

建议先拆三个实际替换点：

```text
AppraisalProvider: ΔO + O + old S + P → AppraisalRecord[]
StateDynamics:    old S + X + ActivityExposure + Δt + P → StatePatch
DecisionPolicy:   O + new S + P + A^O → D + π(A)
```

**X 的最小试验 schema：** `evidence_ids, target_goal_id, goal_relevance, goal_congruence, perceived_control, urgency`；后三类连续值支持 unknown，不能缺失就填 0。先不加入全部 appraisal 维度。`coursework` 是客观 task，角色是否在意、期待什么、为什么失望属于自己的 goal/commitment/S。

**身体更新：** 疲劳、饥饿等不应全靠“心理解释”发生。v0 可保持字段存于 S，但把已执行活动与真实持续时间作为有来源的 `ActivityExposure`，交生理/需求 updater；X 处理意义。若以后把客观身体状态移入 W，必须明确感知与生理状态的映射，不能同时保留两个各自独立更新的“真实疲劳”。

**低耦合的实现合同：**

- `Simulation` 给各 updater 同一份只读旧快照；每个 updater 输出 patch，统一提交，避免调用顺序偷偷改变模型。若本来就需要分阶段依赖，明确 phase 和输入版本。
- 每字段有唯一写入者；多个影响可贡献具名项，由该字段 updater 合成并裁剪一次。心理上的 `pressure → anxiety` 保留为显式输入，不能为解耦而删掉。
- 明确 reads / writes / triggers / config / disabled behavior；构造时注入函数或小接口即可，无须先做 DLL、反射、通用插件容器。
- 时间恢复与事件冲击分开：事件按 ID 消费一次；时间项按各字段自己的 elapsed 更新。拆分 60 分钟为两段时，无新事件的恢复应在声明误差内一致，不能重复获得一次“休息奖励”。
- `CommitmentUpdater` 消费角色可获得的反馈，提交、开始、完成、失败各有时点。W 接受一次学习后可记录角色知道自己开始；远端 task 完成不能因原始 outcome 自动清除承诺。
- 分段响应随相应算子关闭；不能残留对 policy 或其他字段的间接影响。允许模块内部复杂，模块外靠稳定数据合同协作。

这些接口是我们对现有框架的工程提案；论文为状态/解释/动力学区分提供启发，并没有替我们验证 C++ 插件结构。

## 5. 第三项修改：落实 Scene 的组合动作，而非只在文档里分层

### 当前与目标的差距

- `Inc/action.h`：ActionType 是独立 enum，没有 C++ 继承关系。
- `Inc/object.h:15`：Object 持有 `vector<ActionType>`。
- `Src/scene.cpp:5`：初始化床、门、桌等，直接将如厕/取餐挂在门上；该文件没有场景组合规则。
- `Src/world.cpp`：全局 switch 承担合法性、动作展开和后果结算。

因此用户的目标分工是正确恢复出的原设计，**当前实现并没有完整做到**。

### 建议的数据归属

```text
ObjectDefinition: 基础交互能力/局部动作及其局部条件
SceneDefinition:  人工编写的 ActionRecipe，组合对象能力、角色位置、出口与任务
ActionRequest:    recipe_id + actor_id + object_bindings + optional task_id
World executor:   在当前 W 绑定、复核 recipe、生成并结算强类型原子效果
```

例子：床提供躺/休息的基础交互，手机提供浏览；Scene 写“上床玩手机”的 recipe，绑定具体床和手机。门提供通行，Scene 的出口定义才指定可达卫生间/取餐服务。`go_to_bathroom` 仍可合并为一次结算和时间跳跃，不要求实现走路动画。

Object 的“基础动作/affordance”也不等于引擎 `WorldPrimitive`：前者是物品提供的交互，后者是程序实际写入世界的操作。组合可在 Scene 定义，但提交者不能自行注入“钱包 +100” primitive；W 根据可信定义自行生成。

先支持一个实际组合与具体对象绑定，验证同房间两部手机不会被 `ActionType` 去重合成一部。后续同语义 recipe 可复用 policy；有新语义的动作仍需要 effect feature/评估规则，不承诺任意新动作完全零代码。

### 必须一起解决的 O 边界

当前 `Src/observation.cpp:155` 从 `world.available_actions()` 取 A^O。物品可见但某个隐藏条件失效时，动作会先从候选集中消失；角色等于提前获得 W 的答案。这在当前公开房间假设下能跑，做信息干预就不够。

建议让同一 recipe 定义有两种条件解析：W 依据真值产生实际可执行集；角色依据 O 产生“知道/认为可以尝试”的集合，对未知条件保留 uncertainty。于是 A^O 不必是当前 A^W 的子集：角色可以合理尝试一扇不知道已锁的门，W 拒绝，反馈再更新 O。身体疲劳导致不想做，也不能和物理上做不了混为一项。

这是对现有 A^W→A^O 记号的**建议澄清**，不是静默宣布已经改造完毕。全知房间可使二者相等，但接口必须容纳错误信念。
