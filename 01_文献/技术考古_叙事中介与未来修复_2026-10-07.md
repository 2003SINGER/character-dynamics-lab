## 1. Mimesis / reactive narrative mediation（2003）

**E：**Riedl、Saretto、Young，*Managing Interaction Between Users and Agents in a Multi-Agent Storytelling Environment*，AAMAS 2003；[作者原件](https://sites.cc.gatech.edu/fac/riedl/pubs/riedl-young-aamas03.pdf)，重点 §3.3–4.2。对象是有因果结构的部分序故事计划，不是按关键词检索剧情分支。

| 考古字段 | 实际机制 |
|---|---|
| 1 控制问题 | 用户可做计划外动作；系统在用户控制与原故事连贯之间处理冲突 |
| 2 保存对象 | POCL steps、ordering/binding constraints、causal links，以及 exceptional action 对应的 contingency policy |
| 3 输入→输出 | 初始 W、动作 operators、叙事目标与计划 → 运行故事及对异常的 accommodation/intervention |
| 4 触发 | 因果链接的 establishing step 已发生、consumer 在未来；用户可行 action 的 effect 否定链接 literal，并落在威胁区间 |
| 5 搜索/修复 | 扫描 causal links 与可统一的用户 operators，提前生成 contingencies；运行时按动作和区间查 policy；接纳异常后修未执行计划，或用替代结果保原计划 |
| 6 作者工作 | 世界 operators 的 preconditions/effects、目标、替代失败方式及故事评价；可达新计划不自动等于好故事 |
| 7 LLM 可补哪里（I） | 提出替代事件/repair 候选，或协助整理 domain；不能自证 operator 真实，更不能偷偷取消玩家已生效动作 |
| 8 可吸收机制（D） | causal-link threat 检测；把 accept-and-repair 与 prevent/alter-effect 分开；保存修复前后的未来与变更理由 |
| 9 与本项目边界 | 原系统的 intervention 可以把玩家成功改成 miss/jam；如果本项目承诺真实后果，就不能把这种干預伪装成 accommodation |
| 10 baseline/ablation 候选 | no-repair、future-only accommodation、允许 intervention 分条件比较；本轮仅提出比较，不运行 |

`s_establish --literal--> s_consume` 是未来动作前置条件的支持边。用户动作并非计划的一步，不足以构成 exception：还必须有破坏支持边的效果。**consistent** 的计划外行动可以被允许；**constituent** 是计划中的用户步骤。

为复核整理的控制骨架（不是原代码逐行抄写）：

```text
对每条 still-needed causal link 和合法用户动作：
    若 effect 与 protected literal 相矛盾、时间区间允许威胁：
        搜索“保留实际异常结果”的剩余计划
        另列“替代异常结果”的 intervention
        以 history/current action/future 的故事质量启发式比较
运行时匹配实际动作及当时区间，采用相应 contingency
```

**E：**原件明确提醒：accommodation 可能让已发生事件失去未来用途；intervention 太显眼会损伤用户控制感。因此“过去字节未变”不是叙事连贯已获保证。质量启发式是接口，不是作者给出一套通用人物连续性模型；不能宣称原文已证明最小成本 repair 或玩家评分提升。

## 2. 2005 branching story graphs：能力，不是效率证明

**E：**Riedl、Young，*From Linear Story Generation to Branching Story Graphs*，[AIIDE 2005 原件](https://ojs.aaai.org/index.php/AIIDE/article/download/18725/18502/22367)，6 页委派全文审读。它从单条因果计划及 exceptional actions 生成 contingency graph，表达能力论证针对 **acyclic** branching stories。不要把 2005 AIIDE 与后来的期刊版本年份混用。

保存的是计划节点及例外转移边；输入仍是 domain/initial state/goal/线性计划，输出是多个可达 contingency plans。预生成的树/图会把运行时压力搬到展开与存储；“能表达作者的分支”不等于“不需要作者 domain”，也不证明大世界效率或活人感。可借作**固定分支策略基线**，不把全部 graph 离线穷举当默认工程方案。

## 3. 2013 bidirectional accommodation：竟能改隐藏过去

**E：**Robertson、Young，*Modelling Character Knowledge in Plan-Based Interactive Narrative to Extend Accomodative Mediation*，[AIIDE workshop 原件](https://ojs.aaai.org/index.php/AIIDE/article/download/12624/12472)，印刷 pp.93–96；委派全文，主代理复核 Algorithm/Knowledge Annotation/Policy Generation/Bidirectional Accommodation。

| 考古字段 | 实际机制 |
|---|---|
| 1 控制问题 | 仅改未来可能无解；玩家没见过的过去是否能改而不与所知冲突 |
| 2 保存对象 | POCL plan + 用户可能观察到的 steps/effects 数据库；因果/排序约束仍在 |
| 3 输入→输出 | 完整计划、异常步骤、观察模型 → 不破坏已观察事实的重规划 contingency |
| 4 触发 | 原 causal-link threat；主要在运行前生成 policy，不是已经测成实时大世界恢复 |
| 5 搜索/修复 | 删显式排在异常之后的事件；建 possible-knowledge DB；再删异常之前 guaranteed-unobserved 部分；UCPOP refinement 解决 flaws，可在异常前/后插 steps，同时保护所有观察约束 |
| 6 作者工作 | domain operators、目标、位置/可见性语义；“可见即知道”的抽象不免费 |
| 7 LLM 可补哪里（I） | 候选桥接情节，但不能决定过去是否允许重写 |
| 8 可吸收机制（D） | 把已观察约束作为 repair 的硬保护集；审查新计划是否产生回溯冲突 |
| 9 与本项目边界 | **与 authoritative W + persistent execution history 的“过去不改”冲突**；只能单列为 latent-history 分支，不能默默搬入 Kernel |
| 10 baseline/ablation 候选 | frozen-past vs unobserved-past-editable 的权限消融；须先确认应用是否允许后者 |

**E：**部分序计划的所有合法 total orderings 下，只要角色可能同处一地，就保守认作可能观察。看不到 step 不表示看不到其 effect；effect 观察状态不确定时会把 establishing step 纳入保护。这会缩小可修复空间，不能简化成“没渲染的地方随便改”。该短文没有受控玩家研究或运行成本基准。

## 4. 2017 probabilistic mediation：概率从哪里来

**E：**Robertson、Young，*Narrative Mediation as Probabilistic Planning*，[AIIDE workshop 原件](https://ojs.aaai.org/index.php/AIIDE/article/download/12992/12840/16509)，4 页委派全文。输入是 grounded deterministic PDDL 故事域及玩家身份，输出是 probabilistic planning domain / 状态到 system action 的 policy。

它把原来分支由“用户可以选择哪个 action”造成的不确定性改写为 probabilistic outcomes：删除 system pool 中玩家 operator 的复制品，组合具有相交可执行前提的玩家选项；这些玩家 choice actions 不受 NPC controller 直接控制。NPC/system actions 仍是 deterministic、可控；系统与玩家采用 turn-taking。

原示例在两个合法玩家动作间给 `0.5/0.5`，单动作给 1。**这不是训练好的玩家偏好，也不是演员主观 `π(a|O)`。** 小型 Arthur/剑的符号例子说明翻译路线，未给多角色心理、完整 RPG 性能或玩家实测概率。作者手工工作仍有 domain、玩家动作集和原目标。LLM 可以提出 probability model，但估计值必须另校准；不能把 uniform baseline 自称真实玩家。

可吸收的是“对多个玩家未来取 expectation”及 controllable/uncontrollable 分离，不能原封不动搬它的全知 policy 当 actor policy。若未来做 rollout：固定玩家模型及其误差单列报告，最少比较 uniform 与另外一个独立模型；本轮不扩 NPC stochastic planning。

## 5. 手推一个真的 causal-link exception

**I：项目自制教学例，不是论文实验。**计划：`give_key(A)` 建立 `has_key(A)`，未来 `unlock(A,door)` 需要它；再去档案室取账本。玩家在中间成功 `destroy_key(A)`，effect 为 `¬has_key(A)`。

| 阶段 | 原始/候选行为 | 不变量核查 |
|---|---|---|
| 原计划 | give_key → unlock → retrieve_ledger | `has_key` 支持 unlock；retrieve 另需 `door_open` |
| exception | destroy_key 已被 W 接受 | 时间处在 key 的 establisher 与 consumer 之间，效果否定同一 literal；不是只因“玩家偏离”就罚 |
| intervention 候选 | 宣称钥匙没销毁、掉进缝里还能捡 | 改玩家已生效后果；若冻结历史则拒绝此候选 |
| accommodation 候选 A | ask_caretaker → lend_spare_key → unlock | 只有 caretaker 活着、能接触、确有 spare key、愿借且 A 获知这些事实才可执行 |
| 候选 B | forged “此前已藏第二把钥匙” | 在 authoritative frozen W 中不能补造已发生事实；2013 可编辑 latent-history 条件不自动适用 |
| 无合法 bridge | 记录目标当前不可达，换作者允许分支/停在失败 | 不把“需要目标可达”当成有合法 operator 的证明 |

对应最小修复是替换 **unlock 的支持链**，不撤销 give_key、destroy_key；但旧 give_key 现在意义改变，仍需玩家解释/评价。若 caretaker 原本正承担别的任务，合法借钥匙也不足以证明他会无条件帮助。**因果修复、角色意图解释、作者目标达成是三道不同门。**人物意图比较见[导演与意图考古](技术考古_导演优化与人物意图_2026-10-07.md)。

## 6. 本轮吸收结论

**D：**先采用上述表示法在纸上对照，不新增 runtime 字段或导演。未来-only repair 与 hidden-history rewrite 必须分开授权；已经出现的事实与玩家成功后果不能为了通关被隐性否定。

**Q：**本项目一个 narrative node 到底是 fact milestone、已执行事件还是作者 locked passage，目前尚未冻结；概率/目标连续性都是比较对象，不是已选的新算法。没有从本轮考古得到“通用 NPC 框架已成立”的结论。

源码吸收的具体缺口：2003 原文把高效 re-planning 的完整程序留在本文范围之外；本页还原的是 exception matching、policy/strategy 与边界，不是已取得该 re-planner 的完整实现。未来原件复现须补具体 planner 和 failure-mode 库，不能用说明性骨架冒充原算法源码。
