## 2. 空白①：HTN 规划

### 2.1 六项提取

| 来源 | 输入 | 表示 | 更新 | P 的位置 | 动作接口 | 验证 |
|---|---|---|---|---|---|---|
| **HTN Ch12 (Humphreys 2013)** | 传感器 → 编码进 world state | world state = **按 enum 索引的属性向量** | 无跨轮内部状态；primitive task 的 effects 改 world state | — | 复合任务分解为方法（按**方法顺序 = 优先级**），产出 primitive 序列，由 plan runner 执行 | 工程案例（Transformers: Fall of Cybertron）；与同厂前作 GOAP 版（War for Cybertron）做**速度对比** |
| **SHPE (Menif et al. 2014)** | 一阶谓词 / state-variables | PDDL 式 domain + HTN method（SHOP/SHOP2 形式） | — | — | 每个 primitive 拆为 `applicable` / `apply` / `cost` 三函数 | SimpleFPS domain 上的**毫秒级**性能测量（<3 ms） |

### 2.2 可直接搬走的五条

**(a) world state 是"角色所知的世界"，不是世界本身。** 原文：

> "this would be a representation that describes what our troll knows about the world and himself in it. Other types of behavior algorithms might query the actual state of different objects in the world... But with HTN, this information needs to be encoded into something it can understand, called the world state."

且明确"world state only needs to represent what is needed for the HTN to make decisions"，还特意举了抽象化例子（用 `WsEnemyRange ∈ {Melee, View, OutOf}` 而不是实际距离）。**这是 O 而非 W 的工程实现，且是 2012 年 shipped 产品的标准做法。** 见 §5。

**(b) Expected effects：只在规划与计划校验期生效的效果。** 原文 §12.7：

> "Expected effects are effects that get applied to the world state **only during planning and plan validation**. The idea here is that you can express changes in the world state that **should** happen based on tasks being executed."

即：agent 对未来的**预期**与实际结算被显式分成两类效果。这与项目 `W′` 与角色预期之间的落差是同一件事，只是 HTN 把它做成了工程字段。

**(c) 计划中断与优先级：Method Traversal Record (MTR)。** §12.8 指出计划执行中若 world state 变化会触发重规划，导致"仍然有效的当前计划"被无故中断。解法是把每个复合任务选中的方法编号记录成 MTR，新计划的方法编号全部 ≤（更高优先级）才允许替换。**这是一个可搬的承诺/优先级编码方式**，比项目当前的 `commitment_can_bias_study` 布尔门槛更具表达力。

**(d) 不要因自己造成的世界变化而重规划。** §12.8 末尾：任务自身 effects 引起的 world state 变化**不应**触发重规划，因为计划本来就是带着这些变化算出来的。否则会出现"第三次 trunk slam 直接接上旋风攻击、跳过恢复动作"的 bug。**项目若加了"事件驱动重新决策"，需防止同类自触发抖动。**

**(e) 前向分解 vs 后向搜索——直接对应"只决策下一步"。** §12.10：

> "Partial planning... allows the planner the ability to not fully decompose a complete plan. HTN is able to do this because it uses forward decomposition... GOAP and STRIPS planner variants, on the other hand, use a backward search... the planner has to complete the entire search in order to know what first step to take."
>
> "There isn't much point to planning too far into the future since there is a good chance the world state could change, forcing our troll to make a different decision."

**这条为项目"每轮只输出下一行为分布"的 D 层设计提供了正面工程依据**，而且是相对 GOAP 的明确优势论证。这是本次核读中少见的、对项目有利的先例。

### 2.3 规模参考（对 T19 有用，但须注明域差异）

SHPE 2014 引述的对 Killzone 3 与 Transformers 3 的实测研究：① 计划长度**几乎不超过 4 个动作**（最长 12，罕见）；② 同时交给规划系统处理的 NPC **少于一个班（<12）**；③ 平均每 NPC 每秒约生成 1 个计划。

`[项目推测]` 这可作为 T19 多 horizon 曲线设计时"近端 horizon（<10 步）才有工程参照"的旁证，但**域差异极大**：上述是射击游戏的战术规划，不是小房间微行为的长程状态动力学，不能直接外推。

## 3. 空白②：智能对象与 affordance

### 3.1 正式化：Şahin et al. 2007

论文先综述了四种已有形式化（Turvey 的 disposition、Stoffregen、Chemero 等），指出围绕 affordance 的混乱源于**三个视角被混为一谈**，然后给出自己的形式化。**Definition 2（agent 视角）**：

> "An affordance is an acquired relation between a certain effect and a (entity, behavior) tuple, such that when the agent applies the behavior on the entity, the effect is generated."

形式化为 `(effect, (entity, behavior))`，实例：`(lifted, (black-can, lift-with-right-hand))`。

三条对项目 Q05 直接有用的性质：

1. **三个分量全部以 agent 的感知为准。** 原文："all three components are assumed to be sensed by the agent... The entity refers not to an abstract concept of an entity (such as a stone) but to its perceptual representation by the agent." 且 "we assume that this relation **resides within the interacting agent**."
   → 这正是 Q05 要的"Object 提供基础动作"的**主观版本**：affordance 不是 Object 的客观属性，而是角色与对象交互习得的三元关系，存在角色一侧。
2. **以 effect 为索引，可直接当规划算子用。** §6 原文：affordance relation "is indexed by its effect"，其中 entity/behavior "can be considered to correspond to the pre-condition and [effect]" of planning operators。
   → 这条把 affordance 与 GOAP / STRIPS 的 precondition-effect 结构接上了，Q05 的 recipe 可以同时是 affordance 关系和规划算子。
3. **三个视角显式分离**（Definition 3/4/5）：agent 视角 `(effect, (entity, behavior))`、观察者视角 `(effect, (agent, (entity, behavior)))`、环境视角 `(effect, (agent, behavior))`。
   → `[项目推测]` 观察者视角可用于"角色看到另一个角色做了什么"，是未来多角色分支的形式基础；本次不主张。

**诚实边界**：该文是机器人控制论文，验证是实体机器人上的初步实验（学习 lift-ability 等），**与游戏 NPC、与心理状态无关**。搬的是形式化骨架，不是任何心理结论。

### 3.2 工程侧：Environment Tactical Querying（Zielinski 2013，Bulletstorm）

这是本次对 **Q04 / Q05 / Q07 / Q08 最有用的一篇**，四个机制逐条对应项目缺口：

**(a) Context object = 主观世界。** 原文：

> "Context object: The game entity that is asking the question (or more precisely **on behalf of whom** the question is being asked)... this actor's properties will be used to define a **subjective world view**, like, 'Is that spot visible from here?' and, 'Is it within my view range?'"

且 "a context object need not be an AI actor"——查询可以代表任意实体提出。生成器之一 "Context Object's Enemies: Gathers all enemies that **a given AI is aware of**"，即候选集从一开始就是**按可知性过滤**的。

**(b) 同一个 test 同时充当硬条件与软权重。** Table 33.1：

| Test | 作为 condition | 作为 weight |
|---|---|---|
| Visibility | Is (not) visible | Prefer (not) visible |
| Distance | More/less/equal to X | Prefer closer/further away |
| Reachable | Is (not) reachable | Prefer (not) reachable |
| Current item | Is (not) current item | Prefer (not) current item |

原文强调 "we decided we'd have **every test make sense in both roles**"。这正面回答了 [Q04](../00_研究设计/未决问题与机制候选.md#q04-主观动作候选与隐藏条件) 与 [Q07](../00_研究设计/未决问题与机制候选.md#q07-commitment-的信息入口和生命周期) 反复纠结的"硬守卫还是软偏好"：**工程上的成熟答案是同一个谓词声明一次、两个用途**，而不是二选一。

**(c) Validity test = 执行期的持续校验。** §33.5.3：

> "ETQ also allows you to designate certain tests as validity tests. These tests will be used not at cover generation time, but later, when an AI is moving to that cover, or sitting in it, to check if the cover is still valid... 'how to pick a cover point and, later, how to tell if it is still good (**oftentimes not the same thing**)' are nicely gathered in one place."

原文给出的两种替代方案（重跑整个查询、或另建一个轻量查询）都被否掉了：前者太贵，后者要维护两份同步。**"oftentimes not the same thing" 一句是 Q05 recipe 与 Q08 组合动作的关键提醒：选择条件与保持条件必须分开声明。**

**(d) 无项通过时按 option 顺序放宽，而非整体失败。** "If a query template has more than one option, then all of them are processed in a sequence until one produces some items which become the result of a query."

### 3.3 另两篇的补充

- **Smart Zones (Game AI Pro 2 Ch11)**：给出 `Scene` 组合的 authoring 结构——角色（role）→ 行为集 → 时间线编排 → 同步点 → 触发器。**关键中断语义**："For a given synchronization point, when all the behaviors executed by **main roles** end, it leads to the **cancellation of the behaviors of all the other nonmain roles**." 即组合动作的取消是按"主角色"传播的。这与 Q08 的"组合 action 是否原子"直接相关。另：Smart Zone 可重叠，须定义场景间优先级。
- **Possibility Maps (Game AI Pro 2 Ch7, Manslow)**：对**未被观测**的世界状态维护 possibility / probability 分布，按传播规则演化，**只在玩家观测可能与之冲突时才实例化**真值，并支持 **forking** 以推迟决策。机制上极像项目的 `O`（含 stale / unknown），且明确要求"与观测历史一致"。
  **但方向相反、必须标注**：Manslow 的目标是**推迟并回避提交真值**（level-of-detail + 制造"看起来很聪明"的假象，作者自己称为 technically cheating）；项目需要的是**已提交的 ground truth 与角色信念的对照**，用于预测评测。机制可借，目标不能混。

## 4. 空白③：组合动作的中断、部分失败与恢复

### 4.1 Côté 2013（Game AI Pro Ch11）的核心划分

> "reactivity is mostly about **interruptions** while deliberation is mostly about **sustaining states**... Any attempt to conciliate them using a unique model is trying to represent **conceptual antipodes**."

要点：

1. **反应分两类、有优先级**：involuntary（疼痛、窒息、打喷嚏）优先于 cognitive（需情境解释的，如"图书馆里的巨响"）；同类 involuntary 之间还有优先级；可同时发生。
2. **Deliberation 的触发源有两个**：当前动作/计划完成；或上下文变化使当前动作/计划**失效**。
3. **Action Selector 架构**：Deliberation 与 Reactivity 各自使用**独立的决策模型和独立的概念模型**，由 Action Selector 仲裁；Selector 负责**取消当前 deliberate 动作**并通知 Deliberation 重新决策。
4. **决策与执行分离**（§11.4.3）：procedural knowledge 描述两件事——"the decision model to **execute** the task" 和 "the decision model to **manage** the task (e.g., **starting conditions, canceling conditions, completing conditions**)"，并给出三层架构（Deliberating / Sequencing / Controlling Layer）。

**对项目 Q07 的直接判定：项目的 commitment 目前只有"开始"和"完成"两态（None/Active/Suspended），缺的正是原文列出的 canceling conditions。** 这不是新发明，是 2013 年就已明确列出的三类条件之一。

### 4.2 关于 Q01 的滞回：先例存在，但动机不同

Côté §11.3.1 用一整段讲感知抖动导致行为震荡（视线时断时续 → Chase/Patrol 反复切换），解法是：

> "we can solve this issue by hooking the transition's threat-sighted symbol to a **logical representation** of seeing/losing a threat... that would include some form of **filtering (using hysteresis algorithms or other similar methods)** to avoid creating undesirable oscillations."

**必须区分清楚**：这里的滞回用于**感知过滤以避免行为震荡**，不是 [Q01](../00_研究设计/未决问题与机制候选.md#q01-分段逆映射与量变质变) 想要的"量变引起质变"。两者都会用到滞回，但**动机与验收标准完全不同**——Q01 若引用本篇作为依据，只能支撑"用过滤避免抖动"，不能支撑"分段消费函数产生质变"。

### 4.3 部分执行与后台任务（HTN §12.9）

> "we can have the navigation task **start the path following and complete immediately**, since the path following is happening in the background and not as a task in the plan runner. This frees us to plan during navigation... This works as long as we have a world state that describes that we are **navigating** and the current distance to the destination."

即"长动作立即返回、用 world state 表示其在后台进行"。这直接回应 [Q08](../00_研究设计/未决问题与机制候选.md#q08-时间中断与后果可追溯性) 的"组合 action 需决定原子执行、可中断/部分失败"。原文还给了另一种做法（双 planner 分管上下半身）并明确**不推荐**（性能、同步、调试三重代价）。

### 4.4 Dual-Utility（Dill 2015）的 rank 机制

四步算法：① 剔除 weight ≤ 0 的选项（设计者用它标记"不可用"）；② 取最高 rank 类别，剔除其他类别；③ 在剩余项里剔除 weight 远低于最优者（可选，百分比可配）；④ 在剩余项里做 weight-based random。

Zoo Tycoon 2 的用法**与承诺高度同构**：
- 常规需求（饥饿/娱乐/如厕）rank = 0，weight 随情境变化；
- 考拉爬上树 → 树上相关行为 rank 提到约 5，"ensure that the animal didn't pick some other behavior and **pop out of the tree unrealistically**"；
- 海洋动物表演 → 由简单 FSM 协调，rank 98–102，**保证任一时刻的最佳动作被选中**；
- 死亡行为 rank = 1,000,000。

`[项目推测]` 项目当前的"commitment 给学习加 bonus"本质是一种 **weight 调制**；而上述先例显示，**情境性承诺在工程上更常实现为 rank 调制（类别切换）而非 weight 加减**。这可能是 T01 的一个更简洁的选项，但需实验验证，不代决。

## 5. 本次最重要的发现：`W ≠ O` 有比预想更强的先例

上一轮[三方向核读 §2](专题核读_三方向近邻_2026-09-05.md) 判定"由状态产生行为分布 + 承诺惯性 + 目标分桶 + SmartObject + 前置条件校验"不能作为新颖性主张，并留下三条可能站得住的差异，其中第 ① 条是 **`W ≠ O` 作为架构不变量**。本次调查三块空白时撞见了它的直接先例。

### 5.1 Talk of the Town（Ryan & Mateas 2017）——最完整的一个

该项目把"角色知道什么"与"世界实际是什么"做成了带显式对照的数据结构：

- **ground-truth 与信念显式分离**。原文："A given character attribute will have a type (e.g., hair color) and a **ground-truth value** (e.g., brown), but a **belief facet** corresponding to it will represent a character's **potentially false belief** about that attribute (e.g., black)."
- **系统侧追踪、角色侧不可见**。每个 belief facet 带 `Predecessor` / `Parents` / `Evidence` / `Strength` / **`Accuracy`（该信念相对当前世界真值是否准确）**。原文对 predecessor 链："we do not plan to give NPCs access to these data."
- **证据类型学（11 类 5 组）**：起源（Reflection / Observation / Transference / Confabulation / Lie / Implant）、自我强化（Declaration）、劣化（Mutation）、终止（Forgetting）；每条证据带 Source / Location / Time / Strength。
- **信念修正**："If the new evidence is stronger, he or she will adopt the new belief that it supports; if it is weaker, he or she will **not** adopt a new belief, but will still keep track of the other candidate belief and the evidence for it."
- **记忆不可靠建模**：transference / confabulation / mutation / forgetting，其中 mutation 由手工编制的 **belief mutation graph** 给出转移概率。原文："**Belief oscillation is possible, as such, but that is an appeal of the design.**"
- 规模：300–500 NPC，每个 NPC 250–400 个 mental model、800–1200 个 belief facet；NPC 行为选择用 **utility-based action selection**（Mark 2009）。

**判定**：`W ≠ O` 的架构不变量、per-agent 信念、错误信念、来源追踪、系统性地区分"系统知道"与"角色可访问"，**在这套已实现的系统中都已具备**，且明确以 `Accuracy` 字段做真值对照。本项目的 ① 若照原样主张，会被这一条直接覆盖。

### 5.2 另外两条佐证

- **HTN world state**（§2.2a）：agent 推理所依据的是"troll knows about the world"，不是世界对象本身，且刻意抽象化。
- **ETQ context object**（§3.2a）：查询显式"on behalf of"某实体，用于定义 **subjective world view**；候选生成器按"AI is aware of"过滤。

### 5.3 但仍然存在的差异（均为待验证，非已确认空白）

Talk of the Town 与项目在**建模对象**上不同构，这是唯一还能站的地方：

| 维度 | Talk of the Town | 本项目 |
|---|---|---|
| 信念内容 | 关于**实体属性**的事实（发色、职业、行踪） | 关于**事件意义**的评估（X）与**内部状态**（S） |
| 是否有 appraisal 层 | 无 | 有（X） |
| 是否有跨轮内部状态动力学 | 无（status/belief 只有 strength 与遗忘） | 有（每字段独立 U_k） |
| 是否有 P 调制 | 仅有 memory / extroversion 等少数属性影响概率 | P 多处作用（Q09） |
| 评测目标 | 游戏可玩性、叙事效果 | held-out 下一行为预测 + 校准 + 成本 |

`[项目推测]` 真正未被覆盖的可能是：**把 appraisal（X）与 per-field 动力学（U_k）接到 `W≠O` 之上，并用 held-out 下一行为预测来评测**。注意这里含两层，须分开验证：
- **`W≠O` 本身**：已被覆盖，不能主张；
- **`X` / `U_k` 与其组合的预测收益**：在已核读文献中未见先例，但**也未被证伪**——本次与上一轮都没有找到"用 appraisal 状态做 held-out 行为预测"的对照工作。这正是 [T22](../00_研究设计/TODO.md) 的可证伪链要测的东西。

### 5.4 Comme il Faut 缺口已补上

上一轮[三方向核读](专题核读_三方向近邻_2026-09-05.md) §4.1 把 "Comme il Faut (AIIDE 2011)" 记为"三个方向中最大的缺口"。本次取到 **Mateas & McCoy 本人撰写的 CiF 架构章节**（Game AI Pro 卷一 Ch43），该缺口**已关闭**，README 中"PDF 待取得"的条目应更新。

CiF 中与项目直接相关的四点：

1. **Traits（永久）vs Statuses（临时、有方向、二值、带 duration）**——与项目的 `P`（运行内固定）/`S`（各字段自有动力学）高度同构，且 CiF 明确把 status 的超时作为一等字段。
2. **Social networks（私有的、数值的、可 asymmetric）vs Relationships（公开承认的、二值）**。原文："Social network values are the **private feelings** characters feel towards each other. Just because two characters have mutually high friendly feelings towards each other does not mean that they automatically have the publicly recognized social state of being friends."
   **私有感受要变成公开关系，必须经过一次 social exchange。** 这正是[研究问题页 §7](../00_研究设计/前台问题与候选创新.md) 保留分支里"误解经行动成为新事实"的现成先例。
3. **Influence rules：谓词逻辑左部 → 数值权重右部**。原文："By having predicate calculus expressions on the left-hand side of rules, but having them add weights to a sum on the right-hand side, the rules work together to compute a complex utility surface." 且明确"**preconditions are used very sparingly**, only to encode the minimum conditions... to make sense"。
4. **SFKB（社会事实知识库）**：记录每一次 exchange 的完整条目（参与者、分数、时间、effectID、抽象标签），可用 `[SFKBLabel(mean, responder, initiator, 0) window(10)]` 做带窗口的历史查询。
   **注意方向相反**：CiF 保留**完整历史并查询它**，不是压缩成状态。因此 CiF 对 [R01](../00_研究设计/前台问题与候选创新.md) 而言是**强 raw-history 基线的代表**，不是状态压缩的代表。

作者自陈的局限（须如实记录）："The same critique applies to CiF"——即 Evans 对自己早期工作的批评同样适用于 CiF，把社会实践处理成"角色理所当然知道如何参与的活动"，而非角色 actively 共同维持的活动。
