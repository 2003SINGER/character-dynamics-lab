## 2. 状态轨迹约束不是只管剧情：PDDL3 到地标重规划

**E：[Gerevini & Long 2005 技术报告](https://ipc08.icaps-conference.org/deterministic/data/gerevini-long-tr-2005.pdf)，§§1–3。**其轨迹是带时间的状态序列，约束作用于状态命题，可包含数值比较；动作发生本身须通过适当的状态/事件标记表达。硬约束决定计划合法性，`preference` 与 `is-violated` 支持软罚分，不指定唯一求解器。

```text
always φ                         每个状态都满足 φ
within d φ                       截止 d 至少一次 φ
sometime-before φ ψ              每次 φ 都有严格更早的 ψ
always-within d φ ψ               每次 φ 后 d 内至少一次 ψ
hold-during a b φ                 在规定区间维持 φ
```

**关键纠正：**“先证据、后指控”应写 `(sometime-before accuse evidence)`，不是交换参数。它不要求指控最终发生；需要发生时另加 achievement。持续的 `knows_A` 每步都成立，会反复触发 `always-within`；“首次得知后响应一次”应绑定知识获得事件或一次性 obligation。这是状态与事件的区别，不是把文字换成公式便解决。

**E：[Porteous, Cavazza & Charles 2010](https://doi.org/10.1145/1869397.1869399)，TIST 1(2)，Algorithm 1 与 §§2.4–4.2。**域含位置、活动、关系/阵营、视角等谓词和带 pre/add/delete 的算子。约束节点与先后边组成图；选择当前最早的相关地标，把它作为 FF 的子目标，逐动作执行。玩家修改状态或视角后，目标仍适用则重规划当前子问题，否则转下一个地标；最终还处理总目标。实验中并列选择并非最优修复搜索。

这已有**人物状态约束→分段计划→玩家干扰→当前段重规划**，并接游戏可视化。其 visited 标记不能直接当所有约束的严格完成证明。2026-10-08 原图复核还确认 Algorithm 1 line 12 在 planner-success if 之外，无解也会标 visited；具体分支与反事实例以[算法卡](算法积木/02_人物意图与约束规划.md#卡-3pddl3-轨迹约束规格--porteous-2010-地标-ff-重规划)为维护入口。论文未给多 NPC 最小依赖修复或受控总作者工时证据。

**I：具体吸收。**可以借 `constraint DAG + 当前子目标 + 可执行算子 + 失效触发`，而不是重新发明“点之间接桥”。本项目要比较的增量若是保留其他有效活动，必须与这一局部重规划基线分开，不与从头写故事的弱基线单独比较。

## 3. STL 可以监测“线”，MPC 能否控制取决于模型

**E：[Raman 等 2017 扩展稿](https://arxiv.org/html/1703.09563v1)，§§II–V。**STL 的原子数值裕量经逻辑和时间算子递归组合；MPC 在动力学模型、输入/扰动及相应可编码假设下求未来控制，执行首个控制后再观测、再求解。论文的控制保证不是对任意 NPC 描述的保证。

```text
ρ(¬φ) = −ρ(φ)             ρ(φ ∧ ψ) = min(ρ(φ), ρ(ψ))
ρ(F_[a,b] φ) = max_[a,b] ρ(φ)
ρ(G_[a,b] φ) = min_[a,b] ρ(φ)
```

硬约束必须进可行集合，不能被剧情奖励抵消；已执行历史和原 deadline 必须保留。不同数值谓词的量纲/归一化也不会由这个公式自动解决。

**I：纸面接法与反例。**作者说“24 小时内桥梁停用，48 小时内药物到诊所”，可以先写 `F_[0,24h] bridge_closed ∧ F_[0,48h] medicine_at_clinic`，再用 W 的可查询字段监测。这不保证存在绕路，也不保证商人愿运药。

- 三个阶段各要求一次信任阈值下降，允许阶段间大幅反弹；它不是“逐渐下降”的定义。需决定用上下包络、单调约束、变化率还是只要求阶段节点。
- 每次重规划重新从“现在起 48h”算，会无限推迟原截止；应保存原锚点。
- 只检查 boundary 两端可能漏掉中间越界；必须声明采样/插值/连续积分语义。
- 未来 `F` 在截止前尚无见证是 pending，不是已失败；`G` 已出现违规则立即失败。监测器要区分这个前缀状态。

**D：可先借规格与监测，不承诺人物 MPC。**我们目前没有验证过的角色反应预测模型；手写 Demo coefficient 或 LLM rollout 不自动成为可证明的动力学。关系、承诺和 `S` 若没定义可靠 getter/转移，就只能标为待绑定，不能以数值名字充当科学测量。

## 4. 自然语言到公式：语法、绑定、语义、可达性四个门

**E：[GraFT，ICML 2025](https://proceedings.mlr.press/v267/english25a.html)，方法部分。**用原子命题提取/提升与 lifted sentence→TL 的分解；语法约束参与训练及解码。实验检验的是所用翻译数据，不是游戏状态绑定或人物控制。网上同名 [Dubascudes/GraFT](https://github.com/Dubascudes/GraFT) 自称复现，尚未核实作者归属；不能当官方完整实现，或把 lifted TL 训练当论文全部阶段已复现。

**E：[NL2LTL，AAAI 2023 system demonstration](https://ojs.aaai.org/index.php/AAAI/article/view/27068)。**意图/实体提取到逻辑公式，含人工检查接口；不提供游戏 effects executor。父审 [IBM 源码 BasicFilter](https://github.com/IBM/nl2ltl/blob/main/nl2ltl/filters/simple_filters.py) 看到直接返回原输出；GreedyFilter 筛公式冲突/蕴含，不等于证明译文与作者意图等价。该在线源码未固定 SHA，不算复现。

**E：[T³ Planner，2025 arXiv v1](https://arxiv.org/html/2510.16767v1)，§§II-C、IV。**依次提案任务 waypoint、时间 waypoint、运动控制器，验证失败反馈相应阶段。NL→STL 有人核语法与语义；运动阶段输入显式运动学与速度限制，仿真轨迹再验证。能借层级候选/反馈结构，不能外推为未建模 NPC 的心理或世界控制保证。

**I：四门必须分开，不能只有 parser PASS。**

| 门 | 具体检查 | 必须保留的反例 |
|---|---|---|
| 语法 | AST 类型、作用域、时间单位和公式格式 | 合法公式把先后顺序写反 |
| 状态绑定 | 每个 AP 的实体 ID、getter、W/O 所属、观察来源 | 隐藏 W 真不等于 A 的 O 已更新 |
| 作者语义 | 小轨迹正例/负例、真空满足、持续触发、期限锚点 | 不发生指控也满足 before，但作者原意要求指控发生 |
| 可执行/可达 | 冻结算子、合法干预权限、资源/时间、角色选择假设 | 语义正确却无人愿做，或唯一渡船已毁 |

例如 `believes(A, bridge_open)` 是 A 的信念；`knows(A, bridge_open)` 若取知识的事实性含义，还要求它为真。stale O 可以保留错误信念，不能未经定义就叫“知道”。查不到数据应是 UNKNOWN/待绑定，不应一律当 false。

## 5. 真游戏与“AI 小说”：看谁建立事实，不看有没有文字界面

**E：[STORY2GAME，2025 arXiv v1](https://arxiv.org/html/2505.03547v1)，§§III–V。**把故事编译为实体图、动作前提/effects 和可执行交互小说；玩家未支持动作可触发新动作/属性生成，并按对象相关性修订已有前提。这已含局部依赖检查，不是纯写下一段。但它允许扩域；论文明确不保证原故事最终完成，评价还有预置角色/物体位置来测试动作的步骤。

**E：[WSE-bench，2026 arXiv v1](https://arxiv.org/html/2608.15654v1)，§§3–5、Appendix B。**Story Agent 的叙述建立 canon，WMEM 再抽取 delta 经规则 reducer 更新结构状态；更新失败不等于拒绝已写叙述。其三裁判保留 uncertain，另有盲人类参考检查，不能说全无人工验证；这些一致性/丰富性评价不等于执行 pre/effect 的游戏真值。

**E：[Anansi，ICIDS 2024 / proceedings 2025](https://doi.org/10.1007/978-3-031-78450-7_9)，§5。**社会模拟 tick 更新关系/时间/日程，storylet query 绑定角色，按权重选可用块并控制重复/cooldown；Ink dispatch 触发作者定义的社会 effects。角色绑定是选匹配实例，不是自由改写过去。论文方法及 [v0.5.1 源码版本](https://github.com/ShiJbey/Anansi/tree/1f69f67fc5ac93c69c9eb64cf19612053e9e775c)元信息已核，源码细节未完整取得；rollback/无候选 fallback 不填猜测。

**I：本项目真正要保留的闭环**是“玩家/NPC 提交动作→权威 W 校验并结算→合法 O 更新→后续决定”，叙述解释已提交结果，不能反过来补写未执行成功。文字游戏也能有此闭环；多画一个 3D 角色不自动获得它。

offscreen 可以粗粒度推进，不必模拟每个杯子。只要会影响既有库存、运送、承诺或截止，它就应进入权威状态/日志；只有尚未承诺、无外部依赖的细节，才适合晚绑定。把“没看见”当成任意 retcon 权限会破坏这个目标。

## 6. 局部修复应检查哪种依赖：不能只用语义相似度

**E：[Sabre 作者项目页](https://cs.uky.edu/~sgware/projects/sabre/)及 [AAMAS 2021 扩展摘要](https://cs.uky.edu/~sgware/reading/papers/ware2021sabreposter.pdf)。**集中式规划同时考虑作者效用、人物目标和可能错误的信念，以人物相信可助益自身目标来解释行动。作者知道 W 不意味着角色知道 W。这是强近邻，不能把局部知识+作者目标据为新机制。源码为 CC BY-NC 4.0，商业复用不能按 MIT 处理。

**I：下面是待比较的保守修复流程，不是已实现算法或新颖性证明。**承接 Mimesis 的因果威胁与本轮地标规划：

```text
玩家合法动作已提交 ΔW；冻结过去
dirty ← 被改变事实、时段和资源
affected ← dirty 在显式依赖图上的传递闭包
保留暂未受影响的未来；在冻结域/权限内重接 affected 的支持链
把修复候选与保留部分合并，重新验证全部硬约束和共享资源
合法且可解释才可执行；无解则报告，或请求作者批准已允许分支
```

依赖边至少要含 operator pre/effects、因果支持、负前提、资源容量、时间排序、观察传播、作者约束。**相同地点/词义相近不够；不同 NPC 也可能共享唯一马车。**未声明依赖的 LLM 谓词必须保守扩大 dirty 范围，不能假装有最小修复保证。

本地 `A^O` 在 typed rejection 后删去无效候选是一步尝试约束，并不已经实现此多步计划依赖图。也不能据此重开 Runtime。局部 repair 的保留收益、全局校验成本和保守退化频率都需要比较；“改得少”但更容易无解不是胜利。

### 一个跨层纸面例（自制，不是实验）

已存在药物运送计划：A 商人用马车过桥→诊所；B 卫兵承诺保护车队。作者要求原始起点后 48h 内药到、前 24h B 存活。玩家在 t=6h 合法毁桥，B 目击，A 未知；同时另一居民正履行酒馆会面。

| 层/依赖 | 应有变化 | 不应偷偷发生 |
|---|---|---|
| W / 支持链 | 桥路线失效；检索域中已有渡船及可用运力 | 补造过去预留药物、撤销毁桥 |
| O_A / O_B | B 更新；A 保留 stale belief；合法通信才通知 A | 为便于 planner 直接把 B 所见写给 A |
| 承诺/活动 | 保护对象仍存在，运输路线变了不等于 B 自动放弃承诺 | 重规划把所有角色 goals/活动清空 |
| 无关居民 | 若其会面不依赖桥/马车/时间冲突，暂保留并复验 | 因故事换段就重写其有效未来 |
| 作者约束 | deadline 仍锚在原 t=0；先检查可达与存活约束 | 每次从现在再加 48h、无解时静默删目标 |

渡船+传信是已有算子时可提出的世界路径；A 收到消息后是否愿接受仍需人物机制支持。若玩家又毁掉唯一渡船，系统应承认该硬目标可能不可达，不应复活设施或虚构成功。直接编排 A 动作与经世界消息诱导 A 是不同干预权限，要分别比较，而不是前者成功后宣称后者成立。

## 7. 收敛到可检验问题，而不是先造“统一 NPC 控制论”

**Q：候选问题**——在冻结动作域、稀疏作者约束与合法玩家扰动下，依赖/人物信息感知的 future repair，能否比地标当前段重规划、全量再生成保留更多仍有效的活动，减少新增编排和调试劳动，同时维持可达性与玩家感知连续性？这是候选问题，不是已确认 gap；检索到相同方案应直接吸收或收缩。

| 比较对象 | 同条件下要比较什么 | 不能偷换 |
|---|---|---|
| Porteous 地标重规划 / Mimesis future repair | 失效识别、保留范围、计划合法性、额外作者规则 | 用“纯文本重写”代替现成规划强基线 |
| Sabre 或适配其人物解释机制 | 作者与人物目标/信念冲突如何解 | 我们才首次让角色有目标和知识 |
| 结构化 LLM 全量提案 vs 局部提案 | 候选预算、权限、域、validator 与展示一致 | 更长 prompt/更多调用/新增域与 repair 收益混算 |

作者劳动分别记新内容/算子、映射、审核、调试时间；运行 tokens/延迟另账。World-validity、约束达成、保留有效前缀/活动可先机制检查；活人感/玩家 agency 仍要目标玩家的同展示比较，不能被自创 trust 或 robustness 分数替代。
