# Awash：前瞻故事筛选、干预与玩家评价

阅读日期：2026-10-07。主代理读完大学公开 accepted manuscript 的 20 页，包括参考文献；另渲染核对 PDF 第 10–11 页的 influence table、执行流程与 Table 1。没有运行游戏、核查源码或复现实验。

## 结论

这是一条比“给 NPC 加记忆”更直接的机制先例：**匹配正在形成的事件模式 → 绑定参与角色 → 触发有限时长的行为偏置 → 角色继续随机选择合法动作**。它不是只在结束后从流水账找故事，也不是导演直接指定下一动作。但它改变的是角色决策概率，**不是已证明的 world-only 干预方法**。

它另提供了本项目目前缺少的玩家对照证据：12 人在相同游戏中分别体验有/无干预条件。访谈支持更连贯、个人化的体验；日志中的平均完成模式数却没有增加。不能把该结果改写成“干预提高节点达成率”，也不能从一款小型海盗游戏推广到一般 RPG。

## 计算机制（§3，PDF pp.4–11）

底层 Unity 世界由状态机角色与简单实体组成。每个 AI 从其状态机可行动作中按 behavioural bias 随机选择；动作产生事件流。Narrative Appraiser 与 Drama Manager 是两层，不要与本项目人物的情绪 X/appraisal 混淆。

| 表示 | 字段 / 运算 | 实际作用 |
|---|---|---|
| Narratable event | event type、actor、可选 target、tags；实体用唯一 ID | 从模拟事件抽取可查询记录，不是自然语言再编故事 |
| Pattern template | XML 中按时间排列的 event queries、变量、influence IDs | 作者写可复用微故事；角色身份在匹配时确定 |
| Partial match | entity bindings、未完成事件序列、显式 invalidation queries | 保存已经发生的前缀和可能的后续；完成或失效就移出池 |
| Pool advancement | 每个新事件匹配模板，建立实例；再推进已有 partial matches | 默认 advance-directly，某条查询可指定 fork-and-advance；不采用 expiry 或 implied invalidation |
| Influence table | influence ID → narration / stage direction | 匹配到指定阶段后查表；不是搜索任意世界编辑 |
| Stage direction | actor、target、行为方向、delay、duration | 临时提高某类行为倾向，仍由 AI 自己选择动作；论文未披露精确概率合成式 |

Figure 7 的报复示例包含 **delay=3 moves、duration=12 moves**：一艘船先遭攻击、撤退，模式绑定这两艘船；撤退阶段触发延时的 aggression-to-target 偏置，之后更可能重遇并开火。Figure 8 显示偏置在未发生目标动作时持续，而不是强迫下一步开火。

忠实到论文披露层的伪代码：

```text
on event e:
    create partial matches from templates matching e
    update bound matches with e
    discard explicitly invalidated/completed matches
    for a matched stage carrying an influence ID:
        lookup authored narration / delayed, bounded stage direction
        attach the direction to its bound actor and target
on AI turn:
    choose among state-machine possible actions using biased probabilities
```

注意两个边界：论文没有给可复现的概率变换公式；默认直接推进**减少分叉**，但新事件仍可不断创建新实例，没有 expiry，不能据此声称在任意无限运行中池大小有严格固定上界。

## 评价（§4–6，PDF pp.10–18）

- 12 名大学生，每人体验两种模式各 20 分钟，顺序一半 BM-first、一半 IM-first；参与者不知道条件差别，之后约 30 分钟半结构访谈。
- BM：sifter 只驱动鹦鹉旁白；IM：相同旁白机制再加 stage directions。控制的变量是干预是否启用，不是“有旁白 vs 无旁白”。
- 一名研究者归纳编码，第二名讨论复核；对照日志定位体验发生在哪个条件。编码次数不是人数比例，也不是独立玩家量表的显著性检验。
- Table 1：平均 matched/progressed events 都为 **105**；completed patterns **BM=7、IM=6**；IM 平均有 51 次 stage directions。没有展示模式数的统计检验，不能把正文 “no significant difference” 当作报告了检验统计量。
- Table 2：dramatic harmony 编码 BM=1、IM=11；personal BM=2、IM=12；influenced moments felt organic 19 次、felt artificial 5 次。这支持有限的质性体验结论，不是“19/24 玩家觉得自然”。
- 不自然案例包括给不合适的弱船施加攻击倾向，以及很多船同质响应。机制在类型/角色上下文上失配，比是否采用更复杂的心理模型更直接。
- 小世界、短会话、少量模式；没有作者工时比较、长期 NPC 生活评测或 world-only 干预消融。

## 对本项目的影响

**证据支持：**事件前缀、身份绑定、显式失效、延时/有效期的干预，是可搬的具体结构。节点/故事数量与玩家可理解的因果关系必须分开评价。

**项目推论：**可以把用户的“打几个点”同时表示成可达到状态和事件模式，而不必先选统一叙事大模型。模式筛选适合承接已经发生的历史；要主张前瞻控制，还必须说明其影响的是候选分数、角色目标还是世界条件。这篇论文只实现第一类。

**未证明：**低作者成本、世界中心 NPC 的长期自主感、局部知识隔离，以及稀疏硬节点可靠达成。默认不能用这篇结果证明我们已有这些能力。

**唯一下一动作：**在[专题综合审计](专题调研_稀疏作者约束与世界干预_2026-10-07.md)中对齐“节点表示 × 干预权限 × 历史提交”，再决定一个足以区分近邻的小问题。本轮不实施 stage directions，不改 Runtime 或 Dynamics。
