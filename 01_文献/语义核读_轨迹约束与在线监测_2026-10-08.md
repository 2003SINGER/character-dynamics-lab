## 2. PDDL3必须保留的具体区别

- 轨迹是happenings上的状态序列：always检查全部state，sometime检查某state。持有状态不是acquire动作实例发生。
- sometime-before要求每个触发φ的state之前有ψstate（严格较早）；sometime-after可在同state或之后满足。不要凭中文“之后”替它改成严格时间。
- always-within对满足φ的每个state提出bounded response；持续φ不等于一次event trigger。项目用FIRST/EACH事件实例是明确的另一种activation contract。
- 条件从未为真时经典蕴含可以真空满足；项目另外报告NOT_ACTIVATED防止将未启动义务当剧情成功。作者要触发存在需独立约束。
- at-most-once限制连续真值区间的个数，不是event count≤1。
- hold-during使用半开时间区间；项目每个window显式存开闭。数值窗口单位需实际模拟时间，不将STRIPS索引自动解释成分钟。
- preferences不是项目的数值deficit/混合心理评分；后者如要用需自定义并冻结单位与成本。
- 完整规划轨迹布尔语义不自动提供缺数据/有限前缀在线判定，不能用未到deadline的false冒充violation。

## 3. STL / RoSI的计算而非口号

定义2：数值atom由其函数值给robustness；否定取负，合取取min，G取指定时间窗inf，F取sup。要组合谓词必须同一时刻求值；F(p∧q)不可换成Fp∧Fq。

定义3：prefix固定已知信号，completion集合只允许续接未来。定义4：RoSI上下界为所有completion的robustness inf/sup。未来还可能真/假时interval跨0，不能凭prefix宣布完整成功/失败。

原文§3有明确**piecewise constant interpolation**前提；它不是证明游戏连续状态在两个event boundaries间常值。项目连续S若无可靠证书不能以端点皆安全给hard G成功。对缺失的已过去记录，也不能套成任意未来completion而不标缺证据。

零边界：v1 atom写f(x)>0，而定义2后布尔解释用ρ≥0。项目不继承模糊的零约定，EQ/LE/GE和开闭窗口直接固定。项目不是完整STL实现；不支持的Until/嵌套或连续组合必须显式拒绝。

精确多项式极值/积分、保守数值界、缺失/tombstone、模型pin是项目reference设计；不能说这些算法全来自RoSI论文。一个bounds.upper超过阈值仅说明无法证明安全，不是越界真实见证。

## 4. 对项目的改变与准入反例

| 坏实现 | 必须替换为 |
|---|---|
| 未到期限就false | prefix PENDING；past数据缺口单列INDETERMINATE |
| G只查两端 | 完整coverage和内部极值/可靠证书 |
| upper>threshold就失败 | 保守界跨阈值unknown；真实counterexample才VIOLATED |
| p在t0真、q在t1真就F(p∧q)成功 | 对同一时刻公式求值 |
| 相反F目标自动unsat | 只对足够窄的同锚AT/重叠universal证明冲突 |
| 没触发就剧情通过 | 完整trigger stream的NOT_ACTIVATED，另写trigger existence |

最终判定由确定reference测试而不是LLM评分。本轮的研究边界仍是设计准入；玩家是否认为角色“活起来”、作者总劳动是否减少均未检验。
