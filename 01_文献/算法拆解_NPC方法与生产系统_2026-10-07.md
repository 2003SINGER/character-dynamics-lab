日期：2026-10-07。用户要求：“对于之前的每一种工作，我们需要吸收各个部分的方法，不要用文字抽象，要到算法层！”本页接续[学术路线](专题调研_低编排可控NPC框架_2026-10-06.md)与[世界中心外围调研](专题调研_世界中心NPC的制作障碍与活人感_2026-10-07.md)，覆盖其中的生成机制、模拟机制、作者工具及评价方法；不是全库 82 篇逐篇新精读，也不是新的候选系统设计。

## 1. 本轮交付与证据边界

**交付的是可核查的机制卡，不是“已经移植成功”。**每张卡把作者输入、运行状态、选择/更新程序、参数来源和缺口分开。下列伪代码均为我们的说明性翻译，除特别注明对应原算法外，不是原作者代码，不保证可直接执行。未公开的函数保留为未知，不能用通用 GOAP、BT 或 LLM 流程补成某款游戏的真实实现。

阅读分工：Luna 查找/审读生产原件及三条 LLM 路线，主代理复核关键方法段；主代理本轮全文审读 CiF 2011 六页、IPOCL 2004 八页并核对图示，审读 CiF-CK 2017 pp.2–6 方法、FAtiMA Toolkit 2021 §§1–4.3 与固定源码函数、Praxish 原件 `tick`/条件枚举，以及 Rain World 指定日期开发日志。FEAR/Sims 原件由 Luna 全文核读、主代理核对方法段；不把这些提升为主代理全文精读。Versu 沿用此前委派全文审读及主代理段落复核，尚缺原选择程序的逐项源码核对。

机制证据分三级，**不是效果等级**：

- **A**：核心算法可追到原论文明确步骤/公式或固定源码；仍可能有实现细节缺口。
- **B**：开发者原件可重建部分流程，但关键评分、转换或搜索细节未公开。
- **C**：只有摘要/设计访谈；不能声称掌握该系统算法。

“吸收完成”还需能给定一个具体输入，手算/跟踪输出和状态修改，并列出失败反例。本页提供两个手算例；不把其余卡片自动标成完成，也不因卡片存在而授权改 Runtime、Dynamics、训练或新实验。

## 2. 学术与公开算法

### 2.1 CiF 2011：条件理由加权，不是多步规划〔A〕

来源：[McCoy et al., AIIDE 2011](https://ojs.aaai.org/index.php/AIIDE/article/view/12454)，本地原件 `outputs/literature_sources/npc_authorable_survey_20261006/2011_McCoy_et_al_CiF_AIIDE.pdf`，pp.2–5。

**数据/作者输入：**`SocialExchange(intent, preconditions, initiatorRules, responderRules, effects, instantiations)`；规则由条件谓词和权重组成。状态包括角色 traits/status、关系、社会网络、文化知识和带历史记录的 SFDB。`Microtheory(definition, influenceRules)` 在定义条件成立时贡献可跨 exchange 复用的理由。

**选择与更新：**绑定 initiator/responder/other 后，满足前置条件的 exchange 才进入欲望计算。角色侧分数是成立规则权重之和，加上激活 microtheory 的成立规则。Prom Week 由玩家在角色欲望支持的交换中选择；不能把论文实际交互替换成纯 NPC `argmax`。

```text
for exchange e, role binding b satisfying preconditions:
    volition[e,b] = sum(weights of true exchange influence rules)
                 + sum(weights of true rules in active microtheories)
chosen = application_or_player_selects(volition)
accepted = responder_volition(chosen) >= 0
effect = most_salient_applicable_effect(chosen, accepted)
apply(effect); record_social_exchange_in_SFDB()
evaluate_trigger_rules(); record_triggered_consequences()
play_authored_instantiation_for(effect)
```

**吸收对象：**带角色变量的理由模块、互动后的历史谓词、接受/拒绝的独立计算。权重及台词/动画由作者配置，非已训练 policy。effect 的 salience 精确计算和通用自主选择策略未由这篇论文完整给出；共享社会状态不自动满足项目 actor-local O 权限。失败检查应包括“重复历史理由是否反复占优”，不是只看候选非空。

### 2.2 CiF-CK 2017：交换—Quest 映射与私有关系信念〔A/B〕

来源：[Guimarães et al., CIG 2017 作者副本](https://visualnarrative.ncsu.edu/wp-content/uploads/sites/16/2017/08/GSJ_IEEECIG_2017_CIFCK.pdf)，§III、Tables I–III、§IV；本地 `2017_Guimaraes_CiF_CK_CIG_author_copy.pdf` 与上一卡同来源目录。

**数据/作者输入：**exchange 映射为 Quest；角色槽绑定 Quest Aliases，前置条件映射 Quest Start Conditions，表演映射 dialogue/Scene，效果在终阶段应用。角色有 traits/status、对他人的私有 feelings/preferences 与 beliefs；public relationship/history 放静态共享实体。

```text
for NPC in currently processed location:
    desires = influence_rules(NPC, bound_social_moves, perceived_social_state)
GameManager chooses next social participant  # exact arbitration unspecified
start_bound_Quest(move, initiator, target)
run_authored_Scene_and_response()
on_Quest_success_or_failure:
    apply_final_social_effects()
    evaluate_trigger_rules()
    notify_other_social_NPCs()
```

**吸收对象：**同一行为模板通过参与者绑定复用；区别“对方实际感受”与“我以为对方的感受”；只在交换结束检查 triggers。论文不提供完整信念更新公式或 GameManager 仲裁规则。受 Skyrim 脚本处理范围限制，只考虑玩家所在地点，**不是世界中心全域持续模拟的先例**。这里的 CiF-CK 2017 不等同后来 FAtiMA 内的同名 reasoner。

### 2.3 Versu 2014：活动给选择面，人物另行选择〔B〕

来源：[Evans & Short, IEEE TCIAIG 2014](https://ieeexplore.ieee.org/document/6648395/)，§§IV–V、IX、XI、XIV；[Emily Short 原作者说明](https://emshort.blog/2013/02/14/introducing-versu/)。不再发布带限校声明的课程副本。

**数据/作者输入：**social practice 绑定抽象角色；多个实例提供带上下文的 affordances；人物有对世界状态的欲望与评价；story manager 管理特定作品的戏剧进程。玩家与 NPC 能占同样角色槽，选择来源不同。

```text
C = union(affordances from active practices with bound roles)
C = filter_by_available_context(C)
choice = agent_evaluates_world_state_desires(C)  # exact law not reconstructed here
execute(choice); update_practice_and_social_context()
```

这只是已核部分流程。**原效用聚合、并列处理、多步预测与并发冲突程序尚未在本页核到底**，不可借 Praxish 的代码填空。原作者博客评论区中读者自拟的性格方程被 Emily 明确否认，不能拿来当 Versu 公式。可吸收的是活动角色绑定/共享选择面，尚不能声称吸收了其完整选择算法。

### 2.4 Praxish 2023：枚举绑定→一步试算→绝对后状态 utility〔A〕

原件、版本及运行边界由[唯一精读](精读_Praxish论文与原始实现_2026-10-06.md)维护。当前核对 AIIDE 2023 release attachment 的 `noninteractive/praxish.js`：`query`、`getAllPossibleActions`、`performAction`、`tick`，**不是 master**。

**数据/作者输入：**JSON practice 定义 roles/actions/conditions/outcomes；共享逻辑 DB 保存实例和事实；goal 含查询条件与 utility。`eq/neq` 等条件逐次扩展/过滤变量替换；每个有效绑定成为一个候选动作；outcome 包括 insert/delete/call。

```text
actor = next_actor_round_robin()
C = enumerate_instances_and_unify_action_conditions(DB, Actor=actor)
if actor.boundToPractice: choose_random(C in that practice)
elif actor has goals:
    for a in C:
        saved = clone(DB); performAction(a)
        score[a] = sum(goal.utility * count(query(DB, goal.conditions)))
        DB = saved
    choose_random(actions_with_max_score)
else: choose_random(C)
performAction(chosen)
```

**精确区别：**score 是动作后满足目标的绝对匹配数，不是变化量，不是树搜索；相同目标可有多个匹配。原件试算/回滚并非所有外部别名都安全，已由既有实验记录，不能假定 `clone` 实现了一般事务。没有独立 W validator、个体 O 或训练。可借条件绑定、效果模拟、目标查询计分；不借“global DB 就是合法知识”的假设。

### 2.5 FAtiMA Toolkit：规则统一与 appraisal；论文/源码必须分版〔A〕

来源：[2021 Toolkit 论文](https://arxiv.org/html/2103.03020)，§§3.2–3.6、4.1–4.3（本轮方法段阅读，非全文）。2022 作者研究衡量作者产物/成本，不能替代本算法来源。

**数据/作者输入：**KB belief 带 perspective/certainty；结构事件如 `Event(Action-End, actor, action, target)`；appraisal rule 绑定事件、条件、目标和评价变量，再经 OCC 生成/存储 emotion。目标有 significance/likelihood；情绪有 cause/target/threshold/decay。决策规则为 action/target/conditions/priority/layer，条件统一产生具体动作。

**本轮固定源码：**[官方仓库 commit `56b7cbd992f953cfe21a7b12cb1a0e6cdf6ccf9f`](https://github.com/GAIPS/FAtiMA-Toolkit/tree/56b7cbd992f953cfe21a7b12cb1a0e6cdf6ccf9f)。核对函数而非宣称全库审计：

- [`EmotionalDecisionMakingAsset.Decide`](https://github.com/GAIPS/FAtiMA-Toolkit/blob/56b7cbd992f953cfe21a7b12cb1a0e6cdf6ccf9f/Assets/EmotionalDecisionMaking/EmotionalDecisionMakingAsset.cs#L54)：按 layer/conditions 枚举，返回候选，**此层没有排序**。
- [`ActionRule.GenerateAction`](https://github.com/GAIPS/FAtiMA-Toolkit/blob/56b7cbd992f953cfe21a7b12cb1a0e6cdf6ccf9f/Components/ActionLibrary/ActionDefinition.cs#L69)：ground action/target/priority；绑定不了则返回 null；`Utility = parsed_priority + minimum_certainty`，无约束时加 1。
- [`RolePlayCharacterAsset.Decide`](https://github.com/GAIPS/FAtiMA-Toolkit/blob/56b7cbd992f953cfe21a7b12cb1a0e6cdf6ccf9f/Assets/RolePlayCharacter/RolePlayerCharacterAsset.cs#L158)：若有 CurrentAction，返回 committed-action；否则打乱最高 Utility 的并列项，排在其余候选之前，**并非把所有候选完整降序排序**。应用负责执行。

```text
if CurrentAction exists: return committed_action
C = ground_rules_matching_layer_and_KB()
for a in C: utility[a] = priority[a] + minimum_binding_certainty(a)
return shuffle(C with maximal utility) + remaining_C
```

**版本差异：**论文决策段描述 certainty 与 priority 相乘、候选降序；上述源码不是这两条的逐字实现。不得混成一个“FAtiMA 算法”，也不在这里判定哪个版本错误。可借 event/condition 统一、视角 KB、机制 hook；emotion decay 精确公式未本轮核源码，不补指数公式。规则、阈值和优先级是作者输入，不是已训练人物参数；KB 支持视角也不自动证明所有应用都无 W 泄漏。

### 2.6 IPOCL 2004：同时修因果缺口与人物意图缺口〔A〕

来源：[Riedl & Young, AAMAS 2004](https://faculty.cc.gatech.edu/~riedl/pubs/aamas04.pdf)，§3、Figure 1；本地 `2004_Riedl_Intent_Driven_Planner.pdf`，与 CiF 同来源目录。

**数据/作者输入：**动作前置/效果、角色参与者、初始状态与作者想要的结局。plan 保存 steps/bindings/order/causal links/frames；intent frame 保存角色、内部目标、贡献动作和最终动作，以及该目标的 motivating step。

```text
search(partial_plan):
    if bindings/order inconsistent: backtrack
    choose flaw:
      open condition -> add/reuse supporting step and causal link;
                        expose its preconditions; discover possible intent frame
      open motivation -> add/reuse step establishing intends(character, goal);
                         order it before the frame's contributing actions
      intent flaw -> branch include/exclude action from frame;
                     if included, propagate to same-character causal predecessors
    resolve causal threats by ordering refinements; recurse
    accept only if no flaws AND every action belongs to an intent frame
```

**吸收对象：**“动作为什么服务这个人的目标”的可检验归属，不是生成完台词后补理由。它是全局叙事计划的 refinement/backtracking，不是在线部分可观测 NPC；2004 论文没有成熟高效 heuristic 或玩家验证。不能把 frame 直接等同 Runtime RunningAction/commitment，也不能声称它减少了全部剧情编排。

### 2.7 ScriptEase：任务阶段恢复，而非从头再演〔B〕

来源与覆盖由[两页示范精读](精读_ScriptEase中断恢复示范_2026-10-07.md)维护，AAAI 2007 pp.1968–1969；2006 完整方法未读、游戏模块未跑。

**数据/作者输入：**pattern→roles→behaviors→tasks→actions；ambient 动机选择、latent 外部事件响应及合作伙伴。实例绑定 NPC/Storage 等选项后生成游戏脚本。

```text
ambient_behavior = choose_by_current_motivation()
advance_completed_tasks_in_order()
on_external_event: run_latent_behavior(); then resume_appropriate_ambient_stage()
on_cooperation: wait_for_partner_task_or_cancel_when_conditions_change()
```

这是短文确认的阶段语义，不是完整调度算法。四队列的优先级/入出队/恢复游标尚未取得，不能自己写一套队列再称原方法。可借 stage checkpoint 与角色化 pattern；状态保存、伙伴迟滞和取消后的资源清理是必须追到完整方法的缺口。

### 2.8 FEAR GOAP：目标仲裁→有代价搜索→执行 FSM〔A〕

来源：Jeff Orkin，GDC 2006，[作者技术文章公开镜像](https://madwomb.com/tutorials/gamedesign/prototyping/gdc2006_JeffOrkin_AI_FEAR.pdf)，印刷 pp.6–7、11–13；本库 `PDF/2006_GOAP_Three_States_and_a_Plan_FEAR.pdf` 可离线读。

**数据/作者输入：**固定 world-state array，bool/enum/handle/引用值；goal 为期望状态；action 为前置、效果、代价及 C++ procedural checks/activation。attention 系统先选定目标/武器，planner 不同时推理所有对象。

```text
for goal in priority_order(assigned_goals):
    plan = A_star_search(states, action_edges, summed_cost, goal)
    if feasible_plan: break
activate_actions_in_sequence(plan)  # Goto / Animate / UseSmartObject
on_execution_failure:
    record_obstacle_in_working_memory(); replan()
```

可达性等昂贵条件按需检查；符号预测不是瞬时真实效果。可借 action schema 和失败知识回写。原文未披露 heuristic 的可采纳性/一致性、重复状态处理与完整预算，故本文不能独立验证最优性或搜索界限。作者手配 costs/priorities，不是训练。此处有 A* 证据，不能据此说 Ubisoft/KCD 的 GOAP 也必用 A*。

### 2.9 Sims 对象广告 + Zubek needs scoring：两份来源分开〔A/B〕

**原 Sims 接口：**Forbus & Wright，[2001-05-31 创作者技术笔记](https://www.qrg.northwestern.edu/papers/Files/Programming_Objects_in_The_Sims.pdf)，印刷 pp.1–2、6。每个对象保存 check procedure、behavior procedure、need advertisements；自主 Sim 从可行 behavior 选使当前 happiness 最大者，在 Sim 的线程执行对象程序。合作式 Edith VM 逐对象推进；动画/声音异步。广告/人格缩放、距离和 eligibility 是作者调试对象；**该笔记未给完整标量评分公式**。

**可公开追公式的通用变体：**Robert Zubek，[Needs-Based AI 作者 final draft](https://robert.zubek.net/publications/Needs-based-AI-draft.pdf)，发表于 Game Programming Gems 8；§Advertisement Scoring。这是作者吸收 Sims/robotics 后的通用方法，不是原 Sims 零售代码：

```text
# need 值越低越差；delta 为广告承诺的补充量
score(a) = sum_i(A_i(current_need_i) - A_i(current_need_i + delta_i(a)))
C = eligible_object_advertisements()
chosen = argmax(C, score) OR score_weighted_random(top_N(C))
enqueue(chosen.action_sequence); execute_until_complete_or_failed()
```

`A_i` 为非增的 urgency attenuation，如文中 `10/x`；范围、0 值处理和曲线是实现/调参责任。可借对象负责提供行为、人物负责评价，以及**当前→预期后的曲线差**。广告承诺不等同成功结算。曲线/距离权重会使近处低质量行为垄断；无训练。未采用带 confidential 标记的旧设计稿作可传播证据。

另：[Graham 的 Utility Theory 2013](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter09_An_Introduction_to_Utility_Theory.pdf)是行业章节，不是原 Sims 精确算法。其 motive-first 分桶、响应曲线、queue commitment 可作独立基线构件；不要将手册示例回填成某款 Sims 的实现。

### 2.10 Generative Agents：三项检索 + 证据反思 + 分层文本计划〔A〕

来源：[UIST 2023 对应 arXiv v2](https://arxiv.org/html/2304.03442)，§§4.1–4.3、Appendix A；Luna 核读，主代理复核方法段。

**状态/作者输入：**人物种子描述；memory 记录 text/created/last-access，混合 observation/reflection/plan。检索三项分别 min–max 后加权：`score = αr·recency + αi·importance + αq·relevance`；文中三权重均 1，recency 按上次访问的游戏小时指数衰减，因子 0.995；importance 是 LLM 的 1–10，relevance 是 cosine。

```text
retrieve(query): return highest_combined_scores_fitting_context_budget
if recent_event_importance_sum > 150:
    questions = LLM(recent_100_memories, three_questions)
    for q: append(LLM(retrieve(q), five_insights_with_evidence_ids))
plan = decompose(day_chunks -> hour_chunks -> 5_to_15_minute_chunks)
each_step: perceive_and_store(); LLM chooses continue_or_react;
           if react: regenerate_plan_from_now()
```

可借检索的分项分数、反思来源指针、分层计划；不是神经 policy 训练。0.995/150 是实现设置，不是心理常数；summary cache 刷新/失效键未明确。文本自洽、动作合法与真实后果必须分别验，不以流畅解释代替世界验证。

### 2.11 AGA：缓存的是成功计划，不是泛泛“记住经验”〔A〕

来源：[arXiv v2](https://arxiv.org/html/2402.02053v2)，§3.1、Appendices A/B/E；[TMLR 正式入口](https://openreview.net/forum?id=7t1Ybcq5DY)。本轮核 arXiv，不声称与正式版逐字相同。

**数据：**Lifestyle Policy 存 plan description/embedding、subplans/actions 与 execution conditions；Social Memory 另存每个 interlocutor 的事件摘要、关系及感受，二者不是同一缓存。

```text
coarse_plan = LLM(observation, profile)
matching_plans = semantic_matches(embed(coarse_plan), threshold≈0.97)
if a matching plan has a satisfied execution condition:
    reuse_its_actions()
else:
    actions, condition = LLM_decompose(coarse_plan)
    if execution_succeeds: store_plan_graph_and_condition()
```

condition 检查对象存在/状态；0.97 是文本相似阈值，**不是全状态 key**。多个候选的排序/并列规则、条件类型系统、删除/过期传播未公开；不在伪代码中擅定全库 argmax。VirtualHome 失败分支把无效命令加入 forbidden list 再生成；不是永久学习负例的证明。所谓积累 policy 主要是成功序列复用，不是梯度训练；仍要先生成粗计划，不能称完全免 LLM。可借有条件复用，不能把 token 减少当成作者工时减少。

### 2.12 LLM Reasoner + AP 2024：目标重选和计划重算是不同 gate〔B〕

来源：[CCIA 2024 四页正式版](https://journals.sagepub.com/doi/pdf/10.3233/FAIA240443)，§2 的五步与脚注；不混入 2025 扩展稿。

```text
goals, perceptions, AP_problem = Interface.project(world_state)
new = append_new_perceptions(memories, perceptions)
if new: goal = LLM(traits, memories, possible_goals)
if AP_problem_changed OR goal_changed: plan = Planner(AP_problem, goal)
if plan_changed OR previous_action_completed: dispatch(plan.first_action)
```

Interface 的候选目标生成依赖环境；记忆/traits 是文本，plan 是动作列表。可借目标决定与动作链求解分工；但 goal→符号谓词绑定、去重标准、solver/cost/无解恢复没有公开到可复现程度。`project(world_state)` 是论文接口，不意味着符合我们 actor-local O。Mistral 7B/Unified Planning 的使用不等于这里训练了人物模型。

## 3. 世界模拟与生产机制

### 3.1 Rain World：种属导航、局部信念关系、模拟分辨率分开〔A/B〕

来源是原作者开发日志的[归档分页 032](https://candlesign.github.io/Rain-World-Devlog/Pages/032)、[056](https://candlesign.github.io/Rain-World-Devlog/Pages/056)、[057](https://candlesign.github.io/Rain-World-Devlog/Pages/057)，非本轮取得的零售源代码。

**2014-06-12/24 导航机制：**CreatureTemplate 定义种属通行能力/偏好；每 room、每 species、每入口对预计算可达与 cost；当前房间用 tile cells，离线房间用 exit cells，构成粗细组合图。2014-07-02 将 legality 与数值代价分开，不能把“便宜但不合法”当普通最短路候选。

```text
for species, room, entrance_pair:
    cache[species, room, pair] = species_valid_path_and_cost()
graph = loaded_room_tile_graph + unloaded_room_exit_graph
route = species_navigation(graph, legality, costs)
```

**2015-04-11 Update 415 关系机制：**Tracker 持有目标的内部表示；RelationshipTracker 按该表示重算关系，将引用从旧 prey/threat/aggression 模块移到新模块。武器状态不可视时维持旧 belief，不直读目标 W。

```text
if target_visible: update_internal_target_state_from_sighting()
relation = evaluate_relationship(internal_target_state, context)
if relation_changed: remove_old_module_ref(); add_new_module_ref()
```

**2015-04-20 模拟层级：**abstract node 状态维护位置/损伤等，保存 last-update；跨区域简化 catch-up 是该日志中的拟议方案，精确数值法未知。可借 species 图缓存、共享内部表示、关系模块迁移；不能把导航/信念/LOD 合并成一个万能选择算法，亦不把后来版本效果倒推为当年已完成。

### 3.2 原 STALKER：决策查询依赖触发重算；A-Life 有原型/上市差别〔B〕

来源：[2008 开发者访谈](https://www.gamedeveloper.com/game-platforms/interview-inside-the-ai-of-i-s-t-a-l-k-e-r-i-)及[原采访者存档](https://blog.jilecek.cz/blog/2022/04/13/a-life-emergent-ai-and-s-t-a-l-k-e-r-an-interview/)。不是 STALKER 2，也不把 OpenXRay 后来代码当原零售版。

**状态/输入：**在线感知与低层控制；离线粗全局图/任务；开发者叙述 motivation graph 选目标与 action planner。约 150m、70 operators、200 search nodes 均是受版本限定的访谈经验值，不是通用常数。

```text
online:
    read_state_through_evaluators(); record_properties_queried_by_decision()
    if relevant_property_changed: recompute_goal_and_action_plan()
    execute_chosen_action()
offline:
    advance_coarse_position_and_assigned_task()
```

可借**所查询事实的依赖跟踪**和在线/离线表示；离线战斗/迁移的具体数值法未完整公开。早期 dealer/任务/交易原型没有全进发行版，不能当作上市机制。任务/剧情活动与自主活动的优先级仍需作者约束，不是加 GOAP 就自动解决。

### 3.3 Legion Census：人物保留/晋升 + 合同化日程〔B〕

来源：[2020 团队访谈](https://www.gamedeveloper.com/design/how-watch-dogs-legion-s-play-as-anyone-simulation-works)、[2021 官方工具文章](https://news.ubisoft.com/en-ca/article/4po3S9Pwp1YcgBmGPmQxAh/watch-dogs-legion-the-tools-that-built-london)；[GDC 2021 讲稿](https://media.gdcvault.com/GDC%2B2021/Census_GDC2021-Complete.pdf)本轮直接读取受限，仅核搜索索引中的 `Scheduling - Structure/Contracts`，不称全文阅读。

**数据/作者输入：**标签约束人物档案、关系、经历、活动合同。索引显示日程按小时槽，Work/Rest/Leisure 与 travel 分开，至少一个休闲 relation contract；如 Work.Accountant 有职业门。不是对所有路人永久全精度运行。

```text
on_relevance_or_interaction: promote_and_retain(character, relevant_connections)
instantiate_constrained_profile_and_activity_contracts()
advance_schedule_with_travel_slots()
on_event: record_memory_and_update_affinity()  # exact update law unknown
discard_unretained_transient_instances_outside_active_simulation()
```

可借人物生命周期和参数化合同；population/affinity 的概率、空间填充、对象冲突算法未知，不用二手报道补成原公式。按玩家相关性晋升是其产品选择，**不等于我们的世界中心方向必须照做**。

### 3.4 Ubisoft GOAP：对象候选剪枝、代价稳定和排除日志〔A/B〕

来源：[Simon Girard 开发者 postmortem 2021](https://www.gamedeveloper.com/programming/postmortem-ai-action-planning-on-assassins-creed-odyssey-and-immortals-fenyx-rising-)，Environment interactions、Debugging Tools、Performance、design-support。主代理核读方法段。

```text
C = mode_action_bucket + actions_offered_by_loaded_smart_objects
C = prune_by_navmesh_and_distance(C)
plan = least_cost_graph_search(state, C, goal)
execute(plan); log_branches_costs_open_conditions_and_exclusions()
```

AC Odyssey 每 action 类型预选最近 1 个对象；Immortals 放宽至最多 3 个，使后续步骤位置影响目标选择。前者随机 cost 在规划起点一次生成；后者每搜索步更新 cost，改用 last-execution-time modifier，避免同一搜索中随机重抽破坏分支可比性。公式未给，不补指数 cooldown；搜索未具名 A*。条件通过/失败统计用于重排检查顺序，**不是训练行为 policy**。可借候选剪枝反例、稳定代价和排除原因；任意采用“只选最近”会损失多步计划质量。

### 3.5 KCD2：MBT→期望状态→GOAP 与 LOD 是两项未知尚多的机制〔C〕

来源：[Matej Marko，GDC 2025 GOAP/MBT](https://gdcvault.com/play/1035576/Game-AI-Summit-Combining-GOAP)；[Petr Smrcek，GDC 2026 大规模 NPC](https://schedule.gdconf.com/session/supporting-thousands-of-npcs-in-kingdom-come-deliverance-kingdom-come-deliverance-ii/915120)。只核官方摘要，未观看锁定录像。

前者只支持 MBT 指定 desired state、触发 state change 后把目标交 GOAP；后者支持 LOD/线程/标准逻辑下沉的规模工程。**缺：**MBT node/re-evaluation/interrupt、state schema/action costs/search，以及 LOD tiers/state retention/catch-up/hysteresis。不能把 FEAR A* 或 Rain World catch-up 填进 KCD2；目前不能做具体算法移植承诺。下一原件是完整视频/讲稿，不是再读一篇宣传摘要。

### 3.6 Division：可观察决策图与回归测试，不冒充选择公式〔B〕

## 5. 手算：具体机制为什么不能互换

以下是**我们构造的教学输入/推导，不是论文原实验或项目新运行结果**。

### 5.1 一步 utility 会看不到前置准备

DB 初始：`at(woodcutter,home)`，`has(woodcutter,axe)`，没有 `has(woodcutter,wood)`。目标查询是 `has(woodcutter,wood)`，utility=10。

- `walk_to_forest`：前置 at(home)，效果 at(forest)；后状态目标匹配数 0，因此 Praxish 式分数 0。
- `rest`：不产生 wood；后状态目标匹配数也是 0。
- `chop`：要求 at(forest) 和 axe，当前不是候选；效果 wood。

只配最终目标的一步计分会对 walk/rest 并列随机，**不会因为未来能 chop 自动偏好 walk**。若补一个“到森林”的目标会改变评分，但这是新增作者输入，必须记账。GOAP 可在提供同一 walk/chop schema 后搜索 `[walk, chop]`；若 cost 分别 2/3，则链 cost=5。其优势来自搜索长度，不是字段叫 goal，也不证明最终玩家更喜欢它。

这揭示了吸收 activity、scoring、planning 三个部件时必须分开做贡献归因；现有 Praxish 小场景 NO_GO 不被这个教学例改写。

### 5.2 needs 曲线差和最终状态分数不是同一算法

按 Zubek 的示例令 `A(x)=10/x`，need 越低越差，暂只看一个维度：

- 当前 30、改善到 90：`score=10/30-10/90=2/9`。
- 当前 60、改善到 90：`score=10/60-10/90=1/18`。
- 两者终值同为 90，但改善 urgent need 的分数是另一项的 4 倍。

若只是加最终 need，两者无法表达这个差异；若只加广告 delta，也没有同样的 urgency 曲线。这才是一个能写测试/反例的具体候选构件；曲线好坏仍需调试，**不因叫 needs-based 就比现有 Demo 更像人**。

## 6. 可吸收的原子清单：不拼“万能框架”

| 部件 | 具体候选机制 | 需要保留的输入/检验 | 尚不是结论 |
|---|---|---|---|
| 候选构造 | Praxish 条件统一；Sims/Ubisoft 对象广告 | binding、eligibility、target；遗漏候选的反例 | “共享对象行为一定省作者成本” |
| 角色评价 | CiF 条件理由；Zubek urgency curve delta | 分项贡献、作者权重、状态取值 | “utility 已训练/已验证心理机制” |
| 多步求解 | FEAR action schema + search | 前置、预测效果、cost、无解与失败回写 | “有计划就是可置信角色” |
| 目标可解释性 | IPOCL intent frame/motivating step | 动作—因果目标—动机事件的归属 | “能解释就一定玩家认可” |
| 情境活动 | Versu/Praxish role-bound practices | 活动实例与个体选择分离、并发冲突 | “activity 优于公平 utility baseline” |
| 记忆/复用 | GA 三项 retrieval；AGA condition-gated reuse | 来源、版本、成功条件、失效案例 | “保存经验=训练 policy” |
| 重决策 | STALKER queried-property dependency；Reasoner/AP 双 gate | 哪个事实变化导致目标/计划重算 | “每条新信息都应打断动作” |
| 个体知识 | Rain World target internal state；CiF-CK 私有 belief | 可见才更新、旧 belief 合法错误尝试 | “任何共享社会状态都等于 O” |
| 模拟规模 | Rain World coarse/fine graph；Legion 生命周期 | 保留状态、精度、时间投影与回收规则 | “玩家看不到时必须全精度同时运行” |
| 调试/作者工具 | Ubisoft 排除日志；Division 回归环境 | 为什么没选、使用覆盖、实际修改账本 | “日志/工具本身证明省工” |
| 玩家评价 | 受控行为线索与跨遭遇规则条件 | 同展示、条件操纵、分别题项 | “自动总分就是生命感” |

**本项目决策：**“理解其部件”与“纳入候选方法”分开。本轮不从这些行里自动选算法，不把所有部件堆成新框架；尤其不因生产案例的规模优势更改已冻结的 Kernel seam。
