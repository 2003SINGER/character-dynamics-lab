## 2. 核心发现 A：项目的无心理学框架，大量重合于 2005–2013 年的 utility-AI 实践

这是本次核读最重要的结论，直接影响 [T18 查新](../00_研究设计/TODO.md)。

| 项目当前机制 | 已在 utility-AI / GOAP 中确立的对应物 | 出处 |
|---|---|---|
| 状态 → 动作分数 → 概率采样 | 决策因子 → 响应曲线 → utility 分数 → 加权随机 / top-N 加权随机 | Utility 2013 §9.5–9.6 |
| 承诺与恢复、resume gate | **Inertia**：给当前动作加权、冷却期、或"队列空了才重新决策"（The Sims Medieval） | Utility 2013 §9.7 |
| 目标竞争与优先级 | **分桶 / dual utility**：高优先级桶内无有效动作才落到下一个桶 | Utility 2013 §9.6（Dill 2011） |
| Q01 分段响应 | **分段线性响应曲线**：手工调 2D 点 + 线性插值；The Sims 就在用 | Utility 2013 §9.5.4 |
| Q05 Object 提供基础动作 → 组合动作 | **SmartObject**：动画/交互由对象在游戏数据库中指定，角色不硬编码 | GOAP 2006 §Three States |
| Q04 隐藏前置条件 / 失败反馈 | 规划失败 → 把失败知识写入 **working memory** → 重规划时考虑 | GOAP 2006 §Benefit #3 |
| W 校验前置条件、强类型结算 | STRIPS precondition / effect；F.E.A.R. 改用 **procedural precondition/effect** | GOAP 2006 §Differences |
| 目标不应是黑盒、需共享状态 | 解耦目标与动作**强制**通过外部 working memory 共享信息（NOLF2 反例：中弹后仍要站起来推椅子才倒地） | GOAP 2006 §Benefit #1 |

**判定**：若以"由状态产生行为分布 + 承诺惯性 + 目标优先级 + 对象提供动作 + 世界校验前置条件"作为贡献，这些在 2005–2013 年的游戏 AI 工程中已是标准实践，**不能作为新颖性主张**。

`[项目推测]` 真正可能站得住的差异集中在三处，且三者都需独立验证：① `W ≠ O` 作为架构不变量（GOAP / utility 默认 agent 直接读世界状态；PsychSim 与 Generative Agents 部分涉及）；② `X` 由 LLM 做结构化 appraisal 而非直接写状态增量；③ 以 held-out 下一行为预测、校准和成本为评价协议，而非工程可玩性。

## 3. 核心发现 B：Q01 的正确归属是 utility theory，不是 Fleeson——但代价是它不再是心理学主张

[X 维度核读 §6](专题核读_X维度与状态动力学_2026-09-05.md) 已判定 Fleeson 2001 不支持 Q01。Utility 2013 §9.5.4 提供了**强得多的依据**，且理由与用户的原始直觉几乎逐字一致：

> "Designers want a finer degree of control. They want the ability to have a Sim **completely ignore hunger until it reaches a threshold, then get a little hungry, then suddenly get very hungry**. There's no way to build and tune that specific curve with a simple mathematical formula, so the solution is to create a custom curve."

即：**分段响应曲线是成熟工程手段，动机是"设计者需要精细控制"，不是心理学规律。** 原文对折点位置的说明是「hand-tune a bunch of 2D points」，即**手工调参、任意设定**。

两个后果：

1. **Q01 可以保留，但应改称"分段响应曲线（utility response curve）"，并明确它是 authoring 工具，不是心理机制。** 这样它有据可依，且不与 T20 的等维度对照冲突。
2. **正态 ±1σ/±2σ 的折点放置仍然没有依据。** Utility theory 的答案是折点由设计者手调。若坚持用正态分位当折点，那就是在"手工调参"这件已被认可的事情上，额外加了一层未被认可的参数来源。

另有一条方向相反但同样重要的证据：Utility 2013 §9.7 的 **inertia** 与 §9.6 的**分桶**已涵盖 Q01 想要的部分效果（阈值门控、路径依赖、惯性）。若 Q01 的动机是"想要质变与迟滞"，**分桶与 inertia 是更便宜、更有据的实现**，分段曲线不是必需的。

## 4. 三方向对项目的具体价值

### 4.1 人物动机 / NPC 逻辑

- **GOAP 的"Goal Set + Action Set 解耦"是本项目 `P` 与 `A^O` 分离的强先例。** 原文：soldier / assassin / rat 用同一个 Goal Set {Patrol, KillEnemy}，因 Action Set 不同而行为迥异；rat 无法为 KillEnemy 形成有效计划，回退到 Patrol。这比"内向所以不说话"式的 P 更接近项目要的东西。
- **GOAP 的底层架构来自 C4**（Burke, Isla, Downie, Ivanov & Blumberg, GDC 2001, "CreatureSmarts: The Art and Architecture of a Virtual Brain"，MIT Media Lab Synthetic Characters 组）。这是「虚拟角色认知架构」的直接祖先，**待取得**。
- GOAP 参考文献中 **Evans & Barnet 2002 "Social Activities: Implementing Wittgenstein"**（GDC）是 Versu 一脉的早期工作，**待取得**。
- **Comme il Faut / Prom Week** 一脉（McCoy、Treanor、Samuel、Mateas、Wardrip-Fruin）把社会规范与社交互动建模为可重组的可执行单元，是「NPC 逻辑可作者化、可审计」的代表。**本次未取得 PDF，是三个方向中最大的缺口。**

### 4.2 落地游戏工程

- **Utility Theory** 是本项目 π(A) 设计最直接的工程近邻，尤其是「为什么不能只取 argmax」与「top-N 加权随机」的取舍论证，以及**分布不是扁平 softmax 而是分桶门控层级**这一点——项目当前的"激活/阈值/概率采样"应与之对齐或明确说明差异。
- **Behavior Trees 专著**可随时查阅反应式控制与模块化的形式化结果（BT 如何泛化 FSM、HFSM、subsumption、teleo-reactive、决策树），但**与本项目的前向状态动力学不是同一层**：BT 无跨轮状态，每 tick 重估。
- 缺口：**HTN 规划在游戏中的应用**、**智能对象 / affordance 的正式处理**、**动作中断与部分失败的工程语义**（Q08）。本次未取得。

### 4.3 自主化 Agent 社会

三篇都不做「内部状态 → 下一行为预测」，与项目主问题不同构，但各有可借之处：

- **SOTOPIA 最有价值的一点：私有目标。** 原文明确 "Other agents' social goals are invisible"。90 个社会场景 + 角色档案 + 关系约束 + 人类与 GPT-4 双评判。**`[项目推测]` 这 90 个场景及人类交互记录是 T13/T15 缺失的「行为真值 A\*」的候选语料来源**——它自带信息不对称，正好匹配项目的 `W ≠ O` 设定。但它是对话行为，不是小房间微行为，抽取世界模型与动作集仍需独立工作。
- SOTOPIA-Eval 的 7 维评分（含 BELIEF、SECRET）发生在 **episode 结束时**，不是揭晓前的下一动作预测。**它是"干预/结果"评测的近邻，不是 Replay 评测的近邻。**
- **AgentVerse** 的四阶段循环（专家招募 → 协同决策 → 动作执行 → 评估 → 新状态）说明"环境—群体—个体"的闭环模拟已非新奇；与 [PersonaArena](../00_研究设计/) 对"闭环模拟 + 一致性评测"的削弱方向一致。
- **Social Simulacra** 的评测是设计者 red-team 与 N=16 用户研究，同样不含下一行为预测。
