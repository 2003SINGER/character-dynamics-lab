## 卡 1｜IPOCL：因果计划与 intent-frame 支持链

原件：[Riedl & Young, “Narrative Planning: Balancing Plot and Character,” JAIR 39 (2010), 217–267](https://doi.org/10.1613/JAIR.2989)；[作者 PDF](https://faculty.cc.gatech.edu/~riedl/pubs/jair.pdf)。另有 AAMAS 2004 前身，见[继承审计](../调研子审计_AuthorGoals与叙事规划_2026-10-07.md#ipocl因果链加上人物为什么这么做)。本卡复用既有全文审计（IPOCL §§4.2–4.3、评测 §5、限制 §6），不声称本轮重新逐页精读或复现。

- Problem：E｜在满足作者终局情境的部分序计划中，同时消除因果 flaw 与 intent flaw；输出是可解释的 fabula plan，不是运行期人格模拟。
- State：E｜partial plan 含行动步、变量绑定、步序约束、因果链接〈producer, literal, consumer〉及 frame of commitment；frame 记角色、角色目标、服务该目标的动作集合/区间、终末动作与 motivating step。
- Author input：E｜initial situation、目标情境、动作 schema（参与者/intentional actor、preconditions/effects；可标非意图 happening）、角色目标/动机产生所需的动作语义。
- Character input：E｜人物作为 action-schema 的 actor 与 goal holder；算法不从语言或观察数据推断“真实心理”，也不包含 actor-local belief/knowledge 模型。
- World model：E｜经典符号状态与因果动作效果；部分序因果关系。不是实时连续世界、资源/钟表 deadline 系统或角色私有 O。
- Authority：E｜planner 搜索/回溯改变计划结构与约束；作者给定 domain、initial/goal 与动机语义。它不直接写入已运行游戏的 W。
- Search：E｜choose flaw 后 least-commitment refinement：open condition 可新增/复用支持步并建立 causal link；open motivation 寻找建立 intends(actor, goal) 的 motivating step；intent flaw 分支纳入/排除动作；纳入后向同 actor 的因果前驱传播归属；因果 threat 通过加排序约束消解；不一致则回溯。
- Trigger：E｜离线计划构造过程中，有 open condition、open motivation、intent flaw 或 threat 时继续 refinement；不是玩家事件后的在线 repair trigger。
- Repair：E｜threat step 介于 causal link 两端且 assert 与 link effect 相反的 literal。promotion 加 consumer < threat；demotion 加 threat < producer；也可 separation：保留 producer < threat < consumer，但增加变量约束使它不再删除 link effect。每个分支须检 binding/order consistency；不一致回溯。intent-frame 支持链另处理“为何/归谁”，不取代因果 threat。
- Can change：E｜加入/复用步骤、变量绑定、部分序约束、因果链接、动机步及 frame 成员关系；搜索分支可回溯。
- Cannot change：E｜不能撤销实际发生的世界事实、强迫人物在运行时行动、容忍未达成目标的失败结局，或证明心理真实性；标准规划会剪掉无法到作者目标的分支。
- Handwrite：E｜作者要定义 operators、角色目标与哪些效果能建立/支持 intends；给出可形成目标的 initial/goal 与事件域。困难意图冲突可能仍需额外语义/情境推理。
- old cost：E｜domain/intentionality 表示与组合式搜索；原文的 reader study 评的是特定生成故事中的 goal comprehension，不是作者工时、在线自治或动态角色可信度。限制见上方审计。
- LLM replace：I｜可提候选 schema、motivating event、因果链说明，供作者核对后编码；可把 flaw 转为可读诊断。
- must not replace：I｜不得让 LLM 自行改历史、goal/effects 或把事后解释当作已成立的 motivation support；不可略过 causal threat 与 frame 所需因果前置。
- Eval：E｜论文对照 IPOCL/POCL 的特定故事理解问答；不能外推为玩家体验或长期角色行为有效性。项目纸面比较应逐项检查 flaw 是否清零、所有需解释行动是否入 frame、所有 link threats 是否被有序约束解决。
- Failure：E｜矛盾/不可达导致回溯或无解；作者指出意图矛盾识别较弱，某些案例需额外语义。目标最终失败叙事不在其标准求解能力内。

可手推步骤（自制 schema；每行读写对象与结果）

1. 读初态 letter-near(A)，goal delivered(A)，schema read-letter、pick-letter、deliver-letter；drop-letter 标为非意图 happening（因此不要求归入某 frame）。
2. 新增 read-letter(A)：effect intends(A, delivered)；写 motivating-step 候选，并约束它先于贡献给该 goal 的 frame actions。
3. 新增 pick-letter(A)：pre letter-near，effect has-letter；写因果链接 pick-letter —has-letter→ deliver-letter。
4. 新增 deliver-letter(A)：pre has-letter，effect delivered；把它标为 frame 终末步，pick-letter 作为支持步，goal=delivered。
5. 检查 read-letter 的 effect/顺序是否足以建立 intends；不足则这是 open motivation flaw，搜索支持步或回溯，不能只补一句旁白。
6. 若 happening drop-letter 可能在 pick 与 deliver 之间删除 has-letter，则它威胁上述 link；试 promotion：deliver < drop，或 demotion：drop < pick；若两支均与已有序约束冲突则回溯。仅当 drop 有与删除无关的可区分参数/绑定时，才考虑 separation。
7. 检查每个非-happening action 是否归入角色 frame；若 drop 被改成 A 的 intentional action 却未归 frame，它留下 orphan/intent flaw，plan 不接受；本例将其标 happening 才免此归属要求。

自制小例：若已有 read → pick → deliver 顺序，happening drop 目前无序且删 has-letter，算法发现 link threat。给 drop < pick（demotion）后 link 安全；若已有 pick < drop < deliver，promotion 要求 deliver < drop，与已有序冲突，分支失败。这里“读信使角色想送信”是自制 domain 设定，不是论文提供的普遍心理规则。

## 卡 2｜Thespian + POP（2008）：fit、gap、belief suggestion 与作者造桥

原件：[Si, Marsella & Riedl, “Integrating Story-Centric and Character-Centric Processes for Authoring Interactive Drama,” AIIDE 2008, 203–208](https://cdn.aaai.org/ojs/18698/18698-52-22313-1-10-20210927.pdf)。定向核读 overview/Thespian/fit pp.204–205、Algorithms 1–4 pp.205–206、Algorithm 5 p.206、examples pp.206–207；旧审计记录的分工见[技术考古 §5](../技术考古_导演优化与人物意图_2026-10-07.md#5-thespian--pop2008最值得借的人工缺口)。无软件复现。

- Problem：E｜抽象 POP plot plan 因果可行，却可能没有被细粒度 Thespian agent 愿意执行的动机/互动路径；与作者共同把 skeleton 扩为完整 path。
- State：E｜story plan action sequence；Thespian agents 的 state features、action dynamics、reward-goals/weights、policy、对自己与他人的递归 belief；bounded lookahead 评估行动及预期回应。
- Author input：E｜POP plot anchors；角色/动作/状态转移模型；动作候选集 allActionSets 的优先次序、gap 起点偏移 n 与 maxLength；若库里没桥，作者补具体 action model。
- Character input：E｜fit 时逐角色判断是否存在一组 goal weights 使该序列可被角色政策选择；belief suggestion 阶段保持 goals 不变，寻找使指定行动胜过其他选择的 belief change。2008 本文只调用 fit_sequence；下方另外核读其直接引用的 2004 基础工作，展开奖励权重不等式及单/双权重调整，不把它冒充 belief 反求程序或 2008 的完整实现。
- World model：E｜Thespian/PsychSim 多智能体状态与 action dynamics；论文不等于现实角色心理学。算法把计划 action 作为 desired choice 来拟合。
- Authority：E｜fit 成功可设置该角色 goal weights；Suggest_Pick 返回 belief-change suggestion；作者决定是否创造一个 action，使其在故事中造成该变化。系统不是直接把 belief mutation 当已发生事件。
- Search：E｜Alg.1 全序列 fit；失败后按前缀递增找首个失败位置。Alg.2 对 story 中每个角色调用 fit_sequence，全部成功才 fit。Alg.3 先试最高优先级 action set，失败才并入下一组。Alg.4 依 actionSet 顺序枚举 action 并追加；违反 islands 次序则跳过；islands 已全出现时调用 fit，成功即返回、失败则当前层试下个 action；islands 未齐时才减 maxLength 并递归。
- Trigger：E｜plot plan 交给系统后先检查全计划是否 fit；首个失败前缀界定 gap。已足够细且 fit 的计划不需要填 gap。
- Repair：E｜先用既有 action sets 搜 gap；优先 gap 两侧相关人物 small talk，其次相关人物其他动作，最后其他人物动作。若失败/作者不接受，Alg.5 模拟到 gap，为下一个指定 action 调 Suggest_Pick；再枚举其他人物 response，若一层 lookahead 下 actor 会选目标行动，则反求 response actor 的 belief suggestion。
- Can change：E｜fit 会改变被拟合角色的 goal weights；填 gap 会在 skeleton 间加入已有动作；Alg.5 建议 belief effect，但不自动创造造成该 effect 的事件/动作。
- Cannot change：E｜不保证找到桥、不保证多个 gap 独立可修、不保证后续 fit；不是统一最小 goal/belief 改变优化，也不是运行时 replan。一个 gap 成功可能破坏下一个 gap。
- Handwrite：E｜角色、action effects、goals/rewards/weights、belief 与 lookahead dynamics、POP plot domain、候选动作集及优先级；belief 被提议改变后，作者要写能造成变化的具体 action。
- old cost：E｜仍要作者维护两个粒度模型，并逐条审批/补写动作；单个 Red Riding Hood 案例是 preliminary authoring demonstration，不是规模化成本/玩家效果试验。
- LLM replace：I｜可把 belief-change suggestion 展开成若干可执行事件草案，并补状态前提、执行主体、所需信息来源，供作者挑选/拒绝；要把新增 operator 成本单列。
- must not replace：I｜不得把直接 goal-weight fitting 混称“只改环境”；不得把 belief suggestion 当发生事实；不得把作者手写新 operator 伪报成原库搜索结果。
- Eval：E｜以是否 fit 计划、能否填 gap/作者示例展示；此文没有系统性对照的作者时长/玩家效度。项目纸面检查应记录 gap 首失败索引、被试 action set/长度、fit 改了谁的 weights，belief proposal 是否有事件支持。
- Failure：E｜库不够或达不到 maxLength 即失败；后续 plan prefix 当前不参与 gap 搜索目标。Lookahead 只延一层；原算法提到不同 belief 下他人反应可能改变，并由 Alg.5 纳入候选，但仍是有限模型推演。

可手推步骤（此处先演示 gap 外层；下面单独展开底层权重拟合）

1. 输入 skeleton：Red 遇 Wolf；Red 告诉 Wolf Granny 地址。读取动作模型、Red 的当前 goals/beliefs 与每步可选行动。
2. Alg.1 调 fit(全序列)；假设 Alg.2 中 Wolf 与 Red 均可 fit 第一动作，Red 对前两动作前缀 fit_sequence 返回 false。
3. 记最后可 fit 前缀长度 k=1，首个失败前缀长度 k+1=2；gap 在 action 1 与 action 2 之间。算法原文以失败前缀索引 i 表示返回值；这里统一用 k 表达 gap 两侧，避免把失败动作索引误读为边界。
4. 固定 path0=[meet]、islands=[meet,tell]，并显式给候选 actionSet={small-talk,tell}（gap bridge 与需保留的 island 锚点均在候选集）；先枚举到 small-talk，追加后 path=[meet,small-talk]，checkComplete=false，才递归。
5. 在递归分支枚举到 tell 后，path=[meet,small-talk,tell]，islands 才完整；此时调用 fit(path)。fit=true 返回该 path；fit=false 时 Alg.4 当前 for-loop 试下一个 action，不在完整路径上递归 append。
6. 若已有动作库搜索失败，Alg.5 将模拟推进到 gap 边界 k，调用 Suggest_Pick(Red, P[k+1]=tell-about-Granny)，读出“改变某信念后选择该 action”的 suggestion；本文不提供统一的 goal distance 最小化数值式。
7. 枚举他人 response；对每个 response 若 lookahead(Red, other, response) 预测 Red 选择目标动作，再调用 Suggest_Pick(other,response)。返回的是建议而非世界事件。
8. 作者把所需 belief effect 写成可执行新动作并重新建模/验证；比如木匠向 Red 说狼可信（p.204 总览例），或形式示例中安排狼伪装/假装离开/吃饱等桥。不要混淆总览例与 formal Example 1 的 small-talk rapport。

Thespian gap DFS 可手推（Alg.1–5 的过程性转写；gap DFS 按页 206 原图缩进校正；fit_sequence 内部仍是本文引用外部方法的黑箱）

1. 输入 plot sequence P、优先级有序 allActionSets、gap 边界 k、起点偏移 n、最大插入长度 maxLength。
2. 调 Fit(P)：Alg.2 对每个角色调用 fit_sequence(actor,P)；任一角色 false 则整体 false，全部 true 才 true。本文未给 fit_sequence 内部的权重求解伪码/目标函数。
3. 若整条 P fit=true，Alg.1 返回 −1（无 gap）；否则记录最后可 fit 前缀 k 与首个失败前缀 k+1。gap 边界为两动作之间；原文的循环索引/文字/Alg.3、5 参数存在一位换算风险，手推时明确使用边界 k。
4. 按 Alg.3 用 n 切 path0 与 islands：islands 保留 gap 两侧锚点及紧邻的 n 个前置动作，后缀不影响这次填充。
5. 置 actionSet 为最高优先级组；Alg.4 对每个 action 复制 path0、追加 action；若 checkOrder 失败，跳到当前 for-loop 的下一个 action。
6. 若 checkOrder 成功且 checkComplete(islands)=true，调用 Fit(path)；成功就立即返回 True。
7. 若 checkComplete=false（原图中 Else 与该 If 对齐），才令 maxLength←maxLength−1；非负时对当前 partial path 递归 replace_islands。
8. 若 checkComplete=true 但 Fit(path)=false，原图没有从该分支递归加长；它留在当前 action for-loop，尝试下一个 action。
9. 当前组无成功时 Alg.3 依次并入下一优先级 action group 再调用 replace_islands；全部耗尽则返回 False。算法图未澄清递归调用的 maxLength 是否按分支复制，以及布尔 res 与“返回路径”的接口如何传递；本转写不静默修补。
10. fill 失败后 Alg.5 可模拟到 gap，调用 Suggest_Pick(actor,P[k+1])；枚举他者 response，若一层 lookahead 使 actor 会选 P[k+1]，则再 Suggest_Pick(other,response)。返回 belief-effect 建议，作者需造出对应 action。

### 底层不能只写“fit”：奖励权重不等式怎么构造、怎么改

原件：[Pynadath & Marsella, “Fitting and Compilation of Multiagent Models through Piecewise Linear Functions,” AAMAS 2004](https://people.ict.usc.edu/~pynadath/Papers/AAMAS04.pdf)。这是 Thespian 2008 直接引用的基础方法；本轮定向核读 §5、公式 (4)–(8)，并渲染物理第 7 页核对符号。**原式 (6)/(7) 为 ≥0，不是严格 >0。**以下用 θ 表示待调奖励权重、b 表示原式汇总的政策特征系数，避免原件中多个 w 符号混淆。

1. **先固定什么：**状态分布、动作转移、其他角色模型、待比较政策和推演 horizon。把状态传播与政策带来的期望特征贡献预计算为 `b_π`。不是只看动作名字，也不是奖励高就跳过未来状态推演。
2. **线性在哪里：**奖励树的叶值对权重线性；对这些固定输入，式 (4)/(5) 的政策值可写成 `V_π(θ)=θ·b_π`。这不等于整个任意 MDP 的最优政策对参数全局线性。
3. **把示例变成约束：**观测/期望政策 π_obs 至少不差于竞争政策 π_alt：`θ·(b_obs−b_alt)≥0`。这里 `d=b_obs−b_alt`，约束是 `d·θ≥0`；不是“把想要的动作概率设成 1”。原件 §5 先用两政策说明；跨整条、多条示例路径的完整联合求解不是这几行式子自动给出的。
4. **先检查当前权重：**若 `d·θ≥0` 已成立，原方法不必改它；否则计算能把违例修正到边界的候选权重改动。
5. **逐坐标试修：**只改 θ_i，其他坐标不动。由原式 (8) 在违例 `d·θ<0` 时得到 `Δθ_i=−(d·θ)/d_i`（`d_i=0` 不能修此约束）；候选新值为 `θ_i+Δθ_i`。
6. **保留原定性目标：**不接受使权重符号翻转的改动；在可接受的单权重候选中选最小改变量。不能把“偏好伤害他人”通过翻成“厌恶伤害”伪报为同一个角色的微调。
7. **没有单权重解怎么办：**原文再考虑两个权重的组合。奖励树有多个分支时，可调权重扩展到叶节点。正文没有给出完备多坐标搜索、统一范数/全局最优解保证；不能补写成 LP、梯度训练或已实现最小心理距离。
8. **拟合后仍要重新检查：**该修改只满足所比较的约束；其他状态/竞争政策/整条序列还需检查。`≥` 可产生平手；平手如何选动作，不能由不等式保证。下例添加正 margin 是自制稳健性演示，不是论文原算法参数。

**带数字的手算例（自制，非原实验）：**两项正奖励权重初值 `θ=(2,1)`。由固定模型推演得到期望特征 `b_obs=(1,3)`、`b_alt=(3,0)`；于是 `V_obs=5`、`V_alt=6`，`d=(−2,3)`，当前约束值 `−1`，拟合失败。

| 单坐标候选 | 边界改动 | 新权重 | 新约束值 | 原符号保留？ |
| --- | --- | --- | --- | --- |
| 只改 θ₁ | `Δθ₁=−(−1)/(−2)=−0.5` | `(1.5,1)` | `0` | 是 |
| 只改 θ₂ | `Δθ₂=−(−1)/3=1/3` | `(2,4/3)` | `0` | 是 |

最小单坐标改变量是 `1/3`，选第二项；此时两政策价值同为 `6`，满足原件的非严格不等式，却**不能保证原有 tie-break 选 π_obs**。若为了本例给 `d·θ≥0.03` 的额外 margin，单坐标改动分别为 `−0.515` 与 `+0.343333…`；选第二项后 `V_obs=6.03>6=V_alt`。margin `0.03` 是明确新增的讲解设定，不能冒称 Thespian 用过这个数。

## 卡 3｜PDDL3 轨迹约束规格 + Porteous 2010 地标 FF 重规划

两个层次必须分开。规格原件：[Gerevini & Long, “Plan Constraints and Preferences in PDDL3,” technical report, Aug. 2005, 12 pp.](https://ipc08.icaps-conference.org/deterministic/data/gerevini-long-tr-2005.pdf)，本轮核对 §§1–3、printed pp.1–4 中轨迹语义；算法近邻：[Porteous, Cavazza & Charles, “Applying Planning to Interactive Storytelling: Narrative Control Using State Constraints,” ACM TIST 1(2), Article 10 (2010)](https://doi.org/10.1145/1869397.1869399)，[正式版 21 页 PDF mirror](https://www.cs.uky.edu/~sgware/reading/papers/porteous2010applying.pdf)。本轮定向核读 §4.1–4.2、Algorithm 1（printed pp.10:12–10:14），取得完整 PDF 并渲染 p.10:13 核对缩进；非全文新审，无复现。

- Problem：E｜PDDL3 描述一个时间戳状态序列必须满足的终局/轨迹约束与偏好；Porteous 用人物/世界状态 constraint graph 的当前 landmark 生成分段目标，并在玩家改状态后规划当前段。
- State：E｜轨迹是 (S0,0)…(Sn,tn)；每个命题在相应 state 求值。Porteous 状态/节点含位置、活动、关系/阵营、视角等域谓词，地标已访问/当前目标由规划控制器维护。
- Author input：E｜PDDL3 predicates、时间界限、hard constraints 与 preference；Porteous 另需 state constraints/landmark 顺序图、动作 pre/add/delete effects、初态/最终目标及 FF planner domain。
- Character input：E｜PDDL3 不含角色心理；Porteous 的 character/world facts 可进状态与约束，但不是角色局部 belief 模型。
- World model：E｜PDDL3 是 declarative language/spec，不指定唯一 planner；动作时间/状态转移须由 domain/planner 给出。Porteous 依符号行动模型和 FF 规划器求计划。
- Authority：E｜规格仅判合法轨迹/软偏好罚分，不执行动作。Porteous planner 选择待达 landmark 的计划；执行者/游戏状态负责结算玩家与计划行动，之后读取新状态。
- Search：E｜PDDL3 本身无搜索/修复算法。Porteous 的 selectConstraint 只看未 visited 节点；取当前未 visited 图中没有直接 predecessor、且节点事实与当前 singleton PoV 有交集的最早候选；多个候选在原实验中任意选，节点若含析取则选其中一个 fact（任意选或由 user model 选），非最优排序。visited 不是 achieved。把选出的单个 fact c 作为当前子问题 goal；原实验底层为 FF-v2.3（作者说一般也可用命题 planner），不是唯一/通用 FF 规划保证。
- Trigger：E｜轨迹约束用于叙事控制。Porteous 每次交互/视角变化后更新 I、G、PoV；若当前 c 仍属于当前 PoV，回 Algorithm 1 的 planner call 重规划 c；若 c 已不再属于当前 PoV，break 当前 plan loop、mark c visited，继续选下一 applicable constraint。正常完成当前 segment 后也标记 visited；最后对 O、I、conjunctive G 调 planner。
- Repair：E｜PDDL3：逐状态计算轨迹公式真值及偏好违反。Porteous：以最新 I 对同一个仍相关 c 调 FF-v2.3 重规划，不回滚过去。**原图 line 12 的 mark c as visited 在 line 4 的 if planner found a solution 之外**：逐行直读，即使 planner 无解也会标 visited 并继续循环，没有专门 failure recovery。这不是“不相关”的证明，也不意味着 c 已满足；若搬用时想无解即停，属于新增逻辑，必须另标。
- Can change：E｜PDDL3 planner 可以选择未来计划以满足约束/偏好；Porteous 可改未来行动路径和当前子目标阶段。
- Cannot change：E｜PDDL3 不会凭公式创造可达路径；软 preference 不是硬保证；Porteous 不会令已破坏世界复原，也不证明找到全局最小改动。
- Handwrite：E｜需定义谓词与绑定、事件如何体现为状态/AP、时间锚点、硬软级别；Porteous 还要作者画 constraints/landmark graph、定义算子与动作效果。
- old cost：E｜PDDL3 是语言规格，不含求解器成本结论；Porteous 需要人工域与图，搜索/实验不能解释为减少总作者劳动。
- LLM replace：I｜可草拟谓词绑定、轨迹公式、地标/算子候选和反例轨迹；须人工确认谓词语义、事件一次性、期限锚点与规划可执行性。
- must not replace：I｜不得把公式“可解析”当语义正确/可达；不得把 constraint=目标动作已发生；不得把 PDDL3 语言写成完整 planner；不许每次重规划把绝对 deadline 从“现在”重置。
- Eval：E｜PDDL3 检查每个时间戳状态/区间及 hard/soft；Porteous 原件提供交互故事例与系统性评价，具体指标见[续审](../专题调研_多层状态轨迹约束与可执行世界_2026-10-07.md#2-状态轨迹约束不是只管剧情pddl3-到地标重规划)。本卡不补写未在本地审计中核实的数值。
- Failure：E｜公式可能排序写反、持续命题反复触发或空前件真空满足；没有动作域时可能不可达。Porteous 任意选 earliest eligible node；算法图无解时跳过执行 if、仍到 line 12 标 visited，不能用 visited 数冒充达成数。PoV 变化可能使 c 不再适用，但 planner 无解本身不等于 PoV 不适用；全文没有在此给出充分恢复契约。

可手推步骤 A：PDDL3 轨迹判定（严格用 sometime-before φ ψ 次序）

1. 读公式 (sometime-before accuse evidence)：φ=accuse，ψ=evidence；定义为每个状态 i 若 φ 成立，必须存在 j<i 使 ψ 成立。
2. 轨迹 S0{¬evidence,¬accuse} → S1{evidence} → S2{accuse}：对 i=2 找 j=1，满足；S0、S1 无 accuse，不产生义务。
3. 反例 S0{¬evidence,¬accuse} → S1{accuse} → S2{evidence}：i=1 没有任何 j<1 的 evidence，硬约束失败。
4. 空轨迹未发生 accuse 时，此公式仍满足；若作者还要求 accuse 至少发生一次，单独加 sometime accuse。
5. 若状态 evidence 持续为真，公式在每个 accuse 状态仍逐次检查；若作者只想约束首次事件，需用一次性事件谓词/额外状态机表达，而非把持续状态误当单次事件。

## 卡 4｜IDG（AIIDE-17 workshop, 2017）：SPG 层扩展与 goal-set Jaccard

原件：[Amos-Binks, Potts & Young, “Planning Graphs for Efficient Generation of Desirable Narrative Trajectories,” AIIDE-17 Workshop, 146–153](https://cdn.aaai.org/ojs/12989/12989-52-16506-1-2-20201228.pdf)，Algorithm 1 printed pp.150–151，LRRH / Jaccard pp.149–150，limitations p.151 已定向复核。这里 IDG 确为本文 2017 年的 Intention Dependency Graph；不要与其他年份同名 dialogue IDG 混淆。

- Problem：E｜从叙事规划问题快速构造多种带人物目标依赖的 exemplar trajectories，供 exceptional user action 后比较不同未来；不是完整 runtime repair selector。
- State：E｜Φ=(I,G,C,S,Λ) narrative planning problem；SPG 交替 literal/action layers，possible history (PH) 将各层事实/动作追溯到 IDG 顶点；IDG 顶点 label 是 character-goal 集合，边记录动机/意图依赖。
- Author input：E｜groundable action schemas PRE/EFF、角色 goal graphs/motivations、I/G； character goal 是〈character,literal〉；动作必须在某意图路径支持目标，其他前提可由外部路径满足。
- Character input：E｜显式角色目标及其 intentional paths；不是连续心理、置信度、情绪或主体观察模型。
- World model：E｜符号 literals、动作 pre/effects、planning graph。SPG 不建 mutex edges，因此含动作冲突/不可达组合的可能。
- Authority：E｜构图算法同时写 SPG、PH、IDG labels/edges；IDG 输出估计的可行 narrative-content exemplars，不授权执行，也不自动改变人物目标。
- Search：E｜每层枚举可适用 ground actions 且 action 属 goal graph 的动作；在 PRE 的 PH 组合中传播已有 goal dependencies；新增依赖就建 IDG 顶点，label 合并父顶点 labels（新角色 goal 时再并入）；更新边与 PH 并传播至 effects；到 G 达成/层不再增长后连 solution vertices。候选之间论文演示用 Jaccard 距离比较 labels；未报告自动全局最优心理连续性解。
- Trigger：E｜求解/构图时从初始层递归扩图；用于分析新故事规划问题/可能 accommodation，并非实时收到 ΔW 后的完整操作算法。
- Repair：E｜在候选 exemplars 间可以按目标集合差异排序；这是度量/比较步骤，不替代实际重新规划或在线验证可执行性。
- Can change：E｜算法新增 SPG actions/layers/edges、PH 组合、IDG vertices/edges/labels；“选择哪条新未来”是下游 accommodation 决策。
- Cannot change：E｜不能消除 mutex 缺失、保证每个 exemplar 真可执行、列尽所有更长/非必要剧情支路，或断言 Jaccard 小就表示角色心理连续。
- Handwrite：E｜要写动作与效果、人物 goal graph/motivation、初态/目标；IDG 的比较对象由这些模型所生成的 character-goal labels 决定。
- old cost：E｜作者成本转为 ground actions/goal graphs/motivation 建模；论文分析构图开销，但不报告作者工时或人类对 metric 的效度验证。
- LLM replace：I｜可提候选 goal/action schema 供审阅；每个 goal 必须有 author/source provenance 与支持链，不能把生成的标签直接加进 PH/IDG 当事实。
- must not replace：I｜不得把 goal-set Jaccard 称为情绪/心理距离、动作序列距离、世界状态距离或“最小心理变化”；不得省略对候选完整计划的 mutex、资源、时序与运行时验证。
- Eval：E｜论文在 Little Red Riding Hood 示例展示 v4/v7/v8 和效率分析；metric 的 narrative-theoretic validity 明确不在研究范围。项目可复核集合运算，同时单独报告可执行率与标签来源。
- Failure：E｜SPG 无 mutex → unreachable plans/exemplars 被计入；G 达成即终止 → 近最短层，漏更长的不同 goal dependencies；仅保留到达 G 必要的 character goals → 漏兼容 dead-end narrative branches；Jaccard 漏掉“goal 不同但 action set 相同”等情况。

可手推步骤（图扩展+集合比较；数值集合明确是示意，不冒充论文未列出的完整 vertex labels）

1. 读 Φ=(I,G,C,S,Λ)、character goal graphs；建初始 P0=I，IDG 根 v0 的空 label，并令 PH(I)={v0}。
2. 在 A0 枚举 PRE 已满足且属于某 character-goal graph 的 ground action；把 PRE→A、A→EFF 加进 SPG。
3. 对每个 action 的可能历史 PH(PRE)，查看其 character goal 是否已在依赖 label；若依赖组合新增，建 IDG vertex，label 合并 parent goal sets，连 dependency edges。
4. 若 action 开始一个新 motivated character goal，则把新〈c,g〉并入新顶点 label，并连到其所依赖 PH 顶点；更新 PH(A)。
5. 将 PH(A) 传播到 EFF literals，生成下一 literal layer；继续枚举 action，按层构出 SPG/IDG。
6. 目标 G 已满足时，检查 PH(G)；单一历史顶点可直连终点，多个依赖则用 union label 建 exemplar 终点并连接父节点。
7. 只在终点 labels 上比较 Jaccard d(A,B)=1−|A∩B|/|A∪B|；距离越小仅代表两个集合重叠越多。
8. 对照原例，文中说 v4→v8 的单一差异是“bw not eating gm”，并报告 d=.25；v4→v7 报 .66（1−2/6，精确算术为 2/3≈.667）。原文不是心理距离验证。

论文手推集合（只用原文明确给出的差异与基数，不臆造其余 goal 名称）：设共同的三项目标为 S={〈c1,p1〉,〈c2,p2〉,〈c3,p3〉}，c 是 actor、p 是 goal literal；这些是匿名占位符，不是 paper 逐项列出的 v4 labels。原文说 v8 相比目标轨迹 v4 只多出“bw not eating gm”，故按这个集合关系写 L(v4)=S，L(v8)=S∪{〈bw,¬eat(gm)〉}。则交集大小 3、并集大小 4，d(v4,v8)=1−3/4=.25，与原文相符。v7 的原文只给出交集 2、并集 6，故 d=1−2/6=2/3≈.667；论文印作 .66。由于未从可读正文取得 v7 全部 label，不能把缺失元素名字补成“真实集合”。比较顺序仅表示该集合指标上 v8 更近，不等于自动执行 v8，也不等于心理连续性。

## 辅助基线｜Sabre：集中式意图/信念规划（简卡）

原件：[Ware & Siler, “Sabre: A Narrative Planner Supporting Intention and Deep Theory of Mind,” AIIDE 17(1), 99–106 (2021)](https://doi.org/10.1609/aiide.v17i1.18896)；[官方项目页](https://cs.uky.edu/~sgware/projects/sabre/)。本项目既有审计读过全文；不要与 3 页 AAMAS extended abstract 混为一版。源码/运行未复现。

E｜输入：角色、fluents、动作 pre/effects、consenting actors/观察条件、触发器、初态及可错 belief、author utility 和各角色 utility。状态把世界与嵌套 belief 纳入符号表示；不建概率不确定性。搜索以特殊 author character 开始，未提升作者 utility 时挑可执行动作；每个 consenting actor 必须在其 belief 中相信动作可行，且动作可作为提升自身 utility 计划的首步；再更新 state/beliefs 并递归。完整解需提升 author utility 且每个人物动作都有解释。planner 是唯一全局决策者，不是放任独立 NPC 的在线自治。fluents/actions/triggers/utilities 仍需作者定义；无解可能不终止，实验用深度上限；无 soft-goal relaxation。论文 benchmark 报节点/耗时与 intention/belief ablations，不是玩家效度。接缝推论：适合作“行动由作者效用推动、每个角色动作须可由其 belief/goal 解释”的强符号基线；不拿来声称局部自主已解决。

- 若组合这些卡，必须显式定义共同对象、时间/事件语义、权限与验证器；不能把 IPOCL frame、Thespian reward weights、PDDL preference、IDG Jaccard、Sabre utility 合成一个无出处的“人物连续性分数”。
- 作者模型、LLM 建议、执行成功的 W 事实、角色持有的 belief 必须分别记来源；接缝是待检验工程/研究推论，不是文献已证明的统一算法。
