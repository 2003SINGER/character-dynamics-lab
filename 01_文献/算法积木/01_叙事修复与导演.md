## 卡 1｜Mimesis mediation：causal-link threat → accommodation / intervention

**版本边界。**2003 原件是运行中的 mediation 机制；2005 是在其线性计划+重规划能力上证明可表达任意有限无环 branching story graphs（还可表示用户与角色并行），不是同一算法的性能升级；2013 是 Robertson & Young 加角色知识模型的 POCL 双向修复扩展，允许重规划某些“确定未观察”的过去步骤，不等同于 2003 的未来-only accommodation。页码均为论文印刷页。

| 字段 | 可执行含义 |
|---|---|
| Problem | 用户动作可改变世界并威胁预先计划的后续因果依赖；在连贯性与用户控制间选修复或介入。 |
| State | 2003：完整部分序计划 P=(steps, orderings, causal links)、已执行/未执行状态的执行 DAG、当前时间点及 mediation policy。局部历史由已完成步骤和实际世界效果承载；不是只保留最近一步。 |
| Author input | 叙事目标/计划、用户与 NPC 的声明式动作前提效果、可控时序、动作至引擎行为的平行实现；若用 intervention，还要为可能动作定义 failure modes。计划如何生成及高效重规划细节超出 2003 文范围。 |
| Character input | 用户可用动作库及当前 action；系统角色的后续动作/目标在计划内。用户动作交给 Mediator 比对，玩家偏好模型不是 2003 threat test 的必要输入。 |
| World model | 命题/受限一阶谓词、动作 preconditions/effects；causal link `s_e→c` 表示 step `s` 建立 `e`，未来 consumer `c` 需 `e`。现实执行由 MUTS/Execution Manager 承接。 |
| Control authority | **中央导演**预生成计划与 mediation table；可接纳异常并换未来计划，或在执行前用 failure-mode 替代用户动作。后一项会更改动作结果，不是“只修复未来”。 |
| Planner search | 离线：对每条 causal link 枚举能在其时间区间执行、且 effects 含 `¬e` 的用户 operator，建立 policy entry；预先生成 accommodation plan 或挂接合法 failure modes。运行时：Mediator 按 action 与 interval 查表；2003 未给完整 replanner 搜索程序。 |
| Trigger | 仅当 link 的 establisher 已发生、consumer 尚未发生，用户动作可在两者区间内发生，且可统一匹配 effect 否定 link literal 时构成 threat。普通 plan 外但 effects 不碰未执行计划是 consistent，不触发 repair。 |
| Repair semantics | Accommodation：执行实际异常并从该异常点后重排/重规划未执行计划，重建被威胁 causal support。Intervention：异常请求尚未执行时选效果不再威胁计划的 failure-mode 替代。 |
| Can change | 2003 accommodation 可改未执行的未来内容/地点/因果链；介入则替换用户动作效果。2005 可把 contingency 扩成分支图。2013 可在角色知识条件下改未见的前史与未来。 |
| Cannot change | 2003 accommodation 不能让已执行的历史步骤“没发生”；但 intervention 会拒绝真实结果。2013 的过去编辑仅限其模型判定玩家未观察到的部分，已知/可观察事实受保护。 |
| Handwrite | 作者须写 action schemas、story plan/goal、user action domain、因果与先后、失败方式及计划到引擎实现。2013 还需知识/可观察性模型；其“未观察”推断不是零成本。 |
| old cost | 2003 明说完整高效 re-planning 超出论文范围；大幅变化会要求计算昂贵的重规划。预计算 table/contingencies 换运行期响应；没有作者工时或人类连贯性对照数值。 |
| LLM replace | **候选而非论文结论：**可把某个断链需求转成修复事件草案/多个候选，并解释所需 precondition/effect。 |
| LLM must not replace | 不得判定执行引擎中 action 是否成功、伪造 W 前提、删已执行 history、把 intervention 伪装为 accommodation，或自行授权 2013 式潜史改写。候选仍须正规规划验证。 |
| Evaluation | 2003 以银行金库叙事例演示 policy、accommodation 与 shoot failure-mode；无定量用户评测。2005 是表达能力证明，不是实验性能。2013 为算法/小例说明，无用户实验或规模基准。 |
| Failure | 若 accept 实际动作后没有合法替代支持链，则 accommodation 可能无解；本文不提供保证可修复。2003 可退回 intervention，但需作者预置 plausible failure mode。2013 扩大搜索空间但依赖知识模型准确。 |

### 算法骨架（2003；有限 pseudocode 释义）

```text
离线，对每条 link s --e--> c：若 s < α < c 且用户 operator α 含 ¬e，存 (α, interval, response)。
response=accommodate 时，预先从该 α 的实际结果构造一份可接续的新计划并挂到 policy entry。
response=intervene 时，只挂接其效果不威胁剩余 links 的 failure-mode 候选。
运行时接收用户 command α；先查当前执行 DAG 的时间区间和匹配 policy entries。
若没有 exception entry，转发 command；若它是 plan constituent，再将该操作纳入执行 DAG。
若命中 entry 且选 accommodation：让 α 的真实效果进入 W，标记其已执行，保留此前 completed steps。
以更新后的 W 和已完成前缀为条件，调用 planner 求未执行尾部；不能复原的既往 action 不在 repair 搜索变量内。
若命中 entry 且选 intervention：在 α 执行前选一个兼容 failure-mode，并执行其代替效果。
```

`inference from paper`：第 6 行表达原文“执行异常并重构未执行部分”；2003 论文没有给 planner 内部 open-list/refinement 的完整伪代码，故这里不杜撰其搜索控制细节。2005 证明范围是 acyclic branching graphs，证明不等于离线穷举对任意规模都实用。2013 算法另加 possible-knowledge DB、删除保证未观察过去步骤、modified POCL 插入前/后步骤，并保护用户已观察内容；这是不同权限版本。

### 手推例（X；自制事实，不是论文实验）

1. 计划前缀 `P0: 门禁员给 A 钥匙` 已成功执行，效果 `hasKey(A)`；未来 `P1: A 开档案门` 的 precondition 是 `hasKey(A)`，link 为 `P0 --hasKey(A)--> P1`。
2. 现在位于 `P0 < t < P1`。A 执行 `丢弃钥匙`，operator effect 含 `¬hasKey(A)`；统一同一人物 A 后，link 有 establisher 已完成、consumer 未完成、区间匹配、效果互补四条件，因此命中 threat。
3. consistent 分支不成立：本动作确实删除了 P1 所需 literal。不是“偏离故事”本身触发，而是删了保护条件。
4. accommodation 将该动作实际写入 W，保留 `P0` 和丢钥匙的执行记录；若作者已建模且当前可达 `向值班员借备用钥匙`，再由该事件建立新 `hasKey(A)` 支持 `P1`，便可接续。没有此合法 operator/前提时，原文不给“自动编出钥匙”的保证。
5. intervention 可在动作前执行 `钥匙从手中滑落但被接住` 这类作者预置 failure-mode；它保住旧剧情，但 A 的丢弃意图没有真实效果。若游戏承诺玩家成功结果，这条权限必须明确禁用，不能记成成功 accommodation。

## 卡 2｜DODM：全局 plot history 上的优化导演（SAS+ / TD / SASCE）

| 字段 | 可执行含义 |
|---|---|
| Problem | 对可能自由探索的玩家，在剧情进行时选 drama-manager action，提高作者评估的完整故事质量；不必把每个日常世界动作都编成剧情分支。 |
| State | 顺序重要。状态是至今发生的 plot points 与 DM actions；TD 的输入用 `n×n` precedence matrix `M` 编码事件先后，及 DM action history/必要 annotations。不是全世界 W 的完整状态。 |
| Author input | ①事件级 plot points、prerequisites/发生信号与注释；②有合法条件/合理时机的 DM action 库与其低层 refiner；③以 plot/action 注释计算的 completed-story evaluation features/权重；④搜索或 RL 训练配置。 |
| Character input | 玩家模型提供可选合法 plot points 的概率。论文实验的基础模型：在 prerequisites 满足点中均匀选择，hint 过的点概率提高；不是由真人数据拟合。NPC 是被 DM 指挥/调制的对象，不等于被建模为有私有心理状态的行动者。 |
| World model | 抽象的 point prerequisites/availability、发生顺序、DM action 效果及玩家选择转移。Poster 中点/DM action 可以注释地点、揭露信息、操控感等；实物实现属于游戏/refiner。 |
| Control authority | **中央导演**在 plot-point 层插入 cause/deny/temporary deny/reenable/hint；游戏层可以指令或调制 agent、改世界/物件。权限取决于作者 action 与 refiner，不是所有 DM 动作都只是可执行世界事件。 |
| Planner search | SAS+：DM 最大化节点与玩家按模型取期望节点交替，固定深度 full-width；截断节点各采样固定数的合法未来故事，用终局作者分数均值估值；采样时不再介入，先重新启用暂时 deny 点。TD：数千模拟游戏中以 successor 当前估值更新遇到的 state value，终局目标值为作者 J，神经网络近似 state→value；部署选使 successor value 最大的合法 DM action。论文明确说完整 TD 描述超出篇幅，未给步长/折扣率/eligibility trace 公式或参数。SASCE 仅更换训练用 player model。 |
| Trigger | 在 plot-point/DM-action 抽象决策点被调用；不是每个低层世界 tick 或每个 NPC 局部动作都调用。 |
| Repair semantics | 不做因果链 flaw repair；它选使未来 plot trajectories 的作者总评分期望更高的 steer。`null` 是合法“不干预”动作。DM action 可能使 plot point 立即发生或改变玩家可达性/概率。 |
| Can change | 取决于 DM operator：cause 立即触发 point；deny 永久不可达；temporarily deny 暂时关闭；reenable 解封；hint 增加玩家做该点概率。具象世界效果由游戏/refiner实现。 |
| Cannot change | 不能仅凭抽象点模型证明具体世界操作真实合法或 NPC 真愿意做。点序列不是完整 runtime history。DODM 论文没有将其定义为因果 repair、行动代价最小化或人格连续性模型。 |
| Handwrite | plot-point recognizer/signal 与 prereqs、语义注释；DM action 有效/可用规则和 plausible 时机；refiner 将抽象指令变成游戏事件；evaluation feature/权重；玩家概率模型；RL 熟练度/训练。The Guilty 还需 backstory fixedness ideal arc、信息揭露/怀疑特征；NWN 较弱 NPC 要逐项改 dialogue trees，置物等也靠 refiners。 |
| old cost | DODM 将局部 triggers 的全局一致性搬到显式 point/action/evaluator；但抽象 operator→游戏实现需作者/程序员 refiner。作者报告全局改 feature 易于迭代，不是定时的人力研究。大域缺 DM actions 时各 optimizer 差；补 synthetic actions 会提高分数，但增加并不一定可信的作者动作。 |
| LLM replace | 候选：从用户新剧情意图产出 point/action schemas 草案、候选评价特征/剧情序列解释，或把 high-level action 转成 refiner 草稿供人检查。是否减少净作者时间尚未验证。 |
| LLM must not replace | 不得自选评价尺度/权重并宣称客观故事质量；不得伪装 agent 执行成功、隐藏世界改写或玩家概率来源；不得将论文的 manipulativeness annotation 擅自改写为固定“每次 DM action 惩罚”。 |

| Failure | 搜索短视对复杂域可能差；动作库不足导致优化器无从实施高分 story；动作库极强又可能反复 cause 少量相似故事、伤 replay diversity。SASCE 的模拟玩家不是人类概率校准；函数优化好不代表评价函数有效。 |

### 算法骨架（E；SAS+ 与 TD 区分）

```text
给定历史状态 h=(已发生 points/actions 与 precedence M)、DM 合法动作 A_DM(h)、玩家可选点 A_P(h)、终局作者分数 J。
SAS+ 在 DM 节点对每个合法 d∈A_DM(h) 展开；按 d 的定义更新 plot-point 可用/发生状态，null 保持不变。
在玩家节点，按 player model 的 P(p|h') 对所有当前可发生点求期望，点发生后更新 h' 与 M。
树深达到 cutoff 时，先 reenable temporarily-denied 点；从每个 cutoff node 采样 K 条合法续篇，此阶段没有 DM action。
每条续篇到完成故事后算 J；其均值作为该 cutoff 值，自底向上算期望，根选值最大 DM action（包括 null）。
TD 训练：模拟完整故事，terminal target 为 J(h_terminal)；沿已遇 states 以 successor 当前估值反向更新 Vθ。
TD 细节边界：论文 §3.2 只描述 successor-value bootstrap 与 NN function approximation；具体更新式/步长/γ/λ/trace 均未披露，故此处不补标准 TD(λ) 公式。
部署 TD：对每个合法 DM action 求 successor value，选 argmax_d Vθ(T(h,d))；不额外加固定操控罚项，除非它已进入作者 J。
SASCE 训练：对可选玩家后继 s_i 依 p(s_i)=exp(αβ(s_i)V(s_i))/Σ_{s_j∈S}exp(αβ(s_j)V(s_j)) 抽样；α 正/负对应合作/对抗倾向。
其中 β(s)=1，除 DM 曾对该状态提供 hint 时使用常数 c_a>1；α、c_a/q 是训练控制量，不是实测玩家概率或心理量。
```

**precedence matrix 方向（原文 p.777；核对图示矩阵）**：`M[i,j]=1` 表示点 `i` 发生在点 `j` 后面。例序列 `3,4,2`：非零 `M[2,3]、M[2,4]、M[4,3]`；原矩阵第 2 行第 3/4 列为 1、第 4 行第 3 列为 1。这里的 1 是“行点较晚”，不是“行点先发生”。

### 手算例（X；作者自定均匀玩家模型与 toy 分数）

设所有候选方案都在**恰好两个 plot-point occurrences 后结束**； DM action `cause(A)` 本身使 A 作为第一个 occurrence 发生。初态 `A=找到钥匙`、`B=听到传闻` 均可发生；`C=打开密室` 需要 A。玩家在当前合法点中均匀选。自制 terminal evaluator 完整定义同深度所有叶：`J(A,C)=100, J(A,B)=60, J(B,A)=20`；无其他合法叶。数字不是论文数据。

1. `null`：第一步 A/B 各 `1/2`。若 A，第二步 C/B 各 `1/2`，该子树值 `(100+60)/2=80`；若 B，第二步只有 A 合法，概率 `1`，叶值 `20`。根值 `0.5×80+0.5×20=50`。
2. `cause(A)`：仅当该 DM action 在当前状态合法且 plausible；A 已是第一个发生点。第二步 C/B 各 `1/2`，叶值 100/60，根值 `0.5×100+0.5×60=80`。
3. 两个动作下的每条叶路径都恰有两个 plot points；比较同一 horizon，故在这个作者 toy J 下选 cause(A)，80>50。J 没有操控 feature，所以本例不能推出低干预成本或低操控感；也未给 cause 加任意罚分。

本小树展示的是**作者完全给定转移与分数后** expectimax 的手算；原文的 `hint` 只说提高点发生概率，具体概率倍率由模型/实现设定，本文没有提供可移植的普适数值，故例中不用 hint。若只用 TD 手算，则先有 `V(A)=...` 等训练估计；没有训练 checkpoint 不可伪造网络输出。

### The Guilty authoring evidence（E）

## 卡 3｜Narrative Mediation as Probabilistic Planning（2017）：把玩家选择转成 PPDDL outcome

| 字段 | 可执行含义 |
|---|---|
| Problem | 传统 mediation 把玩家备选动作逐个展开为分支 plan tree；将相同互动改写成含随机玩家动作结果的单一 PPDDL planning problem，由概率规划器产生 policy。 |
| State | PDDL story world initial state/goal 与当前 logical world state；policy 是 `state → system action`。需要状态足以判定 grounded action prerequisites。 |
| Author input | grounded 或可系统枚举的 deterministic PDDL actions、initial state/goal、玩家控制角色身份、角色/轮次安排；另给 player choice model。 |
| Character input | 玩家可选合法 ground actions；原文示例假设每个状态均匀随机选合法选项。偏好模型、goal recognition、role assignment 被作者指出可替代，但本例没有估计/训练这些分布。 |
| World model | action preconditions/effects；NPC/system action outcome deterministic=1.0。玩家动作在互斥前提组合的 common applicability 区域被编成一个 PPDDL operator，其 probabilistic effects 对应各 ground action effect。 |
| Control authority | 概率 planner 控制 system/NPC actions；玩家选择对系统不可控，由 nondeterministic/probabilistic transition 表示。假定 system 与 player turns 有显式顺序。不是统一导演直接覆盖玩家结果。 |
| Planner search | 论文提供的是 PDDL→PPDDL operator conversion，不自创 planner；随后交给 standard probabilistic planner 求解 MDP policy。找出玩家 ground actions 前提相交/分化情形，递归生成组合/单选 operator，按 user model 分配 effects 概率。 |
| Trigger | 每个 MDP state 到轮次对应一类 action：system turn 选确定性 NPC action；player turn 用预编的随机 outcome operator 表示其合法选择。不是等 storyline threat 才触发。 |
| Repair semantics | 不逐个保存未来 contingency plan；MDP policy 会按实际状态继续选系统动作。改变的是建模与求解形式，不是 2003 accommodation/intervention 的配对逻辑。 |
| Can change | 可自动组合玩家动作可选集合，表示不同玩家合法动作导致的世界结果概率；策略可因当前状态选不同 NPC/system action。 |
| Cannot change | 转换器不能发现原 PDDL 缺失的动作、效果或事实；uniform 只是 placeholder，不说明真实人类概率。不能凭概率计算保证角色意图可信、故事得分高或物理实现合法。 |
| Handwrite | deterministic domain/problem、玩家/NPC action eligibility、turn ordering、概率选择模型；如希望真实选择概率，需另有数据/choice model 并验证。原文小例自己手写 Arthur/Merlin、Rock/Excalibur、locations、take operator 与目标。 |
| old cost | 把分支 mediation tree 展开转为概率域，再依赖 PPDDL planner；无需逐一手造概率树，但需要覆盖相交 action schemas 并可能递归枚举组合 operator。本文无运行时间/作者工时对照。 |
| LLM replace | 候选：提议缺失 operator/前提或玩家候选动作，并生成可审查的 PDDL 草稿；执行前仍需 schema/type/precondition/effect 验证。 |
| LLM must not replace | 不得给出未测的“真人概率”，把均匀假设讲成经验数据；不得让生成概率在运行时随叙事措辞无依据漂移；不得以 MDP policy 代替 W action validator 或自主 NPC 模型。 |
| Evaluation | 4页 workshop 论文给 Arthur 在 Woods 拿 Excalibur/Rock 的小型转换例；没有性能比较、用户研究或概率校准实验。主要贡献是 formulation/conversion，不是 empirical win。 |
| Failure | 用户分布假设错会令 policy 的期望失真；状态空间/组合算子可膨胀；输入 PDDL 未表达实际世界/角色约束时概率 planner 只会在错误模型内正确求解。 |

### 转换骨架（E；对原文程序的紧凑释义）

```text
输入确定性 PDDL operator schemas、初始状态 I、目标 G、player-controlled actor。保留 NPC/system actions 为概率 1.0。
fully ground 故事域中玩家可能执行的 actions；按各 ground action preconditions 的相交/区分情形构造 applicability regions（原文未先运行 reachability search）。
若一个 region 仅启用一个 ground action，将其写成单一 outcome、概率 1.0 的 operator。
若 region 同时启用多个 actions，把共同成立的前提合并成一个 intersecting operator。
该 operator 的每个 probabilistic effect 对应一个原 player action 的 deterministic effects。
用声明的 player choice model 分配效果概率；原文占位模型对合法选项均匀分配，不是 learned estimate。
递归处理 actions 仅部分相交/部分可用的 regions，生成单选及组合 operator，直至 choice situations 被表示。
将 PPDDL domain/problem 交给概率 planner，得到从 world states 到 system actions 的 MDP policy。
```

### 手算例（E+X：原论文 Arthur–Merlin 例，概率来自明确占位假设）

原文初态：Arthur（玩家）与 Merlin 在 Woods；Rock、Excalibur 都在 Woods；目标 `Arthur has Excalibur`。deterministic schema `take(taker,thing,location)` 要求 taker 与物在同一地点，效果为物离开地点、taker 持有物。原计划选 `take(Arthur,Excalibur,Woods)`；玩家回合另可合法选 `take(Arthur,Rock,Woods)`。转换后原 `take` schema 加前提 `taker ≠ Arthur`，仍作为 NPC/system action 保留且 outcome probability=1.0。

1. 初态两条 Arthur ground actions 同时可执行，故创建组合 player operator：共同前提 `Arthur@Woods ∧ Rock@Woods ∧ Excalibur@Woods`，outcome 分别拿 Rock 或 Excalibur。
2. 论文 placeholder 对两个合法选择均匀：`P=1/2,1/2`。它另保留 NPC 版本 `take(?taker,...)` 且前提 `?taker ≠ Arthur`，确定性 `P=1.0`，因此不会把 Merlin 动作并入玩家随机性。
3. 分化区域：若之后 Rock 已不在 Woods 而 Excalibur 仍在，则只有 Arthur 拿 Excalibur 这一个玩家动作可用，生成它的概率 1.0 单 outcome operator；反向条件同理只生成拿 Rock 的 1.0 operator。
4. 两物都在 Woods 时的组合 operator outcomes 更新对应 `has(Arthur,thing)` 并删除 `at(thing,Woods)`；若 Arthur 已拿 Rock，该状态下原 take(Arthur,Excalibur,Woods) 前提仍成立，下一玩家 turn 的可选性由更新后的 state 再判。
5. PPDDL domain/problem 交给概率 planner 得 state→system-action MDP policy；论文没有报告此玩具 policy 的定量质量或真人选择频率。
