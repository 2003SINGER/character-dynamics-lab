# 统一问题与成熟基线准入

日期：2026-10-08；状态：**READY_FOR_INDEPENDENT_REVIEW；不是方法选择、源码复现、实验准入通过或 novelty 声明。** 范围：把已整理的算法机制映射到统一钥匙—账本实例，区分可复用能力、接口适配和待证候选；不宽泛查新、不重复机制卡、不新增算法。

## 结论先行

- **A（持续世界规划、执行反馈、局部认知与重规划）：** 最小执行基线是 actor-local GOAP + 同一真实 executor + 独立 B 策略；HTN 是强替代规划器条件。Sabre 是集中式符号解释/规划参照，不是自治角色轨迹，也不提供数值或成功率上界。
- **B（以稀疏作者要求控制角色与世界发展）：** 最小选择链是 trajectory monitor、landmark 目标排序、合法机会枚举（含 `null`）与固定 actor/player policy rollout；作者评价选择器可用 DODM-style 搜索。PDDL3 是约束规格而非 planner；未知玩家模型须做策略敏感性分析，不能伪称真人概率。
- **belief / intention / consent 的比较：** Sabre 是集中式作者效用与角色信念/意图解释参照；IPOCL 与 Thespian 分别提供计划内动机支持与人物模型 fit/gap。它们不是“不懂人物”的弱对照，也不等于在线自主 NPC 执行器。
- **桥接与内容系统：** WhatELSE、Anansi、DiriGent 各自覆盖固定动作域内的 event 编译、可复用 storylet 绑定或张力引导；不应被拼成一套全知且有权写入世界的统一导演。
- **基础能力与研究准入判断：** 因果修复、轨迹约束/地标重规划、计划意图解释、belief/consent 规划、作者效用导演、固定域剧情编译与 storylet 绑定分别已有成熟先例；这些基础能力本身不构成本项目的独立新颖性主张，未接入或未实现也不等于 gap。**有限比较尚未运行，目前尚不能认定复合要求存在研究缺口或已形成贡献；可以继续设计有限 E0 协议，执行状态仍为 NOT_READY。**最多三个条件化问题见 §7，不作 novelty 声明。
- **准入判断：** 目前具备形成有限纸面 protocol 的材料，不具备启动预实验所需的冻结实例。交易算子、动作时长/资源、玩家模型、B 的同意策略、搜索/rollout 预算、评价指标和 executor 映射尚未共同冻结。停止在方案审阅；不自动运行实验。

## 2. 统一实例、域约定与判定层

### 2.1 不可混并的五层

| 层 | 需要回答的问题 | 本例证据 |
|---|---|---|
| 世界可达 `W-path` | 给定当前真实状态与动作 schema，若动作都成功，是否存在合法资源/时间路径？ | 有限域搜索返回路径；或完整穷尽后的不可达证明。 |
| 角色可知 `actor-known` | A 的 O 是否能支持下一动作前提？A 是否知道备用钥匙/合法取得方式？ | O 中的合法观察/反馈，或明确的 information gap。世界真值不能代替 O。 |
| 角色动机 `actor-motive` | 在 A、B 各自目标、承诺、资源机会成本和策略下，该角色是否可能选择该动作？ | 被 pin 的角色策略/goal 模型及 rollout；意图解释计划不是实际选择证据。 |
| 真实执行 `execution` | 请求是否通过当前 W 校验、持续期间是否仍合法、何时真正产生 outcome？ | 唯一 executor 的 accepted / failed / interrupted / settled 回执与 ledger 事件。 |
| 作者权限与证据 `director/evidence` | 作者有权提供什么机会/约束？哪条事实可证明目标已经发生？ | 明示授权通道；追加式 committed ledger、来源/时间/序号、Monitor witness。 |

这些层必须分别判定：世界路径存在不自动保证角色知情、愿意、实际执行或作者有权干预。经同域验证的成功轨迹可以提供存在性路径见证，但不能据此保证所有允许响应下成功。规划候选、LLM 文本、运行期提案均不得写成历史事实。

### 2.2 统一纸面场景（X：自制有限域）

本节保留综合报告的纸面例与方法映射前提；具体 E0 状态、动作、预算和测试预期由[钥匙—账本 E0 协议](../../00_研究设计/E0_KeyLedger_Protocol_v0.md)统一维护，待独立审阅。本报告不再充当 E0 执行实例的第二 owner，也不由协议起草推断实验已准入。

- 初始时钟 `t=2`。玩家已成功提交 `destroy_key(player,key0)`，key0 有 tombstone；此事实不可撤销。A 的任务是**不晚于 `t=10`** 曾成功取得 ledger；证据是 append-only 的 `acquired_by_10` 实际 witness，而非截止时仍持有。同场位置是 archive 入口，ledger 初始在内部且 closed，A 知道入口；B 持 key1，A 的 O 不知钥匙存在/位置。
- B 有两个独立目标：取回 A 持有的 B 工具、获得 payment。旧例 `return_tool(A,B)` 只满足前者，不推出 lend；本 X 域给 payment 目标单独定值。B 持有 key1，借出有机会成本；示意 `ΔU_B = 2×payment − 1×loan_cost = +1` 仅证明同意可解释，不强迫真实 B 选同意。
- `offer_loan(A,B,payment)` 只询问 B 是否有可用钥匙并报价条件付款；不带未知 key1 ID、不预设 B 有 spare、不改变世界。B policy 选 `choose_accept/decline`；accept 答复才披露稳定钥匙 ID。`accept_loan(B,A,key1,payment)` 由 executor 检查双方对条款可见且已确认、B 当前持 key1、A 有 payment，再原子交换；A 由合法答复获知 key1。
- 上述交易动机与算子、时长、成本、策略、同场/沟通规则及 `unlock/take_ledger` 全是**X 自制域设定**，不属论文证据，不改 Pilot，也不代表仓库已有能力；所有基线必须固定同一目标、资源与策略，不得调参救特例。
- 作者要求采用绝对时间锚与 `acquired_by_10` ledger witness。若另问“截止时仍持有”，应另设状态约束；两者语义不可互换。
- 同一执行器拥有资源、位置、持有者、时钟与动作结算。动作时长由域定义；LLM/Director 不得编分钟数或自行结算。可行动作者干预只来自事先登记且授权的机会/操作；不允许 `set_owner(key1,A)`、抹除历史或把 B 同意塞入 A 的动作 effect。

### 2.3 实例的最小算子与可手推轨迹

每个 action 时长统一设为 1 分钟（X 假设）；A、B 起始同场，A 有 1 payment，B 有 key1。destroy 已在 t=2 前真实提交。

| action（选择者） | 前提/结算（每项 1 min） |
|---|---|
| `destroy_key(player,key0)` | 玩家成功删除 `held/intact(key0)` 并追加 tombstone；不可回滚，初始 t=2。 |
| `offer_loan(A,B,payment)` | A 询问是否有可用钥匙并报价；不含 key ID，只记消息、不改 W、不预设 spare。 |
| `choose_accept/decline(B)` | B 独立 policy 选一；accept 才披露 B 持有的稳定 key1 ID 与条款，拒绝保持状态。 |
| `accept_loan(B,A,key1,payment)` | 双方可见确认、B 持钥匙、A 有 payment 才原子交换；否则失败且不部分结算。 |
| `unlock(A,key1)` / `take_ledger(A)` | A 在入口持钥匙可 unlock（effect 仅 open）；take 需 open∧ledger_inside，只有成功 take 追加 witness；不要求 t=10 仍持有。 |

合法成功迹：`t2 destroy` 已提交；`t2→t3 offer`、`t3→t4 B accept`、`t4→t5 exchange`、`t5→t6 unlock`、`t6→t7 take`。仅 B 实际选择接受且 executor 全部结算时成立；若 B 的独立保钥匙目标给 `+3` 且拒绝，轨迹止于拒绝，A 不得拿 ledger。

### 2.4 对照公平性与不可达证明

- 所有基线共用相同有限 domain、W、角色初始 O/S/P/commitment、动作/时间/资源约束、玩家扰动、executor、可用授权目录、checkpoint、seed/cassette、horizon 和显式预算。
- 每种规划器都可以重算未来；共用 adapter 保留仍合法的 `RunningAction`、reservation 与 progress。比较 suffix 重算、重新获取资源、切换合法活动的代价及 repair 维护成本；直接 reset 是实现 bug，不是研究收益。原生不支持进度保持时另记 adapter 成本并报告原生行为。
- 搜索 expansions、墙钟、候选数、模型调用/token、rollout N/H、作者补 schema/审核分钟数、覆盖的能力和失败原因均计账。不能让 Proposed 花更多调用预算却只报告成功率，也不能用空壳 LLM/全知 NPC/没有 operator 的传统规划器当弱对照。
- `NO_PLAN_WITHIN_BUDGET` 不是不可达。只有完整穷尽已冻结有限域的状态/计划空间，或形式证明可达性否定，才能报告 `PROVEN_UNREACHABLE_IN_FINITE_DOMAIN`；结论仍限于该域与假设，不外推开放世界。
- 玩家响应未知时，将多种固定策略作为情境轴（如协作、探索、对抗或真实可用的代理策略），报告分布敏感性；不把其中任意一条当估计真人概率。角色 B 的接受/拒绝由独立 pin 的 policy 或预先声明的策略条件驱动。

### 2.5 三类计算对象与有限反例

存在性可达、固定策略成功与作者鲁棒保证是不同对象。对冻结域 `D`、初态 `W0`、绝对 deadline `T`：

1. **世界存在性：**是否存在一组合法 joint controls 及 executor 转移，可在 `T` 时刻及以前产生目标 witness（`∃`）。这不表示角色或玩家会作出这些选择。
2. **策略条件概率：**固定 actor/player 策略 `π` 和随机/响应模型 `M` 后，计算 `Pr(success at or before T | W0,π,M)`。确定性单条 trace 只有该次 verdict；有限样本只能在明确的采样假设下给估计/置信区间，不能给无条件或确定性下界、鲁棒保证或真人概率。
3. **作者鲁棒保证：**是否存在只依据授权历史行动的合法 Director 策略 `d`，对明示允许的外部、玩家和角色响应类均保证不晚于 `T` 成功（`∃d ∀responses`）。这不是 omniscient 固定动作序列，也不授予导演控制 B。需对冻结的有限博弈/模型及完整响应类完成有效证明；有限采样全成功不能证明全称量词。若响应类允许 B 全程拒绝，且不存在替代路径或许可干预，就不能声称此保证。Monitor 只判断已提交事实。

以下均为纸面反例，作用是检查结论边界，不预设任何方法更强；每行仍需冻结所列域事实：

| 反例 | 应得结论 | 不得推出 | 冻结/核对项 |
|---|---|---|---|
| A 不知道问谁，且没有合法信息来源 | 当前 actor 策略/信息集无法提出该路径；应记作待探索的未知信息 | 不能据此说 W 中不存在任何路径 | 合法询问对象、可见信息、信息传播与动作集 |
| B 拒绝当前交易提议，deadline 尚未到 | 当前交易分支未成；若域中已声明较贵替代且时间/资源允许，W仍有路径，任务 verdict 取决于真实后续执行与截止 witness | 不能把当前分支失败写成整个任务 trace 失败、世界不可达或所有策略失败 | 是否可再询问、替代路线及成本、剩余时间/资源、B 策略与 payment 目标 |
| 固定 B 策略在窗口内始终拒绝，且无替代路径、无许可 Director 干预 | 该策略条件下目标失败；在完整冻结域中可检验此条件结论 | 不能单凭此例说其他 B 策略、W 中其他控制路径或别的响应类都失败 | 响应策略类、全部合法路径/干预、作者权限、完整有限域与搜索证明 |
| 玩家提交 destroy 并破坏资源 | 以新 committed W 重算未来；过去事实不回滚 | 不能把资源假定复活或把一次扰动当作所有响应 | 可破坏资源、扰动时点、替代资源、策略/控制权限 |
| 剩余时间不足 | 目标在该绝对 deadline 下可能不可达；仅完整穷尽才是有限域证明 | timeout 或超过预算不是不可达证据 | 时长、起止边界、并行动作、资源冲突和完整域 |
| 交易占用另一项 running task 的共享资源 | 必须按同一资源/进度约束验证冲突；所有基线保留仍合法的 RunningAction 和 reservation | 不能让 full replan reset 制造局部 repair 优势，也不能保留已非法活动 | 资源容量、锁/预约语义、动作 progress、影响依赖 |
| 作者没有覆写 B/玩家的授权 | 导演不能强制其接受；应继续检查其他合法机会与策略 | 无权覆写本身不证明鲁棒保证不可能，也不证明保证成立 | 授权目录、完整响应集合、所有合法替代路径及其是否能保证成功 |
| 初始已持有、期间取得后丢失 | 初始 holds 状态、真实 acquired 事件、deadline 时仍持有是不同性质；历史取得由事件 witness 判定 | 不能用状态快照替代 event，也不能把取得后丢失误判为从未取得 | ledger coverage、事件时间/序号、目标究竟是曾取得还是仍持有 |

### 3.1 Mimesis mediation（因果威胁与异常动作修复）

**E 来源：**Riedl, Saretto & Young, AAMAS 2003, pp.741–748；[作者原件 PDF](https://sites.cc.gatech.edu/fac/riedl/pubs/riedl-young-aamas03.pdf)，§3.2–4.2。现有卡定向核对原件；未核 Longbow replanner 源码。

| 字段 | 映射 |
|---|---|
| 输入/读 | 中央部分序 plan、causal links、已执行/未执行 step 与用户动作 schema（pre/effects、执行区间）；不是仅读最近文本。 |
| 运算/输出 | 对每个 link 检查执行区间中可能否定 link literal 的 user operator，预建 mediation policy；运行时查表。Accommodation 接受异常实际 outcome 后重规划未执行尾部；intervention 在异常动作执行前使用作者预设 failure-mode。 |
| 写权限 | Planner 改 future plan；intervention 会替换当前用户动作结果。Mimesis 2003 未将两者视为同一种 repair。 |
| 本例可做 | 对应 partial plan 中 `lend` 支持 `holding(A,key0)`，初态支持 `intact(key0)`，`unlock(key0)` 前提为两者；destroy 分别删去两 literal、切断支持。Accommodation 保留已提交 destroy 并找未来替代支持；key1/trade 仅在有限域已声明时可用。 |
| 本例不能做 | 不会凭空创建交易 operator；不证明 A 知道 key1、B 愿意借出。禁止使用 intervention 改写已成功的 destroy。它针对计划因果连贯，不是角色意愿估计器。 |
| 时间/失败/成本 | 以计划 step 区间识别例外，不是通用绝对物理 deadline monitor。替代链不存在可无解；完整高效 replanning 细节超出 2003 论文，计算/作者成本未量化。 |
| 状态分类 | 2005 branching graph 是表达能力扩展；2013 knowledge-aware POCL 可删去模型判定未观察的过去 step，属于不同权限版本，不能混称 2003 future-only accommodation。源码/性能未核。 |

**I：**对跨层 repair 可作为直接的因果 threat baseline，但需共享 executor、ledger 与 progress-preserving adapter。**Q：**内部 replanner、通用大域开销与 B refusal 表示未由 2003 原件完整限定。

### 3.2 DODM（作者效用上的中央导演优化）

**E 来源：**Nelson, Roberts, Isbell & Mateas, AAMAS 2006, pp.775–782；[作者 PDF](https://www.kmjn.org/publications/DODM_AAMAS06.pdf)，§1、§3.1–3.3、§4。独立 authoring poster：Nelson, Ashmore & Mateas, AIIDE 2006, pp.127–129；[AAAI 原件](https://ojs.aaai.org/index.php/AIIDE/article/download/18761/18537/22440)。

| 字段 | 映射 |
|---|---|
| 输入/读 | plot points、prerequisites/availability、DM actions 与合理时机/低层 refiner、已发生 plot/action 顺序、作者的 completed-story weighted evaluation；另有 player response model。 |
| SAS+ | max DM / expectation player 的 expectimax；固定深度，cutoff 后抽样 K 条后续 point sequence，均值评分；暂时重新开放被拒绝 point 以避免 dead end。 |
| TD / SASCE | TD 用完结故事评价反向更新 state-value 函数，选最高值后继；state 编码包含 plot-point precedence matrix。SASCE 用价值函数驱动合作/对抗探索分布来训练，非真实玩家模型。 |
| 写权限 | DM action 是中央请求/调制 agent、hint、阻止或世界变化等；null/do-nothing 也是可选 action。效果最终依赖游戏作者提供的响应与 refiner。 |
| 本例可做 | 把 deadline/ledger acquired 作为 plot point，以固定候选机会、拒绝/接受策略和 `null` 比较作者指定故事评价。作为全局导演选择的成熟强基线。 |
| 本例边界 | 论文的玩家模型是 available plot points 中均匀探索、hint 后概率提高；不能当真人响应概率。其状态是抽象剧情历史，不是 W/O/S/P/永久执行账本；score 高不证明人物自主、B 同意或客观质量。 |
| 失败/成本 | 目标由作者特征与权重定义；作者动作/refiner 和概率模型成本仍在。大域搜索 cutoff 会短视；原文指出加 synthetic DM actions 可改善得分但有作者合理性风险。未报告人类作者工时。 |

**I：**若 B 的接受率未知，采用 DODM-style search 时必须固定多个 response policies 做敏感性分析；不能以单一便利概率宣称解决。被作者权力改变的实际动作必须按通道记账。
### 3.3 IPOCL（计划中的意图框架与因果支持）

**E 来源：**Riedl & Young, JAIR 39 (2010), 217–267；[DOI](https://doi.org/10.1613/JAIR.2989)，[作者 PDF](https://faculty.cc.gatech.edu/~riedl/pubs/jair.pdf)，§§4.2–4.3、§5–6。机制卡沿用已完成全文审计，不是本轮重读/复现。

| 字段 | 映射 |
|---|---|
| 输入/读 | 初态、作者终态 goal、经典符号 action schema、参与者/意图标记、可支持 `intends(actor,g)` 的 motivating effects。 |
| 内部状态 | Partial-order plan：steps、bindings、orderings、causal links、commitment frames（角色、目标、服务动作、motivation step、终末动作）。 |
| 搜索/写 | flaw refinement：补 open condition/motivation；intent flaw 对 action 归属 frame 做纳入/排除分支；causal threats 用 promotion/demotion/separation；不一致则回溯。输出是满足故事目标且可解释的 fabula plan。 |
| 本例可做 | 若 action model 有合法交易，它可要求 plan 内的角色目标与 motivating step 支持 B 参与借钥匙，审计“为何在计划里这样做”。 |
| 本例边界 | 计划意图不是在线 O/S、策略概率或真实同意；它不让 B 实际执行，也不处理玩家造成的持续运行反馈。标准目标规划找不到计划时是回溯/失败，不以可接受失败结局为核心目标。 |
| 成本/未知 | 作者需提供动作、目标、intentionality/motivation 语义；原研究评特定故事的 goal comprehension，不是作者工时、动态自主性或心理效度。意图矛盾识别局限见论文 §6。 |

**I：**适合作为“解释型计划”条件或离线审计器；不应取代真实 B 策略或把生成 plan 直接提交到 executor。不能因它有 intent-frame 就把其他方法称作不了解意愿。
### 3.4 Thespian + POP（fit、gap 与 belief-change suggestion）

**E 来源：**Si, Marsella & Riedl, AIIDE 2008, pp.203–208；[AAAI PDF](https://cdn.aaai.org/ojs/18698/18698-52-22313-1-10-20210927.pdf)，算法 1–5、pp.205–207。Fit 基础还引用 Pynadath & Marsella, AAMAS 2004；[作者 PDF](https://people.ict.usc.edu/~pynadath/Papers/AAMAS04.pdf)。现有卡未复现软件，也未核完整 fit_sequence / Suggest_Pick 实现。

| 字段 | 映射 |
|---|---|
| 输入/读 | 抽象 POP anchors；PsychSim/Thespian actors 的状态、action effects、reward goals/weights、belief 与有限 lookahead；action sets 有序、gap 区间及 max bridge length。 |
| Fit/gap | 对整条序列逐角色试 fit；失败时找首个无法被模型解释的前缀。逐级扩大候选 action sets，按序递归插入动作并检查 anchor islands/order；成功路径再 fit。 |
| Suggest | bridge 搜索失败后，对下一个指定动作提出 belief-change suggestion；枚举他人回应并做一层 lookahead，输出可能需改变谁的信念。作者仍须把建议编成真实事件/动作。 |
| 可复用/本例 | 把 B lend 或 A 接受交易置于角色 goals/beliefs 中，可定位“哪一前缀不 fit”或信息缺口，并提示需要何种信念变化。 |
| 边界 | Suggestion 不是信念更新事实；改变 goal weights 与补环境事件是不同修复。模型假设不自动等于真人；它是 authoring/gap 方法，不是连续运行和实际选择器。 |
| 失败/成本 | 候选库/最大长度耗尽会失败；修一个 gap 可破坏后续 fit；Lookahead 仅一层；作者需双粒度 domain、belief/utility 模型和补写动作。 preliminary 示例不测总作者工时。 |

**I：**Thespian 已直接处理部分人物动机/认知对齐，必须作为强威胁/比较方法。场景自制交易的动机是否被合理表示与其能否在线自治，是两个不同问题。

### 3.5 PDDL3 规格与 Porteous landmark/FF 分段规划

**E 来源：**Gerevini & Long, *Plan Constraints and Preferences in PDDL3*, 2005 technical report, 12 pp.; [原报告 PDF](https://ipc08.icaps-conference.org/deterministic/data/gerevini-long-tr-2005.pdf)，§§1–3、印刷 pp.1–6。Porteous, Cavazza & Charles, ACM TIST 1(2), Article 10 (2010), 21 pp.; [DOI](https://doi.org/10.1145/1869397.1869399)，[PDF](https://www.cs.uky.edu/~sgware/reading/papers/porteous2010applying.pdf)，§4.1–4.2、Algorithm 1 印刷 pp.10:12–10:14。现有卡核对了 Algorithm 1 p.10:13 缩进；无 planner 复现。

| 字段 | 映射 |
|---|---|
| PDDL3 输入/读 | PDDL domain/problem 的 predicates、初态、goal、时间戳 plan trajectory、强制 trajectory constraints 与 preference/weight。语义评价有限计划经过的 state sequence。 |
| PDDL3 写/能力 | 作为规格无搜索、执行或修复算法；可定义 `always/sometime/within/at-most-once/sometime-before/sometime-after/always-within/hold-during/hold-after` 等计划轨迹性质及软偏好代价。 |
| 本例映射 | 用绝对 t=10 锚及已声明时间单位表达取得要求；若要求“曾经取得”，可在 action effect 中设持久 `acquired(A,ledger)` predicate，再用 trajectory condition 检查；该动作 occurrence 语义由 domain 编码，非 PDDL3 原生 action-event constraint。 |
| 语义限制 | 原文明确限制为 state predicates，不允许 action-instance occurrence 作为本扩展约束。STRIPS 中 `within` bound 按 plan happenings 计；需核实与物理分钟的 mapping。hard 合法性与 soft preference 不能混用。 |
| Porteous 输入/读 | Grounded facts F、初始 I、最终目标 G、operators O（Pre/Add/Delete）、PoV 与 constraint graph（sometime / sometime-before 节点、排序边）。 |
| Porteous 搜索 | 选未访问、无直接前驱且与当前 singleton PoV 相关的最早约束节点；原实验多个合格节点任意选，析取节点选一个 fact；将该 fact 作为当前子目标调用 FF-v2.3。用户交互更新状态/视角后，当前目标仍相关则重规划；不相关则转节点；最后规划终态 G。 |
| 本例可做 | full symbol-domain goal planner 的强世界可达路径与局部 milestone baseline；新的 W 状态被重新规划读取，不回滚玩家 destroy。 |
| 本例边界/失败 | 不处理 actor-local belief/愿意；visited 不等于 achieved。原算法图 line 12 将 c 标 visited 位于 planner success 判断外，无专门 no-solution recovery；若 adapter 采取停机/保留节点，须标新工程处理。局部段不保证全局最小 repair。 |

**I：**PDDL3/landmark 适合表达和分解作者要求；Monitor 负责证据判定，planner 负责未来可达候选，executor 负责真实效果。不可互相替代。对于软偏好，违反惩罚也不能越过玩家/B 权限或真实安全前提。

### 3.6 Sabre（信念、意图与作者效用的集中规划参照）

**E 来源：**Ware & Siler, AIIDE 17(1), 99–106 (2021)；[DOI](https://doi.org/10.1609/aiide.v17i1.18896)，[作者项目/源码页](https://cs.uky.edu/~sgware/projects/sabre/)。现有审计全文范围沿用，不声称本轮代码执行。项目页所示源码许可为 CC BY-NC 4.0，商业使用条件需另行核对。

| 字段 | 映射 |
|---|---|
| 输入/读 | 集中式行动/世界状态模型、作者 utility、actor goals 与显式嵌套/可能错误 belief。 |
| 规划 | 搜索完整计划。Consent 不是即时 gain 检查：动作须在 actor 所相信的世界中可执行、作为计划首步提升其 utility，且后续他人动作可解释并非冗余，形成 intention/ToM 约束。 |
| 可复用/本例 | 符号解释参照：可检验计划中 B 的交易动作能否由其 beliefs/goals 解释，并比较作者期望与角色目标是否冲突；这不表示真实 B policy 会选择同意。 |
| 边界 | 原文初始 belief 未显式指定时默认等于真实 W，其他 actor belief 默认等于自身 belief。若直接装载 W 而省略 A 对 key1 的 belief，会泄漏隐藏钥匙。Sabre 是确定信念，不是 Known/Stale/Unknown 三值或概率；须显式给 A 错误 belief，或扩展 Unknown 状态并计适配成本。解释计划不是实际 agent 独立选择/拒绝轨迹；同意假设不授予作者强制行动权。 |
| 失败/成本 | 需编写动作、效用、belief 结构和理论心智规划信息。搜索有 max-depth；未解计划可不终止，深度失败不是全域不可达证明。未在项目版本复现，也未在相同 executor 预算下跑本例。 |

**E 定位：**上述 belief 默认与 consenting 约束见论文物理 pp.3–6（印刷 pp.101–104）；原件由父审定向核读。**I：**Sabre 是集中式符号解释/规划参照，不是 A 的执行 baseline；自治策略可实现集合无包含关系。B 的拒绝权需外置真实 policy/choice channel，并记录拒绝与后续重规划。
## 4. 方法映射 II：桥接、内容绑定与结构化模型

### 4.1 WhatELSE（outline 到固定动作域的 LLM compiler）

**E 来源：**CHI 2025 *WhatELSE*；[作者论文 PDF](https://www.research.autodesk.com/app/uploads/2025/02/WhatELSE.pdf)，现有卡对方法/环境/研究定向核读；源码实现与事务隔离未核，也未复现。

| 字段 | 映射 |
|---|---|
| 输入/读 | 作者 outline event、characters/locations/domain、当前 world state/character memory、固定六动作 schema（move/speak/kill/attack/think/save）。论文此输入没有 O-mask；不能把全局 W 透传给 A，否则隐藏 key1 泄漏，须加 actor-visible adapter 并计成本。 |
| 运算/输出 | LLM 提具体 action sequence；coherence reviewer 与逐行动机 reviewer 给软 critique；外部 Game Environment 回报行动成败；反馈进入下一轮生成。通过方案由环境执行、状态更新后继续处理后续 outline。 |
| 可复用/本例 | 本报告 X 域的交易/借钥匙/开锁不在原六种 schema 中；须实现真实 adapter 后才能编译，不可称为论文已有动作。扰动后可重新实例化后续 event。 |
| 边界/失败 | schema 未有交易/授权动作时只能报告 unsupported，不能由 LLM 新建 effect。Reviewer 不是硬 truth。文中对候选因果执行反馈后的状态隔离、clone/reset/rollback 未披露；不能假定安全隔离，也不能断言污染真实提交历史。 |
| 成本 | 降低逐情节写具体分支的压力，但把成本移到领域动作实现、outline、review 与多轮生成；研究参与者/偏好不等于实测总作者工时。 |

**I：**是固定域内桥接基线，不是玩家/角色同意裁决器。任何接入须先证明试执行与真实 W 的隔离或使用明确可回滚 sandbox。

### 4.2 Anansi（Ink storylet、query binding 与社会事件）

**E 来源：**ICIDS 2024 / proceedings 2025；[DOI](https://doi.org/10.1007/978-3-031-78450-7_9)，[开放全文](https://escholarship.org/content/qt21r7h0fq/qt21r7h0fq_noSplash_551994d2dca07b890d023a629e3e27c8.pdf)。GitHub v0.5.1 pin 只核版本元信息，源码机制未完整核；未复现。

| 字段 | 映射 |
|---|---|
| 输入/读 | 角色、位置、日程、关系图、traits/stats、logic DB；Ink storylet、query、tags/weight/cooldown；社会事件另有 roles、preconditions、effects。 |
| 运算/输出 | Query 对变量绑定枚举匹配实例，每个 binding 成为 storylet instance；eligible instances 依权重选择；Ink 控制文本流，`DISPATCH_EVENT` 执行声明的社会 effect。Query 命中只证明可绑定，不代表 B 知情、同意或会按 B policy 选择。 |
| 可复用/本例 | 可复用作者写的对话/交易内容，并按参与者/关系条件绑定；social event 可反映作者明示的关系变化。 |
| 边界/失败 | 绑定出候选不等于角色意愿或借钥匙行动；不凭 query 创造合格角色。Social effects 由作者编写，不是自动因果修复/角色 autonomous LLM。无实例时 fallback、rollback 细节未核，留 Q。 |
| 成本 | 作者仍需维护 storylet、查询、角色关系/规则、社会事件前提/效果及分支，状态/数据库同步增加维护；论文未提供可比总作者工时。 |

**I：**适合作内容实例化/作者素材复用，不作为 planner 或强 baseline 控制器。与 WhatELSE 的动作编译层不同，二者不能因都用“事件”就互换。

### 4.3 DiriGent（LLM tension 推断与 sequence enforcement）

**E 来源：**AIIDE 2025；[AAAI 页面/论文](https://ojs.aaai.org/index.php/AIIDE/article/view/36841)，[固定 prompt/materials 版本](https://gitlab.inf.ethz.ch/prj-cgl/cgl-ai-character/dirigent/-/tree/1aaa1855f1963c9f191eb575a5d8c8083b4b7480)。现有精读覆盖正文 11 页与公开 prompt；附件不是完整运行源码，未复现。

| 字段 | 映射 |
|---|---|
| 输入/读 | 累积 story beats、角色 ideal worlds / beliefs / tension ledger、sequence 目标与提示；候选 action 通过 LLM 标记 addressed tension。 |
| 运算/输出 | 每轮生成四个候选，程序按候选覆盖的 tension IDs 分数求和并 argmax；N=6 序列阈值 enforcement 可用 world prompt 或把 required action 加入角色候选列表，并非 world-only 控制。 |
| 可复用/本例 | 可作角色/世界候选引导的 LLM 对照，研究 sequence-level steering；作为 scenario 文本策略条件而非真实 World planner。 |
| 边界/失败 | 没有对象资源真实状态与硬执行器；prompt 让角色读取完整 beats 的可见性可能与角色 O 不同；required action 被注入候选不等于 B 执行/同意。signed decay 公式仍有歧义，不能视为成熟数值基线；无一般不可达证明。 |
| 成本 | 初始化 ideal/belief/prompt 与多次 LLM 调用；未测作者全成本，完整程序未公开。现有小规模故事/判断研究不能外推长期多人世界。 |

**I：**只能在同一信息权限下作为候选偏置基线；不把文本 beats 当 ledger 或 score 胜出当作成功执行。

### 4.4 GOAP（持续任务的工程规划基线）

**E 来源：**Orkin, *Three States and a Plan: The A.I. of F.E.A.R.*, GDC 2006；[作者/会议 PDF](https://www.gamedevs.org/uploads/three-states-plan-ai-of-fear.pdf)，现有核读 18 页全文。工程经验，不是受控心理/作者成本实验。

| 字段 | 映射 |
|---|---|
| 输入/读 | 角色可感知/可知的 working-memory state、Goal Set、按 precondition/effect 建模的 Action Set、动作代价/对象 SmartObject。角色差异可由 Action Set 表达。 |
| 搜索/输出 | 竞争目标按优先级尝试，A* 后向规划低代价 action sequence；首动作交给执行系统。失败/新知识写入 working memory 后重规划；无法建立计划时回退较低优先级目标。 |
| 可复用/本例 | A 的 actor-local planner 使用自己的 O 和技能规划 ledger route；B 有独立 Goal Set/Action Set，由自己的策略选择是否接受 request。世界执行器再验证。 |
| 边界/失败 | GOAP 不能因持有全知 W 替 A 知道 key1；若输入错给 W 就是权限错误。没有提供世界作者约束 Director、真实拒绝概率或持久心理模型。完整后向搜索可能重算；需同一进度保持规则。 |
| 成本 | 设计算子、procedural pre/effects、SmartObjects、goal 优先级和失败知识；游戏工程先例，不证明作者工时更低/行为更可信。 |

**I：**应作为 A 的认真可执行基线，和实际 actor policy + executor 同构。不要用现有 RulePolicyV0 直接冒充 GOAP；这是不同规划方法。
### 4.5 HTN（部分计划与方法层优先级）

**E 来源：**Troy Humphreys, *Exploring HTN Planners through Example*, Game AI Pro 2013 Ch.12；[章节 PDF](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter12_Exploring_HTN_Planners_through_Example.pdf)，§12.4（印刷 p.156）。另有 Menif et al., *SHPE: HTN Planning for Video Games* (2014)；[Springer](https://link.springer.com/chapter/10.1007/978-3-319-14923-3_9)，属另一方法/性能来源。

| 字段 | 映射 |
|---|---|
| 输入/读 | actor-known state、compound task/method 与 primitive task 的条件和预计效果；预计效果只用于规划/验证，不是 W 结算。 |
| 搜索/输出 | 本章 §12.4 用 DFS 展开 method decomposition，不按 heuristic/cost 排序；方法顺序可表达优先级。MTR 是另述扩展，可记录方法次序以保留当前有效计划。 |
| 可复用/本例 | A 持续任务分解可将取得 ledger 拆为获得信息、达成互惠交易、取得钥匙、开锁和领取；动作当前执行进度继续。B 的子任务和权衡可单独建模。 |
| 边界/失败 | HTN 不会自动判断方法符合真实心理；method/action schema 与 task priority 仍由作者编写。计划内 expected effects 不是 W 结算，也不能让 B 同意。 |
| 成本/证据 | 作者维护 task/method hierarchy、方法顺序与条件；runtime cost 仅作共同预算记账，不称为该章搜索排序。SHPE 是独立性能实验，均非长程人物可信性或作者工时证据。 |

### 4.6 Typed LLM planner（受限提案生成基线）

**E 定位：**StoryVerse [原文](https://arxiv.org/html/2405.13042)，§2.1、§2.3–2.4：abstract acts/前提由 Act Director 转为多步角色候选，经过 coherence、environment feedback、逐角色动机 review 后可重修，实验最多两轮；输入是 world state/domain，不是 O-mask，B 的模拟角色也不等于真实拒绝策略。LLM-Modulo [PMLR 原文](https://proceedings.mlr.press/v235/kambhampati24a.html), pp.22895–22907，主张 LLM 与外部 model-based verifier 双向协作；这是框架立场，不是已验证的 NPC planner。

**R：**本报告 typed baseline 是 schema 内多步 proposal → validator → 逐步 executor/typed feedback → 有界修复；不同于单步 action sampler，也不是把 LLM 作为验证器。Pilot 已规定 proposal → schema/type/authority → 当前 W 校验 → executor settlement，并分离计划与历史；这是候选接口，不是已运行算法。

| 字段 | 映射 |
|---|---|
| 输入/读 | 只能给定 actor O/S/P/history、该角色自己的 goal/task（及其合法可知 deadline）、action catalogue 与显式 domain facts；作者 deadline 仅给 Director/Monitor，除非角色本身合法知晓。全知 Director 规划与 actor prompt 分开。 |
| 运算/输出 | LLM 给 typed action proposal/绑定与理由；Proposal validator 检 schema、权限、operator capability、deadline/resource；唯一 executor 重验当前 W。LLM 不直接给 effect/成功标签。 |
| 可复用/本例 | 可提出 request、信息事件候选或可登记动作序列；未知 operator 返回 `requires_domain_extension`，而不是 prompt 即执行。 |
| 边界/失败 | 结构合法不代表前提真实、角色愿意、规划完整或具有新行动能力；幻觉与调用成本需计账。若同预算弱于 GOAP/HTN，应报告真实结果，不以语言流畅度替代任务成功。 |
| 证据/未知 | 本轮没有本场景的 LLM baseline、模型版本、prompt、预算、调用结果或 held-out 结果；仅有接口设计。角色是否可通过模型明确拒绝及其随机性需冻结。 |

**I：**公平对照应让 LLM 与传统 planner 共享 operator set、grounding、O/W 信息、executor/validator、time/resource/budget；可用 LLM 做候选前端，但不能把它单独称作世界执行器。

## 5. 同一实例下的逐方法短判定

| 方法 | 世界路径 | 角色知道 | 角色愿意/解释 | 历史/执行/权限 |
|---|---|---|---|---|
| Mimesis | plan causal links / future accommodation 可搜索；依声明域。 | 非核心机制。 | 中央 plan 指派动作，不是 B 私有策略。 | Accommodation 保持已发生扰动；intervention 需在动作前拦截，本例禁止。 |
| DODM | plot point prerequisites + DM action 的 abstract future。 | 非 actor-local belief state。 | 作者评分驱动 requests；实验响应概率是模拟模型。 | DM/refiner 需真实游戏动作；point history 不是 ledger。 |
| IPOCL | 符号计划的因果可达。 | 不含 actor-local O。 | frame / motivating step 提供计划内人物目的解释。 | 离线计划，不真实提交或强制运行。 |
| Thespian | POP skeleton 与插入 bridge actions。 | 通过 belief model / suggestion 检查解释。 | 对 policy/weights fit 与一层 response lookahead。 | Suggestion 需作者造合法事件；不是执行结果。 |
| PDDL3 / Porteous | trajectory/landmark 子目标 + FF。 | PoV/state constraint 可过滤剧情视角，不等于完整信息更新模型。 | 不建角色动机。 | PDDL3 仅规格；Porteous 重规划未来、不恢复旧事实。 |
| Sabre | 完整 centralized plan search。 | nested beliefs / 错信念显式建模。 | 每个 consenting actor 的效用提升解释 action。 | 解释规划不等于独立实时执行/可拒绝 protocol。 |
| WhatELSE | 固定 action schema 的 event 编译 + 环境反馈。 | generator 读当前 W/memory；特定可见性边界需 adapter 明确。 | LLM reviewer 给 soft motive critique。 | 试跑/rollback 状态边界未核；真实 effects 由环境执行。 |
| Anansi | 绑定作者 storylet/social event，非通用 goal planner。 | DB/query 决定可绑定角色/状态。 | 内容文本，不是自主 agent consent。 | social event effect 由模拟执行；fallback/rollback 未核。 |
| DiriGent | story beats + tension steering，而非对象级可达 planner。 | 文本/beat 可见性可能全知。 | belief/ideal/tension 推断及候选偏置。 | 无权威资源执行/ledger，candidate injection 不等真实行动。 |
| GOAP | A* action sequence 在声明模型内可达。 | 输入应为该 actor 所知状态。 | goal/action set + priority 表示任务选择，不建心理效度。 | 执行器回执、failure WM 与重规划可对接。 |
| HTN | method hierarchy 分段分解。 | state 可限定为角色所知世界。 | task/method policy 表达优先级与承诺，不推断真实性。 | expected effects 不结算 W；runner/executor 外接。 |
| Typed LLM planner | 只提 schema 内候选，可靠性待比较。 | prompt 可以限于 O，但需要实测不泄漏。 | rationale 不证明选择意愿，需实际 policy。 | validator/executor/ledger 必须外置，不给模型 commit 权。 |

## 6. 成熟基线最小组合（按 A/B 拆开）

不是 12 算法拼盘；只选每个问题足以构成挑战性基线的最小组件。
此处 A/B 与 §7 的 Q1–Q3 仅服务于当前有限比较和近期协议设计，是长期研究版图的小切片，不是完整研究目录或预设论文队列；完整版图由[系统愿景](../../00_研究设计/Character_Dynamics_System_Vision_v0.md)维护。

### 6.1 任务 A：长期规划—执行反馈

1. **最小执行条件：**actor-local GOAP 使用 A 的 known state、A* / failure memory，接同一 executor；B 由独立固定策略决定是否接受，不由 director 代选。HTN + forward decomposition/MTR 是强替代 planner 条件，不与 GOAP 自动叠加。
2. **执行：**各自首动作/primitive task 都进入同一个真实 executor；启动校验、持续 progress、资源占用、失败/中断/部分效果、O feedback、ledger settlement 全相同。计划 effects/expected effects 不得直接写 W。
3. **角色：**A、B 各自有固定 policy/goal/commitment pins。request 事件与 B 的 consent action 分开；B 可以拒绝。角色策略需对所有条件冻结，不让 author planner通过改 B goal 让结果成功。
4. **强解释参照：**Sabre 在同一符号世界/author utility/角色 belief-goal 上给出集中式“可解释 plan”；中央规划与自治策略实现集合无包含关系，belief adapter 后的计划也不是自主执行证据。IPOCL 可作 causal-only vs intent-frame 离线比较；Thespian 可作 authoring fit/gap 对照；二者不属于最低执行组合。
5. **不纳入最低 A 组合：**DODM / Anansi / DiriGent / WhatELSE 不替代行动执行基线；可按不同研究问题加入独立条件。LLM planner 作为与 GOAP/HTN 相同 schema、信息权限和 executor 的额外条件，不取代公平传统基线。

### 6.2 任务 B：稀疏作者约束下的世界/剧情引导

1. **目标与证据：**PDDL3 类 trajectory spec/现有 Monitor 描述硬要求和软 preference；author intent → predicate/event binding 当前仍需确认。Monitor 只读已提交证据并给 witness/violation/unknown。
2. **最低选择器：**枚举合法 author opportunities 和 `null`；对每个候选用冻结的 actor/player policies 做未来 rollout，按固定作者效用选择。Landmark 只排序/选择目标，不与多个 planner 拼成算法合体。
3. **可替代选择器：**DODM-style 搜索可作另一个作者评价选择条件；PDDL3 是 trajectory specification，Porteous landmark/FF 是分段目标重规划近邻，均非最低组件。效用权重、玩家响应模型与预算须冻结；未知响应采用多策略敏感性分析，不造“真实概率”。
4. **角色保护：**candidate enumeration 可读 Director 授权 W-view，但 B 的 action/response 必须由 actor policy 选择。Director 不可以 candidate mechanism 直接 override B；执行 outcome 由同 executor 提交。
5. **作者成本：**计 domain operators、landmark/constraints、DM opportunities/refiners、prompt/review、debugging、runtime/calls 分项；不是只数作者写了多少 storyline 句子。

### 6.3 为什么不是弱对照，哪些仍需验证

- GOAP / HTN 是有实际游戏规划工程经验的基线；Porteous/FF 是计划约束与交互重规划；Mimesis 是 causal repair；DODM 是作者质量优化；Sabre 是 belief/consent/intention 的集中式符号解释参照。它们挑战不同层，不提供相互间数值上界。
- 共用 action domain 与真实 executor，避免规划器“纸上效果”优待。共用信息权限，避免传统方法故意全知或新方法偷看 W。共用 resource/time/cost/compute budgets，避免把工程投入差异藏起来。
- progress preservation 是共同系统契约：合法的 RunningAction 和 reservation 在影响范围外必须保留；必要时统一 adapter，且单列 adapter cost。不以无进度保护的全量重置制造修复算法优势。
- 表达能力/语法接口对不齐时，先定义最小 common domain，而不删掉 B refusal、committed past、deadline 或 progress；任何降格语义另做子实验并明确目标改变。
- 同一方法是否能与 trajectory monitor / actor policies 组合、是否保持语义等价，**需要 adapter property tests / finite-domain comparison 验证**；纸面可组合不等于组合正确。

## 7. 候选研究问题与反证门槛（最多三项）

以下全是 I/Q 候选，不是已发现 gap；A/B 与 Q1–Q3 只是长期研究版图的近期小切片，完整方向由[系统愿景](../../00_研究设计/Character_Dynamics_System_Vision_v0.md)维护。Q1 当前定位为基础正确性关卡，Q2 为待比较的算法候选，Q3 为最贴近系统愿景的核心候选；这是当前研究定位，不是排序、排队或预设三篇论文。共同要求：先固定 domain/action ontology、时间/资源、B 策略、玩家策略、budget、可观察失败、成功证据与简单成熟对照；小实验先验证 instrument/logic，再判断是否值得研究。

### Q1：路径跨 actor 信息与动机后是否仍成立？

- **可观察失败：**候选路径在合法信息到达前就要求 A 绑定 key1，或把 B 自主接受误作必然效果，导致对应执行步骤无法通过 actor_check/真实 rollout。若路径含合法询问并获得答复，A 初始不知道 key1 本身不是失败；B 一次拒绝也不等于整个任务已失败。
- **最近邻：**GOAP/HTN actor-known planning；Thespian fit/gap/belief suggestion；Sabre 的 belief/consent explanation；PsychSim/ETQ 的主观状态/查询过滤实践。
- **已有能力与边界：**已有方法分别覆盖局部状态规划、人物 fit/suggestion、信念/意图集中式解释和主观查询；它们足以否定“此前没有人表示 belief/motive”。但没有在本仓库同一 persistent W、不可变 ledger、同 executor 和真实 B refusal 下运行比较。
- **可能不足（待证）：**多层输出接到真实执行后，belief proposal 无合法事件支持、B 拒绝导致 deadline miss、全知 planner 把世界可达误当 actor 可行。
- **简单替代解释：**当前 domain 缺一条足够清楚的合法信息 action 或交易 operator；不是 planner 机制缺陷。或作者把 B 的目标设成已被 return_tool 满足，根本没形成真实 tradeoff。
- **最小反证比较：**同一完整有限域下对照 actor-local GOAP/HTN、Thespian/Sabre 型计划条件及独立 B strategy；一个 hidden-spare case 加一个信息已知 case、一个 accept 与 reject 策略。若实测显示成熟条件在相同预算下已正确区分五层，且拒绝时保留真实 outcome 并继续按冻结域检查后续机会，则仅对该缩小问题记录“未见独立待研究差异 / NO-GO”；不外推到完整研究计划。
- **当前判定：**belief/intent/consent 基础能力已有成熟先例，不构成本项目的独立新颖性主张；复合场景集成是否成瓶颈未知。该有限比较尚未运行，当前不据此准入独立研究主张。

### Q2：扰动后修复能否保留无关活动与真实历史？

- **可观察失败：**destroy key0 后，suffix 重算/资源重获/合法活动切换代价超过局部 repair；或局部 causal repair 漏掉共享 key/resource 依赖，保留非法 continuation。executor reset 是实现 bug，不算算法优势。
- **最近邻：**Mimesis accommodation、Porteous current-landmark replan、HTN/MTR 对有效计划承诺与方法优先级、GOAP failure-memory replanning。Sabre/IPOCL 可提供解释/因果检验，不代替运行时 repair。
- **已有能力与边界：**未来修复、基于当前符号状态的子目标重规划、有效 plan continuation 均有成熟机制。文献未在本项目的 scheduler-native RunningAction/ledger 接口下进行同域比较；源码未披露不能写成理论不可解。
- **可能不足（待证）：**选择性影响图与资源 reservation 不完整使局部 repair 误保留无效步骤；或共用进度 adapter 后，suffix 重算/重获资源代价仍显著较高。
- **简单替代解释：**domain operators、resource locks、causal dependencies 或 action lifecycle/adapter contract 编码错误；需要先对齐接口语义再比较。
- **最小反证比较：**同 checkpoint/prefix/扰动、完整 domain/进度规则/预算，比较 Mimesis repair、Porteous/GOAP suffix replan、HTN continuation；检查历史、进度、执行 legality、资源时长、重算/重获代价与 repair 维护成本。
- **当前判定：**因果修复与重规划已有成熟先例，不构成本项目的独立新颖性主张；本项目特定跨层收益及是否成瓶颈未知。该有限比较尚未运行，当前不据此准入独立研究主张。

### Q3：稀疏作者要求是否减少总劳动且不靠过度干预？

- **可观察失败：**目标可达但需要逐剧情写特定 operator/DM actions；或约束得分提高却通过强制 B、限制玩家选择、全知信息注入/不实结算实现。
- **最近邻：**DODM（author function + DM action），PDDL3/Porteous（轨迹 constraints / landmarks），WhatELSE（outline 到固定 action schema），Anansi（query-bound storylets），DiriGent（tension/enforcement），以及 StoryVerse/Shepherd 等既有路线（详见范围内专题审计）。
- **已有能力与边界：**作者控制/作者 goal 到世界 event 的多种路线已有；WhatELSE/Anansi 等也把劳动移到 domain/content/review。文献未在共同 W/O、拒绝策略、同预算条件下证明总作者成本或长期体验优势。
- **可能不足（待证）：**加入相同真实干预/限制成本后，稀疏要求仍不能减少编排劳动，或达成率改善完全来自强制候选/超额预算。
- **简单替代解释：**domain 本身稀疏、人工预建路径正好覆盖测试 case，或 evaluator 只数文字节点而没数 operators、review/debug、API cost；不同研究可能用户任务不同。
- **最小反证比较：**统一有限场景，比较直接手写序列、landmark+FF、DODM-style candidate+null、fixed-domain LLM bridge；记录所有作者资产和分钟、calls/预算、真实成功/unknown、interventions、机会数、B refusal、玩家自由分支。先进行作者成本 pilot 的测量可行性检查，不据少数故事做体验大结论。
- **当前判定：**作者驱动规划和内容生成已有成熟先例，不构成本项目的独立新颖性主张；“低作者劳动且保留自主性”的复合目标是否成瓶颈无证据。该有限比较尚未运行，当前不据此准入独立研究主张。
