# 定向核查：玩家视角的 NPC 可置信性评测

核查日期：2026-10-06

状态：候选来源与评测章节定向核查；CharacterBox 另已完成[全文方法/接口审计](精读_CharacterBox_2026-10-06.md)，其他条目未提升为全文精读。没有运行代码或复现论文结果。

范围：NPC-Bench、CharacterBox，并以 CharacterBench 为第三个候选作取舍；另记录 NCP-Bench 与 Generative Agents 的方法边界。

## 问题锚点与标签

**user-confirmed目标**：用户纠正说，不一定要求 NPC 拟合真实人物/真实心理；关心的是“NPC在玩家眼中在游戏里面活起来”。因此旧 Paper-0 关于独立人类 `A*`、有限候选动作分布及持久心理状态充分性的准入门槛，不自动成为这个新问题的前提。

**paper evidence**：下列 benchmark 的可测对象分别是单轮/多轮角色对话、文字虚拟世界中的自主行为轨迹，或角色定制对话能力。它们不是同一个构念，也不能把论文里的“human-likeness”直接等同于真实玩家感到 NPC 活着。

**inference**：与目标最接近的组合是 CharacterBox（多轮行动与对话轨迹，不是多日连续生活验证）加 NPC-Bench（玩家发问时的世界内知识、出戏与安全）。若关注“眼中”，最后仍需在目标游戏可见体验上做盲评/玩家研究；模型裁判得分只能作为可扩展筛查。

**unknown**：NPC-Bench 的原始章节全文、正式评分提示细节、用户研究设计与量表，本次因 Springer 仅开放摘要预览而未核实。不要把仓库中可见问题表误称为论文完整评测协议。

## 候选 1：NPC-Bench

- **paper evidence — 书目信息**：Joseph Gilligan、Ethan Smyth、Lifan Xuan、Yang Hong、Jiangwei Xie、Ben Stobie、Oliver Lemon，*NPC-Bench: A Benchmark Dataset for Immersion and Safety of Generative AI for Non-player Characters*，UKCI 2025 论文集章节，Springer *Advances in Computational Intelligence Systems* 1468，出版年 2026，DOI 10.1007/978-3-032-07938-1_17。官方论文页：[Springer chapter](https://link.springer.com/chapter/10.1007/978-3-032-07938-1_17)。Springer 页面注明发表于 2026-01-02、UKCI 2025；当前页面仅摘要预览，章节需机构/购买访问（Springer 页面“Access this chapter”，摘要与引用信息）。
- **paper evidence — 测什么**：摘要称测试面向 RPG NPC 的自然语言交互，要求角色留在角色内、符合游戏世界知识，并对中世纪设定中的汽车或 Taylor Swift 等越界概念作合乎角色认知的回应，同时覆盖有害/有毒内容安全。作者报告新 prompting strategy 的 benchmark accuracy 改善，以及真实用户研究中若干 gameplay 维度改善；摘要未提供维度细节/实验设计。
- **code/data 可用性与 license**：Springer 摘要页链接作者 Ethan Smyth 的仓库 [ESmyth-dev/npc-bench](https://github.com/ESmyth-dev/npc-bench)；仓库页面将 `LICENSE` 标为 MIT，作者仓库与其公开 fork 均显示该文件。当前可访问的 GitHub 页面只给出许可证类型标签，直接打开 LICENSE 正文遇到页面缓存缺失，故正文条款未核读；记录为 **GitHub 标注 MIT，正文未核实**。仓库公开提供 `MEGAQUESTIONS.csv` 与默认/修改 prompt，README 标明原始 Skyrim fantasy setting，并列出 Game World Knowledge、Real World Knowledge、Knowledge of own Character、Safety 四类问题（README）。数据是否与论文正式测试集完全一致、用户研究材料是否公开也 unknown。
- **paper evidence — 评分/样例/权限**：仓库当前可见的是固定问题集合，不是带确定正确答案的世界状态机或独立事实判定器；例如要求 NPC 讲本地传闻、食物/工作去处、解释自己职业/家人，并询问现实世界中的现代设施、当代人物或安全风险（`README.md`, “Question List”）。用法是将这组问题交给现有 LLM NPC，评分器/基准答案机制需按全文或自建协议另核；不能声称该仓库自身实现了自动可信分数。提示会给玩家问题，但具体 NPC 可见知识/后台数据权限由接入系统决定，公开仓库没有强制的 W/O 权限运行时。
- **适用/不适用**：适合快速探测“玩家问话时会不会像知道不该知道的东西、是否贴合设定、是否安全”。不测 NPC 无人交互时如何安排日常、行动是否有因果、目标游戏场景内的移动/动作是否让世界显得有人生活；对出戏问题集的答复质量也只是玩家可置信性的一小部分。
- **替换判断**：不能直接替换项目 `continuous_runtime` 的手写 policy 来得到同一分数。仓库提供的是文本问答问题/提示素材；若要评当前 C++ 房间 NPC，需做文本 adapter 或把问题和 NPC 对话界面接入，另做定量评分。它没有对现有 action policy 的兼容接口。

## 候选 2：CharacterBox

- **paper evidence — 书目信息**：Lei Wang 等，*CharacterBox: Evaluating the Role-Playing Capabilities of LLMs in Text-Based Virtual Worlds*，NAACL 2025 Long Papers，页 6372–6391，DOI 10.18653/v1/2025.naacl-long.323。官方论文及 PDF：[ACL Anthology 论文页](https://aclanthology.org/2025.naacl-long.323/)、[PDF](https://aclanthology.org/2025.naacl-long.323.pdf)。最终会议版 2025；早期 arXiv 版本为 2024-12 的 2412.05631，不应将其预印本年份写成会议年。
- **code/data 可用性与 license**：论文称代码可用，官方作者仓库 [Paitesanshi/CharacterBox](https://github.com/Paitesanshi/CharacterBox)。仓库 README 提供 `simulator.py`、`quick_start_eval.py`，称论文用 10 个 scripts 的预处理数据在 `data/`；配置角色、narrator、scene，并通过 OpenAI-compatible API 接模型（仓库 README “Quick Start”“Evaluation”）。GitHub 标示 MIT license（仓库 LICENSE 链接/资源导航）；论文、代码 license 与底层原作数据权利须分别看待，数据再利用授权未在本次核实，标为 **data license unknown**。未安装、未运行。
- **paper evidence — 测什么**：Character agent 与 narrator agent 在文字虚拟世界中轮流采取行动，人物可对其他人物回应，narrator 更新人物与环境。论文 §3.2、Algorithm 1 描述 autonomous story play；§3.3（印刷页 6375–6376）用行为轨迹评估七项 1–5 分指标：Knowledge Accuracy、Behavioral Accuracy、Emotional Expression、Personality Traits、Immersion、Adaptability、Behavioral Coherence。GPT-4 先对轨迹生成 critique，再逐项评分（§3.3；公开代码 `evaluate.py` 同样实现这些评分提示）。论文 §6.3（印刷页 6377）报告三位熟悉所选原作场景的专家评分，并以 Pearson 相关评估自动评分：GPT-4 overall r=0.688、CharacterRM r=0.610（Table 4，印刷页 6378）。这是专家相关验证，不等于广泛玩家主观效度。
- **样例与 grounding 权限**：§6.1（印刷页 6376–6377）评估数据来自 10 部小说/剧本，含中英各 5 个来源、100 scenes、232 unique characters、11,692 actions/dialogues。Appendix D（PDF pp.13–17）区分 character 的可观察物理行动与对白/回应，基于当前 scene、profile、观察与 recent memory；narrator 按动作影响更新角色状态/物理环境，无显著物理变化时保持环境不变。Grounding 来自文字 scene/profile/memory，后果由 LLM narrator 生成；这些是提示约束，不是项目隐藏 W 与局部 O 的强制隔离，也不是客观游戏引擎 fact checker。
- **适用/不适用**：这是三项中最贴近“角色像在一个世界里持续生活并作出行为”的可复用参照，指标包含可置信/沉浸、动作连贯和适应变化。但实验基于文本小说/剧本、autonomous story play 与著名原作人物，不能直接回答玩家操控某款游戏时背景 NPC 是否显得活着；“human-likeness”偏向像人，不是所有游戏 NPC 设计目标。
- **替换判断**：不能直接将现有 C++ `continuous_runtime` policy plug in 并获得论文可比成绩。其 Simulator 需要以 CharacterBox 的 scene / character / narrator 文字协议循环，由 judge LLM评输出轨迹；动作并非项目 action schema/Room world transition。可以做自定义桥接或抽取 1–2 个指标作新协议，但那会是 custom-room/text-wrapper 的新实验，不能套用论文榜单。项目当前 runtime 是 C++ 持久 W/O/S/P、动作校验与 typed trace；CharacterBox 是 LLM 驱动 narrator 的独立文字世界（项目 README、00_研究设计/当前实现进度.md；CharacterBox §3.2）。

## 为什么暂不选 CharacterBench

**paper evidence**：*CharacterBench: Benchmarking Character Customization of Large Language Models*，AAAI 2025，22,859 条人工标注样例、3,956 个角色、11 个维度/6 个方面；官方 [AAAI 2025 proceedings paper](https://ojs.aaai.org/index.php/AAAI/article/view/34522) 与[作者代码/数据仓库](https://github.com/thu-coai/CharacterBench)。作者流程用 test set 生成角色回复，再用 CharacterJudge 评估（作者仓库 README “Data Preparation”“Evaluation”）；重点在角色定制/对话回复能力，不是 autonomous NPC 日常动作或游戏世界运行时。官方 repo 页面没显示 license 文件（截至核查时），所以 license unknown；数据另有 Hugging Face 链接，具体数据 license 需单独核查。

**inference**：若新问题收窄到 NPC 和玩家交谈时的人设稳定性，CharacterBench 可能比 NPC-Bench 的单一 fantasy 知识问题更广；但此轮已有 CharacterBox 覆盖持续角色表现，CharacterBench 不增加 autonomous behavior 证据，因此不列为优先两项。

## 方法参照与边界

- **NCP-Bench**：作者的 [NCP-Bench 仓库](https://github.com/NLP2CT/NCP-Bench)提供文本 Narrator 的 open/respond 接口，并由独立 auditor LLM 检查 factuality、commitment、trajectory；仓库许可证为 MIT（README、LICENSE）。它可作文本剧情/叙事规则边界的补充，但不是 C++ 房间动作 benchmark。
- **Generative Agents**：Park et al., *Generative Agents: Interactive Simulacra of Human Behavior*，[arXiv:2304.03442](https://arxiv.org/abs/2304.03442) / UIST 2023。论文 §6.1–6.3 的访谈评估让 100 名参与者比较同一 full rollout 最终状态下四种 memory access 的访谈回答与人写回答；这不是多种完整 policy rollout 的玩家 A/B。§7 报告的两日社会传播/协调属于模拟观察。因此可借用人评/消融组织方式，不可称作现成的玩家 NPC alive benchmark。

## 可讨论的下一步（proposal，未授权执行）

在同一小房间、同一角色外观、同一事件/玩家脚本下，比较规则 BT/utility、强记忆 LLM 与当前 dynamics policy。把两类结果分开：其一是可自动复核的事实/动作合法性/状态结果（防崩坏）；其二是玩家盲评“是否像一个会自行生活、回应具体情境的 NPC”。LLM judge 可做低成本筛查，但须与人工评分做校准，且不可把自动 judge 分数写成玩家效度。该设计不要求先证明真实心理拟合，也不把 `A*` 预测准入门槛带入新目标。
