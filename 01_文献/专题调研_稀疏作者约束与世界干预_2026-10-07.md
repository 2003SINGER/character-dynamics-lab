# 稀疏作者约束、世界干预与持续 NPC：算法级近邻审计

日期：2026-10-07。性质：定向研究审计，不是穷尽查新、方法立项、实现完成或玩家效度证明。基线仓库 `webgpt-sync@4a44ee22`；本轮不改 Runtime、Dynamics、policy、参数或未提交的 paired probe。

## 1. 问题和本轮判断

用户在[本次原始讨论](../90_原始材料/2026-10-07_WebGPT_稀疏作者约束与世界干预/README.md)明确提出：作者节点可以是条件成立后对角色的硬性变化；节点前后的合理性留给角色与世界，系统主要干预世界来促成合理过程。**不能把它收窄成“作者永远不能改角色”或“导演必须只读角色局部 O”。**这些都尚未被用户选定。

据此核查的具体问题是：作者给少量状态/事件约束后，系统怎样在不逐条写路径的情况下填充过程；干预到底作用于动作、目标、可用条件、未定设定还是结果；哪些历史与玩家已见事实不得覆盖？

**结论：这是有真实算法谱系的方向，不是无人做过的接口。**2006 IN-TALE 已把自主生活行为与高层导演目标结合；2008 Story Facilitator 已讨论高承诺 waypoint 并实现 episode/trigger 及世界塑形；Late Commitment 已通过规划补设定；2023 Awash 与 2024 Shepherd 已在运行中的历史模式上施加软偏置；2024 StoryVerse 已用抽象 act 调用生成—检查—修订计划。现有近邻并不意味着用户的大目标无价值，但禁止仅凭这些词的组合宣布创新。

相较原贴，本轮有三项校正：

1. **“早期叙事规划全是中央导演，没有日常自主 NPC”不成立。**IN-TALE 的日常 LAB 由角色竞价/抽样选择，只是剧情 NDB 仍可覆盖它。
2. **“Late Commitment 是随便 retcon，而我们只前瞻干预”是不准确的差异。**它补此前未定设定，本来就要求不推翻既有提交；其原型还明确暴露了漏记否定前提的漏洞。
3. **“轻推之后达成更多节点，所以玩家更觉得活”不是同一个估计量。**Awash 的玩家访谈改善，而完成模式均数没有增加；两种结果应分别报告。

## 2. 作者写的“点”有四种，不宜混写

| 表示 | 数学/数据形态 | 已有先例 | 不能省略的区别 |
|---|---|---|---|
| 中间状态约束 | 命题集合 `g_i(W)` 与顺序关系 | Riedl 2009 Author Goals | 作者要求状态成立；不指定动作，不自带时间窗或在线保证 |
| 条件触发的角色/世界变化 | guard、typed change、完成/失效条件 | FearNot! episode/trigger | `if guard then change` 与保证 guard 迟早成立，是两件事 |
| 事件轨迹模式 | 有身份绑定的事件查询序列、失效事件 | Awash / Shepherd | 识别并推进正在形成的历史，不等于硬性必经节点 |
| 抽象叙事 act | 自然语言 goal、AND/OR prerequisites、跨 act placeholders | StoryVerse | 作者只写抽象目标，但导演仍可能接管整段动作 |

例子“受过帮助后变得信任对方”也要分开：作者可直接声明 `help_observed → trust_patch`，此变化拥有明确作者来源；也可要求系统根据经历自然学出信任。前者是游戏规则，后者是待验证的模型机制，不能混为一项贡献。本轮没有选定 schema 或修改 S/P。

## 3. 已核算法与控制权限

详细输入、伪代码、页码、失败路径与阅读级别分别见三个[子审计 A](调研子审计_AuthorGoals与叙事规划_2026-10-07.md)、[B](调研子审计_StoryFacilitator与LateCommitment_2026-10-07.md)、[C](调研子审计_StoryVerse与Shepherd_2026-10-07.md)，及主代理[Awash 全文审计](精读_Awash前瞻故事筛选与玩家评价_2026-10-07.md)。以下是比较，不另造一套论文未披露的算法。

| 工作 | 实际计算链 | 干预权限 / 日常自主性 | 失败处理与证据 |
|---|---|---|---|
| **Author Goals 2009** | 将有序中间命题作为无效果 author-goal 步骤插入初始 partial-order plan；补 open preconditions，处理 causal-link threats，剪掉无法满足约束的分支 | 中央规划产生路径；“意图被解释”不等于角色独立 runtime policy | 规划空间中不满足约束的路径淘汰；不是开放随机世界中每个在线节点总能到达。例子说明为主 |
| **IN-TALE 2006** | LAB 对下一日常活动竞价，按权重抽样；导演用因果 plan 下达高层目标，NPC 的 NDB 展开执行；可离线分级修复生成 contingency tree，运行时按威胁切分支 | 角色有局部主观工作记忆与日常自主；NDB 可调制、混合、覆盖 LAB，仍需剧情专用内容 | 从局部因果修复到删依赖步骤、增新事件，必要时换目标；不是只改世界。原型示例，不是成本/玩家受控证明 |
| **Story Facilitator 2008** | 按 preconditions 选 episode → introduction → emergent execution → 按作者 priority 执行满足的 trigger → finish/下一 episode | 全知 facilitator；角色目标自行推动行动。设置舞台、角色、可用目标/行为；另一个 double-appraisal 版本选物件/不确定结果 | FearNot! 没有显式大尺度 waypoint planner 或 trigger 变体评估器；连续层级修复是概念部分，不冒称已经实现 |
| **Late Commitment 2008 / Impro-POP 2010** | 不满足目标/动作前提时，用 STRIPS 式 OOC framing operators 补未定事实；partial-order search 加因果链接，限制无 IC 动机的前置动作 | 角色可提 framing，不是纯中央导演；世界/知识是提交对象。公共设定需跨角色协商，博士原型其他角色总批准 | 无可用 operator 时规划失败；明确的 true/false、历史依赖与观众已见内容约束补设定。NaF 漏掉负前提能导致矛盾 |
| **Awash 2023** | 新事件推进带绑定的 partial matches → influence ID 查表 → delay/duration stage direction → AI 继续按偏置概率选状态机动作 | 临时偏置角色策略，不是 world-only；旁白帮助玩家解释已经发生的过程 | 显式 invalidation；无 expiry。12 人两条件短会话质性研究，未证模式达成数提高 |
| **Shepherd 2024** | 动作 trait-utility 总分 + 模板进展的 drama score → 合成 overall score → weighted random | 不直接指定动作，但剧情评分进入 policy；精确合成运算未披露，不能伪造公式 | 模板跟踪与示例；缺冲突/不可达统一策略、系统玩家或作者评价 |
| **StoryVerse 2024** | eligible act → placeholder 绑定 → LLM plan → 连贯性/环境试执行/逐动作动机审阅 → 有界修订 → 执行；无 eligible act 时自主模拟 | 触发时导演计划接管，不是角色始终拥有动作选择权；角色局部 belief 权限未形式化 | 演示了角色死亡后适配；修订预算耗尽后的统一协议未报告。proof of concept，不是玩家/成本结果 |

**仍需补读而不能借题名下结论：**AIIDE 2025 Triangle Framework 是博士提案，不是已验证 landmark 保证；CoG 2026 *Narrative Intervention for Prospective Story Sifting* 已核正式录用/机构记录，但无公开全文，本轮只核摘要，干预算子与实验细节未知。Elsewise 有作者研究，但主要是帮助作者探索叙事可能空间，不是自主 NPC 算法证明。IPOCL 的意图解释机制沿用[此前算法核读](算法拆解_NPC方法与生产系统_2026-10-07.md)，不把中央计划内的 intentions 等同为一个自主持久 agent；Sabre 的本轮阅读范围以子审计 A 为准，不声称全部近邻已覆盖。

## 4. 哪些部分可以吸收，哪些仍缺算法

可以具体借鉴的计算部件，而不是“有导演/有世界”的口号：

- **节点表示：**有序中间状态（Author Goals）；带 guard/trigger/finish 的段落（SF）；actor/target 身份绑定与后续失效（Awash/Winnow）；跨 act placeholder（StoryVerse）。它们不是统一等价表示，先按实际题目择取。
- **历史约束：**partial match 记录前缀；causal links 记录动作依赖；late framing 检查已经提交的正/负事实。观众看到某件事与 NPC 知道某件事不同，不能共用一个“unknown”标志。
- **权限机制：**LAB/NDB 分层仲裁；world-setting/narrative-action；OOC framing；有期限的 policy bias；完整 action-plan handoff。必须分别标注来源，不能把任何一种都叫“轻推世界”。
- **失败机制：**已发生前缀不删，未来 causal threats 修复；绑定角色死亡/关系改变触发失效；有限修订到限要报告失败。不让“永远补一个方便道具/新角色”把可达性检验变成空话。

**论文没有公开的部分仍记缺口：**Shepherd 精确 score combine、Awash 精确概率变换、StoryVerse 到限回退、2026 CoG intervention operators。不能因为伪代码位置空着就由我们猜一条并反称“吸收原算法”。

## 5. 与本仓库真实接口对照

本轮重新读了原始世界模拟动机、完整机制的数据流/对象职责、Q04–Q09、当前研究重建审计，并核对下面的运行接口；**设计文本不作为实现证据**。

| 当前确有的落点 | 源码/运行语义 | 与新问题的距离 |
|---|---|---|
| W 权威执行 | [`World`](../Demo%20codex-generated/Inc/world.h) 的 action validation、completion settlement、真实 task、runtime event source | 可以承载游戏因果后果；当前没有作者约束可达性/干预搜索求解器 |
| O 与角色候选 | [`Observation`](../Demo%20codex-generated/Inc/observation.h) 的持久 facts、known affordances、target bindings、typed feedback | 可表达 stale belief 与未知条件；不是玩家可见历史提交账本，也不是 late-framing 许可系统 |
| 自主执行循环 | [`ContinuousRuntime`](../Demo%20codex-generated/Inc/continuous_runtime.h) / [`execute_next_boundary`](../Demo%20codex-generated/Src/continuous_runtime.cpp) 的 boundary→O→model hooks→gate→policy→W validation | 已分开执行与行为模型；没有一个 Director 读取作者约束、挑允许的世界干预并重新评估节点 |
| 持久角色/历史 | model 的 typed persistent intention、ActorHistory 与不同 policy 输入 | 已能追踪有限生活活动；不能据此说有多 NPC 目标冲突、plot-point planner 或观众解释能力 |
| scene / object / task tape | 固定房间 affordance、task/event 与 opt-in life tape | 现有模块和用户对象化思想相符；预置 tape 是外生条件，不是自适应世界干预算法 |

另外对 `Inc/`、`Src/`、`applications/` 检索 author-goal / landmark / narrative-director / waypoint 等接口名没有命中。这个检索只作辅助，结论来自上述接口职责，**不是声称扫描所有文件就证明不存在任何相关逻辑**。用户尚未提交的 paired harness/V1、CMake 修改完整保留，不随本次调研验收。

因此不应再把“复用对象 affordance”当本轮新方法，也不应说只给现有 Runtime 插一个名字叫 Director 的接口就完成上述方向。缺少的是约束表示、允许干预集合、干预选择/失败协议与相应证据；不是时钟或 typed rejection 又没闭合。

## 6. Sims：哪些是实装缺陷，哪些是设计取舍

对象广告和需求评分的准确来源沿用[算法拆解 §2.9](算法拆解_NPC方法与生产系统_2026-10-07.md#29-sims-对象广告--zubek-needs-scoring两份来源分开ab)，不把 Zubek/Graham 的通用公式当零售版 Sims 精确实现。

[EA 2026-09-22 官方说明](https://www.ea.com/games/the-sims/the-sims-4/news/update-9-22-2026)还给了实现级解释：睡眠中不相干活动被加 eligibility test 阻止；秋千重复通过 cooldown 处理；“协商奖金”入口与后续 interaction 的职业条件曾相反；后台大学课程则是 zone-load 恢复漏掉。**这些分别是保持条件、重复频率、入口/执行前提不一致和非活动世界恢复问题，不能统一归因成缺少 trajectory-level planner。**本轮没有运行 Sims 或审其闭源代码；补丁说明不是完整失效统计。

另一方面，[2026-03-18 Rez Graham 原始访谈](https://www.pcgamer.com/games/the-sims/sims-dont-plan-anything-says-former-sims-4-developer-though-he-always-wanted-to-program-them-to-its-always-shot-down-rightfully-so/)指出多步规划还受到意图可读性与玩家控制空间的制约。这是前开发者对设计的回顾，不是当前版本源码或玩家对照证据。它提醒我们：**内部能推理，不等于玩家能看懂；更自主也不自动更符合游戏需求。**不能反推“别家不会规划，所以我们的复杂 NPC 一定更好”。

## 7. 还值得检验的窄问题，不是已发现空白

目前较有识别力的候选是：

> **在固定稀疏作者约束和允许的干预预算下，主要改变可观察世界条件、而不接管 NPC 的日常动作选择，能否形成玩家可理解的到达/偏离过程；不可达时能否诚实失败，而不篡改历史？**

这是把用户方向变成比较问题，**不是称已不存在近邻**，更没有预先选定 LLM、训练、情绪字段或世界编辑算法。硬性作者角色变化仍可作为共同规则；世界干预只是优先候选通道，不是绝对禁用目标指令/策略偏置。

想验证它，先要把四种情况区分开：

| 条件 | 正确要回答的问题 | 不能怎样自证 |
|---|---|---|
| 无导演 | NPC 自己能否自然达到节点？ | 自主 utility 已做到时仍声称必需新机制 |
| 软偏置 | 加 template/goal score 就够了吗？ | 把动作偏置藏在 world-only 条件里 |
| 未来世界干预 | 一个合法机会/障碍/事件改变后，NPC 根据其 O 自行选择什么？ | 直接编辑 NPC 动作，然后描述成自主回应 |
| 不可达/事实已承诺 | 约束冲突、合法干预耗尽或改写玩家已见事实时，是否报告失败/降级？ | 无上限生道具、生人、改身份，直到强行成功 |

上述是以后讨论的对照结构，不是本轮运行计划。若要硬保证节点，又拒绝任何角色接管，须先说明控制假设：某 NPC 永不选择所需动作、关键条件已被玩家永久破坏时，仅“有个世界干预接口”不提供保证。节点到达、允许修改预算、后果/局部知识一致、日常目标是否被吞掉、玩家因果理解、真实作者工时与运行成本须分账。
