| **一句话** | 我们做的是「会承受世界后果并持续回应的角色」，不是「会聊天的角色」。 | We build characters that **bear the consequences of the world and keep responding** — not characters that chat. |

## §2 一段式（可直接用作 abstract 首段骨架）

**中文**

> 现有 LLM 角色智能体同时存在检索式记忆、动态 persona/state 等不同路线，因此本文不作“业界大多只是检索”的总体断言。我们提出 **Character Dynamics**，关注角色经历的后果是否以持久状态留存并影响未来行为。显式机制链为权威世界 `W`、角色局部可观察视图 `O`、结构化意义 `X`、带独立动力学的状态 `S` 与行为分布 `π(A)`。语言模型承担边界清晰的语义压缩任务，而不是直接决定下一动作。封闭小房间只用于验证信息边界与 `O→X→S` 控制链；持久状态的预测充分性必须在独立 held-out 人类轨迹上检验。

**English**

> LLM-based character agents use multiple memory designs, including retrieval and dynamic persona/state. This work asks a narrower question: do the consequences a character undergoes persist in state, and does that state shape later behavior? We propose **Character Dynamics** as an explicit chain — authoritative world `W`, local observable view `O`, structured meaning `X` extracted from `ΔO`, character state `S` with per-field dynamics, and action distribution `π(A)`. The language model performs bounded semantic compression rather than choosing the next action. The closed-room simulator is used only for information-boundary and `O→X→S` instrumentation; predictive sufficiency of persistent state is evaluated on independent held-out human trajectories.

## §3 定位（T24）：不是二选一，是三层的不同角色

用户原话：「硬要的话，第一个是科研，第二个是工程，不冲突吧？」

**答：不冲突，但它们不是两个并列的选项，是链条上的不同位置。** 本 Paper-0 的科学内核仍是持久状态是否表征并影响后续行为；世界媒介化是信息边界的前提与可单独检验的工程/机制层，不另立一个 Paper-0。

| | 原 framing | 实际角色 | 用途 |
|---|---|---|---|
| **(b)** 「把 authoring 成本降一个量级，从而第一次能系统评测内部表示的预测质量」 | 不是价值主张，是 **enabling condition（可行性前提）** | Methods / 为什么现在能做而以前做不了 |
| **(a)** 「LLM 做出更 believable 的 NPC」 | 是 **value claim（价值主张）**，但**不能靠人类观感评测** | Intro 的动机 / Conclusion 的意义 |
| **(c)** 「**持久状态是否对后续行为近似充分且必要？**」 | Paper-0 的 **research question（可证伪的科学问题）** | 论文的主问题；世界媒介化作为前提/次级干预 |

**(c) 的完整表述**（来自用户调研笔记里的三个候选 RQ 第 1 条）：

> 在局部可观测、可回放的单角色环境中，给定持久状态 `S` 后，完整历史是否仍能提升下一动作预测？与等维度朴素状态、置换状态相比，`S` 的预测收益是否来自其结构而非容量？`W→O` 的延迟发现、部分知情和错误归因只作为信息边界前提/独立干预检验。

**为什么这个 Paper-0 framing 比 (a)(b) 更适合作为首篇可证伪问题：**

1. **可证伪**——有天然基线（raw history、strong summary、naive-S、置换-S），能直接构造回放对照实验。
2. **同时约束科研与工程**——`W/O` 的信息边界决定输入是否合法，但不替代 Paper-0 的状态充分性问题。
3. **直接对应他真正想要的那个东西**——「会承受世界后果并持续回应的 NPC」中的“后果→持续回应”，对应 `history→S→future behavior`。

### ⚠️ 唯一的硬冲突点（必须守住）

> **如果 (a) 用人类观感评分来评测，就与 (b) 的 held-out NLL 协议正面冲突。**

依据（Game AI Pro V3 C04，全套 146 章唯一的真人受试实验）：**83% 的玩家无法识别一个纯随机数生成器**，享受度与实际难度、智力、真实感**均不相关**，且「players invent stories for the nonplayer-controlled characters… They see cheating, bias, motivations, and desires where none exist」。

→ **人类评分测的是叙事可读性，不是机制保真度。**

**守则不冲突的唯一安排**：主指标 **held-out NLL**；人类评分只作**次要指标**，且必须在论文里写明它测的是什么、不测什么。

## §6 T25：为什么它是实验前的最低限度记录

用户要求先不做实验、等待后台文本阅读完成。**这个决定合理：T25 现在只是被说明清楚，不授权改代码，也不启动任何跑批。**

### 6.1 现在每一步实际发生了什么

在 `Demo codex-generated/Src/simulation.cpp:156-157`，每一个决策点都会先算完整的 `DecisionContext`，再从它采样一个动作：

```cpp
trace.decision = decide(observation, state, personality);   // 得到 π(A)
trace.chosen_action = sample_action(trace.decision, action_rng); // 从 π(A) 抽一个动作
```

`decision.cpp:140-161` 已经对所有当前可选动作做完 softmax，故每一步在内存里实际有类似：

```text
π(StudyFocused)      = 0.31
π(StudyHalfhearted)  = 0.18
π(UsePhone)          = 0.27
π(RestAtBed)         = 0.24
```

但现有 `trajectories.csv` 在 `simulation.cpp:245` 只写下：

```text
..., chosen_action, accepted, elapsed_minutes, ...
..., UsePhone,      1,        20,              ...
```

也就是**只留下抽签抽到了什么，没留下抽签前每个候选动作有多大概率。**

### 6.2 一个直觉比喻

把角色的选择理解为掷一个"加权骰子"：

- `chosen_action` 是：这次骰子落在「UsePhone」。
- `π(A)` 是：骰子每一面在掷之前的配重；例如 UsePhone 27%、Focused study 31%、Halfhearted study 18%……

**只存落点而不存配重，就无法区分下面两种完全不同的角色状态：**

| 两次都选 UsePhone | 这代表什么 |
|---|---|
| 第一次 `π(UsePhone)=0.90` | 几乎没有选择空间，角色基本一定玩手机 |
| 第二次 `π(UsePhone)=0.27` | 角色仍有 73% 的概率本会做别的事，这次只是随机抽到了手机 |

看动作日志，这两步是一样的；看 π(A)，才看得出角色的**倾向**是否变了。

### 6.3 T25 最初是为 R01 服务的

R01 不问「角色最后选了什么」，而问：

> **给定 state `S`，是否已经足够预测下一步的行为分布 `π(A)`？**

NLL 的计算需要模型在**真实下一动作揭晓前**给每个候选动作一个概率：

```text
NLL_t = -log p_model(真实发生的下一动作 | 已知信息)
```

所以以后若要比较 `raw history / strong summary / S / N-gram`，每种方法都必须给同一动作一个概率。现有 CSV 只存了实际样本，**不能回放出当时的完整目标分布**；`π(A)` 不落盘，就只能重新跑模拟，而重跑会混入版本变化、随机种子或机制改动，不能做可信的可比回放。

### 6.4 它对你刚拍板的 StudyFocused / StudyHalfhearted 有什么用

拆动作真正关心的不是「一次是否抽到了 Focused」，而是：

```text
当任务压力相当、疲劳相当时，
某个持续状态跨越 Q01 的阈值，
π(StudyFocused) 是否突然上升，且 π(StudyHalfhearted) 是否相应下降？
```

这只有记录每一步的两列 `p_study_focused` / `p_study_halfhearted` 才能看见。

否则即使系统内部发生了从 0.49→0.51 的偏好跳变，抽样后的单条动作序列也可能连续 10 次都恰巧是 `UsePhone`；你会误判为"Q01 没有变化"。

### 6.5 T25 应该最小化成什么（**提案，未执行**）

不改决策，不改采样，不新增模型调用，只在 CSV 每行多写：

```text
known_action_count,
p_use_phone, p_shop_on_phone, ...,
p_study_focused, p_study_halfhearted, ...
```

约 18 列。动作当前不在 `A^O`（角色不知道或不具备）时写 `0.0`。

同时写 `known_action_count = |A^O|`，不是锦上添花，而是**必要列**：当前 `decide()` 只遍历 `observation.known_actions`。一个动作在 3 个候选中拿 0.33，和在 16 个候选中拿 0.33，含义不同；均匀随机猜测的 NLL 基线分别是 ln3≈1.10 与 ln16≈2.77。这里的基线不是 NLL 上限；真实动作概率趋近 0 时 NLL 可以无界增大。

因此 T25 做完后，任何 NLL 结果至少应当：

1. 报告 `|A^O|` 的分布；
2. 按 `|A^O|` 分组报告 NLL，或报告归一化 NLL（`NLL / ln|A^O|`）；
3. 不把不同支撑集大小下的 NLL 直接混成一个平均数。

### 6.6 它**不**证明什么

T25 只补一台"记录仪"，它**不**：

- 证明 S 有用；
- 做掉 R01 实验；
- 解决 LLM 先验归因；
- 解决 N-gram 等记忆对照；
- 让 StudyFocused/Halfhearted 自动合理。

它只是让未来的任何结果可审计：别人能看见角色当时的完整倾向，而不是只看见随机抽到的一次动作。
