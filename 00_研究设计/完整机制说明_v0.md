## 1. 课题要解决的事

第一版只追问一个问题：

> **在受限信息下，持续更新的角色状态能否保留历史中对未来行为有用的后果，并据此产生更可检验的行为分布？**

因此它不是“让 NPC 看起来像人”的泛目标，也不是完整世界模型、通用心理学或任务 Agent。系统必须能在受控世界中：

1. 区分世界实际发生了什么、角色知道什么、角色自身如何变化；
2. 用持续维护的状态产生此刻的条件行为分布，而非每轮用 persona 加全历史重新猜；
3. 在叙事回放中用下一真实行为检验该分布；在自主运行中让同一分布驱动行动；
4. 保留足够的来源链，以便重放历史、干预信息、替换更新器和做消融。
5. 在主验证成立或至少不劣的前提下，比较结构化状态与 raw history/强 summary 的上下文、调用、延迟和控制成本；这是一条部署评价线，不替代主验证。

预测是检验状态是否保留有用历史后果的主尺子，不是项目唯一目的；NPC 运行和创作辅助是同一个前向机制的另外两种用法。效率—效果与可控性是并行的第二评价维度：若质量相近，结构化状态是否减少 token、调用、延迟和长期运行成本，并支持更可靠的局部干预、信息权限、回放和调试；它不能替代 Replay/干预证据。

## 2. 一眼看完整运行链

运行时采用一条权威的、事件驱动的模拟时间线；`RunningAction` 是持久
节点，正常推进传播的是精确的 `Delta-t`、WorldEvent 与 typed outcome，
而不是每分钟空转。旧 Reference v0 的整步结算保留为对照路径，不代表
持续 runtime 的时间所有权。

```text
外部事件 / 时间 / 上次行动
             ↓
        W：权威可执行世界
             ↓
     SceneFilter：角色所在场所的候选变化
             ↓
 PerceptionFilter：可见、可听、注意到、收到的信息
             ↓
    ΔO / O：角色持续维护的主观世界视图
             ↓
   X：此变化对该角色意味着什么（Appraisal）
             ↓
 S：每个字段按自己的动力学更新
             ↓
 D：本轮由 O/S/P 临时得出的决策上下文
             ↓
  π(A^char | O,S,D,P,A^O)：人物级动作的条件分布
             ↓
       选择 / 采样一个 A^char
             ↓
 A^char 展开为一组世界原子操作 a^world
             ↓
       W 校验、结算、记录后果
             └────────────────── 回到下一 runtime boundary

runtime 的时间推进只由 scheduler 完成；W 通过受控 adapter 消费
`Delta-t` 并产生 `WorldEvent`，随后由合法的 observation projector 写入
`Delta-O`。动作开始必须先经过 `W.validate_runtime_start()`；动作完成
使用带有实际 `RunningAction` 时长的 runtime completion settlement，不能
在完成时重新猜测起始时长或再次承担时间推进。
```

`P` 不在链的某一个单点“出现”。它是长期人物响应参数，调制 `O→X` 的解释倾向、`X→S` 的更新幅度/时间尺度，以及 `S→D→A` 的行为表达。

## 3. 每类量的语义与所有权

### 3.1 `W`：权威、可结算的世界

`W` 是运行时认定为真的外部事实和规则，而非任何角色的心理档案。v0 的 W 至少包括：

```text
time / external schedule / external events
scene membership and spatial/environmental state
objects and object properties
character location, pose, held items, ongoing activity
world rules, action preconditions and effects
```

例子：门是否开着、手机实际在哪里、角色是否在床边、当前时间、DDL 剩余多久，均属于 W。W 拥有最终 action 合法性和效果结算权：角色提出动作，不直接改写 W。

### 3.1.1 多角色：`W` 存关系事实；角色侧只存自己的态度与信念（2026-09-05 用户确认，2026-09-05 消歧）

用户确认的多角色设计：

1. **各角色状态仍然分开**——不存在共享的"群体心理状态"。
2. **更新时把他人视作 object**——某个角色的 `O` / `X` / `S` 更新过程中，其他角色以对象形态被感知，不是直接读取对方内部状态。
3. **可验证的关系事实存在 `W` 的图中**——例如亲属/组织/契约身份、已经结算的互动事件及其时间；它们的权威记录归 W，不由任何一方角色的私有状态持有。
4. **角色侧的 `R_i[j]` 是另一类量**——它是角色 i 对角色 j 的私有、有向态度或关系判断（如信任、亲近、怨恨），属于 `S_i`；它不能被误写成 W 的上帝视角心理真值。
5. **`O_i` 只保存 i 有资格知道的 `W` 关系事实及可观察互动**；它既不直读 W 图，也不读取 j 的 `R_j[i]`。关系对行为的影响在具体 `U_k` 中消费 `O_i` 与 `R_i[j]`，不是独立的"社会模块"。

**这条与 Talk of the Town 的做法正相反，属于刻意选择**，需在对外表述中区分：TOT 让每个 NPC 各自持有 250–400 个 mental model、800–1200 个 belief facet（即每人私存对他人的信念）；本项目只将可验证的关系事实置于 W，并使每个角色只持有自己的 `R_i[j]` 与可知投影 `O_i`。

**由此产生的信息边界约束（必须满足，否则构成泄漏）**：

- 关系事实存在 `W` **不等于**角色可以直接读 `W` 的关系图。每个角色的 `O` 中**只能包含该角色有资格知道的那部分关系事实**（自己参与、被目击或被告知的关系）及可观察互动，其余不可见。
- `R_i[j]` 只可由 i 自己的观测、解释与历史更新；不得由 W 的隐藏事实、j 的私有态度或中央图的便利查询直接写入。
- 若某角色依据一条它未曾观察/听闻的关系做出行为，就违反了 `W ≠ O` 的信息边界，与"隐藏前置条件"类问题同源（见 Q04）。
- 第三人称视角的关系推理（"A 知道 B 和 C 的关系"）是二阶知识。见 §3.1.2。

### 3.1.2 二阶知识：**用户 2026-09-05 确认为必需**，从"后续分支"升为 v0 设计要求

用户原话：「二阶知识肯定需要的。」此前把它标为"v0 未定义、属后续分支"的处理**已作废**。

**但"必需"不等于"可以立刻定深度"。** 调研后得到的实际情况是：

**① 游戏工业界完全没做。** 对 Game AI Pro 已提取文本的 47 章全文检索 `theory of mind` / `second-order` / `nested belief` / `believes that … believes` / `knowledge about knowledge`，**命中数为 0**。唯一含"社会"的专章（V1 C35《A Simple and Practical Social Dynamics System》）实际讲的是**注视、人际距离、朝向与交互编舞**：

> "A social dynamic is any social interaction that has to happen in real-time between two or more characters. Typically, there is an element of **spatial position, timing, and orientation** involved."

即：**工业界的"社会"是身体层面的，不是心智层面的。** 该章连"角色间关系值"都没有，更无"A 知道 B 与 C 的关系"。

**② 但学术界做了很多，所以这不是无人区。** Theory of Mind 在发展心理学（Wimmer & Perner 1983 Sally–Anne 范式）、心智理论 benchmarks、以及 LLM 时代有大量工作。**正确定位是接缝，不是空白**：游戏工业界有理由放弃（Gap 1a：玩家看不见），学术 ToM 有成果，两者没接上。

> **因此：在学术 ToM 调研完成前，二阶知识只能登记为"候选"，不能登记为"创新点"。** 以"工业界没做"来主张创新性，是拿一种有理由的放弃当真空白。

**③ 深度取多少，是有心理学约束的设计决策（不是越深越好）：**

| 阶 | 形式 | 状态 |
|---|---|---|
| 一阶 | `A 知道 f` | **已有**（`O` 即为一阶知识载体） |
| 二阶 | `A 知道 B 知道 f` | **用户确认必需** |
| 三阶 | `A 知道 B 知道 A 知道 f` | **无依据** |

心理学证据是**人类在自然情境中可靠使用二阶，三阶显著吃力且极少出现**。**若上三阶，等于在建模一个人类自己都很少用的能力**——这必须在机制说明里写明理由，否则是被审查者优先质疑的点。

**④ 与 §3.1.1 的整合约束（这是二阶知识真正难的地方）：**

- 关系事实 `E^W` 归 `W`（§3.1.1 第 3 条），但**二阶知识不是关系事实，是"谁知道谁知道"的事实**——W 只维护可追溯的知识归属索引；它不把该索引或任一角色的私有 `R_i[j]` 自动暴露给其他角色。
- 每个角色的 `O` 只能包含**它有资格知道的**二阶事实。特别地：**"B 知道 f" 这个事实本身，A 未必知道**。
- 由此产生一个 §3.1.1 尚未覆盖的泄漏风险：**若 A 的行为依赖"A 知道 B 不知道 f"，而这条从未进入 A 的 `O`，就是泄漏**。形式与 Q04 的隐藏前置条件同源。
- **实现含义**：二阶知识需要一个与 `O` 并列的、带来源追溯的**知识归属索引**（who knows what, and how did this character learn it）。这部分 v0 **尚未设计**。

> **待办（新增）**：二阶知识需要一次**独立的学术 ToM 调研**（不能靠 Game AI Pro 支撑，它在这方面的贡献是"空白证据"）。调研完成后再定深度与表示。

### 3.2 `Scene`：局部世界更新和 affordance 的共同边界

`Scene` 不是为了代码好写才加入的容器。它同时限制两件事：

```text
W → SceneFilter → 候选观察流
W^scene → AffordanceResolver → A^W
```

角色在宿舍时，食堂椅子的位置变化不需要进入其候选观察流；宿舍门开合、手机收到消息则可能进入。场景还给出该局部世界目前真实支持的动作空间。它避免全局扫描，也把信息局部性、动作空间和世界结算连接到同一对象/场景本体。

小房间 demo 的对象层级进一步固定为：

```text
W → Scene(home) → Room(student room) → Object(phone / bed / desk / ...)
```

`Room` 是 `Scene` 内的场所容器对象，拥有室内 Object 的集合和灯光、温度等局部物理状态；手机、床、桌子、门等才是 Room 内的具体 Object。这个层级只是 v0 世界表示的可替换实现约束，不把“Room 类”本身误作研究机制或对未来所有场景的唯一建模法。

### 3.3 `O_i`：角色 i 的持续主观世界视图

`O_i` 不是“本帧看见的东西”，而是 i 持续保存的一份世界副本。每个字段原则上可带：

```text
value | known / unknown | confidence | source | observed_at | stale_at
```

它允许旧值继续保留、置信度下降、显式 `unknown`，以及被新证据修正。基础刷新优先交给程序：新信息、环境暴露、消息抵达、感官可及性和时间过期。复杂的社会含义推断可作为候选 LLM 工作点，但必须输出受 schema 限制的更新，不能把 W 的真实事实泄漏给角色。

`W ≠ O_i` 是机制必要条件：同一件事的真实原因、角色看到的表面、角色后续的解释可以不同，从而允许误会、隐瞒、陈旧认知和信息干预。

### 3.4 `X_i`：事件的结构化意义 / Appraisal

`X_i` 回答的不是“状态应该加多少”，而是：**这次 `ΔO` 对 i 意味着什么？** 它把开放事件解释与状态动力学分开：

\[
X_t^i=I(\Delta O_t^i,O_t^i,S_t^i;P_i).
\]

它的候选维度可包括目标相关性、目标一致/冲突、可控性、意外性、不确定性、责任归因或社会拒绝线索；v0 的最小 schema 尚未由论文决定。LLM 可以在这里做开放语义解释，但输出必须是结构化的 `X`，不能直接写“焦虑 +0.3”。新证据可重新解释旧事件，因此 X 也为 re-appraisal 留出接口。

### 3.5 `S_i`：角色自身、会持续变化、且对行为有用的状态

只有同时满足以下条件的量才进入 S：

1. 语义上只属于角色 i；
2. 需要跨轮保存；
3. 此时仍可能改变；
4. 保存它有望改善后续行为预测或干预判断。

S 不是一坨“心理档案”，也不等于情绪集合。当前候选类别是：

| 类别 | 候选例子 | 作用 |
|---|---|---|
| 慢状态 | 持续压力、自我效能、长期动力 | 保存长期但仍可改变的后果 |
| 目标/动机 | 候选目标、目标投入、需求、回避/接近 | 形成当前可能想解决的事 |
| 承诺状态 | intention、终止/失败/重新考虑条件 | 防止人物每轮重置行动方向 |
| 即时状态 | 情绪、疲劳、紧迫感、注意力、认知负荷 | 对近期事件和时间做出响应 |

时间尺度不是一套硬分层本体论。每个字段 `s^k` 自己带动力学：触发、累积、恢复、衰减、饱和、重评估、值域和 P 调制都可不同。

\[
s_{t+1}^k=U_k(s_t^k,X_t,\Delta t;\theta_k(P)).
\]

具体字段、`U_k` 公式和字段间耦合目前均未定；它们将由机制文献和最小实验收缩，而不是为“完整心理学”不断加项。

### 3.5.1 历史、状态与外部日志不能偷换

原始历史不是 v0 policy 的隐形第四份输入。它被保存在 replay/provenance 日志中，用于评测、重放、干预和 `raw-history` 基线；人物运行时的历史后果应当经明确的 `O`、`S`（未来才可能有 P）留下来。若后来引入 memory retrieval，也必须把它命名为单独模块，声明检索来源、写入位置与 policy 输入，不能在 prompt 中悄悄重新塞入全历史。

### 3.6 `P_i`：长期人物响应参数

P 不是人物小传，不是“内向所以不说话”的硬规则，也不与 O/S 直接并列成三段 prompt。它是反应函数的长期参数，例如：

```text
rejection sensitivity | emotion inertia | stress recovery rate
task-start threshold  | risk preference | self-control
conflict avoidance    | decision noise under pressure
```

它可控制相同 `X` 产生多大状态变化、状态如何恢复/累积/衰减，以及相同 S 怎样表现成行为。未来可尝试阈值、饱和或平滑反转，而不仅是线性权重；但目前不承诺某个函数是心理学正确的。

v0 固定 P：

\[
P_{t+1}=P_t.
\]

这里的“固定”只指**同一次运行中**不让日常经历任意重写 P。实验可以在不同 run 设定不同 P 配置，而保持初始 W、事件 trace 与其他条件相同，观察由参数差异形成的不同状态—行为轨迹；这正是 P 作为人物响应差异而非小传标签的可观察方式。“长期行为—世界后果—状态轨迹慢慢反塑 P”则是保留的后续假设，不是 v0 模块。

### 3.7 `D_i`：本轮决策上下文

`D` 是从当前 O、S、P 临时算出的决策量，而非所有影响动作的东西都塞进 S：

\[
D_t=H(O_t,S_t,P).
\]

例如有效谨慎度、此刻冲动性、决策噪声、犹豫或规划深度。D 随本轮决策结束而消失；只有需要跨时间保存并对未来有预测价值的量才提升为 S。

### 3.8 多角色关系：三种所有权已分开，暂不进入 v0

多角色时，`A→B` 与 `B→A` 不能被一个含混的“关系”字段同时表示。固定采用以下三层：

| 量 | 所有权与内容 | 角色可否直接读取 |
|---|---|---|
| `E^W[A,B]` | W 中可验证的关系事实与已结算互动（如亲属/组织/契约身份、公开或已发生的事件） | 否；必须经感知写入 `O_i` |
| `O_i(E^W[A,B])` | i 已知的关系事实及可观察互动，可陈旧或 unknown，并带来源 | 仅 i 自己的这一份 |
| `R_i[j] ⊂ S_i` | i 对 j 的私有、有向态度/判断（如信任、亲近、怨恨） | 仅 i；不是 W 真值，也不是 j 的内部状态 |

runtime 可以为查询而中央存放这些稀疏边，但物理位置不改变语义所有权：访问必须遵守上表。二阶知识另以 W 中可追溯的知识归属索引表示，并同样先进入相应角色的 `O_i` 才能影响行为。单角色最小环境不实现此层。

## 4. 一轮运行到底发生什么

### 步骤 0：事件、时间与决策边界

时间、外部消息、DDL、脚本实体或上一动作的后果更新 W，并产生带来源的 `ΔW`。它们首先是世界变化，尚未自动成为角色已知信息。

数据流不等于“每个原子世界操作都让人物重新思考”。v0 应按事件、时间 tick、动作完成或预先声明的决策时点触发后续 operator：`ΔW` 只进入受影响的观察/状态支路；没有新事件时，只有依赖 `Δt` 的字段运行恢复或衰减。究竟哪些事件触发一次 policy、组合动作能否中断，属于需要在每个实验场景配置中冻结的执行语义，当前还未指定唯一规则。

### 分层时间维护：不是一只“全系统 tick”

demo 维护一个可比较的全局模拟时间和事件队列，但**不同系统、乃至同一系统的不同字段，都可以有各自的更新触发与周期**。它们不应因为一个秒级 tick 到来就整套重算：

| 部分 | 典型触发/周期 | 不应发生的事 |
|---|---|---|
| `W` 的时钟、光线、外部事件、动作持续与结算 | 固定世界时间步、排程事件、动作开始/完成 | 非相关世界字段被重写 |
| `O` 的直接观察、消息和 exposure 刷新 | 信息抵达或场所/注意变化；可另设局部陈旧检查周期 | 全量复制 `W` 或强行同步 |
| `O` 的 stale / `unknown` 维护 | 各字段自己的过期规则或低频审计 | 把旧信息一律删除 |
| `S^k` | 每字段自己的事件触发、恢复/积累周期或 `Δt` 更新 | 所有情绪、目标、疲劳以同一速率更新 |
| `D` 与 `π(A)` | 预设决策点、动作完成、目标失效/满足，或真正影响选择的事件 | 每个 world primitive 都重新做完整人物决策 |
| UI / provenance 日志 | 渲染频率或状态变更时记录 | 以 UI 刷新驱动人物动力学 |

具体周期是 demo 配置，不应现在拍脑袋写死为心理规律。每次更新须记录实际模拟时间、触发原因、受影响字段和使用的 `Δt`，从而可在回放中复现“同一时间维护策略”并把调度策略本身作为可替换的实验条件。

### 步骤 1：场所筛选和感知筛选

用户已确定 Scene 是 W→O 的第一层场所边界，也是 `A^W` 的基本单位。v0 进一步采用 PerceptionFilter：SceneFilter 选取与角色当前场所、通信通道或明确跨场所机制有关的变化；再依据可见性、遮挡、听觉、注意力、睡眠/活动状态等决定哪些内容成为 `ΔO`。每个小环境应把启用的感知规则写在配置中，不能把它们误说成已验证的心理规律。

```text
同一场景发生  ≠  角色一定知道
进入候选流      ≠  立即覆盖 O
```

未观测字段可保持旧值、陈旧化或转为 unknown。这里的输入边界保证 policy 不用上帝信息。

### 步骤 2：解释观测变化为 `X`

对进入 O 的关键变化，解释器结合 `ΔO`、当前 O、旧 S 和 P，给出结构化 X。它可有多种候选解释或置信度，但不能把自由文本直接变为最终心理状态。可重评估意味着：新证据出现时，可修订某次事件的意义，而不是只能继续累加它的第一次解释。

### 步骤 3：按字段更新 `S`

每个启用状态字段运行自己的 `U_k`。例如某状态可有触发和衰减，另一状态可累积和恢复，目标可竞争，intention 可维持直到满足重新考虑或失败条件。更新器应明确输入、输出、边界和来源，而不是一个不可追踪的总 `state_update(S)`。

### 步骤 4：生成 `D` 并维护目标—意图承诺

候选 goals 由关切、O 和 S 激活并竞争；选定的 intention 不应因每个小刺激立即消失。其通用模式是：

```text
Candidate → Selection → Commitment → Reconsideration
```

此模式也可迁移到解释和 O 的 belief revision；但每处是否实际采用、采用什么条件仍待后续确定。

### 步骤 5：解析可行动作并形成行为分布

W/Scene 解析世界客观可执行集 `A^W`；角色侧的 `A^O` 表示依据 O 知道或能设想到的动作。当前实现已用 `InformationAccess` 区分 O-known 前置条件与仅 W 可验证的未知条件；仍保留先生成 affordance、再由 W 结算的路径，且不把 E0 视为行为预测验证。隐藏条件、错误 belief 与实例绑定的扩展仍见[Q04](未决问题与机制候选.md#q04-主观动作候选与隐藏条件)。最终行为分布为：

\[
\pi(A^{char}\mid O,S,D,P,A^O).
\]

对象拥有基础 affordance 和依赖的局部状态；场景可注册少量组合人物动作与出口转换。更精确地说：Object 提供 affordance fragments，Scene/Room 结合对象、地点状态和出口组成 `A^W` 候选，W 负责跨对象 precondition、最终合法性与结算。`ActionType` 是跨层共享的领域值，不是某一个类的“子动作”；角色 policy 只能在 `A^O` 里评分/选择，W 最终仍检查 `A^W`。动作设计的顺序是**现实场景/对象/状态/出口在前，动作在后**：先把一个真实可理解的小房间及其自然延伸场所放进 W，再从床、桌子、电脑、手机、灯、门及其状态中识别自然活动；而不是为了凑 action list 反向添加物品。

### 步骤 6：执行人物级动作、结算世界后果

人物决定的动作具有行为意义，例如“上床玩手机”“坐桌前学习”“关灯睡觉”，并不等于引擎的一次状态修改。一个人物级动作可展开为多个原子操作：

\[
A^{char}\rightarrow[a^{world}_1,a^{world}_2,\ldots]\rightarrow W'.
\]

人物层只提交人物级动作请求，不提交任意可执行 primitive。W 必须自行展开可信计划（或严格验证计划来源和前置条件），以强类型操作结算，不能接受任意字符串字段写入。计划与实际操作分别记录；中断会改变实际时长和实际效果，不能把原计划当作已发生。

因此人物动力学不会在走到床边、躺下、拿手机的每一步重新做完整心理决策；世界仍按原子效果更新对象和角色状态。v0 必须为每个组合动作声明：执行区间、原子效果序列、失败/中断语义，以及这些效果是否在本轮合并结算；不能由未声明的引擎行为决定研究结果。

角色知道自己提交了什么动作、是否被拒绝、以及哪些后果，必须也走显式的自我行动/感知通道写入 O；它不能因为系统已在 W 结算，就自动知道所有远端或不可观察的世界后果。

### 步骤 7：记录 provenance，进入下一轮

每轮至少可追到：

```text
event / ΔW → information access → ΔO → X → StateDelta / S
→ D → action distribution → chosen action → world outcome
```

这既是调试接口，也是后续回放、信息干预、更新器替换和消融的前提。

## 5. 动作粒度与小房间实验床

v0 使用一个小房间或相当小的 Scene、一个主要角色、有限对象和十几个高质量动作。典型对象可以是门、床、桌子、椅子、手机、灯；环境变量可包括时间、DDL、消息、光线和少量外部事件。

对象动作示例：开/关门、坐/躺、查看消息、使用手机。场景组合动作示例：上床玩手机、坐桌前学习、关灯睡觉。组合动作不是“作弊”：场景只是显式定义受控世界中哪些行为对角色有意义；项目研究的是状态怎样改变这些已给定行为之间的条件分布，不是生成现实世界的一切动作。

该环境的研究目标是可回放、可干预的实验床；展示连续数天的时间、行为与 O/X/S/D 变化不等于已具备研究评测。用户亲写代码属于独立的 `E:\Character Dynamics Demo`；本仓库的 [Codex 参考实现](../Demo%20codex-generated/README.md) 可供阅读，不读取、复制或修改前者。实际实现范围统一见[当前实现进度](当前实现进度.md)。

### 5.1 场景必须承载的生活语义

- 无聊、低投入时可能玩手机/电脑；连续设备使用可产生疲劳或不适，使休息更有吸引力。
- 拖延和未完成目标可增加紧迫/焦虑，从而与娱乐竞争；焦虑不保证学习，疲劳也不保证立刻睡。
- 网购只是手机/电脑的一种活动例子，不为这个动作反向设计整个环境。
- 门通向如厕、取餐等自然目的地；首版允许一次人物动作直接结算门外活动、推进时间并留下可知反馈，不必逐步模拟走路。
- 同一初始世界、初始 S、外部事件条件及随机设置，仅调整一个 P 配置，观察 X、S 与动作分布的不同。自主轨迹一旦动作不同，后续 W 也会分化；严格单因素比较需固定/回放输入，不能把后续不同世界称为“完全相同情境”。

### 5.2 局部感知的展示用例

闹钟首先是房间内 Object：事件队列到时改变它的世界状态，再经同场景听觉进入 O，不是强行增加一个外部信息源。天气可作为 W 的独立过程，窗帘影响角色是否观察到；不必建立复杂气象系统。

睡着时 W 的时钟和事件继续，O 的时钟/视觉可以保持旧值，但不是全部 O 冻结：温度能经单独的身体/感官通道刷新，过冷可触发醒来。醒来再按正常感知刷新其余可感知字段。这里的“W=O”只指相关字段重新对齐，不是把整份世界无差别复制给人物。

### 5.3 Task、Commitment 与单步 Action

三个量不得混为一个“学习动作计数器”：

| 量 | 所有者 | 持续语义 |
|---|---|---|
| WorldTask | W | 长期任务的真实工作量、进度、支持动作、截止时间与完成状态 |
| TaskCommitment | S | 角色承诺推进哪个 task，是否暂时暂停、何时重新考虑 |
| Action | 本轮请求；W 结算 | 一次学习、吃饭、休息等 session，并非整个任务 |

v0 只实例化 coursework；完成条件为 `effort_done ≥ effort_target`，不固定为若干次学习。世界占位公式可采用 `base_effort × duration_factor × interruption_factor × seeded_variation`；每个因子、实际时长与最终产出必须可追踪。这是 demo 计算选择，不是心理规律。

承诺最低语义为 None → Active（开始推进任务）；Active → Suspended（暂让位给身体/恢复需求）；Suspended → Active（重新考虑后继续）；任务完成并为角色所知后，关闭对应 task_id 的承诺。暂时娱乐、恢复和放弃不是一回事，失败/阻断/放弃要定义世界事件、信息入口与转换条件后才加入。候选目标竞争也不等于已有规划器。

任务完成应沿 `W completed → O 确认 → X 目标完成意义 → S 更新/承诺关闭 → D` 生效。世界偷偷完成而角色尚不知道，不能直接解除角色压力。当前实现通过 `apply_self_action_feedback` 将可知反馈写入 O，再由 `update_commitment` 消费；不得恢复 `WorldOutcome → commitment` 直连旁路。

W 不得从 S 中暗读 commitment 来解析任务，也不暗读疲劳来修改效率。单任务 demo 可按唯一支持任务结算；多任务之前必须显式传递 `target_task_id`，多物品之前必须传递实例绑定。若要让人物状态影响 session 质量，需要单独设计可追溯的 ActionQuality/Engagement payload，见[Q06](未决问题与机制候选.md#q06-行动质量与任务关联压力)。

## 6. 程序、LLM 与可替换模块的分工

| 职责 | 当前优先承担者 | 边界 |
|---|---|---|
| W 状态转移、precondition、effect、时间结算 | 程序 | 角色不能直接绕过 |
| Scene/Perception、O 的直接刷新、陈旧/unknown | 程序 | 复杂社会推断可另设受限算子 |
| `X` 的开放事件意义解释 | LLM 候选 / 规则候选 | 输出受 schema 限制；不是直接改 S |
| 每字段 `U_k`、数值边界与时间演化 | 程序/明确理论算子 | 必须可追溯、可替换 |
| 行为候选与偏好 | LLM、规则或混合均待比较 | 只能在 `A^O` 内，不能绕过 W |
| 日志、回放、干预、消融 | 程序 | 每轮保存完整配置与来源 |

这是一份工作划分假设，不是对 LLM 优势或方法新颖性的结论。

## 7. 三种运行模式与评测位置

| 模式 | 在 `π(A)` 后发生什么 | 目的 |
|---|---|---|
| 回放/评测 | 暂停，映射真实下一行为 `A*` 后对照概率/排名 | 检验状态是否有行为预测价值 |
| 自主运行 | 从分布中选择或采样 `A^char`，交 W 执行 | 使角色在受控世界继续活动 |
| 创作辅助 | 呈现候选、倾向和可追溯状态理由 | 供作者采纳、拒绝或补写转折 |

真实行为 `A*` 是评测接口，不得提前泄漏为自主循环的输入。后续评测还可比较同一世界不同可知信息、同一终局不同历史，观察分布变化是否符合预先写定的干预预期。

## 8. 低耦合、消融与数据流要求

低耦合指工程修改彼此独立，不要求心理过程互不影响。更新器读取声明过的输入，输出显式结果；字段耦合需声明，不应靠执行先后顺序意外形成。允许先有较丰富的状态，再用比较和消融收缩，不按字段数量评价贡献。

每个字段/模块至少定义：

1. 值域、初值、时间尺度与恢复/累积/突变条件；
2. 中性语义，以及哪些 X/观察/其他字段可以影响它；
3. updater 的输入、配置、输出 patch 与唯一写入方；
4. 它直接或间接影响哪些 D/policy/其他状态；
5. event/operator/旧值/请求变化/实际变化的 provenance；
6. 禁用更新、移除 policy 输入、替换实现或中性化的消融方式。

置 0 只有在 0 确实中性、且切断所有旁路时才是有效消融。文本、类别、阈值和非线性量可能需禁用算子或使用 baseline value；不能把“更新冻结”与“没有行为影响”等同。StateDelta 要区分 requested 与裁剪后的 applied，日志不能把前者说成真实变化。

最小依赖约束：W 不读取 S/P；X 不读取原始 W；D/policy 不写 W；Object 不拥有跨对象全局规则；时间、随机数、配置和日志显式传入。新增一个普通 Object 不应迫使修改 CharacterState；新增一个心理字段不应迫使修改 World settlement，除非明确增加跨边界 payload。先有可替换函数/组件和边界测试，不为“像插件”预造动态加载平台。

同一输入 trace 应能使用不同配置重放。每轮记录 W/ΔW、信息权限与 ΔO、X、requested/applied StateDelta、S、D、候选动作与分布、选中动作、计划/实际结算、来源、模拟时间与 Δt。世界生成种子、世界过程/场景种子、动作采样种子分别命名；禁止模块内部隐藏随机源。

世界规则、初始世界生成、运行时 delta 是不同层：seed 不能在运行中重新生成世界并抹去行动后果。运行输出和配置必须保留于不覆盖的 run 目录；回放器、记录器不能各自复制一套推进规则。

接入有成本的推断器后，记录模型/版本、token、调用/缓存、失败重试、延迟和单位成本；这些是评价数据，不混成一个未经定义的“总效果分”。具体验收动作见[TODO](TODO.md)，尚未落实的抽象见[未决问题](未决问题与机制候选.md)。

## 9. v0 明确不做什么

- P 自动学习或人格塑形；
- 多角色复杂关系、ToM、关系图动力学；
- PCC/PDS 或 persona-drift critic/repair；
- 开放世界、完整 Galgame 自动抽取、无限动作生成；
- 在线 LLM API 的异步 worker、请求合并/成本控制、超时重试与面向玩家的滞后世界呈现；
- “行动酝酿/准备中”层：它是可能有价值的后续决策机制，不在 v0 中与 `S` 或 `D` 混写；
- 人类心理学全覆盖或“真实人格”宣称；
- 用 demo 的存在替代可判定实验。

这些可以在主线机制被证明有用后再讨论；当前不应吞掉状态更新、行动分布和验证问题的注意力。
