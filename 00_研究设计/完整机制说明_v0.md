# Character Dynamics：完整机制说明 v0

更新时间：2026-09-02  
状态：**当前机制总说明。接口、范围与用户确认的设计决定已收束；变量选择、更新公式、文献归因、实现和实验收益均未验证。**

本页把当前分散在机制骨架、精读决策与最小环境构想中的内容合并成一个可连续阅读的机制说明。它是研究/编码前的共同语义，不把 `W/O/X/S/D/P` 本身当作新颖性主张，也不替代[原始对话](../90_原始材料/README.md)。

## 1. 课题要解决的事

第一版只追问一个问题：

> **在受限信息下，持续更新的角色状态能否保留历史中对未来行为有用的后果，并据此产生更可检验的行为分布？**

因此它不是“让 NPC 看起来像人”的泛目标，也不是完整世界模型、通用心理学或任务 Agent。系统必须能在受控世界中：

1. 区分世界实际发生了什么、角色知道什么、角色自身如何变化；
2. 用持续维护的状态产生此刻的条件行为分布，而非每轮用 persona 加全历史重新猜；
3. 在叙事回放中用下一真实行为检验该分布；在自主运行中让同一分布驱动行动；
4. 保留足够的来源链，以便重放历史、干预信息、替换更新器和做消融。
5. 在主验证成立或至少不劣的前提下，比较结构化状态与 raw history/强 summary 的上下文、调用、延迟和控制成本；这是一条部署评价线，不替代主验证。

预测是检验状态是否保留有用历史后果的主尺子，不是项目唯一目的；NPC 运行和创作辅助是同一个前向机制的另外两种用法。效率—效果与可控性是并行的第二评价维度：若质量相近，结构化状态是否减少 token、调用、延迟和长期运行成本，并支持更可靠的局部干预、信息权限、回放和调试；它不能替代 Replay/干预证据。

## 2. 一眼看完整运行链

```text
外部事件 / 时间 / 上次行动
             ↓
        W：权威可执行世界
             ↓
     SceneFilter：角色所在场所的候选变化
             ↓
 PerceptionFilter：可见、可听、注意到、收到的信息
             ↓
    ΔO / O：角色持续维护的主观世界视图
             ↓
   X：此变化对该角色意味着什么（Appraisal）
             ↓
 S：每个字段按自己的动力学更新
             ↓
 D：本轮由 O/S/P 临时得出的决策上下文
             ↓
  π(A^char | O,S,D,P,A^O)：人物级动作的条件分布
             ↓
       选择 / 采样一个 A^char
             ↓
 A^char 展开为一组世界原子操作 a^world
             ↓
        W 校验、结算、记录后果
             └────────────────── 回到下一轮
```

`P` 不在链的某一个单点“出现”。它是长期人物响应参数，调制 `O→X` 的解释倾向、`X→S` 的更新幅度/时间尺度，以及 `S→D→A` 的行为表达。

## 3. 每类量的语义与所有权

### 3.1 `W`：权威、可结算的世界

`W` 是运行时认定为真的外部事实和规则，而非任何角色的心理档案。v0 的 W 至少包括：

```text
time / external schedule / external events
scene membership and spatial/environmental state
objects and object properties
character location, pose, held items, ongoing activity
world rules, action preconditions and effects
```

例子：门是否开着、手机实际在哪里、角色是否在床边、当前时间、DDL 剩余多久，均属于 W。W 拥有最终 action 合法性和效果结算权：角色提出动作，不直接改写 W。

### 3.2 `Scene`：局部世界更新和 affordance 的共同边界

`Scene` 不是为了代码好写才加入的容器。它同时限制两件事：

```text
W → SceneFilter → 候选观察流
W^scene → AffordanceResolver → A^W
```

角色在宿舍时，食堂椅子的位置变化不需要进入其候选观察流；宿舍门开合、手机收到消息则可能进入。场景还给出该局部世界目前真实支持的动作空间。它避免全局扫描，也把信息局部性、动作空间和世界结算连接到同一对象/场景本体。

小房间 demo 的对象层级进一步固定为：

```text
W → Scene(home) → Room(student room) → Object(phone / bed / desk / ...)
```

`Room` 是 `Scene` 内的场所容器对象，拥有室内 Object 的集合和灯光、温度等局部物理状态；手机、床、桌子、门等才是 Room 内的具体 Object。这个层级只是 v0 世界表示的可替换实现约束，不把“Room 类”本身误作研究机制或对未来所有场景的唯一建模法。

### 3.3 `O_i`：角色 i 的持续主观世界视图

`O_i` 不是“本帧看见的东西”，而是 i 持续保存的一份世界副本。每个字段原则上可带：

```text
value | known / unknown | confidence | source | observed_at | stale_at
```

它允许旧值继续保留、置信度下降、显式 `unknown`，以及被新证据修正。基础刷新优先交给程序：新信息、环境暴露、消息抵达、感官可及性和时间过期。复杂的社会含义推断可作为候选 LLM 工作点，但必须输出受 schema 限制的更新，不能把 W 的真实事实泄漏给角色。

`W ≠ O_i` 是机制必要条件：同一件事的真实原因、角色看到的表面、角色后续的解释可以不同，从而允许误会、隐瞒、陈旧认知和信息干预。

### 3.4 `X_i`：事件的结构化意义 / Appraisal

`X_i` 回答的不是“状态应该加多少”，而是：**这次 `ΔO` 对 i 意味着什么？** 它把开放事件解释与状态动力学分开：

\[
X_t^i=I(\Delta O_t^i,O_t^i,S_t^i;P_i).
\]

它的候选维度可包括目标相关性、目标一致/冲突、可控性、意外性、不确定性、责任归因或社会拒绝线索；v0 的最小 schema 尚未由论文决定。LLM 可以在这里做开放语义解释，但输出必须是结构化的 `X`，不能直接写“焦虑 +0.3”。新证据可重新解释旧事件，因此 X 也为 re-appraisal 留出接口。

### 3.5 `S_i`：角色自身、会持续变化、且对行为有用的状态

只有同时满足以下条件的量才进入 S：

1. 语义上只属于角色 i；
2. 需要跨轮保存；
3. 此时仍可能改变；
4. 保存它有望改善后续行为预测或干预判断。

S 不是一坨“心理档案”，也不等于情绪集合。当前候选类别是：

| 类别 | 候选例子 | 作用 |
|---|---|---|
| 慢状态 | 持续压力、自我效能、长期动力 | 保存长期但仍可改变的后果 |
| 目标/动机 | 候选目标、目标投入、需求、回避/接近 | 形成当前可能想解决的事 |
| 承诺状态 | intention、终止/失败/重新考虑条件 | 防止人物每轮重置行动方向 |
| 即时状态 | 情绪、疲劳、紧迫感、注意力、认知负荷 | 对近期事件和时间做出响应 |

时间尺度不是一套硬分层本体论。每个字段 `s^k` 自己带动力学：触发、累积、恢复、衰减、饱和、重评估、值域和 P 调制都可不同。

\[
s_{t+1}^k=U_k(s_t^k,X_t,\Delta t;\theta_k(P)).
\]

具体字段、`U_k` 公式和字段间耦合目前均未定；它们将由机制文献和最小实验收缩，而不是为“完整心理学”不断加项。

### 3.5.1 历史、状态与外部日志不能偷换

原始历史不是 v0 policy 的隐形第四份输入。它被保存在 replay/provenance 日志中，用于评测、重放、干预和 `raw-history` 基线；人物运行时的历史后果应当经明确的 `O`、`S`（未来才可能有 P）留下来。若后来引入 memory retrieval，也必须把它命名为单独模块，声明检索来源、写入位置与 policy 输入，不能在 prompt 中悄悄重新塞入全历史。

### 3.6 `P_i`：长期人物响应参数

P 不是人物小传，不是“内向所以不说话”的硬规则，也不与 O/S 直接并列成三段 prompt。它是反应函数的长期参数，例如：

```text
rejection sensitivity | emotion inertia | stress recovery rate
task-start threshold  | risk preference | self-control
conflict avoidance    | decision noise under pressure
```

它可控制相同 `X` 产生多大状态变化、状态如何恢复/累积/衰减，以及相同 S 怎样表现成行为。未来可尝试阈值、饱和或平滑反转，而不仅是线性权重；但目前不承诺某个函数是心理学正确的。

v0 固定 P：

\[
P_{t+1}=P_t.
\]

这里的“固定”只指**同一次运行中**不让日常经历任意重写 P。实验可以在不同 run 设定不同 P 配置，而保持初始 W、事件 trace 与其他条件相同，观察由参数差异形成的不同状态—行为轨迹；这正是 P 作为人物响应差异而非小传标签的可观察方式。“长期行为—世界后果—状态轨迹慢慢反塑 P”则是保留的后续假设，不是 v0 模块。

### 3.7 `D_i`：本轮决策上下文

`D` 是从当前 O、S、P 临时算出的决策量，而非所有影响动作的东西都塞进 S：

\[
D_t=H(O_t,S_t,P).
\]

例如有效谨慎度、此刻冲动性、决策噪声、犹豫或规划深度。D 随本轮决策结束而消失；只有需要跨时间保存并对未来有预测价值的量才提升为 S。

### 3.8 多角色关系：已定语义，暂不进入 v0

多角色时，`A→B` 与 `B→A` 是不同的、稀疏的角色关联状态，可包含关系类型和少量数值（如信任、亲近、怨恨），而不是一大段自然语言。实现上可以置于 runtime 的中央有向图以便查询；语义上仍属于角色侧 `R_i[j]`，不能当作 W 的上帝视角心理真值。单角色最小环境不实现该层。

## 4. 一轮运行到底发生什么

### 步骤 0：事件、时间与决策边界

时间、外部消息、DDL、脚本实体或上一动作的后果更新 W，并产生带来源的 `ΔW`。它们首先是世界变化，尚未自动成为角色已知信息。

数据流不等于“每个原子世界操作都让人物重新思考”。v0 应按事件、时间 tick、动作完成或预先声明的决策时点触发后续 operator：`ΔW` 只进入受影响的观察/状态支路；没有新事件时，只有依赖 `Δt` 的字段运行恢复或衰减。究竟哪些事件触发一次 policy、组合动作能否中断，属于需要在每个实验场景配置中冻结的执行语义，当前还未指定唯一规则。

### 分层时间维护：不是一只“全系统 tick”

demo 维护一个可比较的全局模拟时间和事件队列，但**不同系统、乃至同一系统的不同字段，都可以有各自的更新触发与周期**。它们不应因为一个秒级 tick 到来就整套重算：

| 部分 | 典型触发/周期 | 不应发生的事 |
|---|---|---|
| `W` 的时钟、光线、外部事件、动作持续与结算 | 固定世界时间步、排程事件、动作开始/完成 | 非相关世界字段被重写 |
| `O` 的直接观察、消息和 exposure 刷新 | 信息抵达或场所/注意变化；可另设局部陈旧检查周期 | 全量复制 `W` 或强行同步 |
| `O` 的 stale / `unknown` 维护 | 各字段自己的过期规则或低频审计 | 把旧信息一律删除 |
| `S^k` | 每字段自己的事件触发、恢复/积累周期或 `Δt` 更新 | 所有情绪、目标、疲劳以同一速率更新 |
| `D` 与 `π(A)` | 预设决策点、动作完成、目标失效/满足，或真正影响选择的事件 | 每个 world primitive 都重新做完整人物决策 |
| UI / provenance 日志 | 渲染频率或状态变更时记录 | 以 UI 刷新驱动人物动力学 |

具体周期是 demo 配置，不应现在拍脑袋写死为心理规律。每次更新须记录实际模拟时间、触发原因、受影响字段和使用的 `Δt`，从而可在回放中复现“同一时间维护策略”并把调度策略本身作为可替换的实验条件。

### 步骤 1：场所筛选和感知筛选

用户已确定 Scene 是 W→O 的第一层场所边界，也是 `A^W` 的基本单位。v0 进一步采用 PerceptionFilter：SceneFilter 选取与角色当前场所、通信通道或明确跨场所机制有关的变化；再依据可见性、遮挡、听觉、注意力、睡眠/活动状态等决定哪些内容成为 `ΔO`。每个小环境应把启用的感知规则写在配置中，不能把它们误说成已验证的心理规律。

```text
同一场景发生  ≠  角色一定知道
进入候选流      ≠  立即覆盖 O
```

未观测字段可保持旧值、陈旧化或转为 unknown。这里的输入边界保证 policy 不用上帝信息。

### 步骤 2：解释观测变化为 `X`

对进入 O 的关键变化，解释器结合 `ΔO`、当前 O、旧 S 和 P，给出结构化 X。它可有多种候选解释或置信度，但不能把自由文本直接变为最终心理状态。可重评估意味着：新证据出现时，可修订某次事件的意义，而不是只能继续累加它的第一次解释。

### 步骤 3：按字段更新 `S`

每个启用状态字段运行自己的 `U_k`。例如某状态可有触发和衰减，另一状态可累积和恢复，目标可竞争，intention 可维持直到满足重新考虑或失败条件。更新器应明确输入、输出、边界和来源，而不是一个不可追踪的总 `state_update(S)`。

### 步骤 4：生成 `D` 并维护目标—意图承诺

候选 goals 由关切、O 和 S 激活并竞争；选定的 intention 不应因每个小刺激立即消失。其通用模式是：

```text
Candidate → Selection → Commitment → Reconsideration
```

此模式也可迁移到解释和 O 的 belief revision；但每处是否实际采用、采用什么条件仍待后续确定。

### 步骤 5：解析可行动作并形成行为分布

先从 W/Scene 得到世界客观可执行集 `A^W`，再依据 O 得到角色知道或能设想到的 `A^O`：

\[
\pi(A^{char}\mid O,S,D,P,A^O).
\]

对象拥有基础 affordance 和依赖的局部状态；场景可注册少量组合人物动作与出口转换。更精确地说：Object 提供 affordance fragments，Scene/Room 结合对象、地点状态和出口组成 `A^W` 候选，W 负责跨对象 precondition、最终合法性与结算。`ActionType` 是跨层共享的领域值，不是某一个类的“子动作”；角色 policy 只能在 `A^O` 里评分/选择，W 最终仍检查 `A^W`。动作设计的顺序是**现实场景/对象/状态/出口在前，动作在后**：先把一个真实可理解的小房间及其自然延伸场所放进 W，再从床、桌子、电脑、手机、灯、门及其状态中识别自然活动；而不是为了凑 action list 反向添加物品。

### 步骤 6：执行人物级动作、结算世界后果

人物决定的动作具有行为意义，例如“上床玩手机”“坐桌前学习”“关灯睡觉”，并不等于引擎的一次状态修改。一个人物级动作可展开为多个原子操作：

\[
A^{char}\rightarrow[a^{world}_1,a^{world}_2,\ldots]\rightarrow W'.
\]

因此人物动力学不会在走到床边、躺下、拿手机的每一步重新做完整心理决策；世界仍按原子效果更新对象和角色状态。v0 必须为每个组合动作声明：执行区间、原子效果序列、失败/中断语义，以及这些效果是否在本轮合并结算；不能由未声明的引擎行为决定研究结果。

角色知道自己提交了什么动作、以及哪些后果，必须也走显式的自我行动/感知通道写入 O；它不能因为系统已在 W 结算，就自动知道所有远端或不可观察的世界后果。

### 步骤 7：记录 provenance，进入下一轮

每轮至少可追到：

```text
event / ΔW → information access → ΔO → X → StateDelta / S
→ D → action distribution → chosen action → world outcome
```

这既是调试接口，也是后续回放、信息干预、更新器替换和消融的前提。

## 5. 动作粒度与小房间实验床

v0 使用一个小房间或相当小的 Scene、一个主要角色、有限对象和十几个高质量动作。典型对象可以是门、床、桌子、椅子、手机、灯；环境变量可包括时间、DDL、消息、光线和少量外部事件。

对象动作示例：开/关门、坐/躺、查看消息、使用手机。场景组合动作示例：上床玩手机、坐桌前学习、关灯睡觉。组合动作不是“作弊”：场景只是显式定义受控世界中哪些行为对角色有意义；项目研究的是状态怎样改变这些已给定行为之间的条件分布，不是生成现实世界的一切动作。

该环境首先是可回放、可干预的实验床；它将展示连续数天中的时间、行为和 `O/X/S/D` 的可追踪变化。成为 GitHub 演示或现代 C++ 学习项目是后续使用方式，不反过来主导研究问题；用户将自行在独立 coding 会话中实现，不在当前研究会话继续编码。

## 6. 程序、LLM 与可替换模块的分工

| 职责 | 当前优先承担者 | 边界 |
|---|---|---|
| W 状态转移、precondition、effect、时间结算 | 程序 | 角色不能直接绕过 |
| Scene/Perception、O 的直接刷新、陈旧/unknown | 程序 | 复杂社会推断可另设受限算子 |
| `X` 的开放事件意义解释 | LLM 候选 / 规则候选 | 输出受 schema 限制；不是直接改 S |
| 每字段 `U_k`、数值边界与时间演化 | 程序/明确理论算子 | 必须可追溯、可替换 |
| 行为候选与偏好 | LLM、规则或混合均待比较 | 只能在 `A^O` 内，不能绕过 W |
| 日志、回放、干预、消融 | 程序 | 每轮保存完整配置与来源 |

这是一份工作划分假设，不是对 LLM 优势或方法新颖性的结论。

## 7. 三种运行模式与评测位置

| 模式 | 在 `π(A)` 后发生什么 | 目的 |
|---|---|---|
| 回放/评测 | 暂停，映射真实下一行为 `A*` 后对照概率/排名 | 检验状态是否有行为预测价值 |
| 自主运行 | 从分布中选择或采样 `A^char`，交 W 执行 | 使角色在受控世界继续活动 |
| 创作辅助 | 呈现候选、倾向和可追溯状态理由 | 供作者采纳、拒绝或补写转折 |

真实行为 `A*` 是评测接口，不得提前泄漏为自主循环的输入。后续评测还可比较同一世界不同可知信息、同一终局不同历史，观察分布变化是否符合预先写定的干预预期。

## 8. 低耦合、消融与数据流要求

每个状态模块/更新器必须声明：字段、时间尺度、输入 operator、输出接口、provenance 和关闭方式。关闭不是机械地赋值 0；只有 0 对该字段确有中性语义、且不存在政策旁路时才算消融。其他情况应禁用更新器、移除 policy 输入或使用明确 baseline。

同一 trace 应能在不同配置下重放，至少记录世界、可知信息、`X`、状态变化、动作候选/分布、选择、世界后果、随机种子和启用模块。详细实现约束见[原型实现与消融接口原则](原型实现与消融接口原则.md)。

## 9. v0 明确不做什么

- P 自动学习或人格塑形；
- 多角色复杂关系、ToM、关系图动力学；
- PCC/PDS 或 persona-drift critic/repair；
- 开放世界、完整 Galgame 自动抽取、无限动作生成；
- 在线 LLM API 的异步 worker、请求合并/成本控制、超时重试与面向玩家的滞后世界呈现；
- “行动酝酿/准备中”层：它是可能有价值的后续决策机制，不在 v0 中与 `S` 或 `D` 混写；
- 人类心理学全覆盖或“真实人格”宣称；
- 用 demo 的存在替代可判定实验。

这些可以在主线机制被证明有用后再讨论；当前不应吞掉状态更新、行动分布和验证问题的注意力。

## 10. 还必须由文献和实验回答的四个问题

1. `X` 的最小 schema 应含哪些 appraisal variables？
2. 第一版保留哪些 `S` 字段；每个 `U_k` 怎样定义触发、恢复、累积、边界与 re-appraisal？
3. `P` 的哪些参数真正应该调制哪些更新器和 policy？
4. goal/intention 的 activation、commitment、failure 和 reconsideration 条件如何可计算、可验证？

每篇精读文献都按“输入/观察 → 状态 → 更新 → P 的位置 → action 接口 → 验证”回答；每个最终选择都必须能在最小世界中对应一个可比较的预测、校准或干预结果。
