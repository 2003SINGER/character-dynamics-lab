## 1. 已确认的设计决定

本次没有改写 `W → O → X → S → D → π(A^char) → W` 主链，而是修正它内部三种时间尺度的混淆：

```text
WorldTask：客观、长期、可推进/完成的任务对象
TaskCommitment：角色当前对某 Task 的持续承诺或暂停
ActionType：每轮只做一次的具体单步行为
```

`StudyAtDesk` / `StudyAtComputer` 仍是单步 action；它们不再等价于“任务本身”，而是一次会结算连续 effort 的学习 session。v0 仅有一个 `coursework` Task；不在本轮引入多 Task 竞争、规划树、多步宏动作、在线 LLM 或人格可塑性。

## 3. 当前机制缺口

### 3.1 已加入最小 reconsideration gate；尚未成为规划

暂停承诺现在仅在 O 已知 task 为 `active`、O 已知至少一种学习 action，且疲劳/饥饿/如厕需求低于 v0 门槛时，才给学习动作 commitment bonus；否则日志明确标记为 `defers return`。这修复了 `Suspended` 只作标签的错误，但仍不是 goal reconsideration：尚不比较替代目标、不表示 task failed/abandoned，也不学习恢复阈值。

### 3.2 Task 的 O 边界还没有接受检验

当前房间 demo 会直接将每项 Task 的 effort/status 写入 O。已修复 `coursework_pending = !known(completed)`：现在只有 O 已知 `active` 或角色已有该 task commitment 时，才作为未完成任务处理；未知/stale 不再被偷换为“已知未完成”。但同房间直接观察的假设本身仍未接受信息遮挡干预。

最小干预应固定 W 为已完成，分别让完成确认对角色可见或不可见/stale；前者才应产生 completion relief，后者不应凭空解除压力。

### 3.3 单一 Task 允许暂时省略 target，但接口不能永远依赖隐式选择

当前 decision 对 `"coursework"` 有硬编码，World 对一个学习 action 取第一个支持它的 active Task。这在单 Task v0 可运行，但多项都可由 `StudyAtDesk` 推进时会产生目标歧义。

多 Task 之前，应升级为 `A^char = { ActionType, target_task_id }`，并让 reminder、commitment、effort settlement 与 outcome 都带同一 task id。现在不实施多 Task；只把它列为接口门槛。

### 3.4 S 尚未明确影响已开始学习的质量

疲劳、焦虑和屏幕疲劳目前主要改变“是否选择学习”，而 task effort 主要由 W 的 base effort、时长、打断和 seed 决定。状态差与状态好的人一旦选到同一 action，产出差异很小。

不能让 W 偷读所有 S 后暗中修改 effort。若要模拟同一 session 的质量差，需增加可追踪桥：

```text
S + commitment + O → TaskEngagement / ActionQuality → A^char payload → W effort settlement
```

它必须有明确字段、来源和日志，避免把世界因果与人物状态所有权混在一起。

### 3.5 task_pressure 与 anxiety 的语义过载、完成 relief 过硬

`task_pressure` 同时承载 deadline、未完成任务、拖延、自责、提醒和休息时的未完成感；完成时又以固定大幅 delta 解除。它修复了饱和，却无法表示“任务已完成但仍疲惫、亢奋或有残留压力”。

最小候选拆分是：

```text
goal_pressure：特定未完成 Task 的进度/截止压力，完成后可显著解除
residual_arousal/general_stress：累积紧张与恢复负担，完成后缓慢衰减
```

焦虑也不应只是 reminder 加常数再乘 `task_anxiety_sensitivity`。后续 X 应优先实验 goal relevance、urgency、progress discrepancy、controllability、expected coping 等中间 appraisal，而非增加更多未定义情绪数值。

### 3.6 P batch 是压力测试，不是人格效应证据

32 个独立均匀随机 P 和 8 个 scenario seed 能发现崩溃、饱和、接口断链和极端轨迹；不能支持真实人格机制结论。字段在现实中未必独立，规则已预埋方向，且 scenario 同时改变 deadline、目标 effort 和日程。

下一轮应以受控干预替代“更多随机人”：固定世界、P 与 action seed，只改变 completion visibility、deadline、fatigue 或 interruption；或固定世界和 seed，只改变一个 P 维度，记录 `ΔX / ΔS / Δπ(A) / Δcommitment / Δeffort`。

### 3.7 Action appraisal 仍然近似动作本质论

当前 `UsePhone`、`StudyAtDesk`、`RestAtBed` 等主要对应固定正负 delta。同一动作在不同目标、时机、是否取得进展、是否自愿或是否连续重复下应有不同意义。后续 LLM 或规则升级的合理位置是 `ΔO + O + old S + P → X` 的结构化解释候选，而不是直接代替 W 或整个 policy。

## 4. 推荐顺序

1. 先做单一 coursework 的 O 信息干预，并将当前最小 Suspended gate 扩展为可比较的 resume / continue defer / abandon 实验条件；
2. 再定义 action-quality/engagement 的最小、可追溯桥；
3. 用目标完成、压力恢复、行动控制/commitment reconsideration、appraisal 的文献约束 X 与 S 的具体规则；
4. 通过受控干预收缩 P 的作用位置和强度；
5. 只有 task id 穿过 action、outcome、O 和日志后，才引入多 Task 竞争。

上述顺序保持课题锚：检验持续状态是否保存对未来行为有用的历史后果；不让任务系统扩张成独立的通用规划项目。
