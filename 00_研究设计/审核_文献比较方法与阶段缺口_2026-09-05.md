## §0. 先认错：我这几天一直在犯用户已经指出的那个错误

调研稿里用户两次爆发，两次都是同一个问题：

> 「tmd每次让你找你都会说，唉，我查了一圈叉叉叉不是你的创新点啊，我他妈这几天已经听过几十次你这样说了」

> 「你总是混淆一些概念……你去别的人的论文那里找到一个客观世界就说重合呢。Tm的**具体机制完全不是这样的**。」

**这正是我这几天一直在做的事。** 具体证据：

| 我说过的话 | 问题 |
|---|---|
| 「状态→分数→采样、承诺惯性、目标分桶、SmartObject、前置条件校验这五项在 2005–2013 年 utility-AI / GOAP 中已是标准实践，**不得再作为新颖性主张**」（T18） | 概念标签层比较 |
| 「`W ≠ O` **已被 Talk of the Town 覆盖**」 | 概念标签层比较 |
| 「二阶知识 TimeToM 已做」 | 概念标签层比较（且查自己库后发现有歧义） |
| 「六条 Gap 中 Gap 1a/4 不成立」 | 虽是立场判断，但同样在标签层 |

**用户的批评是对的，而且直接适用于我。**

### 错误的结构

```
具体机制 → 压缩成概念标签 → 找同标签的论文 → 宣布重叠
```

**任何一个概念都能被拆成别人做过的零件。** 顺着这条路走，结局一定是研究问题被削成针尖，或者干脆认定自己什么都没得做。

### 正确的方法（用户稿里给的，我照抄并落地）

```
具体机制 → 抽取接口和因果角色 → 把对方也抽到同样粒度 → 逐项比 → 才判断
          相同 / 部分相同 / 互补 / 实际不同
```

> **只有当"输入、输出、更新方式、因果位置、实验作用"都高度相似时，才有资格说"这个机制已经被做过"。**

## §1. 【新规则】文献比较必须逐项填这 13 个维度

从调研稿提取，定为本项目**强制比较模板**。以后任何"X 已被 Y 做过"的断言，必须附此表，否则无效。

| # | 维度 | 说明 |
|---|---|---|
| 1 | **表示什么** | 它到底存的是什么 |
| 2 | **谁拥有它** | 角色私有 / 世界 / 系统 / 无主 |
| 3 | **它从哪里来** | 输入源 |
| 4 | **谁能修改它** | 写入权 |
| 5 | **它什么时候更新** | 触发时机 |
| 6 | **它的输入是什么** | |
| 7 | **它的输出是什么** | |
| 8 | **它位于因果链的哪里** | ⭐ 最关键 |
| 9 | **它是否跨时间保存** | |
| 10 | **它是否参与动作选择** | |
| 11 | **它是否参与世界结算** | |
| 12 | **它能否被角色错误地认知** | |
| 13 | **它在实验里到底验证什么** | ⭐ 最关键 |

### 输出格式（强制）

```text
模块：W

你的机制：[完整描述]

论文 A：[完整描述]

表面相似：都表示外部状态

关键差异：你的 W 是权威结算层，并通过 O 隔离角色认知；
          A 的 world 只是 planner state，角色直接访问。

因此：概念重叠，但机制位置和职责不等价。
```

**注意最后一句的措辞**：是「概念重叠、机制不等价」，不是「已被做过」。这两句话差得非常远。

### 举例说明为什么这很重要（取自调研稿）

两个系统都有 `World`：

| | 我们的 W | 另一系统 |
|---|---|---|
| 输入 | 外部事件、上一动作、时间 | 当前 planning state |
| 输出 | ΔW、候选观察、A^W、世界后果 | 下一 planning state |
| 所有者 | simulation/runtime | planner |
| 角色能否直接读 | **不能** | 能 |
| 角色能否直接改 | **不能** | — |
| 作用 | 真实世界 + action validator + consequence layer | 规划变量 |

→ **结论只能是"都使用世界状态这个抽象，但机制职责不同"**，不能说"你的客观世界别人已经做过"。

同理，`appraisal` 也不能因为别人也叫 appraisal 就判重合——要问：输入什么、输出什么、直接决定 emotion 还是影响 action utility、是否结构化、是否允许 re-appraisal。

## §2. 【冻结】母问题——不再继续削窄

用户明确指出：**每查到近邻就缩一刀，是错误循环。** 从现在起冻结母问题：

> **Character Dynamics：让角色通过持续更新的状态保留经历的后果，并让这些状态实际影响未来行为。**

### 新判断规则（两条，只判断这两条）

任何新想法（Object 挂 affordance、Scene 管局部世界、NPC 对玩家后果响应、P 产生不同轨迹、O 保留陈旧信息……）**只问**：

1. **它是否服务于已冻结的母问题？**
2. **它是否让系统更可检验 / 更有用？**

**不再逐条做 novelty 审判。** 整体创新边界只在专门做"相关工作定位"时一次性判断。

> 连带处理：我此前基于"查到近邻"写下的若干"不得作为新颖性主张"的条目，**需要按 §1 的 13 维模板逐条重审**。在重审完成前，它们**暂停作为约束力**，只作为提示。这一点已同步到 T18。

## §3. 调研稿里的方向候选（记录，不是已定方向）

用户在对话中推进到过一个具体角落，值得保留，但**按 §2 规则，不做 novelty 审判，只记为候选**。

### 三条路（用户与另一 AI 达成共识）

| 路 | 内容 | 状态 |
|---|---|---|
| **A** | 角色一致性检测 / next-action prediction | 科学主线 |
| **B** | 游戏 NPC 驱动 | 应用 |
| **C** | 社会模拟 / agent society | **明确排除** |

### B 路里用户倾向的角落

> **不是做"会聊天的 NPC"，而是做"会承受世界后果并持续回应的 NPC"。**

关键链条（这确实是 W/O/X/S 的直接应用）：

```text
Player Action
    ↓
ΔW：世界真的变了
    ↓
NPC 不一定立刻知道
    ↓
经过 Scene / Perception
    ↓
在 t+τ 时刻形成 ΔO_i        ← 她只知道"药不见了"，不知道"玩家偷了"
    ↓
X_i：这件事对我意味着什么
    ↓
S_i 持续改变
    ↓
未来若干次决策 π(A) 都受影响
```

**与"NPC 记住玩家偷过东西"的区别**：这里研究的是
`world consequence → belief acquisition → appraisal → persistent behavioral adaptation`
而不是 `player event → reaction`。

### 小房间 demo 的可能改造

从「小人自己在房间里生活」改为「**玩家可以偷偷改变房间**」——拿走手机、移动物品、关灯、留下食物、破坏电脑、锁门、留消息。然后测：

> **NPC 什么时候发现？它到底知道了什么？这个后果怎样改变它之后几小时的生活？**

同一次干预换 P，看不同角色的不同反应。这确实能让 `W/O/X/S/P/D/A` 每一层都有明确意义。

### 三个候选 RQ（记录，未决）

1. **世界媒介化是否有必要？** 相比"把玩家事件直接喂给 NPC"，`Player → W → O_i → X_i → S_i` 能否在隐藏行为、延迟发现、错误归因等情境中产生更正确的响应？
2. **能否减少 bespoke authoring？** 作者只定义对象状态/affordance/角色字段，不为每种组合写 reaction rule，能否覆盖未专门编写的世界后果？
3. **状态是否产生长期价值？** 相比 direct-LLM / event-script 基线，持续 S 是否让数小时/数日后的动作仍反映过去的世界后果？

### LLM 的位置（这个提法值得记住）

> **LLM 作为「开放世界事件 → 有限角色动力学变量」的语义压缩器。**

不是让 LLM 每轮决定"下一步干嘛"（太普通），而是让它解决一个具体的语义接口问题：
`(\Delta O_i, O_i, goals_i, S_i, P_i) \rightarrow X_i`
——**一个开放的世界变化，对这个特定角色"意味着什么"？**

且 LLM 只能吐结构化 `X`，不能直接写 `anxiety += 0.7`。这个边界我们机制说明里本来就有。

### 4.3 `awesome-research-agents`（6 大能力分类）

`Scientific Discovery` / `Idea Generation` / `Literature Review` / `Research Engineering` / `Paper Writing & Presentation` / `Research Assessment`。

代表项目：`AI-Scientist`（端到端）、`gpt-researcher`（文献）、`AIDE` / `MLE-Agent`（实验工程）、`CAJAL`（写作+模拟评审）、`Dr. Claw`（全栈工作台）。

相关 benchmark：`CORE-Bench`（计算可复现性）、`PaperBench`、`EXP-Bench`、`RE-Bench`、`Dr. Bench`（深度研究报告质量）。

**对我们的用处有限**：这些是"**让 AI 自己做科研**"，而我们需要的是"**帮人做科研的工作流**"。可以借鉴的是它们的阶段划分与可复现性标准。
