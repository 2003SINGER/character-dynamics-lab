# 从原始对话到研究空间：筛选整合（不替代原文）

更新时间：2026-09-02  
状态：工作底稿。它从原始对话中筛出仍应保留的推理与分支，并接上当前文献证据；原文优先于本页，模型提出的论断不自动成为用户结论。

## 一、先把“你在想什么”放回正确尺度

你不是在选“做游戏”还是“做论文”，也不是把一个系统缩成单一心理变量。这里有四个同时存在、但不该混为一谈的尺度：

| 尺度 | 你关心的内容 | 现在是否要一次做完 |
|---|---|---|
| 长期愿景 | 人物在经历、局部世界与他人互动中改变；其行为既可解释又可预测，并可部署为 NPC | 否 |
| 研究纲领 | 动态人物行为一致性：何为合理变化、如何预测、如何验证 | 否 |
| 可切分问题 | 状态表征/更新、信息边界、行为分布、反向状态推断、漂移失败、多主体社会动力学 | 一次只取一项或一组紧耦合项 |
| 工程载体 | 受控世界、回放器、日志、行为集、世界生成、游戏 UI | 只做到支撑当前检验所需 |

因此，**收束的是一次可否证实验，不是你的整个好奇心。** 世界 seed、时间自然演化、游戏、多个 NPC 与社会涌现都不是被删掉的想法；它们是不同阶段的系统分支。

## 二、不可丢失的系统直觉：双状态与受限接口

你最早反复强调的不是“加心理学”，而是权威世界、角色世界视图与角色自身状态不能混写：

\[
W_{t+1}=G(W_t,A_t,E_t,\Delta t),\qquad O_{t+1}^i=M_i(O_t^i,W_{t+1},\text{information access})
\]
\[
\Delta S_t^i=F(\Delta O_t^i,S_t^i;P_i),\qquad S_{t+1}^i=U(S_t^i,\Delta S_t^i,\Delta t;P_i),\qquad A_{t+1}^i\sim\pi(O_{t+1}^i,S_{t+1}^i;P_i)
\]

- `W`：权威的可执行故事世界，含物体、身体、剧情事实、时间/事件后果、affordance 与多主体关系图；它必须可枚举、可验证，不能让 LLM 任意续写。
- `Oᵢ`：人物 i 维护的局部世界副本/估计。字段可陈旧、未知或附带来源与置信度；人物不因世界中存在某事实就自动知道它。
- `Sᵢ`：只属于 i 自身、当前仍变化且对未来行为有用的状态；包括但不限于慢性状态、目标/动机、即时情绪/认知/身体状态、临近决策状态。关系真值或“i 认为 B 怎样”分别在 W/O，而不塞进 S。
- `Pᵢ`：长期人物响应参数，调制 O→S、S 的维持与 S→A；不是人格小传或直接行为脚本。
- `A`：人物模型先产生候选与条件概率/排名；W 决定何者可执行并校验其结构化效果，不应从单个心理量直接跳到剧情结局。

已确认的职责拆分是：W/affordance 层产生并校验当前可执行性；人物层依 O/S/P 产生候选与偏好；程序或模型可选择/采样高分候选；动作带结构化世界效果但由 W 最终结算。`O` 的普通更新由信息流、暴露、局部刷新、过期/unknown 维护，复杂观察含义才可能委托给 LLM。LLM 的两个核心候选工作点是 `(ΔO,S,P)→ΔS` 的开放语义解释，和 `(O,S,P)→π(A)` 的行为生成/评分；规则、理论与学习模型在这些位置如何分工仍是实验比较，而非既定算法。

这是一条**研究母题与系统边界**，不是可直接宣称的新架构。尤其不能把 PsychSim 的 factored ground-truth decision state 与这里对象化、可执行、带 affordance 和观察接口的 `W` 混为一谈：前者直接覆盖 true-state/belief/decision 的部分骨架，后者仍须与 Generative Agents、AI Town 等分别按职责比较。FAtiMA/EMA、BDI 叙事也分别覆盖其中的重要组合；这条边界仍决定了你应怎样比较方法、避免信息作弊、以及如何把小说回放与 NPC 运行接起来。

数据流在此不是另起一个研究对象，而是实现该边界的工具：`world event → masked observation → StateDelta/operator → state → action`。它应保留来源和影响路径，以支撑重放、反事实干预、operator 消融和多时间尺度更新；“用了流/DAG”本身不构成贡献。

## 三、真正相连的研究问题群

### 3.0 预测是检验尺子；方法是具体计算链

`预测下一真实行为`、`回放`、`teacher forcing` 是评测或运行协议，不能替代模型机制，更不能成为以任务名查重后的唯一比较单位。要逐项追问：

```text
W 如何表示并产生 affordance / O？
O 如何被解释为 StateDelta？
稳定性格 P 如何调制 StateDelta？
P 与 S 怎样把同一组可执行动作变成不同概率？
真实 A* 与预测不符时，S 如何被修正？
```

这条链保留了用户确认的重点：小动作不是“低级版剧情动作”，而是人物状态持续显现的主要载体；`P` 不是 prompt 顶部的介绍，而至少同时影响“受事件后变成什么状态”与“同一状态怎样显现为行为”。

### 3.1 条件行为分布：一致性不等于重复

你的判准不是“真实动作是否唯一正确”，而是实际动作是否落在当时合理的条件分布中：

\[
P(A_t\mid S_t,O_t),\quad H(P(A_t\mid S_t,O_t))
\]

同一 0.08 概率行为，在平静、重复、目标明确的日常可能异常；在冲突、信息不足、多目标竞争下可能合理。这留下两个不能分开的判断：预测哪个动作，以及此刻人物应有多不确定。它不是把 temperature 调大，而是区分世界随机性、人物解释不确定性与决策随机性。

**证据位置**：BehaviorChain 等已做连续下一行为；DYNToM/Dynamic Persona Coherence 等已做动态心智或一致性。仍待严查的窄问题是：是否已有工作把“条件分布及其熵的校准”作为角色动态一致性本身来评估。

### 3.2 干预式评价：关心变化规律而不是一次“像不像”

对同一人物更换历史、对同一历史只改可知信息、对同一环境换角色、或固定其他随机源只改一个变量，检验：

\[
do(X=x_1)\;vs\;do(X=x_2)\Rightarrow \Delta P(A)
\]

例如长期受 B 帮助与长期被 B 欺骗，终局都为“B 请求帮助”，预注册的方向预期是前者的 `P(help)` 更高。这个思路同时依赖 3.1 的分布观与第二节的信息边界；不应降格成一句“做 counterfactual”。

**证据位置**：部分可观测、ToM、反事实评测与角色 benchmark 已相近；尚未完成系统查新，不能声明这是空白。

### 3.3 Predictive subjective state：历史应留下什么

状态不是史料库或 prompt summary，而要保留对未来行为有效的历史后果：

\[
P(A_{t+1}\mid H_{\le t},W_t)\approx P(A_{t+1}\mid S_t,W_t)
\]

这要求把 raw history、summary memory、显式状态、学习状态放在同一信息预算下比较。SyncStream 只提供“按预测代表性保留历史”的跨域启发，不能被改名成人物理论。

### 3.4 LLM 顺坡/过冲：先作为可被推翻的 failure mode

你的实际担忧是：LLM 擅长顺着负面叙事补全，轻度受挫可能被一路写成绝望，历史文本又反过来加重下一次解释。问题不是预设某个诊断标签，而是检验：

\[
S_t\rightarrow\operatorname{Interpret}(E_t\mid S_t)\rightarrow S_{t+1}
\]

是否产生不相称 state jump、单调负向漂移、framing amplification、恢复缺失、轻刺激过敏或过强路径依赖。只有这些现象在控制情境中稳定出现，惯性、恢复、边界、饱和、保护因素或 appraisal 约束才是有针对性的候选修复。

### 3.5 多时间尺度：是约束空间，不是预先选定的理论

情绪、压力、信任、习惯、稳定特质可能有不同的累积、衰减和突变方式；世界时间自然流逝也能触发恢复。这里不应把“快中慢三层”写成既定方法：Dynamic Persona Coherence 已使用多时间尺度。可问的是，在 3.4 的 failure mode 下，何种动力学约束实际改善预测、校准或干预响应。

## 四、你明确提出的 Forward–Inverse 对偶

### Forward：由状态预测行为

\[
(S_t,W_t)\rightarrow P(A_{t+1})
\]

小说/剧本可用真实时间序列回放：每步给真实已发生历史，预测下一真实行为，避免预测误差无控制地滚进输入；开放运行则让同一模型采样行为来驱动 NPC。

### Inverse：由真实行为或反馈修正状态

\[
(A_{t+1}^{*},W_t)\rightarrow P(S_t\mid A_{t+1}^{*},W_t)
\]

这将小说人物、长期用户交互、评分/点击/回复等理解为 latent-state estimation 的不同观测面。它不是“直接反向传播”这个实现承诺，而是可用贝叶斯、inverse planning、IRL、POMDP、拟合或其他方法实现的方向。

### 已知边界

PsychSim 已有主观 belief、以历史观察比较候选 mental model 的可能性、以及根据行为拟合目标权重。因此 Forward–Inverse 这一抽象回路不能主张新；但其 inverse 是在预设候选模型间 revision，不能直接等同于从长程角色轨迹估计并持续修正“最有助于未来行为预测”的动态状态。尚待单独查的是：自然叙事/长交互中，面向未来行为的最小状态估计、校准、干预验证和在线状态修正是否已有等价的完整实验。

## 五、从研究到系统：两种运行模式与长期分支

### 5.1 Replay / simulation 不是两个毫无关系的项目

```text
真实叙事：真实事件更新世界 → 回放/teacher forcing → 检验预测有效性
同一模型：状态与策略接口不变
开放世界：模型行动更新世界 → 生成 NPC 行为
```

前者有 ground truth，后者没有。连接它们是长期系统设计价值，不等于已证明同一模型在两侧都成立。

### 5.2 世界工程应可扩展，但不是第一阶段负担

保留的工程路线是：对象 ontology/affordance、`seed + runtime delta`、自然时间函数、事件队列，以及彼此独立的 `world_seed / simulation_seed / agent_seed`，使比较可以复现并隔离随机源。它们未来支持游戏和模拟，不应吞掉第一个研究实验。

这里还有两条不能遗失的工程原则：世界侧尽量由传统可执行程序维护，LLM 不应自由编造世界事实；并且世界规则、世界生成、运行时状态是三层不同东西。前者规定“可存在什么、如何变化”；seed 产生初始世界；运行时仅保存发生过的 `delta`，不能重新生成后抹掉角色行为和自然时间的后果。

### 5.3 多主体社会动力学是后期科学分支

误解可经行动转化为事实：B 未回复 → A 误判 → A 疏远 → B 反应 → 关系真实恶化。它连接 trust、reputation、self-fulfilling prophecy、group dynamics；当前不该被简化成一个 `relationship` 数值，也不应被塞进第一阶段。

### 5.4 叙事到有限实验世界是另一条可独立的技术线

若从小说自动抽取对象、状态、动作与信息遮罩，需单独承担抽取正确性和 ontology 完备性的研究责任；在人物实验中，它应先是人工/半人工受控输入，而非免费获得的前处理。

### 5.5 可替换、可回放的数据流是实验地基

事件、可见信息、解释、`StateDelta`、状态、动作、世界后果应保留 provenance，便于回答“哪段历史导致当前不信任/行为变化”、替换一个算子、移除一个事件做反事实，以及定位错误。数据流本身不是论文贡献；它是让 3.1–3.5 的对照、消融、回放和负结果可复查的条件。

## 六、什么必须被过滤掉

- “这些点五星、很有前景、肯定能发”是模型判断，不是证据。
- Big Five、appraisal 名称、JSON 字段、某一更新公式、LLM/rule/hybrid 都只是可替换实现候选。
- 训练专用模型、高性能模型或端到端学习不是当前前提。原始设想允许先用通用 LLM 承担理解/候选生成/决策中的可替换部分；是否训练、何处使用 LLM、是否采用规则结算，都应由后续实验成本与证据决定。
- “世界 seed”“Godot”“地图”“多 NPC 聊天”不是当前 research question；但作为愿景和后期工程分支保留。
- 不能因为架构已被 PsychSim/FAtiMA/BDI 做过，就把整个问题空间扔掉；也不能因为自己有更完整的愿景，就把架构重述当创新。

## 七、当前最诚实的研究姿态

已确认：问题空间有真实的技术/理论先例，架构层面拥挤。  
仍值得保留：对“状态是否足以预测、何时该不确定、干预后是否按方向变化、LLM 是否发生可测顺坡”的具体实验关切。  
仍未证明：这些关切中是否有未被覆盖的、足以构成论文的窄问题。

下一次不应再问“整个想法是否新”，而应任选一条并做可复现查新：**它的已有任务、输入信息、状态是否学习/手写、动作空间、是否预测概率/熵、是否做干预、数据来源和评测到底是什么。**

## 八、已确认的研究推进方式：先造 v0，再由实验收缩

用户确认并非要把每个状态模块拆为独立论文，而是希望先做一个相对完整的 Character Dynamics prototype，再通过比较、粗消融和失败分析删掉无用模块或修改更新机制。这是允许的研究过程；约束是所有模块必须服务同一主张：**持续更新的角色状态是否比 raw history / 普通 summary 更能保留对未来行为有用的历史影响。**

操作上应将三件事并行而非串行：

1. 精读状态更新机制，固定统一比较卡：输入事件/观察、状态字段、更新算子、性格介入处、状态到动作的接口、恢复/累积/突变、评测；
2. 搭一个足够小的 `W/O/affordance/action` 测试场，同时跑 persona、raw history、summary 与 `v0 state`；
3. 用早期结果指导下一轮阅读和机制修改。正式大规模消融靠后，但小规模消融应尽早判断哪些信息或模块实际改变行为分布。

完整世界、丰富 NPC 和游戏 UI 保留为长期应用；它们不应阻塞这一最小闭环。

## 九、与动态用户意图跟踪的可迁移母题

用户报告，导师建议的方向涉及用户意图/目的在连续交互中的收敛、漂移、暂停与恢复。它与本项目不是同一应用：前者重点是从用户外部输入/行为估计 intent/goal，后者还需由角色状态生成行为并作用回世界。二者的可迁移部分是：

\[
\text{stream}\rightarrow\text{dynamic latent-state estimation/update}\rightarrow\text{future prediction}
\]

因此可并行吸收 intent/goal/dialogue-state tracking、dynamic user modeling、preference/concept drift 与 change detection 的状态维护方法；但不得把它们对用户意图的结论直接外推为角色情绪或关系的更新规律。
