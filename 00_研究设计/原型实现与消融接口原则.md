# Character Dynamics 原型：低耦合与消融接口原则

记录日期：2026-09-02  
状态：**用户确认的原型实现原则；不是已经验证有效的研究方法。**

## 要解决的工程问题

第一版不必因“论文最终可能删模块”而做成一次性、难改的脚本。应当尽早把角色链做成低耦合、可替换、可回放的原型：状态字段可先较丰富，后续以比较、消融和失败分析删除、合并或重写。

这服务于研究，而不是为了“架构完整”：每个模块都要能被单独关闭、替换或追溯，才能回答它是否真的改变动作分布。

## 最小接口链

```text
World event / time tick
  → observation mask
  → interpretation / StateDelta operators
  → CharacterState
  → affordance provider
  → action policy / distribution
  → world executor
  → provenance log
```

建议让每一段只接收明确输入、输出明确结果；`World` 不由角色 LLM 直接改写，角色只提交候选或选择后的 action，再由 world executor 检查并结算。

## 状态模块设计

每个候选状态模块（如 emotion、relation、belief、goal、attention、habit）至少应有：

1. **字段与时间尺度**：值域、初始值、恢复/累积/突变规则；
2. **中性语义**：何种值表示“该模块不偏向任何行为”，不默认把数值 `0` 误当通用中性；
3. **输入 operator**：哪些 observation/event 可改它，产生什么 `StateDelta`；
4. **输出接口**：它通过哪里、怎样改变 action distribution 或另一个明确状态；
5. **provenance**：哪一事件、哪个 operator、哪个旧值导致当前值；
6. **ablation switch**：关闭后，必须切断其更新和所有对 policy 的直接/间接影响，或明确改为中性值。

“把值设为 0”可作为一种消融方式，但只有满足中性语义与无隐藏旁路时才成立。对于文本状态、类别状态、阈值变量或非线性更新，可靠做法可能是禁用 operator、移除 policy 输入，或使用该模块定义的 baseline value。

## 推荐实验接口

配置应能独立指定：

```text
enabled_state_modules: [emotion, relation, goal]
enabled_update_operators: [appraisal, relation_update, temporal_decay]
policy_inputs: [personality, emotion, relation, goal, observation, affordances]
ablation_mode: neutralize | disable_update | remove_policy_input
```

每轮 run 保留：固定世界/角色/轨迹、模块与 operator 配置、随机种子、每步 `W/O/StateDelta/S/action distribution/action outcome` 日志。这样同一 trace 可以重放，不同消融只改一个配置，而不是重写整个系统。

## 研究上的使用边界

- 原型可以先有多个状态模块；最终论文方法由结果收缩，不能拿模块数量当贡献。
- 早期小消融用于发现问题；正式消融须在冻结任务、基线、指标和配置后再报告。
- 若关闭模块后行为完全不变，优先检查它是否根本没接入 policy，或存在其他路径泄漏，再讨论“该心理成分没用”。
- 低耦合不等于过度抽象：先保持接口数量足以支持当前最小世界、基线和状态更新比较。
