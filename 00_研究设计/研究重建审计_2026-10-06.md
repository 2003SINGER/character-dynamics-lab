## 2026-10-10 路线历史检查点：成熟方案先复现，传统基线覆盖全链

截至此历史检查点，用户纠正了当时的推进顺序：先把成熟方案复现在以后要研究的游戏/系统平台；寻找更合适的文字冒险；不一次开发完整插件系统，但尽量覆盖传统机制全链，再看哪里需要补。**这覆盖同日较早 MC-first 恢复总结的下一动作，不否定世界中心目标，也不把 MC 删除。**两份原文分别私密保存；来源 SHA-256 为 `eaff4986b9ef711834e8c82d1c6172e5a560688fd0453a0756964ee22e24ad60`。当时 LIGHT、FAtiMA/Ensemble 和“边境送信”来自模型建议，尚非冻结选型。此后用户已另行选择 Evennia 为主平台、Ensemble 为首个原生人物机制参照，并授权 P1/P2；当前唯一运行状态见[Native Platform P1/P2](../02_实验/Native_Platform_P1P2_v0/README.md)。

推进顺序是：**成熟原件的原生行为复现 → 小范围平台适配 → 传统组合基线覆盖全链 → 从失败轨迹定位问题 → 公平比较/消融验证。**全链至少包含世界与真实动作、局部认识/历史、事件评价、目标/社会动机、行动选择与多步规划、执行反馈/修订、作者约束与合法干预。不能只接“选动作→执行”，再称完整传统基线；也不需要先实现全部长期蓝图。

原件复现、适配与自行按论文重实现分别记账。E0/E1、现有 C++ 和有限 Python 样机保留为已测诊断与候选组件，**不强制新平台围绕我们的既有蓝图改造，也不把自有 h=0 搜索器或 Monitor 自动当作原 GOAP/DODM 的忠实复现。**原件 bug、接线/权限错误先归工程缺陷；原件在匹配条件下仍出现的限制，才进入研究问题候选。系统构建暴露问题，但拼装成功不是新方法证据。

在上述历史审查阶段，LIGHT 原生无模型入口是优先候选，Evennia 为回退候选，TextWorld 为规划专项候选；彼时仅做官方入口/部分源码核查，没有最终选型。之后开展的 LIGHT 限时独立探针及当前 P1/P2 路线状态只见[Native Platform P1/P2](../02_实验/Native_Platform_P1P2_v0/README.md)，不在此重复或据此推断引擎/算法能力。更早的技术事实由[只读技术准入报告](../01_文献/技术准入_传统全链基线与文字平台_2026-10-10.md)维护；接线设计快照见 [IntegrationBlueprint §07](草案/IntegrationBlueprint_v0/07_INTEGRATION_GAPS.md)。MC 暂缓为后续候选，不再默认下一步挖煤/建门。

另有两条不能混淆：任务内根据反馈重规划不是跨任务改进算法；成熟机制的复现/组合不是科研有效性验证。SyncStream/Transformer 的类比、ModularRSI 的跨任务改进建议不构成该次原论文审计或新模块授权。该历史审查只核查来源与维护路线；之后获批的 P1/P2 原生执行仍不授权训练、完整 Director、修改冻结 Kernel 或正式 NPC 实验。

## 用户目标校正：游戏中的可置信 NPC

2026-10-06 用户明确：“我们不一定要真实，而是要NPC在玩家眼中在游戏里面活起来。”项目应用目标是玩家感知的自主生活、行为连贯与情境响应，**不以真实人物心理拟合为必经前提**。此前将项目推进普遍绑定“先取得真人动作标签再研究”的路由过窄，现予纠正。

科研证据仍须成立，但应对准这个目标：明确可执行机制，在相同场景与展示条件下比较适当基线，并检验玩家体验增益与运行成本；并非因目标是虚构就可以只靠自有评分器自证。手写规则或预训练 LLM 都可作为候选，是否训练、是否使用具名心理状态，不能代替实际比较。

**长期应用目标进一步澄清：**用户希望适用于 RPG/开放世界的 NPC 框架，不只是 AI 替作者写内容。候选研究问题是：作者能否定义角色目标、偏好、知识权限及游戏约束，而不逐情境枚举响应，仍产生可信、可控的行为？共享玩家能力只是手段之一，商人/伐木工只是例子，未选型；当前干扰/恢复场景只作有限开发探针，不代表整个方向。新增[学术路线调研](../01_文献/专题调研_低编排可控NPC框架_2026-10-06.md)分别检查活动/规则复用、玩家体验和作者成本，不因文献存在而宣布框架贡献、启动完整心理系统或自动迁移实现。

**2026-10-07 用户进一步确认世界中心方向**：“以世界为核心而不是以玩家为核心。”NPC 的活动不只为玩家触发；作者效率是可能的贡献维度，不替代此体验目标。目前有执行基座和可比较先例，**尚无已选定的原创方法或已证实的研究缺口**。[制作障碍与活人感对照](../01_文献/专题调研_世界中心NPC的制作障碍与活人感_2026-10-07.md)交付生产经验、玩家实验与原型/上市差别。用户随后要求各工作到算法层；[算法拆解](../01_文献/算法拆解_NPC方法与生产系统_2026-10-07.md)分别维护作者输入、条件/评分/搜索/更新、源码版本、手算与缺口，不能以“有记忆/有规划”算作吸收完成。当前是机制调研，不自动启动新实验、训练或改 Runtime。以下 Praxish 否定仅限其共同小场景，不否定该应用方向。

现成评测的覆盖与局限见[NPC 可置信性评测定向核查](../01_文献/定向核查_NPC可置信性评测_2026-10-06.md)。CharacterBox 已另完成[全文方法与接口审计](../01_文献/精读_CharacterBox_2026-10-06.md)，NPC-Bench 仍仅核查可访问来源。前者更接近行为轨迹，后者偏对话设定；模型裁判分数不自动代表目标游戏玩家的感受。2026-10-06 新 active goal 已启动下述阶段 1—3 开发；没有因此启动正式玩家招募、付费调用或机制训练。

**下文独立 `A*` / actor-visible admission / 心理状态识别要求，只约束相应 Paper-0 或行为预测主张，不是上述游戏目标的统一准入门。**冻结 Paper-0 的问题与失败证据不改写；已完成 SourceRankingV1 仍是有限来源排名开发结果，不被包装成 NPC 可置信性证据。

## 现在可以确认什么

- **Runtime / Engine 工程保留 `CLOSED / FROZEN`。** 其时间、World/Observation 边界、动作校验和 trace 是可复用执行设施。Runtime closure 不意味着行为模型、Evaluator、Objective、Optimizer 或 Paper-0 完成。
- **Demo 手写 dynamics 不是训练出的科学模型。** Demo Living 的数值法则用于可运行展示和工程压力测试，已确认的多写者、重复疲劳、reconsideration、task-pressure 积分等缺陷在对应修复批次中纠正；批次可证明实现行为和确定性，不证明现实人物机制。
- **ResearchDynamicsV1 仍是手写 fixture/candidate。** fatigue、task-pressure、boredom、satisfaction 使用固定数值 law；`policy()` 返回 max-score-normalized 相对分数而非概率分布；`zero/frozen/wrong_field` 当前落同一默认分支，源代码字符串检查也不是功能信息边界负控。artifact reproducibility 测试导入时会运行写文件脚本。故不得称为已训练模型或已通过机制 gate；相关 artifacts 不重生成、不覆盖。
- **Theory-S v2 现为 `ExpectedEffectEMAProxyV0` 历史诊断 proxy。** 它的 LIGHT 结果不能代表新的多维研究对象。Run 1–4 仅是 development-only rank-matched probe/intervention/failure diagnostics；Theory-S 对错配历史有敏感性，但尚无可靠 zero-vs-correct 净增益。
- **H0b / compression 的 episode-disjoint generalization 未证明。** 历史拆分按 `trajectory_id::actor` hash 分组，导致同一 episode 的不同 actor 跨集合。只读取 full-view 中 `trajectory_id` 与 `actor` 的复核见 `outputs/research_reset_audit_20261006/split_audit_v3.json`：13,463 行，旧 train/test 共用 279 个 episode；train/validation 563、validation/test 70，pairwise overlap 合计 912（非 unique episode 数）。按 episode 分组的建议切分 overlap 为 0。既有 actor-unit bootstrap 可能低估 episode 相关性；原结果保留为开发切片探索，不升级为 episode-independent evidence。
- **Laya 早期规模运行暴露输入契约错误。** v2 的数值 scheduler clock 前进但格式化 `clock.time` stale，旧 choice surface 又缺少 Rule-soft-filtered candidates；v1/v2 一些多日或多人结果不可解释。v43 52/52 request 的 clock/token/candidate/replay engineering checks 通过，但单 seed 的 no-history 分支睡眠 1,149 分钟，history 首请求的 π(idle) 由 0.1031 变为 0.6776；这是强烈的单 tape 行为 scale-gate 失败与输入敏感性信号，不是一般行为结论。没有继续扩成 64 actors / 7 days。
- **早期统计估计量也发生过纠正。** `3531efc` 对内部 Self-Evaluation 的同 seed/step branch alignment、状态差与 policy TV 混用、trajectory aggregation 和重复率等口径作过修正；旧汇总不能沿用为对应效应的证据。修正后的 synthetic evaluator/split 仍是内部工程发展证据。

## 想法到可执行机制：当前落点

本项目早期弯路不只是“模型太简单”：运行规模先于识别条件、多个模块一起上导致归因困难，以及用自生成行为再由自有评分器评估，都让结果难以回答独立研究问题。简单公式或单层结构本身不构成科研失败；关键缺口是可识别的预测目标、明确的估计/假设依据与有力对照。

| 层次 | 已有落点 | 证据边界 |
|---|---|---|
| 可执行工程 | Runtime 有冻结的时间、世界、动作执行、观察边界、验证、gate 与 trace 契约；CharacterPolicy 是独立接口。 | 证明工程语义可执行，不证明这些语义是心理规律，也不代表 Runtime 默认使用已训练 policy。 |
| 手写可比较假设 | X/S 字段与更新规则、具名状态，以及 ResearchDynamicsV1 的固定状态步进和 peak-normalized policy 分数。 | 可作为显式假设或 fixture 比较；尚未由角色数据拟合，也未作心理/测量验证。 |
| 有限数据拟合 | PredictionBaselineV1 与 SourceRankingV1 在来源动作标签上做 DEVELOPMENT 条件预测；SourceRankingV1 使用冻结 split、CE/Adam 和独立训练器。 | Laya 预训练不是本项目 policy 训练。SourceRankingV1 不是 actor-visible policy；本次 GRU 对 context 略优、对 learned pool 三个 seed 均劣，保留为有限来源排名结果，不推出状态顺序编码必要性。数值唯一维护于 [INPUT_REVIEW](../02_实验/LIGHT_SourceRankingV1/INPUT_REVIEW.md)，不在此重复结果表。 |

## PredictionBaselineV1：当前 DEVELOPMENT 方法基座

`PredictionBaselineV1` 已完成 DEVELOPMENT 条件预测拟合，并通过固定 seed 的精确复现核验；训练细节、NLL、计数和区间只由[RESULTS](../02_实验/PredictionBaselineV1/RESULTS.md)维护。它使用数据源自身观测到的动作标签作为 supervision；标签独立于本项目手写人物 dynamics，但每份数据仍按其 provenance 标注，**不得未经审查叫作真人 gold `A*`**。source observed candidate 列表只表示来源记录，不代表角色主观候选集 `A^O`。当前状态为 `DEVELOPMENT_TRAINED_REPRODUCIBLE / READY_FOR_INDEPENDENT_REVIEW`；这不是心理状态 `S` 或 Runtime policy 的训练证据。

- 以完整 episode 分组 train/validation；同 episode 不跨集合。所有此前已用于开发、筛选或审计的数据均为 exposed data，不能充当 untouched formal test。
- 以标准 categorical cross-entropy 训练 O-only 与 history conditions；先建立 O-only、低阶历史与 mean-history，再比较可执行序列模型（例如 GRU）的预测表现。
- 当前比较检验预测方法是否从过去观测动作获得信号，不检验某个状态变量的心理含义。**不声称总参数/容量匹配**，不将 source candidates 写成 `A^O`，不称作 Paper-0 formal pass。
- source 的剩余权限由[任务准入审计](../01_文献/精读_LIGHT与本地预测任务准入_2026-10-06.md)维护；新开发比较的任务/通道已在[SourceRankingV1](../02_实验/LIGHT_SourceRankingV1/README.md)冻结，实现与下一动作只见[INPUT_REVIEW](../02_实验/LIGHT_SourceRankingV1/INPUT_REVIEW.md)。不会将同轮 speech 加入输入；已暴露数据仍不构成 untouched formal test。
