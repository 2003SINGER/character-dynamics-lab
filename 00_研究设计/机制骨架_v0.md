# 机制骨架 v0：角色动力学的持续计算接口

更新时间：2026-09-02  
状态：**研究/工程边界已确认；具体状态字段、数学更新、理论依据与实验收益未验证。**

本页是后续精读论文与编码时的接口约定。它不替代原始对话，也不把 W/O/S/P 作为新颖性主张。

## 0. 课题锚与第一版停止线

第一版问题固定为：

> **在受限信息下，持续更新的角色状态能否保留历史中对未来行为有用的后果，并据此产生更可检验的行为分布？**

因此，W 是行为的世界约束与后果，O 是防止上帝信息泄漏的角色世界视图，S 是保留行为相关历史后果的动态自身状态，P 是人物响应差异的长期参数；它们都服务于同一条前向链，不能各自扩张为独立课题。

第一版的范围进一步固定为：固定 P、有限 W/O、少量经文献与预测贡献筛选的 S、有限动作集、回放/干预接口以及 raw-history/summary/v0-state 的比较。以下内容保留为后续，不作为 v0 前置条件：P 的可塑性、多角色关系演化、完整 Galgame 自动抽取、开放世界 Agent 平台、专门 W/O/S/P 模型训练。

以后讨论新模块时先问：它是否直接改善“维护对未来角色行为有用的状态”或“由状态预测/生成行为”？若否，写入后续分支而不插入当前主循环。

## 1. 要让什么运行起来

模型不是每一步把“人物设定 + 全历史”交给 LLM 重新猜动作，而是维护一个会继续演化的角色状态，并输出当前行为分布：

\[
\pi_t(A)=G(O_t,S_t;\theta(P))
\]

同一输出有三种模式：

| 模式 | 在输出后做什么 | 用途 |
|---|---|---|
| 回放/评测 | 暂停，随后以外部真实行为 `A*` 对照 | 检验真实动作在 `π(A)` 中的概率或排名 |
| 自主运行 | 模型或程序从 `π(A)` 选择/采样 `A` | 驱动 NPC 的下一步 |
| 创作辅助 | 展示候选、倾向与状态理由 | 供作者采纳、忽略或补写转折 |

回放不是自主循环的输入解析步骤。真实文本动作映射到动作接口，是**评测接口**；自主运行时，行为决策应一次给出结构化动作及其候选世界效果，再由 W 校验。

## 2. 四类状态及其所有权

### W：权威故事世界

`W` 保存系统认定为真的、可结算的故事世界：对象及属性、人物位置和身体状态、时间、剧情事实、多主体关系图、可行动性与世界规则。

例如 `hostility(B,A)` 是一个关系真值，属于 W，而不是 A 的内心。W 可以因自然时间、随机世界规律、外部事件或行为而改变；它拥有动作的合法性校验权。

### Oᵢ：角色 i 眼中的世界

`Oᵢ` 是 i 维护的局部世界模型，尽量与 W 共享表示结构，但每个字段允许：值、陈旧时间、来源、置信度以及 `unknown`。

- 新信息流入或环境暴露时，相关 W 字段可复制/更新到 O。
- 未刷新字段可继续保留旧值；也可降置信度或转为“i 知道自己不知道”。
- 基础刷新、遗忘和暴露规则优先由普通程序维护。
- 只有“观察意味着什么”的复杂推断，例如 i 从回避动作推断关系恶化，才考虑让 LLM 生成受 schema 约束的 O 更新。

`W ≠ Oᵢ` 是必要能力，而非噪声：信息差、误会、隐瞒与错误估计由此表达。

### Sᵢ：角色 i 自身的动态状态

`Sᵢ` 的纳入标准不是“它像心理学”，而是：**它只属于 i、此刻仍会变化、且对未来行为有预测价值。**

初步内部层次可包括：

| 子层 | 例子 | 与行为的距离 |
|---|---|---|
| 慢状态 | 持续压力、满意度、自我效能、长期动力 | 可持续很久，但仍可改变 |
| 目标/动机 | 当前目标、目标投入、回避/接近动机、需求 | 决定人物想解决什么 |
| 即时状态 | 情绪、疲劳、饥饿、紧迫感、注意力、认知负荷 | 快速响应事件/时间 |
| 决策状态 | 当前意图、谨慎度、犹豫、冲动、时间余量 | 临近动作，但还不是动作 |

这不是已定本体论。后续只保留能被文献支持、又在实验中提高预测/干预效用的字段。

### Pᵢ：长期人物响应参数

`Pᵢ` 不是人物小传，也不是“内向 → 不说话”式的硬脚本。它描述这个人物通常如何受世界影响、如何维持状态、如何把同一状态表达成行为。

候选参数包括敏感度、阈值、恢复/累积/惯性、风险偏好、自我控制、冲突回避、探索倾向、压力下的决策随机性等。概念上：

\[
\Delta S_t=F(\Delta O_t,S_t;P),\qquad S_{t+1}=U(S_t,\Delta S_t,\Delta t;P),\qquad \pi_t(A)=G(O_t,S_t;\theta(P))
\]

P 主要改变响应函数本身，而不与 O、S 粗暴并列为三段 prompt。

## 3. 主循环与 LLM 位置

```text
W ──信息边界/局部刷新/过期──> O
O 的变化 + 旧 S + P ──语义解释──> ΔS ──数值/时间动力学──> S
O + S + P ──候选与偏好──> π(A) ──选择/采样──> A + 结构化效果
                                                    ↓
                                           W 校验、结算、更新
```

### 应优先由程序承担

- W 的状态转移、时间/随机世界过程、action 合法性与效果结算；
- 信息边界、环境暴露、O 的直接复制、过期、`unknown` 和局部刷新；
- S 的数值边界、衰减、累积、恢复与时间尺度；
- 模块日志、来源链、重放和消融开关。

### LLM 的两处核心候选工作点

1. **语义解释算子**：`(ΔO, S, P) → ΔS`。把开放事件对这个角色的意义，映射为 schema 允许的稀疏状态变化；它不重写整份 S。
2. **行为算子**：`(O, S, P) → {候选动作、概率/排名}`。先给可能行为与偏好，再由模型或程序选择/采样。动作可以带结构化效果提议，但不得绕过 W 的校验。

这一分工是当前“LLM 带来的窗口”：传统认知/情感 Agent 已有显式状态循环，却常需人工写开放事件到状态的规则；纯 LLM 又会把状态藏在历史和上下文里。这里探索的是受约束的语义解释与显式动力学结合，**不是已被证实的新颖性结论。**

## 4. P 如何可塑：保留为两个待验证机制候选

P 需要稳定，不能被普通事件任意重写。用户提出的两条候选均保留，但尚未选择公式或宣称心理学正确：

1. **慢性巩固**：长期反复出现的 S/目标/行为模式，积累为长期证据后逐步调整相关 P。
2. **阈值门控**：事件先影响 S；只有某个行为相关 S 的强度或累积量超出预定义阈值，才允许有限的 P 改变。

这让“P 影响 S、S 经长期或强烈轨迹反塑 P”成为可测试的反馈，而非“发生大事就改人格”的特殊规则。第一版可先将 P 固定，待已有状态机制、数据和实验条件允许后再单独打开该模块。

## 5. 下一阶段：用论文决定具体计算，而非继续加顶层模块

每篇状态机制论文都用同一张卡阅读：

1. 输入是世界事件、直接观察、解释、历史还是行为反馈？
2. 状态字段表示什么，哪些快/慢，哪些必须持久维护？
3. 更新由手写规则、appraisal 函数、学习模型、LLM、还是混合方式完成？
4. P/trait 在哪里进入：敏感度、基线、时间常数、决策偏置还是 prompt 描述？
5. 状态怎样进入 action，动作如何受世界/affordance 限制？
6. 怎样验证状态更新真的有用：预测、干预、校准、消融或人评？

首批阅读对象：EMA、FAtiMA、BDI、Dynamic Persona Coherence；同时对照 PsychSim、Generative Agents 与 BehaviorChain，防止把已存在的闭环、评测或状态分层误写成空白。

## 6. 编码前的最小验收接口

第一版无需完整游戏，但至少应能保存并重放：

```text
world event / information access
→ O delta
→ semantic interpretation and S delta
→ state update
→ action candidates and ranking
→ chosen action / world validation
→ provenance log
```

每个模块要能替换或关闭；“设为 0”只有在该值确有中性语义且无隐藏旁路时才算消融。具体原则见 [原型实现与消融接口原则](原型实现与消融接口原则.md)。
