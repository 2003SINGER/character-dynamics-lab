## 1. 值域分段：从量变到可审计的行为阶段

### 用户提出的候选

对归一化到 `[0,1]` 的某些状态、心理变量或 P 字段，保留数值的连续加减，但让其作为其他函数输入时呈现不同阶段：

用户已明确，“逆过来”就是借正态分布概率比例做逆映射：`u → Φ⁻¹(u)` 可将中心段映射到约 ±1σ，再向外对应更远的阶段。可以实际计算逆函数，也可以直接用 u 上的对应分界；二者的阶段划分等价。下面保留精确分界，用户原话的近似配置为 `0.025 / 0.16 / 0.84 / 0.975`，不要把两者混用。

```text
0.1587 — 0.8413  （0.50 ± 0.3413）：typical / 常态区，约对应标准正态 ±1σ 的 68.27%
0.0228 — 0.1587、0.8413 — 0.9772：distinctive / 特异区，约对应 ±1σ 到 ±2σ
[0, 0.0228)、(0.9772, 1]：extreme / 极端区，约对应 ±2σ 之外
```

这里的 `typical / distinctive / extreme` 是机制标签，不是对角色作临床“正常/异常”判断。更重要的是：分段要改变**响应函数**，而不只是给输出换名字；例如极端疲劳可提高睡眠 action 的可用性或改变 appraisal/恢复函数形状，极端拖延 P 可使同一 task-pressure 输入进入不同的行动偏置区间。

### 需要先决定/验证

1. 逆映射可作为人为的响应坐标变换，不要求先有人群百分位数据；但轴上 68% 的宽度不代表人物 68% 的时间在该阶段。是否能解释为真实人群 percentile 是另外的校准问题。
2. 存储仍为 `u∈[0,1]`；消费函数可实际计算 `z = Φ⁻¹(clamp(u, ε, 1-ε))`，或直接分段。分段连续、硬阈值和平滑 gate 都是待比较选择，不能为了平滑而抹去用户要的阶段差异。若加入滞回，额外保存的阶段记忆须单列消融。
3. 每个字段须单独定义：参考中心、尺度、是否允许双侧含义、何种输入函数受阶段影响、以及极端区是否会恢复/饱和。`fatigue`、`task_pressure`、`self_control` 不能默认共用同一解释。
4. 用受控干预验收：固定 W、O、其余 S/P 与 action seed，只跨越一个边界，记录 `ΔX / ΔS / Δπ(A)`；若没有可解释的差异或出现不连续伪影，就撤销/重设该 gate。

**优先级：文献阅读后的小型机制实验；现在不把它塞进参考 demo。**

## 2. 低耦合：把“可替换”变为工程验收项

目标不是过早做插件框架，而是让一次机制改动不迫使 W、O、X、S、D、日志和 batch 同时重写。

### 目标依赖方向

```text
World / Scene / Object --(facts, A^W)--> Observation updater --(O, ΔO)--> Appraisal X
Appraisal --(StateDelta)--> State updater --(S)--> Decision / policy --(A^char)--> World executor
                                                  └──────────> provenance log
```

- `World` 不读取 S/P 来偷偷修改后果；
- `X` 不读取原始 W；只处理 O/ΔO、旧 S、P；
- `Decision` 不直接改 W；只产生人物级 action/分布；
- `Object` 不拥有全局规则；它只声明潜在 affordance；
- 时间、随机性、配置和日志是显式依赖，不能藏在模块内部的全局状态。

### 后续工程验收

1. 每个 updater/policy 接口都有显式输入、输出、配置与 provenance；
2. 能以替换实现、禁用更新、移除 policy 输入三种方式做模块消融；
3. 一个新 Scene/Object 不应要求修改 `CharacterState` 或 `Decision` 的核心类，除非它确实引入新的心理/行为语义；
4. 一个新 S 字段不应要求修改 World settlement，除非明确引入了 typed `ActionQuality` 等跨边界 payload；
5. 单元测试覆盖每个边界，集成测试只覆盖主链；避免由一个万能 `Simulation` 类吞掉所有规则。

现有参考实现已经把主循环收敛为 `advance_one_decision()`，但它仍是阅读型 demo，不应被误说成完整插件化架构。

当前首要缺口：X 仍直接给状态 delta；状态更新集中于一个函数；commitment 直接消费 WorldOutcome。拟按新方案拆出解释、字段动力学与可知反馈更新，采用只读快照和显式 patch；允许字段间有声明过的心理影响。

**优先级：每次添加模块时按此验收，不单独为“插件化”做大重构。**

## 3. 动作所有权：Object 的 affordance、Scene 的组合、W 的权威

“动作属于谁”必须拆成不同层次，不能把它简化为一个类的子类关系：

| 层 | 拥有什么 | 例子 |
|---|---|---|
| `Object` | 基础 affordance / 依赖的局部状态 | phone→浏览/网购；bed→休息/睡觉；lamp→开关 |
| `Scene` / `Room` | 将对象、地点状态、出口和可见上下文组合成有意义的人物动作候选 | lit desk + coursework material→学习；door + reachable service→如厕/取餐 |
| `World` | `A^W` 最终合法性、跨对象 precondition、时间推进与所有后果结算 | 钱包是否足够、任务是否仍 active、门外行动的结算 |
| 角色 policy | 在 `A^O` 中评分、选择或采样 `A^char` | 当前疲劳/任务压力下选择 `study_at_desk` |

因此：

```text
Object affordance fragments
  → Scene action composition / A^W candidate construction
  → O filters to A^O
  → policy selects A^char
  → W validates and settles typed a^world primitives
```

`ActionType` 在 C++ 中是跨层共享的领域值类型，不应被解释为“World 的子类”或“Object 的子类”。第一版可让 Object 直接列出有限 `ActionType`；规模变大后再演化为 `AffordanceDescriptor`，其中 object 只声明能力，而 Scene/World 结合上下文解析出具体 action。组合动作由人依据 Scene 设计，是对的；但组合**不等于**绕过 W 的最终校验。

**优先级：当前就作为代码审查规则；等第二个 Scene 或复杂组合动作出现时再升级 descriptor。**

实现核对：当前 `Scene` 尚无组合动作定义，`Object` 直接挂完整 ActionType，W 用 switch 处理展开和结算。因此上述是目标所有权，不能视为已落实。拟先做一个带对象实例绑定的 Scene recipe；同时审查 A^O 从真实 A^W 过滤是否泄漏隐藏条件，详见修改方案 §5。
