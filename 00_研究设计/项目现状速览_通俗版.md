## 我们在做什么

在局部可观测、可回放的环境中，测试持久状态 `S` 是否保留对下一行为预测有用的历史后果。评价以 held-out action NLL 为主，不把“看起来像人”当作机制证据。

## 当前走到哪了

- **RoomDemo baseline**：C++17 规则化参考实现，可编译运行，用于机制接口与控制链 smoke；不等同于外部行为实验。
- **External/Replay baseline**：LIGHT restricted dev slice 已接通 `Replay → SceneSnapshot → transition/appraisal → canonical Theory-S trainable candidate → canonical raw features → conditional NLL`；仍是 development-only。
- **T14/T20 v1**：Run 1–Run 4 development diagnostic chain 已完成：Run 1 full-refit、Run 1b frozen-model intervention、Run 2 frozen-θ incremental、Run 3 trajectory bootstrap、Run 3b permutation-assignment robustness、Run 4 Theory failure decomposition。所有结果仍明确标记 `development_only`，不是 formal test。
- `StudyAtDesk` 已拆为 `StudyFocused` / `StudyHalfhearted`；这是已实现的历史决策，不是当前待拍板事项。
- 二阶知识范围已拍板为“二阶，不做三阶”；不再列为未决事项。

## 2026-09-07 主线纠偏

- Run 1–4 只登记为 **development identifiability diagnostics**；`correct Theory-S ≈ zero` 不能推出 Theory-S 有效或无效，正式实验尚未开始。
- mechanism sandbox 与 v1.2 trajectory sanity 已完成，结果只属于工程回归；不作为现实数据预测证据。后续不再围绕 v1/v1.2 加 Run 5、调 eta 或扩机制覆盖。
- Theory-S v2 当前是 canonical Python trainable dynamics candidate：补完既有 per-field dynamics 与 T14/T20 readout 的梯度形式化；X/S 语义、真实参数和外部预测有效性仍未冻结/验证。LIGHT 也不承担全部 persistent-S 识别责任，按各数据集实际可观测能力分工。
- 场景线采用 `scene/object/affordance → A^O` 的独立候选生成：先冻结规则、再揭晓外部 `A*`；`A* ∉ A^O` 记为 support miss，不为覆盖 gold action 倒塞候选。
