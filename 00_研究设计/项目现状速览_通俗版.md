## 我们在做什么

架构上要分开看：我们共享一台“时间、世界、动作执行、观察边界”的发动机；人物为什么吃饭、休息、逃避或学习，是可替换的 Dynamics Model。科研 candidate 与 Demo Living model 共用执行发动机，但互不冒充、互不倒灌。

Character Dynamics 的主线是一个可持续运行的 NPC 角色动力学框架。运行时由三条流组成：`TIME` 推进 W dynamics、S continuous dynamics 与 RunningAction progress；`EVENT` 将 WorldEvent/ActionOutcome 投影为合法 ΔO，再进入 X→S；`DECISION` 只在 DecisionGate 打开时执行 A^O→π→ActionIntent→W validation。`W → O → X → S → π` 是角色因果子路径，不是完整 runtime。Paper-0 的 persistent representation、Replay 和 LIGHT 只是研究支线。

用户已明确应用目标是“NPC 在玩家眼中在游戏里面活起来”，不必先证明真实人物心理拟合。当前应围绕玩家可见的连续行为、情境响应与运行成本建立比较；真人动作预测的准入只约束旧 Paper-0 分支。唯一目标与设计判断见[研究重建审计](研究重建审计_2026-10-06.md#用户目标校正游戏中的可置信-npc)。

## 当前走到哪了

- **RoomDemo baseline**：C++17 规则化参考实现，可编译运行，用于机制接口与控制链 smoke；不等同于外部行为实验。
- **Runtime / Engine v1**：已 `CLOSED / FROZEN`。统一时钟、RunningAction、事件/信息边界、DecisionGate、typed rejection、commitment、fixtures、trace、case-isolated CTest 与 CI 已闭环；后续不再以“再加一条 runtime 测试”为由重开本 milestone。
- **System self-evaluation v0**：曾在 32 personalities × 8 world seeds × 256 decisions 上运行内部 scorecard；这是同一套手写参考机制生成的 development regression，不是独立人物行为真值、外部自然性或心理机制证据。详见 [Self-Evaluation v0](../02_实验/Self_Evaluation_v0.md)。
- **PredictionBaselineV1**：development fit 与 seed 复现已完成，当前待独立外审；详细数值只见[RESULTS](../02_实验/PredictionBaselineV1/RESULTS.md)。这是来源动作标签上的条件预测基座，不是心理状态 `S` 或 Runtime policy 的训练证据；source observed candidates 不等于人物的 `A^O`，已暴露数据也不可能充作 untouched formal test。
- **Demo / ResearchDynamics**：Demo Living 和 ResearchDynamicsV1 都是手写固定 law，不是训练出的科学模型。ResearchDynamicsV1 当前干预与测试覆盖不足，不能视作机制 gate 已通过。
- **旧 Theory-S**：`ExpectedEffectEMAProxyV0` 历史诊断 proxy，不代表新研究模型，也未在真实 development source 上运行其文档化多维训练计划。
- **T14/T20 v1**：Run 1–4 development-only rank-matched diagnostics 已完成。LIGHT 上 Theory-S 错误历史置换会伤害，但正确状态的净增益仍接近零；不构成 formal test。
- **LIGHT H0b / compression**：此前按 actor-unit 切分导致同一 episode 跨 train/test；复核发现 train/test 共享 279 个 episode，pairwise overlap 总计 912。原数值保留，但 episode-independent generalization 与相关 CI 未证明。
- `StudyAtDesk` 已拆为 `StudyFocused` / `StudyHalfhearted`；这是已实现的历史决策，不是当前待拍板事项。
- 二阶知识范围已拍板为“二阶，不做三阶”；不再列为未决事项。

## 2026-10-06 研究重建顺序

- 保留并冻结 Runtime 工程边界；不因科学模型问题重开 Engine。
- 旧 fit/复现和[LIGHT 来源诊断](../01_文献/精读_LIGHT与本地预测任务准入_2026-10-06.md)保留；新的来源条件排名已冻结任务、通道和比较，训练器实现、准入及运行进度只由[INPUT_REVIEW](../02_实验/LIGHT_SourceRankingV1/INPUT_REVIEW.md)维护。它不是“角色行动前预测”或完整心理模型，不因输入投影或训练通过就调人物、改 Runtime 或宣称科研完成。
- M2 的 `scene/object/affordance → A^O` admission 仍是 Paper-0 formal blocker，但不再被当作禁止一切新开发学习的规则。
- 本阶段只使用 DEVELOPMENT 数据与切分。已有暴露样本不作 formal test；基座拟合成功不等于研究假设成立。

## 当前停止点与下一阶段

Engine 已冻结；来源预测分支保留待独立复核的开发结果，不再冒充应用主目标。NPC 评测方面已完成 [CharacterBox 全文与接口审计](../01_文献/精读_CharacterBox_2026-10-06.md)，但没有运行 benchmark 或得到玩家结果。下一阶段的单一比较问题、强基线、候选/gate 控制与玩家呈现缺口统一见[研究重建审计](研究重建审计_2026-10-06.md#玩家目标的第一个可比较问题proposal未执行)；实验、评分器与招募尚未批准执行。

## 仍未证明什么

当前没有独立玩家证据证明 NPC 更可置信或更有生命感。预测分支也仍未证明：psychological/runtime dynamics 已从数据学得、外部独立行为真值上的泛化收益、角色可重建候选集上的预测优势、persistent-S 近似充分性/必要性、心理机制成立或任何新颖性主张。H0b/compression 的 actor-unit bootstrap 也不能替代 episode-clustered uncertainty。
