# 项目现状速览（通俗版）

> 更新：2026-10-16（角色 Planner 与语义分工澄清；仅维护文档，未新增实现或运行实验）
> 本页只同步当前事实，不维护易过期的文档数量、待办数量或历史争论。

## 我们在做什么

长期目标是把作者不同抽象程度、不同控制粒度的创作意图，变成游戏世界里合理、可执行的未来。角色自己的 Planner 就可以是自驱动：根据合法信息、目标和经历组织行动，再交游戏真实结算；不必另配心理内核，也不必把“复仇”等每个概念写成游戏变量。角色规划与作者规划可复用实现，但须区分目标、信息、控制权限与来源；关闭导演不等于关闭角色规划。规划解释不是已发生事实，也不自动证明玩家觉得自然。详细定义见[F0/F1](CharacterDynamics_FormalProblem_v0.md)，架构与不同应用路线见[系统愿景](Character_Dynamics_System_Vision_v0.md)。

成熟算法组合不自动构成研究贡献；公平近邻和差异仍须独立检验。原始 P0 与 LLM 路线状态见[原始 P0 RESULTS](../02_实验/Planner_P0_v0/RESULTS.md)。当前 P0 Baseline Gate 是 **DEVELOPMENT / READY_FOR_INDEPENDENT_REVIEW** 的固定三场景比较，详细结果与边界只见[唯一 RESULTS](../02_实验/Planner_P0_Baseline_Gate_v0/RESULTS.md)；它不等于完整传统系统或独立 NPC agency。P0-Integration 原有限检查点继续由[其 RESULTS](../02_实验/Planner_P0_Integration_v0/RESULTS.md)维护；P5 shared-supply 失败保留，不自动进入 P6。

现有 C++ / Demo 有一套已冻结的时间、世界与角色模型分层；它是实现实例，不是当前游戏规划问题必须复用的系统架构。新问题的输入和执行应落在具体游戏原生状态、事件、规则与执行器上，规划层可以跨越异构底层过程。

旧 C++ / Paper-0 的 OHXSP 人物机制只是参考模型，不是每个游戏都必须采用的输入 schema，也不是全系统目标。可用 LLM 与成熟规划方法承担语义、因果候选、grounded 绑定、层次细化及反馈修复；不要求每层都由 LLM 实现。具体候选组织（层次、联合或混合）尚未冻结。作者可从零约束到全编排；NPC 独立性不是压过作者控制的绝对禁令，直接角色/世界编排可在授权下使用，但不得伪造历史结算或角色隐藏知识。间接 Director 只是已有 P5 模式之一。

## 仍未证明什么

当前没有新机制、组合增益或人类可信度的证据。近期开发/阶段结果仍不能证明系统研究贡献；要回答组合是否产生超越单组件的作用，需先固定可检验未知数与公平基线，再由获批协议决定比较和消融。旧 Paper-0 分支的心理预测主张仍有其独立准入缺口，不构成当前游戏规划目标的统一前置条件。
