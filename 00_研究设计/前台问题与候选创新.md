## 1. 课题锚与研究尺度

> 在受限信息下，持续更新的角色状态能否保留历史中对未来行为有用的后果，并据此产生更可检验的行为分布？

长期愿景是人物随经历、局部世界及互动改变，既能预测也能作为 NPC 自主行动；一次研究只检验其中一个可证伪命题。收束的是一次实验，不是删掉其余问题。

主轴并非“心理数值 NPC”或“动态 persona”，而是严格区分：世界发生什么、人物知道什么、如何解释、留下什么持续后果、怎样改变下一行为分布。数据流、字段、公式、C++ 和游戏界面只是不同层的工具。每个新增模块都应回答：是否直接帮助维护行为相关状态，或由状态预测/生成行为？否则进入后续分支。

本项目仍属于 Agent/interactive character，但不以外部任务完成率作为唯一策略目标。任务完成是世界事实；角色为什么会继续、拖延、休息或放弃，才是人物模型要表达的行为差异。不要因为 demo 有 coursework 就把研究改成最优任务规划。

### Paper-0 接受边界（2026-09-05）

首篇只问：在**局部可观测、可回放**的角色环境中，紧凑而持续的 `S` 能否保留预测未来行为所需的历史后果，且不让角色未知的 `W` 事实越界进入决策。它只有三项可失败检验：**信息边界**（policy 仅消费 `O/S/P`）、**预测近似充分性**（相对可得历史的预测与残余信息）、**状态必要性**（去除、置换或弱化 `S` 后的退化）。`W/O/X/S/P/D` 是实现与测量仪器，不是论文题目或贡献清单。

Paper-0 只做 Forward；`P` 在单次运行固定，`D` 从当前状态导出。Inverse、多角色/二阶 ToM、`P` 漂移、Scene Manager、广泛心理字段扩张与 Q01 的高级响应曲线均保留为后续分支，不进入首轮主张。

## 2. 两个研究方向：首轮 Forward，Inverse 留作后续

### Forward：由状态预测下一行为

给定人物实际可知的历史和当前信息，维护 S，并先输出下一行为分布。在叙事回放中，之后才揭晓真实行为 A*；在自主模式中从同一接口采样行动、交 W 结算。回放/teacher forcing 是检验协议，不是状态更新方法本身。

“微行为”不是低级版剧情动作：玩手机、短时学习、休息和回应消息，正是持续状态显现的载体。P 既可能影响经历后变成什么状态，也可能影响同一状态怎样表达为行为，不能仅作为 prompt 顶部小传。

### Inverse：由行为或反馈反推、修正状态

真实后续行为与预测不符后，能否更新对潜在状态的估计，并改善再下一步预测？小说中的行动、对话、有限心理描写，与用户的点击、回复、评分等，都可能是隐状态估计的观测，但应用语义不同。

这不是已经承诺“反向传播”：贝叶斯更新、inverse planning、IRL、候选模型比较或其他估计器都是可能方式。新行为只能在发生/揭晓后用于修正；不能反向泄漏进本步预测。还需区别“估计器修正了对人物的认识”和“人物因事件真的发生变化”，否则把预测错误一律写成人格/情绪改变。

Forward 为状态提供预测约束，Inverse 用新证据修正状态；不能把两个方向概括成一个 history→action 后丢掉后者。PsychSim 已有相关 mental-model revision/目标权重推断先例，抽象回路不能声称新；自然叙事或长交互中的状态学习、在线修正和干预验证仍需职责级查重。v0 优先 Forward，Inverse 保留为清楚的后续实验问题，不要求本轮实现。

## 3. 候选问题及其最小检验

### R01：面向未来行为的历史压缩

S 保存“历史在人物此刻留下什么”，不是完整史料或漂亮摘要。可用下式表达研究假设：

\[
p(A_{t+1}\mid H^{obs}_{\le t},O_t,P)
\approx p(A_{t+1}\mid S_t,O_t,P).
\]

这里 Hobs 只含角色获准接触的信息，P 和动作接口条件保持一致；不能把完整 W 作为角色 policy 的免费输入。近似充分性是待测假设，不是给 S 起名后的事实。

比较 persona only、raw history、结构化 history、强 summary、`no-S`、`naive-S`、置换 `S` 与显式/混合 state；控制信息可得性、模型和预算。还须直接报告 `S`、history 与 `S + history`：若后者仍有明显收益，`S` 就未达到近似充分；若 raw history 同等或更优，不能把压缩本身说成优势。S 可以是结构化字段、短摘要或学习表示的混合，不要求手写心理数值永远获胜。

### R02：一致性是条件分布及不确定性，而非重复

目标明确、情境稳定时应有稳定倾向；历史改变后允许有理由地改变。信息不足、目标冲突时可能更分散。除真实动作的概率/排名，还应检验概率校准和预测的不确定性。

不能仅凭单次低概率行为就判断“角色崩了”。同一数值概率在不同动作空间、基础率和数据条件下含义不同；早期“平静时 0.08 异常、冲突时合理”只是说明分布背景重要，不是判定阈值。世界过程随机性、解释/认知不确定性和策略采样随机性须分开，不能统一调 temperature。

### R03：通过受控干预检验变化规律

同一终局、不同历史（被帮助/被欺骗，之后同为 B 请求帮助）；同一 W、不同观察 mask；同一已知环境，只改 P 的一个维度；或只改一个状态模块。分别记录 ΔO、ΔX、ΔS、Δπ，不混为一次“反事实”。

方向假设要在看结果前说明，且应有数据或独立评价依据。观察到手写规则按自己规定的方向变化，只证明接口接通，不证明人物机制正确。E0 的作用仅是检验数据流和干预是否受控；只有独立 held-out replay 才能提供 Paper-0 的行为证据。若真实后续无法唯一判定，使用分布、排序或预定义评价协议，不编造唯一正确行为。

### R04：LLM 自由更新是否发生过冲和叙事自强化

先检验轻微负面事件是否稳定导致不相称跳变、单调负向漂移、恢复缺失、framing 放大或过强路径依赖：
旧 S → 对新事件的解释 → 新 S → 下一次解释。

如果失败现象成立，再比较惯性、恢复、饱和、保护因素、重评估或其他更新约束。若现象不存在，不为“心理学化”硬加修复器。情绪/压力/信任/习惯可能有不同动力学，但快中慢分层本身已有先例，不能仅加三层就宣称贡献。

### R05：历史保留是否由预测贡献而非新近性决定

来自 SyncStream 的跨域启发：旧经历仍能解释未来行为时不应机械遗忘；很近但无预测作用的事件也未必值得保留。可以比较 recency、固定摘要、代表性保留及状态更新。数据流分类中的 representativeness 不是人物心理机制，也不直接提供这里的标签或损失函数。

## 4. 第二评价维度：效率—效果与可控性

已采纳为部署评价线，不替换课题锚。在预先冻结的质量容差下比较成本，例如：

\[
\min Cost(M)\quad\text{s.t.}\quad NLL(M)\le NLL(baseline)+\epsilon.
\]

至少比较 raw history、强 summary、Character State；不能只赢不断增长的原历史。记录输入/输出 token、状态维护及摘要更新调用、缓存、失败重试、P50/P95 延迟、单位决策成本、长轨迹吞吐量。计入维护状态的成本，不只计决策那一次 prompt。若研究扩展 NPC 数量，再测扩展性。

分层计算是一种待测部署办法：程序维护高频 W/O/时间，规则或轻量策略处理常规行动，开放语义 appraisal/复杂交互按事件调用模型；不是“改成 JSON 就自动便宜”。

存读档、局部干预、信息权限、来源审计、跨模型迁移和确定性回放是可控性候选价值，各自需要验收。summary 也可以带结构、来源和局部更新，不应把弱摘要设成必败对手。若 summary 在质量、成本、可控性都不差，应接受更简单方案；预测不占优但质量相当且成本显著降低，也可以是有效系统结果，不能冒充心理机制突破。

## 5. 数据与实验的成立条件

- 先人工/半人工构造一个有限对象世界、动作映射和可知性规则，再冻结预测问题与干预对。自动从小说抽取世界要另负抽取正确性的责任。
- 在真实下一行为揭晓前输出概率，保存所有失败和低概率结果。行为支持集不匹配要报告，不事后移除难例。
- 控制角色身份泄漏、叙事措辞/皮肤、相同信息权限、模型配置和动作空间。保留原始输入输出、各类 seed、错误、负结果及不覆盖的运行目录。
- 拆分开发与测试；先固定主指标、质量容差、基线和配置，再做正式比较。粗消融可以更早用于定位无效模块。
- 模块无效果时先检查没接入 policy、被其他变量替代或信息旁路；不能直接宣布该心理成分无用。
- 允许 prototype 初期较丰富，阅读、实现与小实验并行；结果应收缩字段与机制，而非继续扩建框架代替测试。

当前规则 batch 是工程压力测试，尚无上述研究结果，具体证据只在[实现进度](当前实现进度.md)维护。

### 6.1 落地游戏工程的先例（2026-09-05 核读，判定为否定）

既有先例不止于学术 Agent 论文。逐条比对 2005–2013 年的 utility-AI / GOAP 工程实践后（完整提取见[三方向核读 §2](../01_文献/专题核读_三方向近邻_2026-09-05.md)）：

| 项目当前机制 | 已在工程中确立的对应物 | 出处 |
|---|---|---|
| 状态 → 动作分数 → 概率采样 | 决策因子 → 响应曲线 → utility 分数 → 加权随机 / top-N 加权随机 | Utility 2013 §9.5–9.6 |
| 承诺与恢复、resume gate | **Inertia**：给当前动作加权、冷却期、或队列空了才重新决策（The Sims Medieval） | Utility 2013 §9.7 |
| 目标竞争与优先级 | **分桶 / dual utility**：高优先级桶内无有效动作才落到下一个桶 | Utility 2013 §9.6（Dill 2011） |
| Q01 分段响应 | **分段线性响应曲线**：手工调 2D 点 + 线性插值；The Sims 就在用 | Utility 2013 §9.5.4 |
| Q05 Object 提供基础动作 → 组合动作 | **SmartObject**：交互由对象在游戏数据库中指定，角色不硬编码 | GOAP 2006 §Three States |
| Q04 隐藏前置条件 / 失败反馈 | 规划失败 → 把失败知识写入 working memory → 重规划时考虑 | GOAP 2006 §Benefit #3 |
| W 校验前置条件、强类型结算 | STRIPS precondition / effect；F.E.A.R. 改用 procedural 版本 | GOAP 2006 §Differences |

**判定：若以「由状态产生行为分布 + 承诺惯性 + 目标优先级 + 对象提供动作 + 世界校验前置条件」作为贡献，这些在 2005–2013 年的游戏 AI 工程中已是标准实践，不能作为新颖性主张。** 做 T18 查新、或写任何「机制新颖」表述前，先过一遍这张表。

### 6.2 差异清单的第二次修订：`W ≠ O` 也不能再作为架构不变量主张

上一版把 `W ≠ O` 列为三处可能站得住的差异之首。2026-09-05 补做工程三空白核读时撞见了它的直接先例，**该条已被覆盖，必须撤下**。完整提取见[工程三空白核读 §5](../01_文献/专题核读_工程三空白_2026-09-05.md)。

最强的一条是 **Talk of the Town**（Ryan & Mateas，Game AI Pro 3 Ch37；架构自述 fully implemented）：

- **ground-truth 与信念显式分离**：「A given character attribute will have a type and a **ground-truth value** (e.g., brown), but a **belief facet** corresponding to it will represent a character's **potentially false belief** about that attribute (e.g., black).」
- 每个 belief facet 带 `Predecessor` / `Parents` / `Evidence` / `Strength` / **`Accuracy`（相对当前世界真值是否准确）**；11 类证据类型学（Observation / Transference / Confabulation / Lie / Declaration / Mutation / Forgetting…），每条证据带 Source / Location / Time / Strength。
- 系统侧追踪与角色侧可访问被显式切开：对 predecessor 链原文明言「we **do not** plan to give NPCs access to these data」。
- 信念修正按证据强度比较，并在原文中明言「**Belief oscillation is possible, as such, but that is an appeal of the design**」。
- 规模：300–500 NPC，各自 250–400 个 mental model、800–1200 个 belief facet。

另有两条佐证：HTN 的 world state 明写是「what our troll **knows** about the world」，且刻意抽象化（用 `WsEnemyRange ∈ {Melee, View, OutOf}` 而非实际距离）；ETQ 的 context object 用于定义 **subjective world view**，候选生成器按「AI is **aware of**」过滤。

| 4 | **规模与深度互斥** | 「they should be pretty predictable, because there were **too many of them** in the building for the player to care about them in detail」（V3 C34 §34.2.2） | 项目须处于"少角色"区间 |
| 5 | **Authoring 全靠人工** | 维度选择 = 「**Put yourself in the character's shoes**… Distill these reasons into concrete metrics」；任意曲线「intimidating and possibly even unintuitive」，实际只用预设调色板（V3 C13 §13.5） | **LLM 最显著的切入点** |
| 6 | **没有评价协议** | 已核读 34 章中**无一章以"下一行为预测准确率"为指标**；验收是 playtest / QA / fun | 项目要建的正是这个 |

**§6.3.1 Gap 1 必须拆成两条——用户 2026-09-05 质疑「这么严重？」，质疑成立，原写法过重。**

Rabin, *The Illusion of Intelligence*（V3 C01）§1.3.6 的原文：

> "Some programmers have this **weird obsession** with trying to get game AI to **simulate emotions**. … **Without simulating everything that makes up human-level intelligence, this approach for the purposes of games appears misguided.**"
>
> "**Players can only see an AI's behavior, not what is being simulated.**"

**先说它到底有多硬：这是一句立场陈述，不是论证。** 全节没有给任何数据、对比实验或失败案例。它是 Game AI Pro 主编的经验判断，语气强不等于证据强。上一版把它写成"正面否定"是**我把语气当成了力度**。

**但它背后有一条完整的论证链，拆开看才有意义**：

1. 玩家只看得到行为（事实）
2. **行为受"词汇"限制**——动画、配音、交互的数量有限（隐含前提）
3. 所以内部状态的细微差别传递不出去（推论）
4. 所以模拟内部状态是浪费（结论）

**关键在于步骤 2 是隐藏前提，而且它正是 Gap 3。** 词汇瓶颈一旦解除，整条链断掉。因此：

| | 内容 | 依赖 Gap 3 | 在本项目的处境 |
|---|---|---|---|
| **Gap 1a** | "模拟的状态不会渗透进行为" | **是** | **部分成立**（2026-09-05 复核修正，见下）。**上一版写"不成立"是错的，已撤回** |
| **Gap 1b** | 玩家感知受期望管理，真实 ≠ 被感知为真实 | **否** | **仍然成立，且不因技术改进而消失**。§1.1：「if expectations are not properly managed, then **even truly human-level intelligent behavior might be perceived as incompetent**」 |

> **⚠️ 2026-09-05 复核修正**：上一版判定 Gap 1a "在本项目里不成立"，理由是「项目是文本/结构化动作，词汇近乎无限」。
> **这个前提是错的**——它描述的是未来可能的文本化版本，不是现在的实现。
> 实际实现 `Demo codex-generated/Inc/action.h:6` 的 `ActionType` 是 **16 项封闭枚举**，且 `ActionDefinition` 只有 `default_duration_minutes` 常量，**没有强度/方式等连续参数**。
> Rabin 的例子是 2 音效 + 4 动画；我们是 16 个动作。**量级大 4 倍，但性质相同：封闭、离散、无连续维度。**
> **正确判定：Gap 1a 部分成立。** 它不成立的那部分不是"词汇无限"，而是"评测目标是 π(A) 分布而非单个已实现行为"——但留一预测的 ground truth 是**实际发生的那一个动作**（16 选 1），所以**对我们的主指标而言 Gap 1a 成立**，其作用是**限制可测效应量的硬上限**（ln 16 ≈ 2.77 nats）。
> 完整复核见 [`审核_整合系统视角复核_2026-09-05.md`](审核_整合系统视角复核_2026-09-05.md) §1、§3。

**修正后的判定**：

- **Gap 1a 对本项目的威胁恢复，但边界精确**：它不否定机制，只**封顶可测效应量**。直接后果是 ΔNLL 的判定阈值**必须与动作集规模挂钩**，否则实验必然失败（见复核 §3）。这条要在任何对外表述里显式处理，否则会被直接引用来打本项目。
- **Gap 1b 保留**。它不反对内部状态建模，只反对"内部状态自动等于被感知"。对本项目是一条设计约束：**若最终要面向人类评价，期望管理是独立变量，必须控制**（对应 T15 里的"控制叙事 framing"）。若评价协议是 held-out NLL 而非人类评分，1b 也不适用。
- 原「若主张 S 让 NPC 更 believable 则被否定」的判定**只在 3A 动作游戏语境下成立**，不应外推到文本场景。**上一版外推了，已撤回。**

**§6.3.1.1 Gap 3 详述**（用户 2026-09-05 要求展开）

Rabin V3 C01 §1.3.2 提出 **vocabulary of the AI**：

> "Let us call this the **vocabulary of the AI**. The vocabulary consists of **every dialog clip, every grunt, every animation, every movement, and every interaction**. Imagine that an AI character had only two sound clips (an attack grunt and a death cry) and had only four animations (idle, walk, attack, and die). … **There is virtually no way you can convey a deeply intelligent AI with such a limited vocabulary.**"

程序员唯一能**程序化**增加词汇的手段是**视线控制（head look）**，原文说得很直白——用它为一个"瞬间做出、之后就再不关心"的决策表演出深思熟虑：

> "This can **telegraph deep intelligence** to the player for something that the AI **instantaneously chose and is no longer concerned with**. However, it is the showmanship of the situation that will convey a conscious and relatable AI character."

另两个例子：Façade（2005）在听不懂玩家输入时让角色**挑一下眉**——"the interpretation is left up to the player, because it is an **ambiguous reaction**"，让玩家自己投射解读；F.E.A.R. 的守卫战斗对话"Where did the player go?" / "He is behind the boxes!"——原文自承是 "**smoke and mirrors**"，由一个模块监控战况后在合适时刻调用对话。

**三条推论**：

1. **解释了为什么"厉害的 NPC"最先出现在文字/对话场景**，而不是 3A 动作游戏。
2. **"3A 游戏 NPC 很弱"不能当基线论据**——那不是 AI 差，是表达带宽受限。
3. **表现力与可检验性是反向的**。原文的意思是：词汇越贫乏，越能用表演掩盖内部状态的缺失。反过来——**表达通道一旦变丰富（文本），内部状态是否真实就变得可检验了**。这条对本项目的定位是**正面的**。

**§6.3.2 LLM 打破的是成本与带宽，没有打破需求与取舍。**

| Gap | LLM 是否打破 |
|---|---|
| 1 玩家感知优先、2 公平性优先 | **未打破**——是设计选择，不依赖技术能力 |
| 3 表达词汇瓶颈 | **已打破**——自然语言/结构化动作近乎无限词汇，3A 的动画配音瓶颈不存在 |
| 4 规模与深度互斥 | **部分打破**——降了单角色成本，但"上千 NPC 时没人在乎细节"仍成立 |
| 5 Authoring 成本 | **已打破（最显著）**——维度与参数不必 hand-tune；但可调试性可能变差 |
| 6 无评价协议 | **无关**——这是项目自己要建的 |

`[待用户确认]` 由此得出一个**定位建议，不代决**：若写成「用 LLM 做出更 believable 的 NPC」，会同时撞上 Gap 1（业界否定）与 Gap 4（规模下无需求）；若写成「**把 authoring 成本降一个量级，从而第一次能系统评测这些内部表示的预测质量**」，则不与 Gap 1 冲突、直接填补 Gap 6，并对 Gap 5 给出可检验的替代——**T20 的等维度对照，测的本质就是"理论维度 vs 设计师 applied role-play 等维度"**。这条影响 [T13](TODO.md) 问题卡怎么写，建议尽快拍板。

**§6.3.2.1 为什么"上千 NPC 时没人在乎细节"对项目不成立：主语是 the player，而人物一致性检测里没有 player。**

用户 2026-09-05 指出「游戏里面的驱动系统和人物一致性检测实际上有点区别的」，并表示即使在游戏里也不完全认同 Zubek 那句话（"NPC 有自己的有限生活和故事是比较好的，虽然不能太过"）。这个区分成立，且可以精确化。

Zubek（V3 C34 §34.2.2）原句的语法主语是 **the player**：

> "they should be pretty predictable, because there were too many of them in the building **for the player** to care about them in detail"

**Gap 4 的成立条件是"存在一个会失去耐心的玩家"。人物一致性检测任务里没有这个角色。** 差别不在技术，在评价者：

| | 游戏驱动系统（Zubek 的场景） | 人物一致性检测（本项目） |
|---|---|---|
| 评价者 | 玩家 | held-out 预测协议 |
| 评价方式 | 实时、主观、可容忍、可跳过 | 逐决策点、客观、**不可跳过** |
| 能否"不在乎" | 能——这是该句成立的前提 | **不能——协议强制你必须预测下一个行为，无论你想不想关心这个 NPC** |
| 数量与深度 | **互斥**（Gap 4 成立） | **不互斥** |
| 刻板是否可接受 | 可接受，甚至是设计目标（"stereotyped, routinized lives"） | 刻板 = 高可预测性，但那是**要测的结果**，不是设计目标，也不是缺陷 |
| 失败模式 | 玩家出戏、觉得假 | held-out NLL 高 |
| Gap 1a（状态渗透不进为） | 成立（词汇贫乏） | **不成立**（文本通道） |
| Gap 4（规模深度互斥） | 成立 | **不成立** |

**判定**：六条 gap 中，**Gap 1a 与 Gap 4 都是在"游戏驱动系统"语境下成立、在"人物一致性检测"语境下不成立**。**这不只是辩护，它是本项目的定位依据**——项目做的不是游戏驱动系统，是后者的评测协议。因此：

- 上一版把 Gap 4 转成"NPC 数量须 1–10"的 T13 硬约束，**这个转换是基于误用的语境**。深层建模的需求约束来自评价协议与成本，不来自"玩家是否在乎"。**T13 的该约束已改为建议而非硬约束。**
- 用户的直觉（NPC 有有限的自己的生活是好的，但不要太过）与文献不冲突：Zubek 反对的是**深度**而非**存在性**——他要的是"stereotyped lives"，不是"没有 lives"。§1.3.4（Have a Reason to Exist）甚至明确支持后者：「AI characters should have **a reason to exist beyond the player**」。

**§6.3.3 一个必须处理的术语冲突：personality。**

V3 C01 §1.3.5：「a carefully crafted personality can convincingly convey there is something beneath the surface of your characters, **whether there is or not**」；「a strong personality goes a long way to **covering up any inconsistencies in the behavior or logic**」。

| | 业界用法 | 本项目的 `P` |
|---|---|---|
| 作用 | 掩盖机制的不一致 | 驱动机制 |
| 与行为的关系 | 为不一致提供豁免（"strong personalities can be irrational and unpredictable"） | 应产生一致、可预测的行为倾向 |

**项目的任何对外表述必须显式区分这两者**，否则会被按业界默认含义理解成"用个性掩盖不一致"——与本意正好相反。

**§6.3.4 两条附带修正。**

- **"3A 游戏 NPC 很弱"不能作为基线论据**。那不是 AI 差，是表达带宽受限（Gap 3）。比较对象应选文本/对话场景的近邻。
- **Goap/HTN 类"通用机制"有一条实证反驳**：Zubek（V3 C34）的 planner「performance exceeded expectations」，仍被弃用，因为 NPC 生活刻板导致「only a handful of distinct plans actually got created and then cached」——**通用机制的复杂度在刻板场景下是纯浪费**。

当前库是定向种子库，未完成可复现检索式、数据库覆盖和引文追溯；尤其不能保证已覆盖 ACM、IEEE、Springer、ACL、AAAI/IJCAI、AAMAS、NeurIPS/ICLR、CogSci 及心理学/计算社会科学文献。**游戏工程侧的缺口更大**：GDC 与 Game AI Pro 全文不在任何学术索引内，本次只有 2 篇属该来源。未查到可能是漏检、索引/全文访问限制，也可能已有等价工作；不能据此保证新颖性或发表前景。

## 7. 保留、但不挤进首版的分支

- **P 可塑性两条原意**：反复 S/目标/行为轨迹的慢性巩固；强事件先作用于 S，超过预定义阈值才允许部分沉淀进 P。均待公式与证据，不是发生大事就改人格。
- **多角色社会动力学**：B 未回复 → A 误以为被回避 → A 疏远 → B 反应 → 关系真正变化。保留误解经行动成为新事实的链，而不是 relationship -= 1；有向角色关系的所有权见完整机制。
- **叙事自动变成实验世界**：对象、状态、affordance、信息 mask 的抽取是独立技术责任，先不作免费前处理。
- **专用模型与开放世界**：机制有效后再考虑训练理解 W/O/S/P 的模型、丰富 NPC、游戏引擎/UI；不作为研究启动前提。
- **动态意图跟踪的迁移**：连续证据→隐状态估计→未来预测与用户 intent/goal 的收敛、漂移、暂停、恢复有方法交点；两个项目的任务、语义和证据不能合并。
- **在线延迟的三种工程想法**：行动酝酿、向玩家显示落后于计算世界的副本、角色显示“思考中”并暂停下一动作。保留为后续选择，不在同步 demo 中新增三套系统。
