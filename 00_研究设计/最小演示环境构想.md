# 最小演示环境构想：单角色 Character Dynamics Lab

记录日期：2026-09-02  
状态：**演示规格已细化；具体状态机制、动作策略与实验数据仍待定。用户将在独立 coding 会话中自行以现代 C++ 实现。**

## 目的

做一个“小房间 + 一个人 + 连续几天”的可回放 demo。它同时承担两种职责：

1. **实验装置**：受控地产生 `W/O/StateDelta/S/action` 轨迹，比较状态更新方法、基线、干预与消融；
2. **公开演示**：在实验稳定后，以最小可复现仓库展示“同一角色因经历与状态不同而做出不同微行为”。

它不是完整游戏，也不以做地图、UI 或多 NPC 社会模拟为第一目标。时间与界面并非装饰：应让人看见角色在几天内经历什么、知道什么、做了什么、哪些状态发生变化，以及这些变化如何影响下一动作。

## v0 场景边界

```text
一个房间（连续数天）
一个角色 A
少量对象：床、桌子、椅子、电脑、手机、灯、门
少量世界变量：日期/时钟、动作持续时间、可选的金钱/订单状态
可选外部事件：消息/未回复、时间流逝、门外动静、网购订单状态变化
```

`W` 保存对象状态、位置、时间、事件与动作合法性；角色只接收 `O` 中允许看见或收到的信息。角色并不直接改世界，而是从 affordance provider 给出的合法动作中产生分布，再由 world executor 结算。

场所仍是 W→O 的第一层过滤器：A 在某场所时，该场所变化进入候选观察流；具体哪些字段更新到 `O_A`，再由可见/可听/注意力等可配置规则决定。离开场所后，对应 O 视图保留并可随时间成为 `stale` 或 `unknown`。

现有 [demo/](../demo/) 是此前留下的浏览器脚手架，不是用户将要编写的 v0，也不应被当作研究实现或 C++ 参考。保留它以免无授权删除；后续 C++ 实现由用户在单独 coding 会话中自行启动，本研究会话不继续改动其代码。

## 连续数日的可展示轨迹

每一轮至少展示：

```text
Day / clock / 当前场所与对象状态（W）
角色本轮可知的信息（O，含 fresh / stale / unknown）
事件的结构化意义（X）
启用状态字段及其变化原因（S）
本轮决策上下文与候选动作分布（D / π(A)）
选中的人物级动作、世界原子效果与来源链
```

第一批行为链不是最终心理学规则，而是 demo 必须能承载、用来检验状态/动作接口是否真的连通的**情境要求**：

```text
无聊 / 低投入 → 玩电脑或玩手机
长时间设备使用 → 不适、疲劳或睡意上升 → 更可能睡觉/休息
感到自己拖延或懒散太久 → 焦虑/紧迫感上升 → 可能短时学习
产生购买欲 → 在手机/电脑可用、且角色知道相关条件时 → 网购
```

这些链条必须允许竞争和失败：焦虑不保证一定学习，疲劳也不必每次立刻睡；它们只要求状态的改变能让动作分布出现可追踪的方向变化。具体使用哪些 X/S 字段、怎样更新、每种变化的大小和阈值，留给状态机制阅读与实现配置决定。

`网购` 的世界后果也必须可结算，例如订单创建、可用余额/物品状态、后续到货事件；不能只作为一条不改变 W 的文本动作。

## 实验要回答什么

同一终局、不同历史或可知信息时，比较：

```text
persona only
persona + raw history
persona + summary
persona + Character State v0
```

观察真实/预设目标动作的排序与概率、干预后的分布方向，以及关闭某个 state module/operator 后的变化。demo 的场景脚本和随机种子必须固定，以便不同版本可重放。

## 建议的最小运行模式

```text
Replay mode
固定事件 trace → 更新状态 → 输出各动作概率 → 与 trace 中目标动作比较

Intervention mode
复制同一终局 → 只改一段历史或观察 mask → 对比 state/action distribution

Simulation mode（后置）
按分布采样动作 → world executor 结算 → 继续下一 tick
```
