# 任务、承诺与单步行为改造方案 v0

更新时间：2026-09-05  
状态：**已确认的 Demo 改造方案。目标是修正任务进度、长期承诺和单步行为之间的语义混淆；不改写 W/O/X/S/D/P 主链，不把本方案当作心理学验证。**

## 1. 修改动机

当前 Demo 把下列三种不同时间尺度的量混在了一起：

```text
长期任务：完成 coursework
单步动作：StudyAtDesk / StudyAtComputer
短期持续性：PersistentIntention
```

现有结算是固定的：

```text
一次 StudyAtDesk 或 StudyAtComputer
→ task_progress +1
→ task_target = 8
```

因此“完成长期学习任务”严格等于完成 8 次学习动作；同时，`PersistentIntention` 只保存一个 `ActionType` 并给同一动作加有限决策点的 activation bonus。它无法表达“同一任务可经不同动作推进”“吃饭后暂停而非放弃”“任务完成后压力解除”等语义。

本改造要实现：

```text
Task：长期要推进什么
Commitment / Intention：当前优先推进哪项 Task
Action：本轮只执行哪个单步行为
Settlement：该 Action 对 Task 实际推进多少 effort
```

## 2. 不修改的主链与边界

既有运行链保持不变：

```text
W → SceneFilter → PerceptionFilter → O
→ Appraisal X → State S → Decision D
→ π(A^char) → W settlement
```

具体不改动的职责：

- `W` 仍是世界事实、动作 precondition、时间和后果结算的唯一权威；
- `O` 仍只保存角色可知、可见或陈旧的世界信息；
- `X` 仍将观察与上次自我行动解释为结构化意义；
- `S` 仍维护疲劳、饥饿、焦虑、满意度等持续自身状态；
- `D` 仍是仅本轮存在的决策上下文；
- `ActionType` 仍是每轮只选择一个的单步动作；
- 人格参数、世界事件种子、动作采样种子和 provenance/replay 方向保留。

v0 不引入：多步宏动作、复杂规划树、在线 LLM、人格可塑性、未记录的随机心理结果，或“行动酝酿/准备中”层。

## 3. 通用世界任务

### 3.1 任务语义

任务是世界中长期存在、可推进、可完成或可阻断的对象，而不是若干 action 的别名。第一版只实例化一个 `coursework` 任务，但接口必须允许未来添加报告、阅读、整理、锻炼、回复消息等任务。

建议数据结构：

```cpp
enum class TaskStatus {
    Active,
    Completed
};

struct WorldTask {
    std::string id;
    std::string label;
    double effort_done = 0.0;
    double effort_target = 8.0;
    TaskStatus status = TaskStatus::Active;
    std::vector<ActionType> supporting_actions;
    int due_at_total_minutes = -1;
    double urgency = 0.0;
};
```

任务属于 `W`：其真实进度、完成判定、可被哪些动作推进、截止时间与任务相关世界事件均由世界保存和结算。

### 3.2 连续 effort，而非固定动作计数

任务完成条件从：

```text
8 次学习 action
```

替换为：

```text
effort_done ≥ effort_target
```

`StudyAtDesk` 与 `StudyAtComputer` 仍是单步 action，但其含义变为一次学习 session。每次 session 的实际产出可变：

```text
coursework：2.40 / 8.00
StudyAtDesk（30 分钟）
→ effort_gained = 0.48
→ coursework：2.88 / 8.00
```

因此相同的 8.0 工作量可以由不同数量的 session 完成；它不再等价于恰好 8 次学习 action。

## 4. 任务绑定的 Commitment / Intention

当前动作级 `PersistentIntention(action, remaining_decision_points)` 替换为任务级承诺：

```cpp
enum class CommitmentStatus {
    None,
    Active,
    Suspended
};

struct TaskCommitment {
    CommitmentStatus status = CommitmentStatus::None;
    std::string task_id;
    std::string reason;
    int started_at_total_minutes = -1;
    int suspended_decision_points = 0;
};
```

承诺不要求人物重复同一 action。例如：

```text
Commitment(coursework, Active)
→ StudyAtDesk
→ GetMeal：Commitment 变 Suspended
→ RestAtBed：仍可保持 Suspended
→ 条件恢复后 StudyAtComputer
→ coursework Completed：Commitment 清除
```

最低限度的状态转换：

```text
None → Active：学习动作开始推进未完成 task
Active → Suspended：吃饭、如厕或休息等短期身体需求优先
Suspended → Active：任务仍未完成、可支持动作可用、身体需求不再主导
Active / Suspended → None：task completed。`failed / blocked / abandon` 是后续扩展；在其各自的 W 事件、O 可知性和转换规则被定义前，不预留“看似支持、实际未结算”的枚举状态。
```

## 5. 单步 Action 与目标任务的关系

每轮仍只选择一个 `ActionType`，并不选择“完成任务”或自动执行多步脚本。对能够推进任务的 action，结算时使用当前 active/suspended commitment 指向的 task；无承诺时，首次可用学习 action 可建立对唯一未完成任务的承诺。

第一版不必新增 `CharacterAction { ActionType, task_id }` payload：因为仅有一个 `coursework` task，世界可安全地从 commitment 解析目标。未来引入多个同类 task 时，再将 target task 显式放入人物级 action/provenance，避免一个 `StudyAtDesk` 对多项任务的目标歧义。

## 6. 可复现的任务 effort 结算

任务推进由 `W` 结算。第一版采用可追溯、确定性的公式：

```text
effort_gained =
  base_effort(task, action)
  × duration_factor
  × interruption_factor
  × seeded_variation
```

各因子边界：

- `base_effort`：由 task 的世界配置和 action 类型决定；
- `duration_factor`：来自真实结算的 action duration；
- `interruption_factor`：世界事件缩短/中断 session 时降低；
- `seeded_variation`：由 scenario seed、task id、执行序号确定，限制在 `[0.90, 1.10]`。

任何一次结算应记录基础值、variation、是否中断和最终 effort。相同 scenario seed、同一动作序列下结果必须一致。

`W` 不应直接读取所有心理状态后偷偷改变效率。疲劳、焦虑、屏幕疲劳首先经 `S → D → π(A)` 影响角色是否学习、选择哪种学习 action、是否休息。若后续需要表示“相同 session 但状态差导致低效率”，必须单列可追踪的 action-quality 接口，而非跨层隐式读取。

## 7. 任务完成闭环

任务完成不能只让学习 action 从可行动作集消失。正确数据流为：

```text
W：effort_done 达到 effort_target，task status = Completed
→ O：角色通过自我行动和任务可见事实得知完成
→ X：task_completed / achievement / deadline_resolved
→ S：降低与该任务关联的压力和焦虑，提高 satisfaction
→ Commitment：关闭对应 task_id 的承诺
→ D：不再把该 task 作为活跃目标；任务提醒不再生效
```

这样修复旧版“任务已完成但 task_pressure/anxiety 仍长期饱和”的机制缺口。

## 8. 适量的世界种子随机性

`scenario_seed` 可以决定：

```text
- task effort_target；
- deadline、reminder 和外部打断的时间；
- desk/computer 对该 task 的基础效率；
- seed variation 的确定性序列；
- task 相关世界事件是否出现。
```

不允许使用未记录来源的随机状态增减、不可重放的成功率或任务完成概率。角色动作采样继续由独立 `action_seed` 控制，避免把世界难度与人物选择随机性混为一谈。

## 9. 实施范围与验证

### 修改模块

- `world.h/.cpp`：引入 `WorldTask`、任务查询、连续 effort 结算与完成事件；
- `state.h`：将动作级 `PersistentIntention` 改为 `TaskCommitment`；
- `decision.h/.cpp`：决策说明和学习 action bonus 改为 task-bound commitment；
- `appraisal.h/.cpp`：增加任务完成 appraisal；
- `observation.h/.cpp`：暴露 task 状态/进度，并将完成作为可感知更新；
- `simulation.cpp`：将 commitment 传入世界结算、扩展 CSV、补充 verify；
- `README.md`：更新当前任务和 batch 语义。

### 必须通过的验证

1. 同一世界种子、动作种子和人格配置重复运行，任务 effort 与完整轨迹一致；
2. 每轮仍只选择一个 `ActionType`；
3. coursework 完成不再等价于固定 8 次学习 action；
4. 吃饭、如厕、休息会 suspend 而不是销毁未完成任务的 commitment；
5. 已完成任务不会再发出相关 reminder；
6. task 完成会关闭 commitment，并对 task pressure/anxiety 产生可记录的 completion update；
7. batch 仍运行 `32 × 8 × 256 = 65,536` 个决策点，并输出可比较的 CSV；每次运行创建唯一子目录，CSV 明确区分 `pre_*`、`outcome_*` 与 `post_*` 时间切片。

## 10. 后续但不在本次改动内

本次只修复“单一通用 task 的连续进度与任务承诺闭环”。完成后才单独引入多个任务，研究 candidate goal、selection、commitment 和 reconsideration 的竞争；届时需要显式的 `(ActionType, task_id)` 人物级动作 payload，并将每项 task 的提醒、deadline、进度与状态写入日志。
