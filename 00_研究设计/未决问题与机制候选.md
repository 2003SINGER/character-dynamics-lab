## Q01 分段逆映射与量变质变

### 用户原意，不能再换成模型的说法

> 可以引入正态分布的那个比例，但是是逆过来的，比如说0到1中间那68%就对应着正常阶段，0.5+-0.34就是正常，再0.135就是独特，再向外就是异常，这个划分不仅仅是命名方面，还可以作为公式设计进入机制，具体来说，数值加减仍然保持，但是以人物状态或心理或P为输入的函数就需要区分开这几个阶段，达到量变引起质变的效果，体现出差异性。

用户进一步明确：“逆过来”说的就是逆映射。它不是“状态应该服从正态分布”的要求，也不只是分段命名。

### 两种等价的分区实现

保存值 u∈[0,1]，数值更新仍连续加减；消费函数按阶段产生不同响应：

| 阶段 | 用户近似分界 | 两侧不能混成同一种含义 |
|---|---|---|
| 低端极端 | [0, .025) | 低值的领域语义 |
| 低端独特 | [.025, .16) | 从低端进入常态 |
| 中央常态 | [.16, .84] | 中央 68% 轴宽 |
| 高端独特 | (.84, .975] | 从常态进入高端 |
| 高端极端 | (.975, 1] | 高值的领域语义 |

可以直接按上述边界分段；也可以先做 z=Φ⁻¹(u)，再按对应 z 区间使用不同响应。若采用精确标准正态 ±1σ/±2σ 分区，则 u 边界约为 .02275/.15866/.84134/.97725。近似版与精确版单独命名配置，不能混用后宣称完全一致。计算逆函数需处理 0/1 的无穷端点；仅分段则无需真的求逆函数。

### 真正需要设计的是消费函数

- u 的增减与存储不必更改；X、U、D/policy 中消费该量的位置可采用阶段响应，而非只换日志标签。
- 连续分段可保持函数值连续、但越界后斜率改变；硬阈值可改变行为模式或门控；sigmoid 可平滑阶段过渡。不能擅自只许平滑，抹去用户要的质变。
- 一个高端连续分段示例是 h(u)=a0·u+a1·max(0,u−.84)+a2·max(0,u−.975)。这只是待比较形状，不是选定公式；低端需独立设计。
- 若采用滞回（例如 .84 进入高区、.78 退出），它会增加跨轮阶段记忆，必须明确所有者、初始值和独立消融，不是免费的数值技巧。
- 疲劳低端可代表充分恢复，不是疾病或“异常人格”；压力、满意度、自控也不能共用解释。所谓正常/独特/异常是机制分区，不作临床判断。
- 轴上 68% 不是人物 68% 的时间，也不是已经校准的人群百分位。可以先作为人为响应坐标，之后再检验尺度。

### 最小判定

先选一个变量与一个消费位置，例如 fatigue→recovery_drive，比较线性/连续分段/阶段 gate；其余 W/O/S/P、seed 和输入固定。边界两侧记录实际函数、Δπ、行动资格与后续状态，检查阶段差异、抖动、饱和和恢复。P 也能使用此映射，但先固定一个作用位置，运行内仍不学习 P。

这是拟议实验，不是已经写入 C++。要证明心理/预测收益，还需独立行为数据或干预评价，不能用自己编出的轨迹当答案。

### 文献判定（2026-09-05，结论为否定）

Fleeson 2001 的密度分布模型**不能**为本分区提供依据。它是**个体内（within-person）跨时间**的状态分布；本节的 σ 直觉是**人群横截面**分位，两者坐标轴不同。论文未检验状态分布正态性、未使用任何 σ 分位切点、不支持"消费函数按段落产生不同响应"，并给出替代解释：个体差异由**情境线索**触发，而非状态值 u 自身越过阈值。论文图 3 的正态曲线是外加绘图假设，非被检验结论。

若要保留本机制，建议改以角色自身的 `(μ_i, σ_i)` 为基准做**角色相对**分位（依据：Location 稳定性 r=.87–.98、Size 稳定性 .55–.90）。这会补上 S 目前缺失的 σ_i，但属语义变更，需用户确认，不由核读代决。完整判定、原文引句与替代文献指引见[X 维度与状态动力学核读](../01_文献/专题核读_X维度与状态动力学_2026-09-05.md) §6。

### 文献判定补充（2026-09-05，utility theory：支持"分段响应"，不支持"正态折点"）

Fleeson 不支持本分区，但**分段响应本身有强得多的正面依据**。Utility 2013 §9.5.4 描述该手段的动机，与用户原意几乎逐字一致：

> "Designers want a finer degree of control. They want the ability to have a Sim **completely ignore hunger until it reaches a threshold, then get a little hungry, then suddenly get very hungry**."

两个后果，方向相反：

1. **支持保留**：分段响应是成熟工程手段，有据可依。但应改称**「分段响应曲线（utility response curve）」**，定性为 **authoring 工具，不是心理机制**。作为 authoring 工具，它不与 T20 的等维度对照冲突，也不必宣称心理学收益——它本来就是给设计者用的。
2. **不支持正态折点**：Utility theory 对折点位置的答案是「hand-tune a bunch of 2D points」，即**手工调参、任意设定**。若坚持用正态 ±1σ/±2σ 当折点，是在已被认可的"手工调参"之上，额外加了一层**未被认可的参数来源**。

还有一条更便宜的替代路径：Utility 2013 §9.7 的 **inertia** 与 §9.6 的**分桶**已涵盖 Q01 想要的部分效果（阈值门控、路径依赖、迟滞）。**若 Q01 的动机是"要质变与迟滞"，分桶 + inertia 就够了，分段曲线不是必需的；** 分段曲线相对它们多出来的，只是折点位置的连续可调。

本项按用户 2026-09-05「先不拍板，再调查调查」的要求保持未决。以上只登记证据，不代决。

#### ⚠️ 实现条件核查（2026-09-05 复核）：**Q01 在当前动作集下不可检验**

此前"保持未决"的理由是**资料不足**。复核后发现更根本的问题：**拍板所需的实验条件还没建立**。

Q01 的核心是「量变引起质变」——需要一个**可被观测的"变"**。但当前实现：

```cpp
// Inc/action.h:6 —— 当前为 16 项实际动作 + Count 哨兵（旧版 15 项实际动作 + Count；不是 16→17）
enum class ActionType { UsePhone, ShopOnPhone, UseComputer, StudyAtComputer,
    StudyAtDesk, RestAtBed, SleepAtBed, GoToBathroom, GetMeal, TurnLightOn,
    TurnLightOff, TurnOffAlarm, OpenCurtain, CloseCurtain, Idle, Count };

// 无强度 / 方式 / 时长选择等连续参数
struct ActionDefinition { std::string_view name; int default_duration_minutes = 0; };
```

于是「心不在焉地学」「专注地学」「咬牙硬撑地学」**全部映射到 `StudyAtDesk`，不可区分**。

**后果：任何基于行为序列的评测——留一预测、N-gram 对照、ΔNLL——都测不出 Q01 的差异。** 状态带不同，行为标签相同。

任务进度（`task_effort_gained`）虽然变化，但它来自 `world.settle()` 的**世界结算**且带 `settlement_variation` 噪声，**不是 agent 的决策输出**。拿它当观测量，等于把世界噪声当成行为质变，正踩 `前台问题与候选创新.md:58` 的警告。

**要检验 Q01，必须先三选一（设计决策，需用户拍板）：**

| 方案 | 做法 | 代价 | 备注 |
|---|---|---|---|
| **(a) 动作加参数维度** | 保留 `ActionType`，增加 `intensity ∈ [0,1]` 或离散档位，决策时同时选类型与强度 | 动作空间 16 → 16×K，N-gram 基线的 `E` 随之扩大 | 表达力最强 |
| **(b) 动作标签分级化** | `StudyAtDesk` 拆成 `StudyHalfhearted` / `StudyFocused` 等 | 词汇表膨胀，但保持离散 | **与 N-gram 基线最兼容**，不需改 π(A) 形式 |
| **(c) 承认当前射程不够** | 明确写「v0 只检验类型级选择，段内质变推到下个版本」 | 最省事 | 等于把原始核心想法推迟 |

**倾向 (b)**：离散标签兼顾可检验性与基线兼容性，只需把 `E` 从 16 换为更大值。但这是设计决策，不代决。

详见 [`审核_整合系统视角复核_2026-09-05.md`](审核_整合系统视角复核_2026-09-05.md) §2。

#### ✅ 拍板（2026-09-05 晚）：选 (b)，但落法是「拆分」不是「加参数」

用户决定：**`StudyAtDesk` 拆成 `StudyFocused` / `StudyHalfhearted`。**

即 |A|：16 → **17**。ln17 ≈ 2.833 nats（ln16 ≈ 2.771），熵上限变化 +0.06 nats，可忽略；π(A) 形式、softmax、N-gram 基线**全都不用改**。这是三个方案里改动代价最小的。

**但拆分本身不等于 Q01 可检验。** 拆完之后还有一个设计约束必须满足，否则实验会自我实现：

> ⚠️ **禁止让 focus/halfhearted 的选择成为 S 的确定性函数。**

若两者共用同一组 state 字段、仅系数不同，那么"预测 focus 还是 halfhearted"就只是"预测那组字段的线性组合"——多一个自由度而已，不是机制上的新东西，raw-history 基线照样学得会。

**要让 Q01 真正可检验，拆分必须引入原 `StudyAtDesk` 不消费的输入。** 该动作已拆为 `StudyFocused` / `StudyHalfhearted`；以下建议保留为后续实验约束，不表示尚未实现拆分：

| | 建议额外依赖 | 理由 |
|---|---|---|
| `StudyHalfhearted` | `boredom`、`commitment.suspended_decision_points`、**距上次中断的步数** | 「被打断后回来学，人在心不在」是**历史依赖**的，raw-history 需要自己把这段历史翻出来 |
| `StudyFocused` | `satisfaction`、**连续未中断的步数**、距 deadline 的余量 | 同上，需要跨时间的量 |

这样 Q01 的检验才落到它本来的意思上：

> **P(Halfhearted \| task_drive, fatigue) 在某个字段的阈值附近是否存在跳变，而不是线性渐变？**

这一条**不需要新实验就能看**——只要 T25 把 π(A) 列落盘，就能直接在数据上做回归检验。这是 T25 价值最大的一个副产品。

**连带影响**：`decision.cpp:85` 的 `advances_committed_task` 判断里显式列了 `ActionType::StudyAtDesk`，拆分后必须同步（两个新动作都应算作推进任务）。

### 文献判定补充 2（2026-09-05，Côté：滞回有先例，但动机是去抖不是质变）

Q01 提到"若采用滞回"。Côté 2013（Game AI Pro Ch11 §11.3.1）确实用了一整段处理滞回，场景是视线时断时续导致 Chase/Patrol 反复切换：

> "we can solve this issue by hooking the transition's threat-sighted symbol to a **logical representation** of seeing/losing a threat... that would include some form of **filtering (using hysteresis algorithms or other similar methods)** to avoid creating undesirable oscillations."

**必须区分清楚**：这里的滞回用于**感知过滤以避免行为震荡**，不是 Q01 想要的"量变引起质变"。两者都用到滞回，但**动机与验收标准完全不同**——引用本篇只能支撑"用过滤避免抖动"，**不能**支撑"分段消费函数产生质变"。若要主张后者，仍需在 T22 的可证伪链里单独测。

## Q02 X 与字段动力学如何真正分开

现代码 Appraisal 直接携带 boredom/fatigue 等九个状态增量；state.cpp 再加时间/P 项并裁剪。文件拆开了，但还不是“事件意义 X”与“字段自身 U_k”的完整语义拆分。同一 use_phone/study 动作仍近似固定正负效果。

待决定：最小 X 是否采用目标相关性、进度差距、紧迫性、可控性、coping/预期后果等少量维度？如何结合目标、时机、自愿性、实际进展与重复，区分同一动作的不同意义？新证据如何重评估，而不是把第一次解释永久累加？

建议先以规则实现同一动作的两个目标情境，输出结构化意义，再由一两个字段 updater 消费；保留旧映射作为基线。不要一次搬入整套心理学指标，也不默认 LLM 直接给 StateDelta。文献依据和提案来源见[三项 TODO 定向核读](../01_文献/专题核读_三项TODO与机制修改方案_2026-09-05.md)；该文是定向核读，不等于所有心理学论文已精读完毕。

2026-09-05 补充：**「X 不直接写状态增量」有直接文献依据**（EMA 2009 把 appraisal 建模为只读的 continuously active feature detectors，状态写入由 coping 经 `update belief / update intention / update plan` 完成）。但**「每个字段各有自己的 U_k」在已核读的 12 篇中一篇都没有**，属本项目自创，不能引这些文献背书。可搬的只有"appraisal 只读 + 独立控制过程写状态"这一分层。最小 X 维度候选与术语冲突见[X 维度与状态动力学核读](../01_文献/专题核读_X维度与状态动力学_2026-09-05.md) §2。

## Q03 独立更新如何做到低耦合而不割裂机制

用户要求的是工程上的独立简单、容易替换，不是各心理字段互不作用。当前 state updater 集中在一个函数；没有按字段注册的可替换实现，日志/batch/内建验证也仍集中于 simulation.cpp。

候选做法：读取同一只读快照和显式配置，各 updater 产生带 provenance 的 patch，再由唯一写入方按声明的依赖顺序合并。需决定同一字段多 patch 的冲突规则、何处裁剪、跨字段依赖是否用旧值、每字段 Δt 怎样计算；不能让插件调用顺序偶然决定心理结果。

最小验收是替换一个更新器不改 World，不改变无关字段；增加普通 Object 不改心理状态类；关闭模块确实切断更新及直接/间接 policy 影响。只为这些需要引入接口，不做动态加载器或庞大规则 DSL。simulation 拆分只有在职责确实妨碍修改时才做。

## Q04 主观动作候选与隐藏条件

v0 已修正：`A^O` 不再从 `world.available_actions()` 取真实合法动作，而由 O 中可见对象、稳定 affordance 与**已知前置条件**生成；W 独立检查钱包、任务、物品故障及房间条件，拒绝结果再经 typed self-feedback 回 O。内建 verify 固定了两个反例：余额不足时 `ShopOnPhone` 仍在 `A^O`、故障电脑仍可见且 `UseComputer` 可被尝试后拒绝。T42 已接通最小 `InformationAccess` 与 O-known/W-authoritative 区分；对象级错误 belief、遮挡、实例绑定和一般化反馈策略仍未实现。正确目标仍是 `A^O = ResolveAffordance(O, B^{precondition})`：角色已知“灯已开/窗帘已开”可以移除无效候选；未知余额、内部故障、远端服务状态不能提前移除，仍由 `A^W = ValidateWorld(W)` 在结算时决定。

这只是最小语义，尚未等于一般的 belief/action 系统：当前场景把在场对象及其稳定 affordance 直接视为角色已知；没有对象级错误 belief、遮挡规则、实例绑定或“角色以为对象不在但其实在”的生成器。不可见、消失、不可用仍必须分开建模，不能用一个 stale 标记代替。

任务完成也不得因 W 已结算而直接解除 S：默认 self-action completion feedback 会把完成写入 O；测试可显式抑制该反馈，此时 W 已完成但 O 未确认，commitment 必须保持。`ScenarioConfig.information_access` 已贯穿 trajectory；当前仍是最小三布尔权限，不等于完整的 visible/hidden/stale 感知系统。E0 已作为控制链回归 fixture 使用，但不作为 held-out 行为证据。

2026-09-05 补充：Q04 的"硬守卫还是软偏好"这个反复出现的选择题，**工程上已有成熟答案——同一个谓词声明一次、同时充当 condition 与 weight**，不必二选一。Environment Tactical Querying（Zielinski, Game AI Pro Ch33，Bulletstorm）的 context object 明确用于定义 **subjective world view**，其候选生成器按"a given AI is **aware of**"过滤，正是 A^O 所需的形态。缺点是该方案是作者手写的 test 类型表（Visibility / Distance / Reachable / Current item…），若 A^O 由 LLM 生成则无法直接复用其类型系统。

## Q05 Object 基础动作、Scene 组合及实例绑定

用户已确认目标所有权：Object 提供可接受的基本交互；人根据现实 Scene 设计有生活意义的组合；W 负责最终合法性和结算。这里不是让 Action 从 World/Object 继承。

当前 ActionType 为全局 enum；Object 直接挂完整 use_phone/study/shop 等类型；Scene 只持有 Room/对象查找，没有组合 recipe。W 用 switch 展开与结算；按 ActionType 去重，多个同类型 Object 仍可能取第一个匹配，未绑定具体实例。

候选最小改法：先在 Scene 加一个人工 recipe，明确所需物品/地点条件，输出带 object_id 绑定的人物动作请求；W 解析可信操作。已有动作逐步迁移，保留阅读性，不先做无限动作组合。两个手机、两种学习位置和一个不可用对象应能区分。加入多 Task 前另需 target_task_id 贯穿选择、结算、观察及日志。

recipe 的声明位置与 executor 的实现位置不同：把组合声明移进 Scene，不意味着把世界写入权移出 W。

### 文献补充（2026-09-05）：Q05 拿到了正式骨架

"Object 提供基础动作"这件事在文献里有精确的形式化，Şahin et al. 2007 的 **Definition 2（agent 视角）**：

> "An affordance is an acquired relation between a certain effect and a (entity, behavior) tuple, such that when the agent applies the behavior on the entity, the effect is generated."

记作 `(effect, (entity, behavior))`，实例 `(lifted, (black-can, lift-with-right-hand))`。三条可直接用的性质：

1. **三个分量全部以 agent 感知为准，关系存放在 agent 侧。** 原文："all three components are assumed to be **sensed by the agent**... The entity refers not to an abstract concept of an entity (such as a stone) but to its **perceptual representation** by the agent"，且 "we assume that this relation **resides within the interacting agent**"。
   → affordance **不是 Object 的客观属性**，而是角色与对象交互习得的三元关系，所有权在角色一侧。这正对上本项目的 `O` 而非 `W`。
2. **以 effect 为索引，可直接当规划算子用。** §6：该关系 "is indexed by its effect"，entity/behavior "can be considered to correspond to the **pre-condition and [effect]** of planning operators"。
   → **recipe 可以同时是 affordance 关系与规划算子**，不用两套表示。这条也把 Q05 与 W 侧的前置条件校验接上了。
3. **三个视角显式分离**（Def. 3/4/5）：agent `(effect, (entity, behavior))` / 观察者 `(effect, (agent, (entity, behavior)))` / 环境 `(effect, (agent, behavior))`。
   → `[待用户确认]` 观察者视角可能是未来多角色分支的形式基础，本次不主张。

**诚实边界**：该文是**机器人控制**论文，验证是实体机器人上的初步实验，**与游戏 NPC、与心理状态无关**。搬的只是形式化骨架，不提供任何心理结论，也不能拿它主张本项目的心理学贡献。

另一条与 Q05 组合相关的提醒来自 ETQ §33.5.3 的 validity test：

> "'how to pick a cover point and, later, how to tell if it is still good (**oftentimes not the same thing**)' are nicely gathered in one place."

→ **recipe 的"选择条件"与"保持条件"必须分开声明，但要放在同一处。** 原文明确否掉了两种替代方案（重跑整个查询太贵；另建轻量查询要维护两份同步）。

## Q06 行动质量与任务关联压力

当前 effort 来自世界基础效率、真实时长、中断与 seed；S 主要影响是否学习而非同一 session 的产出。这是已明确的简化，并非必须立即修复的 bug。

若要研究状态影响质量，候选桥为 S/O/commitment → ActionQuality/Engagement → action payload → W settlement。需要定义可执行字段、范围、来源、损耗/中断关系，防止 W 暗读整个 S。先判定任务是否需要该效果，再实现，避免为丰富度增加自由参数。

task_pressure/anxiety 又混合未完成感、DDL、提醒、拖延自责和持续紧张，完成 relief 为固定幅度。候选拆分是 task-specific goal_pressure 与可残留的 general_stress/arousal；只有场景/数据确实需要区分时才加字段，不把新名字当机制。要检验“完成后目标压力解除但疲惫/残留紧张不瞬间归零”。

## Q07 Commitment 的信息入口和生命周期

v0 已修正直接旁路：`update_commitment` 只读取 `Observation.last_self_action`；W outcome 先由 `apply_self_action_feedback` 转写为带来源的 O。默认场景把自己完成刚执行任务视为可立即观察的反馈，但 verify 也覆盖“W 已完成、completion feedback 被抑制”时 commitment 不得自动清空。学习 session 仍会重写 `started_at`，且此最小语义尚不一般化到多任务/远端后果。

本次核对还确认：commitment_can_bias_study 的疲劳/饥饿/如厕门槛只决定是否加学习 bonus。即使门槛未满足，其他分数仍可能使学习被选中，随后 update_commitment 将其设为 Active。因此旧审计的 “gate/defers return” 不能理解为硬禁止恢复。

需要决定：

1. resume 是软偏好还是硬状态转移守卫？若是软偏好，命名/日志不能宣称禁止；若硬守卫，行为与承诺状态要一致并测试。
2. 哪些结算事实是角色立即知道的自我反馈，哪些必须等待观察？以 typed known-feedback 更新承诺，而不是生吞所有 WorldOutcome。
3. started_at 是首次承诺时刻还是本次恢复/活动时刻？两种含义分开，连续学习不能无意重写开始时间。
4. 完成、失败、阻断、放弃与主动切换是否分别关闭对应 task_id？当前只支持 None/Active/Suspended，不把不存在的状态标为已支持。
5. 多目标竞争前，如何区分暂时休息、顺手娱乐与真正改变承诺？不默认每次选择不同 action 就放弃。

最小验收覆盖接受/拒绝、暂停/继续、门槛未满足但仍选学习、可见/不可见完成、连续 session 的时刻及目标绑定。

### 文献补充（2026-09-05）：缺的是 canceling conditions，且承诺可能不该用 weight 实现

**(a) 上面第 4 点"不把不存在的状态标为已支持"现在有了对照物。** Côté 2013（Game AI Pro Ch11 §11.4.3）把 procedural knowledge 明列为两件事——"the decision model to **execute** the task" 和 "the decision model to **manage** the task (e.g., **starting conditions, canceling conditions, completing conditions**)"。

**项目当前只有 starting 与 completing 两态（None/Active/Suspended），缺的正是原文列出的 canceling conditions。** 这不是新发明，是 2013 年就已明确列出的三类条件之一——也就是说，补上它属于**对齐既有工程实践**，不是贡献。

同篇还给了架构前提：reactivity 与 deliberation 使用**独立的决策模型与独立的概念模型**，由 Action Selector 仲裁，Selector 负责**取消当前 deliberate 动作**并通知 Deliberation 重新决策。原文明言两者是 "**conceptual antipodes**"，任何试图用统一模型调和的做法都是在表示一对概念对立面。→ 这提示"中断"与"维持承诺"不应塞进同一个更新器。

**(b) 承诺的更合适实现可能是 rank 而非 weight。** Dual-Utility（Dill 2015，Game AI Pro 2 Ch3 §3.3）区分两个量：**rank**（绝对量，用于分类）与 **weight**（类内相对量）。Zoo Tycoon 2 的用法与承诺高度同构：常规需求 rank=0；考拉爬上树后树上行为 rank 提到约 5，"ensure that the animal didn't pick some other behavior and **pop out of the tree unrealistically**"；表演由 FSM 协调，rank 98–102；死亡行为 rank=1,000,000。

`[待用户确认]` 项目当前的"commitment 给学习加 bonus"本质是一种 **weight 调制**；而上述先例显示，**情境性承诺在工程上更常实现为 rank 调制（类别切换）**。这解释了为什么 weight bonus 版本会出现"门槛未满足但仍选学习"的语义漏洞——**weight 加减天然是软的，rank 切换才是硬的分类**。这是 T01 的一个更简洁的候选选项，但需实验验证，不代决。

**(c) 承接 Q05 的 validity test 提醒**：选择条件与保持条件分开声明、放同一处，这一条对 Q07 同样适用（"开始学习的条件"与"继续学习的条件"不是同一件事）。

## Q08 时间、中断与后果可追溯性

单一模拟时间、字段独立周期是目标；当前主要在决策边界统一推进，睡眠期间有专门的感知/冷醒逻辑，不等于通用多周期调度器。

组合 action 需决定原子执行、可中断/部分失败、哪些事件触发新的决策点；避免重复计算跨越事件或把计划时长当实际时长。task effort 目前在 primitive 循环后额外结算，日志虽有 outcome，不能说“一切世界后果均在 primitive 序列内”。需决定纳入 typed task primitive，还是明确 outcome 的独立子结算段及其来源。

在线 API 异步、成本合并、酝酿/思考中、滞后呈现等已延期，见[研究分支](前台问题与候选创新.md#7-保留但不挤进首版的分支)。不要因为整理此问题页而开始实现它们。

### 文献补充（2026-09-05）：长动作"立即返回 + 后台进行"是可搬模式

Q08 的"组合 action 需决定原子执行、可中断/部分失败"这个问题，HTN §12.9 给了直接答案：

> "we can have the navigation task **start the path following and complete immediately**, since the path following is happening in the background and not as a task in the plan runner. This frees us to plan during navigation... This works as long as we have a **world state that describes that we are navigating** and the current distance to the destination."

即可搬模式是：**长动作立即返回决策权，用 world state 上的一个显式状态量表示"它正在后台进行"**。对应到本项目，就是组合 action 不必原子执行完才归还控制权，但必须在 `W` 里有可查询的进行中状态。

原文同时给出另一种做法（双 planner 分管上下半身）并明确**不推荐**，理由是性能、同步、调试三重代价。→ 若后续 Q08 考虑"决策与执行并行"，不要走双规划器路线。

结合 Q05 的 validity test：进行中的组合动作需要**持续校验**（"它还有效吗"），而持续校验的条件与当初选择它的条件**不是同一组**。
