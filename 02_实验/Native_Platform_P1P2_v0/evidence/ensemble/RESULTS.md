## Bridge contract for parent acceptance

Start `node tools/native_platform_v0/ensemble/runner.mjs`; exchange newline-delimited JSON on stdin/stdout. Example input:

```json
{"op":"propose","eventId":"event-001","actor":"hero","responder":"love","facts":[]}
```

Proposal response gives `proposalId`, `volitions`, bound `actions`, and a trace confirming `doActionCalled:false`; no selected action effects are applied. Facts must use example schema and cast and pass direction/type/range checks.

After the trusted external bridge has actually settled the action, it sends a commit with source event identity, receipt ID, and a proof signed with `ENSEMBLE_BRIDGE_SECRET`:

```json
{"op":"commit","proposalId":"p1:event-001","eventId":"event-001","settlementStatus":"settled","settledActionName":"writeLoveNoteReject","actionName":"writeLoveNoteReject","settlementReceiptId":"#123","settlementProof":"<HMAC-SHA256 from trusted bridge>"}
```

The confirmed proposed action must match `actionName`. Commit applies original social effects, explicitly runs trigger rules, and advances the timestep. Duplicate commit within the same process is idempotent. Unknown proposals, unproposed actions, mismatched settlement, and malformed/out-of-schema facts are rejected. The wrapper does not persist its state across process restart and does not own Evennia/world settlement.
