# 机制识别循环与反事实诊断 v0

> 这是实验能力边界，不是新的心理机制，也不是本轮 counterfactual engine 的实现授权。

## 允许进入主线的三项能力

### A1. Event-level counterfactual replay

对同一条 factual trajectory `H`，在保持 `mechanism_revision`、`semantic_rule_version`、初始 `S/P`、数据版本和随机种子不变的条件下，只对历史输入施加一个明确干预：

```text
H                    → canonical replay → X / S / π(A)
remove/replace/mask/delay(event_k)
                     → canonical replay → X' / S' / π'(A)
```

至少输出 `ΔO`、`ΔX`、逐字段 `ΔS` 和 `Δπ(A)`；不要只比较最终 chosen action。反事实轨迹是诊断干预，不是另一条真人 ground truth。

当前只定义接口和记录要求，不实现通用 engine，不自动搜索反事实，不做 causal discovery，不让 LLM 编造“合理历史”，也不为它新增心理字段或 intervention DSL。

### A2. History-contribution probe

每次事件/历史段干预至少记录：

```text
intervention_id
affected_time_range
ΔS by field
Δπ
Δlog p(A*) (仅当有外部真实 A*)
```

它用于找出被状态保存的有用后果、dead field、过度敏感字段和错误 decay/persistence。没有真实 `A*` 时，`Δπ` 只能作 diagnostic，不能冒充预测证据。

### A3. Semantic-rule version comparison

对同一 raw trajectory，在动力学完全不变时比较 `semantic_rules_v0` 与 `semantic_rules_v1`，并记录 `X`、`S`、`π(A)` 及真实 `A*` 的 likelihood/rank（若有）。不得把 semantic-rule 修改和 dynamics 参数修改混成一次未标记的 joint iteration。

每次比较保存：`semantic_rule_version`、`mechanism_revision`、`dataset_revision`、`trajectory_id`、干预/版本说明和完整 trace。

## Canonical runtime boundary

正确路径是：

```text
ReplayRecord → apply one explicit input intervention
             → canonical runtime/replay path
             → trace → compare
```

不得复制 `counterfactual_simulation.cpp` 或特殊 replay pipeline 来重写 `O→X→S→π`。在第一个真实 adapter 接通前，只维护本协议；接通后才实现一个最小单事件 remove/replace smoke test。

## 研究边界

这三项能力服务于 Paper-0 的 approximate sufficiency / state necessity 与机制定位；不改变 `S` 字段、`U_k`、utility、action ontology、runtime 行为或 frozen claims。
