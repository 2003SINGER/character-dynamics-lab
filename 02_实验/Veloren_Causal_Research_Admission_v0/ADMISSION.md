# Veloren 因果研究实例准入裁决

日期：2026-10-18。**当前实例：NO_GO / READY_FOR_INDEPENDENT_REVIEW。** NO_GO 的关键理由是：当前未建立同一 state、同一权限下至少两条合法因果路径；不是“必须先跑新实验”的门槛，不是传统 planner 失败，也不是 Veloren 全局不可能。源码级设计准入可以成立；UNKNOWN 不等于不存在。

版本与因果图见[CAUSAL_NETWORK.md](CAUSAL_NETWORK.md)。官方源码固定为 `1d12f35edd6cdbfc1fb921c167cdd7beeeffe248`，项目审阅基线为 `a7a6e8f`。既有 [Talk 接口结果](../Veloren_Vertical_Slice_v0/RESULTS.md)与[招募结果](../Veloren_Native_Decision_Integration_v1/RESULTS.md)分别保存有限 Talk、476→442 Hired/follow 证据，不复制旧日志。Loaded Msg 补丁及 SHA、与官方版本的分账见因果图文档。本轮零新游戏运行、零构建、零模型调用；未修改源游戏或旧 RESULTS。

## 七项实例准入条件

1. **原本多个自主角色。**候选世界中已有多个 NPC 各自的原生决策/行为链，不由外控器直接替代角色行动。
2. **可观测既有任务/目标持续行为。**能观察角色已在持续执行的任务或目标及其状态变化。
3. **多个原生行为因果依赖。**候选内容至少包含多个由游戏原生规则结算的因果依赖，而非只改台词或遥测。
4. **至少两条实质不同的合法方案。**两条路径在同一 state、同一角色权限下均可执行，且有实质因果差异。
5. **作者中途未来约束与一次后续编辑/真实扰动。**世界持续运行时先加入未来要求，再有一次修改或真实扰动；不抹去已提交历史。
6. **原生 state/event 能核验满足、违约或未知。**证据可区分成功、失败和无法判断，不以 planner 预测或消息发送代替原生事实。
7. **不改规则编能力预写唯一解。**不得新增/改写游戏规则以制造候选路径，也不能把唯一答案硬编码进场景或 planner 输入。

## 最多两个候选的准入矩阵

状态：`SOURCE_ONLY` 表示源码机制可追踪；`UNKNOWN` 表示重要事实当前无法裁定；`NOT_ESTABLISHED` 表示当前实例没有建立该条件。它们不等于整个游戏不存在该能力。

|---|---|---|
| 1. 原本多个自主角色 | **SOURCE_ONLY：**原生 pirate leader、member 行为与单链旧运行存在；不等于这一个候选已有两个角色同时持续任务 | **SOURCE_ONLY：**NPC 及 escortee 行为源码存在；此实例未确定 |
| 2. 既有任务持续行为可观测 | **SOURCE_ONLY：**旧 476→442 Hire/follow 有有限原生回执；C1 同一 state 的初始任务/目标尚未冻结 | **NOT_ESTABLISHED：**还没有符合本候选的双角色持续任务输入 |
| 3. 多个原生行为因果依赖 | **SOURCE_ONLY：**Job→follow→结束及攻击→HP→受伤者 sentiment→RIVAL/quit 可追踪；Report 不是伤害 sentiment 的必要环节 | **SOURCE_ONLY：**Character 创建 quest/job 后原生 escortee 跟随、到达对话及 arbiter 结算有源码路径 |
| 4. 同 state / 同权限的两条实质合法方案 | **UNKNOWN：**EndHire 与受伤→RIVAL 是候选两路。已有非对称 ENEMY 起点不被 Hire 准入排除；但同一 state 下受伤可达、同派伤害实际结算、角色/权限、命中次数与存活期限、两路是否可择均未确定。死亡 Report 的 pirate 同组 guard 是独立限制，不是伤害攻击禁令 | **NOT_ESTABLISHED：**缺 NPC 自主作为 escorter 接单的原生入口，不能把 Character 接单与 NPC escortee 当作两条 NPC 自主方案 |
| 5. 作者中途未来约束/一次编辑或真实扰动 | **NOT_ESTABLISHED：**尚无该关系过程中的编辑/扰动实例 | **NOT_ESTABLISHED：**尚无此双 NPC 实例及中途编辑 |
| 6. 原生事实可判定满足/违约/未知 | **SOURCE_ONLY：**Job、HP、sentiment、RIVAL/quit 有可读状态/事件路径；C1 完整证据契约未建立 | **SOURCE_ONLY：**quest/job、到达、arbiter resolve/timeout 有源码结果；未证明 NPC escorter 路径 |
| 7. 不改规则、不预写唯一解 | **SOURCE_ONLY：**现有原生分支与外部只读观察接缝可区分；C1 尚无锁定输入可审核 | **NOT_ESTABLISHED：**不能靠新增 NPC escorter 规则补缺，也不能预写唯一解 |

C1 的攻击路径不应被简化为“同派伤害被禁止”。官方 combat 路径有 `permit_pvp` 检查，未发现通用 RTSim faction 拦截；同派死亡 Report guard 只约束社会评价写入。故 `ENEMY → 真实攻击 → 受伤者 RIVAL/quit hire` **SOURCE_ONLY，可能成立**，具体实例仍 UNKNOWN。直接攻击要求攻击者已有 ENEMY，是起始状态前提，不构成算法必然循环。EndHire 源码路径存在，但其 leader 流程启动需至少四名合格候选，正常停招有雇员数门槛，候选耗尽也可结束；raid 本体 TODO。本轮不扩四人/raid，不借此否定 EndHire，也不把下发 EndHire 已是现成外部权限。

两个候选只给结果、不预写过程：C1 是“已在活动中的 A、B 于绝对期限 D 前结束该雇佣关系，双方存活，已发生事件保留”；不是命令它一定受伤或一定等返家。C2 是“原生商人 A 在期限前完成目的地护送，由另一持续自主 NPC B 承担护送，保留 B 的既有事务约束”。D 必须晚于运行中作者插入时刻，后续编辑只作用未来；未锁定可达初态与合法控制边界前不填写一个假精确 D 或假设可强制 B 接单。

当前停止在“设计准入不足”：C1 最强反例值得保留，但没有证据证明两路同 state、同权限可选；C2 则缺自主 NPC escorter 入口。当前不选择候选、不写 protocol、不启动新运行、不实现新规则。

## 科学问题 A–E

**核心问题：**在多个自主角色已经持续执行原生目标、存在多条真实因果依赖且作者可中途改约束的游戏实例中，成熟规划方法能做到什么；还剩下什么必须研究？

**A｜成熟方法可解的部分是什么？**

传统 HTN、GOAP、事件驱动规划与轨迹约束方法已能表示有限目标、动作前提/效果、顺序和过程义务，并可在真实反馈后重规划未来。Author Obligation Planning 的既有结果中，**14 个不同的可行任务**有原生 PASS 证据，证明有限手工域的过程约束可参与搜索及历史进度更新；它不证明 Veloren 的多 NPC 场景已经解决。Mature Methods 的真实 GT/event-driven 配对在 T7 规范化执行序列 diff=0，没有速度比较或方法优势证据；其 Evennia 手工内容不等于 Veloren 能力。

**B｜真实未知在哪里？**

不是抽象地问“planner 是否能写约束”，而是：Veloren 是否有某个不改规则的同一 state，使多个原生角色各有持续任务，存在至少两条同权限、实质不同且可结算的因果路径；作者一次中途编辑后，路径选择、已提交历史、真实结果和成本如何变化？C1 的非对称 ENEMY→攻击→RIVAL 路径提供了具体反例候选，但其同世界可达性、权限可择、伤害结算、存活/期限仍 UNKNOWN。

各环节不能混账：**意图绑定**上，“结束雇佣”可落到 Job，但“保留旧事务进度”不能由 Job=None 代证；**合法模型**上，攻击生成、实际命中、社会报告更新是不同算子，原生分支存在不等于外部已获调用权限；**承诺协调**上，Hire 可覆盖旧 Job，缺恢复旧任务栈的保证；**未来修复**上，本关系场景没有已冻结的编辑/扰动契约，不能借旧平台结果称已验证；**计算成本**上，未准入共同问题前没有可解释的搜索性能结论；**作者劳动**上，新增绑定、模型、监测和调试所需时间尚未测量，少写一段脚本不等于总成本降低。这些是不同的未知项，不自动归为新算法贡献。

**C｜对应的传统近邻机制是什么？**

复用现有算法卡，不扩文献清单或声称新全文精读： [Mimesis](../../01_文献/算法积木/01_叙事修复与导演.md) 用因果链接威胁触发 accommodation，保留已执行前缀并重规划未来；作者需建动作前提/效果、因果链接、时序及可能的 failure modes。PDDL3 表达轨迹约束语义而非 planner；Porteous 以 PoV 选择 landmark 子目标并在交互后重规划，须人工建模动作和约束图，无解恢复不是原方法保证。作者成本没有可直接套用的工时结论。

**D｜值得比较的具体问题及证据是什么？**

仅当因果实例准入后，比较有严肃机制的 **event-driven/GOAP** 与现有 **HTN**：同一初态、权限、原生动作/事件、作者约束版本和扰动下，分别看是否找到合法实质不同的方案、编辑后如何保留历史与重规划、原生约束满足/违约、规划调用/搜索成本及作者建模成本。不能用弱固定顺序脚本作主要对手，也不能把不同条件或内容域配对成算法效果。现有 14 项有限作者任务与 GT/event diff=0 只能帮助定位基线，不能替代该 Veloren 证据。

**E｜若成熟方法足够，是否还需要新算法？**

若成熟方法能在合理的作者建模和计算成本内满足真实实例的约束、重规划与核验要求，则停止“新 planner”创新候选，保留成熟方法集成问题。只有具体比较指出成熟方法无法处理的、可重复且非载体缺口导致的失败，才重新提出窄化的新机制问题；当前 NO_GO 不构成失败证据。
