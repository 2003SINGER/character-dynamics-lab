≥20-action session 共 2,562 actions：click 2,355、input 187、terminate 20；action-type entropy 仅 0.442 bits。click subtype 有 13 类、entropy 2.929 bits（review 826、product_option 413、search 263 等），说明可做描述性受限标签，但不能把 observed labels 当作每一步完整 candidate set。

这批数据对“同一用户的重复 session”有足够结构（42/52 用户至少 2 条 session），但长度本身不证明持久状态 `S`。在**这一次** deterministic user-disjoint 候选 split 中，test 有 10 条 ≥20、6 条 ≥30，统计把握弱；这不是数据集固有的 test 池规模。若改用 session-level split，必须明确 estimand 是 same-user new-session，而不是 unseen-user generalization；未来若真的检验 unseen-user，应另行比较 group K-fold/leave-users-out 等方案。

## Split 与泄漏判定

filtered session table 实测为 437 train session / 49 user、90 test session / 15 user，**12 个 user 同时出现在 train 与 test**；去重后为 52 个 user ID。这与数据卡/论文所述 51 用户存在一处需向作者或 release history 核对的差异。无论原因为何，当前官方 split **不能直接作为 user-generalization 的 held-out split**。

正式比较前必须从 52 个 release user ID 中重建 user-disjoint group split，并让同一 user 的全部 session 只落入一个 split。session-level held-out 可回答“同一用户的新 session”，但不得误写成“未见用户”。同时禁止将 target row 的 rationale、后续 HTML、后续 action 或 products 泄漏进预测输入。

## `A*`、候选集与 NLL 的边界

OPeRA action 是真实参与者的浏览行为，故可提供独立 `A*`；其 HTML/URL、按时序 action 和 persona 也使 `H^obs` 可回放。可是 exact action target 由开放字符串、semantic ID、element metadata 等给出，release **没有给出该步可点击/可输入目标的枚举候选集**。因此：

1. 可以拟定受限协议：预测 `action_type`，或在 click step 内预测 finite `click_type`，用 categorical NLL/ranking；必须把 action-type 与 click-type 的条件化口径写清。
2. 不能把该协议称为当前房间中有限 `A^O` 的 NLL，也不能做 exact target NLL 后假称候选集完整。
3. rationale 仅可作揭示后/诊断标签；在未证明其在 action 前可得之前，禁止喂给 policy 或状态更新器。

## T0d 判定与下一门槛

通过：独立真人轨迹、按时刻 O、真实 action、session/user 标识、时间序与有限粗标签都可复核。

未通过/待补：现成 split 的用户泄漏；exact target 的候选集合；rationale 的因果时间位置；release 用户数与官方 51 的不一致。

下一步不是训练：先写一页 **OPeRA pilot protocol**，冻结 (a) user-disjoint 与 same-user 两种 estimand 是否都报告，(b) 目标层级（action type 或 conditional click type），(c) `<t` 可用字段，(d) 最小 session/action 长度，(e) NLL/ranking 口径与 failure conditions。该 protocol 完成前，不启动 T14–T17 或任意模型比较。
