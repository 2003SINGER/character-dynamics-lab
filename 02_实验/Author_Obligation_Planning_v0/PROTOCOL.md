# Author Obligation Planning v0 — 有限开发协议

状态：IMPLEMENTING；基线 `49895f2`。本协议在新任务搜索和原生运行前保存。

## 问题与边界

本包检验：相同终态但不同作者过程约束，是否真正改变搜索、实际执行和反馈后的剩余义务。沿用原版 Open Adventure 1.22 和冻结 B0 的有限、手工来源标注的动作模型，不将该模型称为游戏完整状态。旧 B0、Admission、作者时间诊断与 E0 的成功/失败记录均保持不变。

作者输入必须保留原文、任务 ID/版本、终态中明确指定的正/负条件以及事件义务；未指定桥、物品或灯状态不补为作者要求。结构化人工 reference 与模型候选若有，分别保存，不把人工 reference 当成模型输出。暂不进行正式 B1/B2、算法性能或玩家体验实验。

## 固定候选集合

28 个静态任务：A–F 六组 × 最终桥无/有/不限；另 G1–G10 变化物品、地点、灯与过程。4 个在线任务 H1–H4：撤销尚未执行的建桥要求、追加西岸往返要求、追加与最终有桥冲突的全过程禁建要求、原生命令真实拒绝后恢复。完整输入保存在机器可读 manifest；不提供正确命令攻略。

全体先做绑定/合法性检查与有限搜索；H 的完整结论须实际在线触发编辑/反馈，离线分析不冒充在线验证。所有静态任务均要求完整区间无死亡。

## 搜索与证据

- 使用经典 unit-cost search 与有限事件监测器的 product state；搜索去重包含当前世界投影和作者义务进度。事件摘要须有限、满足后饱和，不能把无限可增长历史当搜索状态。
- 每次搜索最多 10,000 次扩展、10 秒；原生每局 80 个任务输入、累计搜索 120 秒。沿用 seed 20261014，在启动答复之后设置，启动前随机性不受控。
- `FOUND`、`EXHAUSTED_FINITE_MODEL`、`BUDGET`、未支持绑定、执行失败、证据未知分别报告。有限模型不可达不等于全游戏不可达；不扩大预算刷过。
- 原生命令通过现有 P1 Session 执行。作者进度只由完整的真实回执更新，预测效果不充当历史。真实账本 append-only；编辑仅改变活跃作者版本，保留历史并重新评价新版本。
- 最后通过原生 look、inventory、灯反馈及完整回执独立检查终态、历史、禁止条件与死亡。日志缺失或反馈歧义返回 UNKNOWN，而非从预测补证据。

## 原生选择及停止

预先选 16 个机制覆盖任务：A1、A2、A3、B1、C1、D2、E2、G3、G5、G6、G8、G9、H1、H2、H3、H4。搜索预算不足或绑定失败则保留该失败，不换简单任务凑成功数。每项不自动重跑。

H4 是明确标注的 feedback-delay negative control：即将开格栅前，harness 经原生命令返回建筑、放下钥匙再回格栅（沿用旧 B0 已验证的五条合法输入），暂缓这些公开反馈；过时 unlock 被原版拒绝后，按原序交付反馈并原生刷新再规划。不是自然 NPC 干扰或数据库修改。同地 drop keys 不能制造该失败，因为原游戏允许使用当地地上的钥匙；此方案已在任何新原生运行前据源码纠正。

交付代码、输入、原始成功/失败、逐任务结果与局限后停止于 READY_FOR_INDEPENDENT_REVIEW。不扩地图、平台、NPC、Director、关系状态或通用时序语言；不宣称科研创新或通用作者理解已经成立。
