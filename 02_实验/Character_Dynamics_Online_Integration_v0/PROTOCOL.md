# Character Dynamics Online Integration v0 — Protocol

**协议状态：DEVELOPMENT / 运行前预算已定。** 本文规定本轮集成、观察和停止边界，不预写运行结果；实际代码及输入快照须在启动前固定。旧候选的两条合法路径要求不作为本包开发门槛。

## 问题与实现目标

在同一持续 Veloren 世界过程中集成角色自身目标、作者未来要求与在线编辑、计划协调、原生行为、真实反馈和后续重规划。系统持续开发与科学验证是同一过程：记录成熟方法解决了什么、所需信息与人工建模、扰动后的计划保留、作者劳动/运行成本，以及失败来自算法、模型、权限还是游戏能力。成熟方法可直接复用；某些算法对照需要的多条合法方案不是系统开发门槛。

固定 G0（既有游戏规则），不增加规则或写入专用成功脚本。G1 明确扩展未来可作为研究对象，但不在本授权内。保留历史 C1/C2 `NO_GO` 文档与结果；它们只描述原候选，不作为当前统一目标的停止条件。

## 来源、权限与状态边界

每个决策和证据按来源区分：`NATIVE`、`ACTOR`、`AUTHOR`、`DIRECTOR`。角色 ACTOR 依据其自身职业任务/目标和合法局部观察运行；Director OFF 不关闭 ACTOR。作者结构化目标可绑定既有 NPC/Job 事实，含绝对游戏时间期限；在线追加/编辑须产生版本并保留历史。角色 local observation 与作者全局 monitor 分开。只有原生状态/回执能证实执行效果；已发生历史不得被新版本抹除。无原生取消能力时记录 inflight，不声称已取消。

只复用已有原生 RecruitMember → RequestHire → Hired → Following 能力。不得直接写 NPC Job、伪造成功或调用未核实的核心接口；实现入口、API、调用方式须由代码检查确认。不得把跨游戏动作域当作 Veloren 原生规则。

本版角色 Planner 的目标是应用显式配置的 `ACTOR party_quota=2`（当前局部观察见证的受雇成员数），代表本集成中给职业角色设置的任务；它不是原生海盗完整四人流程的完成判据，更不是新增作者要求。原生 `population >3` 是既有 RecruitMember 准入 guard，仍由游戏决定，不能因应用 quota=2 而放宽。角色的历史已见成员与当前可见成员分别记录，离开24m视野不能被解释成全局 Job 解除。作者监测在本版使用原生 Job 转换见证判断一次未来发生，不冒称持续成员关系监测。

## 运行配置与资源边界

记录三种 headless 配置：

1. `NATIVE_ONLY`：仅游戏原生 NPC 行为。
2. `ACTOR / DIRECTOR_OFF`：角色 Planner 运行，不施加作者要求。
3. `ACTOR / DIRECTOR_ON`：运行中加入作者未来要求并编辑一次。

唯一初态来源为本地既有 `native-server-copy-a-20261016T131239Z` **当前完整 checkpoint**；运行前固定其六份 world 文件的实际哈希，三组副本必须一致，不修改任何 world 内容。预检发现地图/meta/RTSim 仍匹配旧 Loaded Msg 输入，但 SQLite 三文件字节哈希已不同；记录该漂移，不宣称与旧 freeze `9eb7a53bcd14cc1d10184b4f86fc6bc4ba4db26d05e673995405e1f22dce42ca` 完全相同，也不推定差异仅为无害布局变化。禁止从别的 checkpoint 拼接匹配旧哈希的 DB。它不是新生成世界，也不是跑后挑选的成功存档。复制成三份独立 userdata，设置仅做必要路径归一化；原 checkpoint 与旧 OFF/ON 不被写入。随机流不保证严格配对，不以相同 seed 声称逐帧相同。G0 使用同一已验证的 Loaded Msg 修复 binary、资产和相同的原生 persister/观测配置，不冒称未打补丁的官方 binary。

| 配置 | 含进程启动的 wall 上限 | 允许提交的请求数 |
|---|---|---|
| NATIVE_ONLY | 60秒 | 0 |
| ACTOR / DIRECTOR_OFF | 120秒 | 最多3条 |
| ACTOR / DIRECTOR_ON | 120秒 | 最多3条 |

实际向原生请求文件写入一条请求即计数，拒绝也计；不补跑、不换世界、不到失败后加预算。每条 TTL 为60原生 Time秒，决策使用不超过1.5秒 wall age 的 ActorView；原生 Loaded 前缀沿用至少3个不同游戏时间采样和至少2秒 wall。两个具完整原生归因的不同 NPC Job 效果出现后继续观察15秒可提前停止，否则运行到上限保留 PARTIAL。正常关闭宽限最多45秒，须单列实际耗时，不混入“运行在上限以内”的结论；超时终止不是游戏内动作取消。

ON 的测试作者在首条 ACTOR 请求提交后约 +0.4、+0.8 原生 Time秒分别加入和编辑目标，绝对 deadline 固定为该请求的 Time+90，不随版本编辑顺延。测试目标从真实 ActorView 中另一批现存合法候选绑定；它们只是作者的对象/结果输入，不是请求序列。若候选不够或编辑时条件已失效，输出实际阻断，不临时替换对象刷结果。首条请求已在途时，后续作者编辑不取消它；后续选择必须消费新版本和真实反馈。

优先完成一个边界明确的纵向运行，记录初态、输入/请求、作者版本、决策来源、执行与原生回执、观察、历史和预算。尝试不同 NPC 的两个原生状态效果；若候选、权限或时间不允许，保留实际失败并标 `PARTIAL`，不更换世界刷结果。

## 观察与结果记录

分别观察：Director OFF 时 ACTOR 是否实际决策；作者要求是否在运行中进入；编辑是否改变后续计划或形成明确合法阻断；原生世界是否结算至少一个多 NPC 状态变化（优先两个连续效果）；作者版本编辑后已发生事实是否保留；约束完成后角色是否继续自身/原生活动；轨迹能否区分四类来源。记录成熟方法复用、缺失能力、人工规则/建模、计划修复、作者工作量与运行成本。单次轨迹差异不构成算法优势证据。

允许结果为部分完成或失败，按实记录，不以未运行架构宣称通过。运行、原始结果、失败、成本及限制仅由本包后续 `RESULTS.md` 维护；主级完成真实运行验收后再创建。`READY_FOR_INDEPENDENT_REVIEW` 与 `CLOSED` 需遵循项目级审阅纪律。
