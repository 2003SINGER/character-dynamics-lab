# Demo Living V1 mechanism-repair audit

Status: `READY_FOR_INDEPENDENT_REVIEW`. This replaces the premature
baseline-freeze claim for the Demo/application model only. It is not research
evidence.

## Confirmed defects

1. **Recovery had three fatigue writers.**  A running Rest/Sleep action
   changed fatigue continuously, its settlement appraisal changed fatigue
   again, and `Recovery` semantic signals could change it a third time.  The
   repair assigns fatigue recovery exclusively to the running-action
   continuous path.  Settlement retains typed O feedback and non-fatigue
   meaning, but has no fatigue mutation.
2. **Sleep utility double-counted fatigue.**  `recovery_drive` already
   contains `fatigue_recovery_drive`; `sleep_readiness` also contained a
   direct fatigue term.  Sleep readiness is now a circadian/screen/body
   context signal, while fatigue enters sleep selection only through recovery
   drive.
3. **A long running action could not be reconsidered on a new subjective
   boundary.** The kernel now exposes a model-requested reconsideration hook.
   It keeps the current action and elapsed progress when policy elects to
   continue, and only replaces it through the existing typed validation path.
   V1 requests it for urgent bodily-need escalation and sleep recovery
   satiation; it does not encode V1 thresholds in the Runtime.
4. **Task pressure was an impulse stock.** It is now a continuous target
   derived from observable deadline, own progress, remaining workload and
   commitment. The Runtime projects its authoritative total-minute clock into
   O before model dynamics run, so the target never reads hidden W time.

## Implemented repair scope

- `DemoLivingDynamicsV1`: fatigue recovery and screen strain each have one
  continuous owner; settlement and semantic paths retain meaning but no
  longer mutate those physical loads. Sleep utility no longer double-counts
  fatigue.
- `CharacterDynamicsModel` and `ContinuousRuntime`: a generic,
  model-requested reconsideration hook is available. The Reference model
  inherits a no-op default, preserving its behavior. The Kernel contains no
  V1 action threshold or state law.
- `ContinuousRuntime`: authoritative runtime time is projected as the typed
  observable fact `clock.total_minutes` before continuous model integration.
- `DemoLivingDynamicsV1`: task pressure moves continuously toward an
  O-derived target; appraisal reports that target rather than injecting a
  pressure impulse. Anxiety no longer has a generic zero-attractor pump.
- World, action schema, Reference dynamics, ResearchDynamicsV1 and Laya are
  unchanged. `batch_48h_v1_mechanism_repair/` supplies the same-seed 128×48h
  evidence, including a byte-for-byte deterministic rerun of every actor.
