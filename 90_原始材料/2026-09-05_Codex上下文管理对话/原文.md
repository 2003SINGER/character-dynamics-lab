### 如果还是没窗口，第二刀查 `cua_node`

这条我觉得对你也非常可疑，因为你是**刚更新完立刻出现问题**。

Codex Windows 最近还有另一个完全相同的 bug：

> 更新后需要重新释放 `cua_node` runtime，但复制 `node_repl.exe` 失败，于是留下 `.staging-xxxx` 半成品目录，App 就一直后台运行而不显示 UI。

而且该 issue 的症状同样是 **5 个左右 ChatGPT 进程 + `MainWindowHandle=0`**。([GitHub](https://github.com/openai/codex/issues/42501))

先只检查，不修改任何东西：

```powershell
$root = "$env:LOCALAPPDATA\OpenAI\Codex\runtimes\cua_node"

Get-ChildItem $root -Directory -Force | ForEach-Object {
    [PSCustomObject]@{
        Name     = $_.Name
        NodeExe  = Test-Path "$($_.FullName)\bin\node.exe"
        NodeRepl = Test-Path "$($_.FullName)\bin\node_repl.exe"
        Modified = $_.LastWriteTime
    }
} | Format-Table -AutoSize
```

**把这个输出给我。**

如果我们看到类似：

```text
.staging-xxxxxxxx-xxxx    True    False
```

尤其是有一个**今天 20:45 更新以后新生成的 `.staging-*`**，那基本抓到凶手了。

已有报告的实际修复办法就是用 Windows 的：

```text
xcopy /G
```

把新版包内 `app\resources\cua_node` 完整复制出来，因为 `/G` 能绕开 Microsoft Store 文件的加密/Protected relocation 问题。修复后窗口立即恢复。([GitHub](https://github.com/openai/codex/issues/42501))

不过**现在先别执行复制修复**。先跑上面的检查命令，我们确认你的情况是不是这个，再针对你 `26.901.5280.0` 实际需要的 runtime hash 写命令，免得手工拷错目录。
