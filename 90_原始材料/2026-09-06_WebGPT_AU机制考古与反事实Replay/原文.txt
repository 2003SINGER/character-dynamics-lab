结论是：你记得对。早期 AU 那批想法绝大多数不是另一条研究路线，而是在补 Character Dynamics 这个框架的机制细节。仓库其实已经吸收得相当多了。

A. 已经完整吸收，不用重新发明

这些早期想法现在已经是正式框架的一部分：

W ≠ O，角色只能通过感知/信息入口获得世界信息；
O 不是一帧 snapshot，而是可以 stale / unknown / wrong 的持续主观世界；
X 把“发生了什么”转成“这对角色意味着什么”，再由 U_k 更新 S；
每个 S 字段可以有自己的触发、累积、恢复、衰减、饱和和时间尺度；
P 不只是静态 persona 文本，而是调制 O→X、X→S、S→A；
微动作很重要，角色的一致性不只在“大剧情选择”中体现；
Object/Scene 给出 affordance，人物级组合动作再展开成世界 primitive；
replay 和自主 NPC 本质上用同一套 forward mechanism，只是 π(A) 后一个拿真实 A* 对照，一个采样执行；
行为应该是条件分布，不是“这个人格一定做 X”；
世界随机性、语义/认知不确定性、decision sampling randomness 不能全塞进一个 temperature。

所以这些不用再从 AU 里捞回来，已经活在现有设计里。

B. 已经记住了，但现在还没有真正做——这批最值得保留

这里有几条我觉得尤其重要。

1. 反事实“删掉一段历史”再 replay

早期数据流材料里明确提到：

provenance 不只是为了 debug，还应该支持反事实移除某事件。

我们现在已经有：

event
→ ΔO
→ X
→ ΔS
→ π(A)

也有 replay/provenance。

但当前 loop 更多是：

改参数
改规则
做 ablation

还没有把这种实验正式写成一类标准诊断：

原 trajectory H
→ π(A)

删除/替换 event e_k
→ replay
→ π'(A)

比较 ΔS、Δπ

这个我认为很值得补进未来 mechanism loop。

因为它直接回答：

某一段经历到底有没有真的通过 S 留到未来？

甚至比单纯看某字段非零更接近我们母问题。

2. “误解 → 行动 → 变成客观社会事实”

这是早期材料里一个很有意思、现在被压得比较深的想法。

原来的链不是简单：

A 对 B 有错误 belief

而是：

A 误解了某件事
↓
形成 X / S / 决策
↓
A 因误解做出行为
↓
这个行为真实改变 W
↓
B / C 再观察到新的客观事实
↓
原本主观的错误认识
通过行动产生了真实社会后果

这和单纯 ToM benchmark 很不一样。

现在仓库已经有：

W relationship facts
R_i[j]
O_i
二阶 knowledge

所以地基在。

但**“subjective misconception causally crystallizes into objective social state”** 这条动态模式，目前没有被特别突出。

它明显是未来多人 Character Dynamics 很漂亮的一种 demo / experiment。

不过 Paper-0 绝对别碰。

3. Forward–Inverse 对偶

这个没有丢，现在正式文档已经明确：

Forward:
S → behavior prediction

Inverse:
new behavior evidence → revise latent-state estimate

但目前我们全部精力放在 Forward，这完全正确。

早期更大胆的版本里还包括：

预测用户行为
→ 用户反馈/真实行为
→ 修正画像
→ 下一轮预测

甚至说到“反向传播”。

现在已经正确降级成：

inverse planning / Bayesian update / latent-state estimation 等候选，不承诺神经网络 backprop。

所以这一条属于：

保留得很好，暂时不要实现。

C. 有一条老机制我觉得以后应该重新认真看：Action Quality

D. LLM 过冲 / 自强化这个老问题，现在有了新的位置

早期有一个很明确的担忧：

LLM 看到一点负面信息，就顺着故事越解释越极端，状态一直负向累积，又不会恢复。

这现在已经写成 R04。

但经过我们今天决定：

前期不用 runtime LLM
→ fixed semantics

以后它的位置变得更漂亮了。

等 mechanism v1-fixed 做出来后，可以专门比较：

fixed semantic rules
vs
live LLM semantics

然后看 LLM 有没有：

semantic overshoot
path dependence
negative reinforcement
recovery failure

所以早期这个想法没有废掉，只是从：

“我们现在为什么要限制 LLM”

变成：

未来 LLM semantic frontend 的一个明确 stress test。

这个转化挺好的。

E. 还有一个早期想法已经吸收，但我觉得 loop 里可以更强调

就是：

状态不是为了完整记录过去，而是为了保存过去中对未来行为还有用的后果。

这个现在已经成为 Paper-0 的 approximate sufficiency。

一、现在允许进入主线的实验能力

原则：

只允许增加“更好地攻击、诊断现有机制”的能力，不增加“让角色模型更丰富”的新心理模块。

A1. Event-level counterfactual replay

在现有 factual replay 基础上增加一种诊断：

original trajectory H
→ replay
→ X / S / π(A)

counterfactual H'
→ replay
→ X' / S' / π'(A)

其中 H' 只允许对过去输入轨迹做明确干预，例如：

remove(event_k)
replace(event_k, alternative_event)
mask_observation(event_k)
delay_observation(event_k)

目的不是生成“另一条真实历史”，而是检查：

某一段过去经历到底有没有通过当前机制持续影响未来状态和行为分布？

必须保持：

same mechanism revision；
same semantic-rule version；
same initial state/personality；
same random seeds where applicable；
除 intervention 外其余输入不变。

输出至少比较：

ΔO difference
X difference
S difference
π(A) difference

不能只看最终 chosen action。

明确用途

例如某个早期事件 e17：

H                 → π_t(A)
H - e17           → π'_t(A)

如果外部行为/后续数据表明 e17 对未来仍应重要，但：

S_t ≈ S'_t
π_t ≈ π'_t

则当前状态机制可能忘掉了行为相关历史后果。

反过来，如果删除一个显然无关事件却导致：

large ΔS / large Δπ

则机制可能保留了不该保留的历史噪声。

这和 Paper-0 的 approximate sufficiency / state necessity 是同一主问题下的诊断，不是新研究方向。

A2. History-contribution probe

在 counterfactual replay 上增加一个轻量诊断概念：

event/history contribution to future behavior

不要求现在定义复杂的 causal attribution 指标，也不要引入 SHAP、causal graph framework 等。

初期只需要能够对一个事件或一段历史报告：

intervention_id
affected_time_range
ΔS by field
Δπ
Δlog p(A*)

如果已有真实 A*，记录：

Δ log p(A*)

没有真实 A* 时只作为 diagnostic，不冒充预测证据。

后续可把这种 probe 用于：

判断哪些经历真的被 S 保存；
判断哪些 S 字段承载了这些历史后果；
找 dead field；
找过度敏感字段；
找错误的 decay / persistence；
比较 semantic_rules_vN 改动前后，哪些历史影响发生变化。
A3. Semantic-rule counterfactual / version comparison

当前 Stage 0/1 使用 fixed semantic mapping，因此 loop 要支持：

same raw trajectory
same dynamics
semantic_rules_v0
vs
semantic_rules_v1

然后比较：

X
S
π(A)
A* likelihood/rank

用途是区分：

failure 来自 raw event → X 的语义映射，

还是：

failure 来自 X → S → π 的 dynamics。

不要让 semantic rule 修改和 dynamics 参数修改在同一次实验中混在一起，除非明确标记为 joint iteration。

至少保存：

semantic_rule_version
mechanism_revision
dataset_revision
trajectory_id
intervention/version comparison
A4. Counterfactual replay 必须沿用 canonical runtime

不要为上述实验复制一套：

counterfactual_simulation.cpp
special_replay_pipeline.py

来重写 O→X→S→π。

正确方向是：

ReplayRecord
→ apply one explicit intervention to replay input
→ canonical runtime/replay path
→ trace
→ compare

目前若真实 replay API 尚未完成，只在 loop/protocol 中定义接口与输出要求。

本轮不要实现通用 counterfactual engine。

等第一个 ClubFloyd/LIGHT adapter 真正接通后，再做一个最小实际用例。
