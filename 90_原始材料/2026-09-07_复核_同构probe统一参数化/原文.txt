看看同构 linear probe  能不能用到别的计算部分？这样可以快速梯度确定出一套合适的比较好的参数！

可以，而且我觉得这甚至可能成为我们系统一个很漂亮的工程/研究分层：

符号机制负责“什么能看见、发生了什么、状态表示什么”；可微 probe 负责“这些量应该以多大权重影响行为”。

这样我们就不用继续手填 0.70 / 0.25 / 0.35 / 0.20 这种明显只是占位的数字了。

现在其实已经有一大片计算天然是线性的。比如 candidate 预测可以统一写成：

$$ z_{t,a} = \beta^\top\phi_{t,a} + \gamma^\top b_{t,a} + S_t^\top W\phi_{t,a} $$

其中：

\(\phi_{t,a}\)：action semantics，比如 goal_progress / stimulation / recovery / reward / environment_control ...
\(b_{t,a}\)：Scene binding，例如 target_in_scene / visible / already_carried
\(S_t\)：persistent state
\(\beta\)：动作语义的基础权重
\(\gamma\)：Scene/O 对动作的影响
\(W\)：S 对不同动作语义的调制
最后 softmax 得 \(\pi(A)\)

然后直接用真人 A*：

$$ L=-\sum_t\log \pi(A_t^*) $$

梯度一次性把这些参数学出来。

这会比现在这种：

goal_progress * 0.70
stimulation * 0.25
recovery * 0.50

visible → +0.08
not in scene → -0.35

S influence → 0.20

科学得多。

我尤其想把 current scene 的手工 bias 也干掉

现在我们有类似：

target 不在 scene    → -0.35
visible              → +0.08
already carried      → -0.12

这些其实根本没必要写死。

直接暴露：

target_in_scene
target_visible
target_in_inventory
verb_target_match
...

作为 candidate features。

然后：

$$ z_a = \cdots +\gamma_1 I_{\text{scene}} +\gamma_2 I_{\text{visible}} +\gamma_3 I_{\text{inventory}} $$

让 train split 自己学：

γ_scene
γ_visible
γ_inventory

这样 SceneSnapshot → candidate 的结构仍然是我们设计的，但“visible 到底值 +0.08 还是 +0.37”不需要拍脑袋。

连 U 都能做一部分可微

我们现在：

$$ S_{t+1} = S_t+\eta(X_t-S_t) $$

其实就是：

$$ S_{t+1} = (1-\eta)S_t+\eta X_t $$

完全可微。

令：

$$ \eta=\sigma(\rho) $$

那么 ρ 是任意实数，而 η 永远自动限制在 \(0,1\)。

于是可以：

trajectory
↓
X1 → S1
↓
X2 → S2
↓
...
↓
π(A)
↓
NLL

直接 backprop through time，把 η 也学出来。

以后多维甚至可以升级：

$$ S_{t+1} = A S_t + B X_t $$

其中：

A = persistence / decay
B = appraisal 写入状态的方式

这就是一个很小的可解释线性 state-space model。

例如：

positive_conduciveness
        ↓ B
satisfaction-like state

negative_conduciveness
        ↓ B
tension-like state

再由 held-out behavior 决定这些 coupling 有没有预测价值。

这就开始很有意思了。

但是这里有一道必须守死的线

不是所有东西都应该梯度学。

我会这样切：

部分	是否适合 gradient fit	原因
Candidate semantic 权重 \(\beta\)	非常适合	纯 policy calibration
Scene/O feature 权重 \(\gamma\)	非常适合	替代人工 +0.08/-0.35
\(S\times action\) interaction \(W\)	非常适合	我们正在设计的同构 probe
softmax temperature	适合	纯概率校准
EMA \(\eta\)	可以，但要谨慎	已进入 state dynamics
多维 \(A,B\) updater	可以，后期做	可作为 constrained dynamics
appraisal event → X 的具体结构	主实验不要随便学	这是 theory-S 的核心定义
W→O 可见性边界	不能用 A 调*	会产生信息泄漏
affordance / world legality	不能靠 NLL 学	是世界规则，不是人物偏好
gold candidate support	不能学	数据评测边界

最重要的一句就是：

参数可以学，但“哪些变量存在、谁能看到什么、哪个事件属于哪个 appraisal”不能全部一起用 A 学。*

不然最后会变成一个普通 latent-state predictor，而不是 Character Dynamics。

而且我们可以设计两种模式

这个我觉得特别适合我们。

diagnostic / research mode

为了检验 theory-S：

X definition      frozen
state dimension   frozen
U form            frozen
candidate features frozen

只学：

$$ \beta,W,T $$

必要时学少量共享参数。

这样能够公平回答：

这个 representation 到底有用没用？

best-system mode

等论文消融已经做完以后，我们可以让更多参数一起优化：

$$ \theta = \{\beta,\gamma,W,\eta,A,B,T,\dots\} $$

在 train 上端到端最小化 held-out-style action NLL。

于是变成：

symbolic W/O/X skeleton
+
differentiable dynamics
+
differentiable policy

这时候我们就真的得到一套数据拟合出来的人物动力学参数。

不是：

“我觉得 fatigue decay 应该 0.12。”

而是：

“在训练轨迹中，约束为正且稳定的一阶动力学最优时间常数对应 η=xxx；在未见轨迹上冻结评测。”

这个就像正经模型了。

对我们现在这个实验，我甚至建议更严格一点

不要一上来把所有参数都 joint-train。

先分两阶段：

Stage 1:
no-S 数据
→ 学 β、scene γ、temperature
→ 得到一个合理的 state-independent base policy
→ 冻结

Stage 2:
加入 S
→ 只学 W
→ 比较 Activity / ActionSupport / Theory

这样非常漂亮。

因为：

$$ z_{t,a} = \underbrace{\beta^\top\phi+\gamma^\top b}_{固定 base policy} + \underbrace{S_t\,w^\top\phi}_{状态新增信息} $$

此时 Theory-S 好一点，就很难说是：

“因为 Theory 条件重新把整个 action scorer 训练得更好了。”

它只能通过 S × φ 那条新增通路获得收益。

这个比我们刚才说“每个 S 独立训练整个 β+w”还要更强。

当然可以两套都报告：

A. shared frozen β + fit only w
   → 最纯的 representation incremental test

B. each condition refits same probe family
   → 每种 representation 的 best achievable performance

A 我会作为主结果。

η 怎么处理也能非常漂亮

否则又不公平。

做一个共享 η。

validation 上按预注册规则选一个共同 eta。
