## 什么时候才真的应该拆成第二篇论文？

比如你的 Forward：

$$
S_t,W_t\rightarrow P(A_{t+1})
$$

和你以后特别想做的 Inverse：

$$
H_{\le t},A_t\rightarrow P(S_t)
$$

如果 inverse 只是：

> 用行为预测结果辅助检查 state，

它完全可以放同一篇。

但如果你后来发现 inverse 本身要搞一套新的：

- latent-state inference
- posterior estimation
- identifiability
- multiple possible internal states
- inverse planning
- 专门的数据集与指标

那它就已经足够大到**单独成为下一篇论文**。

同样：

> “不同时间尺度的情绪/关系状态应该怎么更新”

如果只是你的模型一个组件，可以放一篇。

但如果后来发现这本身需要一个新的 hierarchical dynamics algorithm，而且有一整套实验，那又能长成下一篇。

所以不是：

> 第一篇只能做 State，第二篇 Prediction，第三篇 Dynamics。

不是这么机械。

而是：

> **第一篇先把一个完整、可工作的核心系统讲通。研究过程中发现哪个子问题足够深，再自然长出下一篇。**

**大方向对，但顺序我会稍微改一下。**尤其是你说“前两个花相当多时间，等完善机制以后再看效果”，这里有个坑：**不要先闭门把机制完善几个月，再第一次跑实验。**

你现在应该是三条线并行，其中前两条最重：

1. **读“状态怎么更新”的相关工作**
   重点不再泛看什么 Agent、persona、一致性，而是专门拆：
   `输入什么事件 → 保存什么状态 → 怎么更新 → 性格在哪参与 → 状态怎么影响 action`
   
   你现在真正该啃的就是 FAtiMA / EMA / DPC，以及再往外找 affective computing、character modeling、belief/goal dynamics、interactive narrative 里具体的 state update 方法。因为你已经知道，“稳定人格 + 动态状态”这个大想法本身不是创新；真正要找的是**你的更新机制到底和他们有什么计算差别**。

2. **一边读，一边设计你的第一版机制**
   
   例如先形成一个很粗的：
   $$
   S_{t+1}=F(S_t,O_t,P,\Delta t,\text{Outcome})
   $$
   
   然后不断问：
   - state 到底有哪些变量？
   - 数值还是文本？
   - event 怎么映射成 state delta？
   - personality 是直接影响 action，还是影响 state update？
   - emotion 是否衰减？
   - relation 是否累积？
   - 不同变量是否不同时间尺度？
   - observation 没看到的事情能不能更新？
   
   **这些才是你真正的方法设计工作。**

3. **但很早就搭一个最小实验场**
   
   不用等机制成熟。
   
   哪怕先只有几十/几百个受控轨迹：
   ```text
   世界 + 人格 + 历史
   ↓
   预测下一行为
   ↓
   已知真实下一行为
   ```
   
   同时把几个 baseline 跑起来：
   ```text
   persona only
   raw history
   history summary
   你的 v0 state
   ```
   
   因为你的核心检验本来就是：**这个动态 state 有没有比 raw history / summary 更有未来行为信息？**

这一步特别重要。比如你读了两周论文，设计了一个特别漂亮的 `emotion + trust + goal + belief` 系统，第一次小实验发现：

> `persona + raw history` 比你还强。

这不是失败，反而立刻告诉你：

> **当前 state compression 丢信息了。**

你就知道接下来读论文、改机制应该往哪里走。

所以我会把你的近期科研过程画成：

```text
           ┌→ 读状态更新相关论文 ─────┐
           │                         ↓
定义最小任务 → 设计 Character State v0
           │                         ↓
           └→ 同时搭 baseline/测试场 → 小实验
                                      ↓
                                看哪里失败
                                      ↓
                         回去读论文 + 改机制
                                      ↓
                                  v1 / v2
                                      ↓
                              大规模正式实验
                                      ↓
                                   消融
                                      ↓
                              分析各模块作用
```

也就是说，**真正耗时间的确实会是“读文献 + 想机制 + 反复改机制”**。不是最后跑一次实验最耗脑子。

但“看效果”不要放到很后面，而应该变成一个不断给你反馈的小循环。

---

还有一点：**正式消融确实偏后做，但小消融可以很早做。**

比如 v0 里有：

$$
S=\{emotion,relation,goal\}
$$

你完全可以随手跑：

```text
完整        61.2
-emotion    55.0
-relation   60.8
-goal       61.1
```

看到这个结果，你马上就会怀疑：

> relation / goal 是不是当前表示方式不对？  
> 还是数据里的行为压根不需要它们？

正式论文的严谨 ablation 是最后做；**研究过程中的粗糙 ablation 是拿来帮你思考的。**

所以你接下来最重要的事情，我会排序成：

**第一优先级：研究 state update mechanism。**

这里面同时包含**读别人怎么做 + 形成你自己的机制**，两者应该不断来回。

**第二优先级：尽快搭一个足够小的实验闭环。**

不是为了现在就出结果，而是为了防止你研究一个月以后才发现“根本测不了”或者“raw history 已经吊打我”。

**第三优先级：逐渐扩大数据/场景，再正式比较和消融。**

至于完整游戏、NPC 自主活动、漂亮 world engine，**现在反而不急**。AI Town 那套工程边界你以后可以借；你的第一阶段只需要一个足够严格、能产生 `W/O/action` 的最小环境。你现在的研究对象已经是“Character Dynamics Model”，而不是先造一个完整游戏。

所以你现在确实已经到了一个比前几天清楚很多的位置：

> **不再继续漫无目的找“和我像的 Agent 论文”；开始集中攻“历史怎样变成人物当前状态，以及这个状态怎样计算地影响下一行为”。**

这应该成为你接下来一段时间最主要的科研工作。
