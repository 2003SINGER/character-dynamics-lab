我还有个问题，数据流视角是可以作为工具来操作状态更新的吧？这个好吗？还有我们的研究和传统agent是不是不太一样？传统agent不都是看怎么干活或者coding吗

对。数据流视角非常适合作为你“怎么实现/组织状态更新”的工具，而且我现在觉得它跟你的方向是天然契合的；只是要注意，“采用数据流”本身大概率不是论文的核心创新。

你可以把现在的人物动力学直接理解成一个有状态的数据流系统：

$$ \text{World Events} \rightarrow \text{Observation Stream} \rightarrow \text{State Update Operators} \rightarrow S_t \rightarrow \text{Action Policy} $$

比如游戏里连续进来：

23:01 B 没有回复消息
23:04 A 看了一次手机
23:07 B 上线了，但仍未回复
23:10 A 回到宿舍
23:11 室友问“你怎么了？”

不是每次都把整个历史重新塞给 LLM，而是让这些 event 流过状态更新模块：

B 未回复
   ├─→ expectation ↓
   ├─→ disappointment ↑
   └─→ relation 轻微变化

再次查看手机
   └─→ attention/preoccupation ↑

回到宿舍
   └─→ environment/context 改变

室友询问
   ├─→ 当前合法社交行为集合变化
   └─→ emotion × personality
        → response tendency

最终维护：

$$ S_t= \{ emotion,\ relation,\ expectation,\ goal,\ldots \} $$

然后下一步行为不是重新解释全部历史，而是：

$$ P(A_{t+1}\mid S_t,P,O_t,\mathcal A_t) $$

这其实就是你文件里一直在强调的：状态不是历史档案，而应该保存历史对未来行为仍然有效的后果。

为什么数据流视角对你特别好

因为你的状态天然就是在线更新的，而不是一次性算出来。

比如：

$$ S_{t+1}=F(S_t,e_t,P,\Delta t) $$

每来一个事件 \(e_t\)，只更新受影响的部分。

而且你以后完全可以有不同的 update operator：

event
 │
 ├─ appraisal operator
 │      → emotion update
 │
 ├─ relationship operator
 │      → trust / closeness update
 │
 ├─ expectation operator
 │      → expectation violation
 │
 ├─ goal operator
 │      → short-term intention
 │
 └─ temporal operator
        → decay / accumulation

甚至时间尺度也很好表达：

fast stream
emotion / attention
几秒～几分钟

medium stream
expectation / goal / stress
几小时～几天

slow stream
relationship / habit
几天～数月

stable prior
personality / values

这比一句：

“LLM 根据历史更新人物心理档案”

工程上清楚太多了。

它还有几个对科研很有用的性质：

可解释：可以追踪是哪一个事件把哪个 state 改了；
可消融：直接断掉某个 operator 看性能变化；
可干预：改掉某个历史 event，重新流一遍，看未来 state/action 怎么变；
在线性：特别符合真正运行中的游戏；
可组合：以后替换某个 update 方法不需要推倒整个系统。

所以我很赞成你继续保留数据流 / stateful stream processing 作为系统设计语言。

但有一句必须记住：

数据流是“怎么把你的想法做清楚”的工具，而不是默认等于科研贡献。

如果最后只是：

“我们用 DAG 把 emotion、trust、memory 串起来。”

这不够。

真正值得研究的是：

流里的状态是什么？事件怎样选择性地修改状态？更新 operator 怎么设计？这种状态更新为什么比 summary/raw history 更能预测未来行为？

这才是你的东西。

你感觉到的没错。

但不是因为我们“不算 Agent”，而是因为现在互联网语境里 Agent 这个词被 task agent 占得太严重了。

现在非常流行的一支确实是：

用户：

近期 LLM-agent 文献里，tool use、planning、feedback learning确实都是非常主流的范式。

它优化的是：

$$ \boxed{\text{How do I accomplish the task?}} $$

而你现在研究的 Character Agent 问的是：

$$ \boxed{\text{Given who I am and what has happened to me, what would I do now?}} $$

这两个东西区别非常大。

假设门开着。

Task Agent

目标：

“把房间保持安静。”

那么：

检测门开着
→ close_door()

完事。

重点是：

有没有完成任务。

Character Agent

没有一个硬性的“关门任务”。

角色刚跟 B 吵完架，疲惫、烦躁、想一个人待着。

此刻世界提供：

close_door
sit
look_phone
talk_roommate
leave_room
...

人物可能：

P(close_door) = .43
P(sit)        = .24
P(look_phone) = .18
P(talk)       = .04
...

如果他是另一个性格、另一个情绪状态，分布就变了。

重点不是：

“哪个 action 最能完成任务？”

而是：

“哪个 action 是这个人在这个时刻更可能做的？”

这就是你和大量 task-oriented LLM Agent 最本质的区别。

而且“不以完成任务为目的”恰恰是 Character Agent 很有意思的地方

人很多时候干的事情压根没有一个显式任务目标。

你一直喜欢的这些例子：

顺手关门、看一眼手机、停顿一下、坐远一点、避开某个人、没接话、走得快了一点……

如果拿 coding-agent 那种框架去理解，甚至会问：

“这个 action 对完成 objective 有什么帮助？”

可能答案就是：

没有。

但是它对：

“这个角色是不是活的”

非常重要。

所以你研究的是一个不同的 policy：

Task Agent 大致更像：

$$ a^*=\arg\max_a \text{TaskUtility}(a) $$

而 Character Agent 更接近：

$$ a\sim P(a\mid \text{world}, \text{personality}, \text{dynamic state}, \text{history}) $$

它不是必须每一步都“最优”。

甚至人物可以：

犹豫；
做无意义的小动作；
因情绪做次优决策；
因习惯重复某件事；
因错误 belief 做错事；
明知道某件事不好却还是做。

Character Agent 如果永远像一个理性的 coding agent，反而不像人。

所以从整个 AI Agent 领域来看：

你没有离开 Agent。

只是你的支系不是现在最火的：

而更靠近：

character agent / believable agent / social agent / affective agent / game AI

然后你又把现代 LLM 引进来，研究动态状态到底怎么维护才真正具有行为预测价值。

我现在甚至觉得可以把你和“主流 LLM Agent”的区别画得很清楚：

	主流 Task Agent	你的 Character Agent
核心问题	怎么把事做完	这个角色此刻会怎么做
核心状态	task progress / memory / tool results	personality + emotion + relation + belief + goal…

不过两边底层结构其实很相似：

$$ observe\rightarrow state\rightarrow decide\rightarrow act\rightarrow observe $$

区别在于 state 的语义和 objective。

这也是为什么你前面那条路没有跑歪。

其实导师给我推荐的课题是，追踪用户的意图或者目的的收敛甚至持续变化
记忆已更新

这其实一下把你现在的方向和导师给你的课题串起来了。

你导师说的：

$$ \text{用户连续输入/行为} \rightarrow \text{当前意图/目的状态} \rightarrow \text{持续更新} $$

要研究的不是“这一句话是什么意图”这么简单，而是：

用户一开始目的模糊，随着交流逐渐收敛；
或者本来目标是 A，中途变成 B；
或者同时有几个目的，其中一个暂停、恢复、消失。

这本质上已经是一个动态状态跟踪问题。

而你现在的 Character Dynamics 是：

$$ \text{世界事件/人物经历} \rightarrow \text{当前角色状态} \rightarrow \text{持续更新} \rightarrow \text{未来行为} $$

你看，它们的计算骨架其实非常像。

导师的题目
对话/行为流
    ↓
用户 latent state
 ├─ 当前意图
 ├─ 目标
 ├─ 优先级
 ├─ 是否收敛
 └─ 是否发生漂移
    ↓
预测用户下一步需求 / 帮助 Agent 行动
你现在的题目
世界/事件流
    ↓
角色 latent state
 ├─ 情绪
 ├─ 关系
 ├─ belief
 ├─ intention/goal
 └─ 其他动态状态
    ↓
预测角色下一行为 / 驱动 NPC

所以我现在甚至不觉得这是两个毫无关系的科研方向。

它们有一个非常明显的共同母题：

在连续交互过程中，怎样维护一个随新证据持续变化的内部状态，使它保留对未来行为有用的信息？

这句话同时能罩住两个。

而且你之前一直在想的数据流视角，现在就更合理了。

导师那个问题天然就是：

$$ x_1,x_2,x_3,\ldots $$

不断有用户输入进来，然后：

$$ I_{t+1}=F(I_t,x_{t+1}) $$

其中 \(I_t\) 不是死的：

有些 intent 越来越确定；
有些 confidence 上升；
有些被新的 evidence 推翻；
有些暂停；
有些重新激活；
有些发生 drift。

你的人物状态也是：

$$ S_{t+1}=G(S_t,O_{t+1},P) $$

所以你真正可能长期积累的技术能力，反而是：

stateful sequential modeling / dynamic state tracking

而不是什么狭义“心理学”。

不过二者有一个很重要的区别

导师的问题主要是：

我怎么从外部行为推断用户内部到底想干什么？

也就是很强的 Inference / Tracking：

$$ H_{\le t}\rightarrow I_t $$

而你现在这个 Character Dynamics 不仅要推断，还想拿状态生成行为：

$$ H_{\le t}\rightarrow S_t \rightarrow P(A_{t+1}) $$

甚至：

$$ A_{t+1}\rightarrow W_{t+1}\rightarrow S_{t+1} $$

所以你的东西比单纯 intent tracking 多了一整个：

状态 → 行为 → 环境 → 新状态

的闭环。

这也是为什么你最后会自然走向游戏 Agent。

更有意思的是：“intent”其实可以直接成为你角色状态的一部分

例如人物：

长期人格：
谨慎、回避冲突

当前关系：
对 B 信任下降

当前情绪：
烦躁

当前 goal：
想早点回宿舍

当前 intention：
暂时不想和 B 讲话

这里：

goal / intention

本来就是你的动态 state。

导师研究的是：

这个 intention 怎么从交互里追踪出来、什么时候收敛、什么时候改变？

你研究的是更广的：

intention + emotion + relation + belief 等状态怎样共同演化，并影响行为。

所以你导师那条线甚至可能直接给你贡献一个很重要的方法来源：

不要只看 affective computing。

你现在还应该开始注意：

intent tracking
goal tracking
dialogue state tracking
dynamic user modeling
preference drift
concept drift / change detection
belief/state estimation

因为这些领域虽然不研究“游戏人物情绪”，却可能已经解决了你非常需要的一个底层问题：

一个不可直接观察、又会变化的状态，怎么从连续证据里稳定地更新？

这个比再看十篇“情绪有哪六种”可能更有计算价值。

所以你现在其实出现了一个挺漂亮的研究主线

你不要把自己锁死成：

“我是研究 NPC 心理学的。”

可以往上一层看：

我对 Agent 中持续变化的隐状态（dynamic latent state）感兴趣。

导师给你的应用：

用户 intent / goal tracking。

你自己最感兴趣的应用：

character state / behavior dynamics。

这两个场景都需要：

$$ \text{stream} \rightarrow \text{state estimation/update} \rightarrow \text{future prediction} $$

这就非常计算机了。

而且这对你还有个很现实的好处：你不是为了做游戏，把自己钻进一个极其小众的 NPC 坑里。

你研究出来的状态表示、增量更新、状态漂移检测、多时间尺度更新、预测验证这些东西，如果做得好，是可以迁移回一般 Agent/user modeling 的。

所以如果以后导师问你：

“你怎么从我推荐的用户意图追踪跑去做游戏角色了？”

你其实完全可以解释成：

我没有完全换问题。我现在感兴趣的是连续交互里的动态状态跟踪。用户意图是这种状态的一种，角色的情绪、关系、目标和 belief 是更丰富的一组状态。我想先在可控的游戏环境中研究状态如何更新以及它是否具有未来行为预测力。

这个逻辑我觉得比“我突然想研究计算心理学”稳得多。

而且现在我会建议你接下来查文献的时候，不要只开一条 “character emotion/state update” 线，而是同时开一条 “dynamic intent / user state tracking” 线。很可能你真正的方法灵感，反而会从导师推荐的这条线里出来。
