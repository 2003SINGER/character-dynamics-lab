但正式训练前，我认为协议还差 4 个必须冻结的点

这些不是推翻设计，是把最后的统计公平性封死。

1. phi(t,a) 必须精确列出来

现在只写：

frozen candidate semantics（含 scene bias 的固定字段）

还不够。

正式协议必须明确类似：

phi =
[
  goal_progress,
  stimulation,
  recovery,
  hunger_relief,
  bathroom_relief,
  short_term_reward,
  environment_control,
  context_relevance,
  scene_bias
]

以及：

是否标准化
是否加 intercept
缺失值如何处理
scene_bias 是单独 feature 还是提前加到 logit

否则以后完全可能出现：

看到结果不好 → 偷偷改 phi。

所以 phi 本身也必须 versioned。

2. regularization / optimizer 还没冻结

协议现在只写：

same regularization
same optimization
same training budget

但没写具体是什么。

正式开跑前至少冻结：

loss = conditional multinomial NLL

optimizer = ?
L2 lambda = ?
max iterations = ?
convergence tolerance = ?
random seed = ?

如果 λ 要调：

train
↓
validation 选 λ
↓
test 只跑一次

而且三种 S 必须用同一 λ grid 和同一选择规则。

不能每种 S 单独人工挑一个最好看的 λ。

3. 当前 140 steps 绝对不能成为正式 test

这个尤其重要。

这 140 steps 我们已经反复看过：

verb-only
scene-aware
theory-S
permuted-S

而且正是根据它发现：

empirical rank≈1

然后设计了这个 protocol。

所以它已经是：

development set

不可能再叫 held-out test。

Luna 的协议现在也写了“正式训练待独立行为真值准入”，这个判断是正确的。

正式实验需要：

train
validation
untouched test

并且至少 trajectory/episode-disjoint。

如果角色/persona 在多个 trajectory 重复出现，还得审：

persona identity leakage

是否需要 persona-grouped split。

4. no-S 最好分成两个不同概念

这个我刚重新想了一下，挺重要。

目前协议里的：

no-S

如果单独训练：

$$ z=\beta^\top\phi $$

只有 β。

而 S 模型有：

$$ \beta + w $$

所以参数量更多。

这并不意味着 no-S baseline 错，但它回答的是：

最优的无状态模型 vs 最优的有状态模型。

而necessity最好再加一个更硬的 intervention：

trained Theory-S → test-time zero-S

训练：

correct Theory-S

测试时只把：

S_t := 0

其余：

β
w
phi
candidate set

全部不变。

于是最终最好有三个不同东西：

Retrained no-S
    → 最强无状态模型

Theory probe + zeroed S
    → 同一模型里移除状态信息

Theory probe + permuted S
    → 同一模型里换错历史状态

这三个作用完全不同：

条件	回答什么
retrained no-S	状态模型整体是否优于最佳无状态模型
zeroed-S intervention	当前 probe 是否真的消费 S
permuted-S intervention	是否需要正确归属的历史 S

这个会让 Paper-0 necessity 非常漂亮。

Activity-S 还有一个小语义注意点

现在定义：

x=1 iff ΔScene/O contains any transition event

这是可以的。

但我们已有：

ObservedEntityGained/Lost

是通过 observation 文本里的 entity label matching 推出来的，噪声比较大。

所以协议最好明确：

Activity-S 使用与 Theory-S 同一个 frozen transition compiler 输出，不另加/删 event 类型。

这样即使它很 noisy，也是预先冻结的 naive baseline，不是后来为结果服务。
