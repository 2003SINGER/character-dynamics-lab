## 真正好的地方

最重要的是，**之前最危险的 AI 行为已经被控制住了**。

`90_原始材料` 虽然里面有几十万字的聊天原文，但它现在明确只是 archive，不参与前台 truth。这个千万别因为“看着大”去删。那是 provenance，不是屎。

`00_研究设计/README.md` 也已经建立了 ownership：

```text
机制 → 完整机制说明
问题 → 前台问题
未决 → 未决问题
行动 → TODO
实现事实 → 当前实现进度
历史 → 归档
```

这个治理思路是对的。

而最新 Replay 侧甚至比普通学生科研仓库规范很多：

```text
raw source
→ ReplayRecord
→ SceneSnapshot
→ transition/appraisal
→ S
→ raw features
→ fixed probe
→ optimization
→ intervention
→ manifest
```

再加：

```text
goldless prediction boundary
dev/test 区分
field provenance
lambda sweep
optimizer trace
module hashes
dirty-worktree
permutation controls
```

这些不是 AI 堆功能，反而是在**限制 AI 乱动**。

## 从整个项目角度看

其实我现在比昨晚更放心。

之前最大的问题是：

> 概念很多 → 文献很多 → 数据集很多 → demo 很复杂 → 但没有一个能杀死想法的实验。

而现在已经收敛到了：

```text
Paper-0 question
↓
LIGHT restricted dev
↓
same candidate support
↓
Activity / ActionSupport / Theory S
↓
same probe family
↓
gradient fitting
↓
correct / zeroed / permuted
↓
NLL
```

这是**科研主线越来越窄**，不是越来越散。

所以现在项目最大的危险已经不是“AI 写出来一个没人懂的系统”。

而是：

> **AI 很勤快，导致周边文档不断刷新，最终“哪个文件才是真的”再次模糊。**

这很好解决：**实验往前走，文档停止增殖，只同步 canonical truth。**

我的总体评价会是：

> **代码层已经从 AI 原型进入“能做实验”的状态；研究层也终于有可证伪主链。当前真正需要治理的是文档状态漂移，而不是再做架构清洗。**

今晚做到这里，我觉得屎山回顾可以结束了。明天第一优先级应该是**跑数据，不是再整理仓库**。
