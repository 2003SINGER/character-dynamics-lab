- `support(supporter, supportee)`

$$
W_t =
\{\text{objects, properties, relations, affordances, events, time, causal consequences}\}

O_t^i=M_i(W_t)
$$

$$

game layer 决定“维护什么状态、如何随时间变化、如何响应输入”；game engine 专门运行 tick、保存/加载 world state、处理 inputs；agent 层可以调用 LLM，但**不能直接随便修改游戏状态，而要提交 input 给 game engine**。([GitHub](https://github.com/a16z-infra/ai-town/blob/main/ARCHITECTURE.md))

而且它有非常明确的：

```text
input
→ invariant check
→ game engine
→ state delta
```

比如 `moveTo` 会先检查“正在对话的人不能直接移动”，合法才修改 pathfinding state。世界还可以自己随 tick 演化，比如人物位置持续变化、碰撞触发重新规划。([GitHub](https://github.com/a16z-infra/ai-town/blob/main/ARCHITECTURE.md))

这个跟你之前说的：

> “LLM 不能说关门就随便改 prompt；世界里本来得有这扇门、它得允许 close，然后由世界执行这个 action。”

**工程理念上已经非常接近。**

所以“AI 小镇很菜”那次我们其实也说得太快了。

它的人物认知很简单，但**世界和 agent 的职责隔离恰恰是值得你借鉴的**。

不过 AI Town 架构文档没有给我足够证据说明它像 Generative Agents 原论文一样严格实现：

$$
W\rightarrow O_i
$$

的 epistemic mask。agent operation 本身能查询 game state，所以我不会把“严格局部可见”也算给它。([GitHub](https://github.com/a16z-infra/ai-town/blob/main/ARCHITECTURE.md))

---

### FAtiMA 反而是“人物系统插件”——这对你非常关键

FAtiMA 不是要自己当游戏世界。

它负责的主要是：

```text
beliefs
autobiographical memory
emotional state
goals
appraisal
decision
action
```

世界事件进来，人物认知系统处理，人物 action 出去。

Toolkit 里虽然有一个 `World Editor`，可以配置 action consequences，但是论文明确说，这些 action effect **完全可以直接写在外部 game engine 中，再通过 events 通知 FAtiMA**。([arXiv](https://arxiv.org/pdf/2103.03020))

实际项目里也是这么做的：

> integration with the game engine was handled directly by the developers；

而 FAtiMA 管人物 beliefs、reactions、actions。([arXiv](https://arxiv.org/pdf/2103.03020))

这就意味着：

```text
Game / World engine
       │ event
       ▼
     FAtiMA
 belief / memory / appraisal / emotion
       │
     action
       ▼
Game / World engine
```

**这个职责划分其实和你现在想要的系统比 PsychSim 更像。**

区别是：FAtiMA 研究的中心是“角色认知和情感架构”，不是“世界层应该怎样设计”。

所以它真正压你的是：

- 人物显式状态；
- appraisal；
- emotion；
- memory；
- goals；
- 状态影响行为；
- 外部事件推动状态更新。

这也是为什么我现在更不建议你把“加入 trust / emotion / appraisal / memory”当方法创新。FAtiMA 这条线几十年前就在干。

---

### EMA 更不能被说成“它也有 world，所以跟你一样”

EMA 的核心对象叫 **causal interpretation**。

原文自己定义得特别清楚：

> agent 对自身 agent–environment relationship 的当前解释；

里面统一保存：

- beliefs
- desires
- intentions
- plans
- probabilities
- causal history
- 当前世界状态
- 未来可能结果

而且这个 representation 会随着 observation 和 inference 变化。([Stacy Marsella](https://stacymarsella.org/publications/pdf/EMA_Dynamics.pdf))

注意：这是**人物脑中的 causal interpretation**。

它甚至能表示：

```text
state propositions
actions
preconditions
effects
causal links
threats
duration
asynchronous effects
```

所以从“人物怎样理解一个动态世界”来说，EMA 非常强。([Stacy Marsella](https://stacymarsella.org/publications/pdf/EMA_Dynamics.pdf))

但它不是你所说的客观 `W`。

更关键的一枪是作者自己写的：

> EMA currently makes the assumption that the world is fully observable.

也就是过去和当前 proposition 没有 epistemic uncertainty；不确定性主要存在于未来 action outcome 和其他人的 intention。([Stacy Marsella](https://stacymarsella.org/publications/pdf/EMA_Dynamics.pdf))

所以：

> **EMA 对你的 `S` 动力学极危险，对 `W→O` 信息边界反而不是直接先例。**

它真正值得你读的是：

$$
\text{event}
\rightarrow
\text{causal interpretation}
\rightarrow
\text{appraisal}
\rightarrow
\text{emotion}
\rightarrow
\text{coping}
\rightarrow
\text{action / cognition}
$$

尤其你那个“LLM 轻微负面事件会不会越滚越负面”“恢复为什么缺失”的问题，EMA 比 PsychSim 更该查。

---

### DYNToM：现在可以明确说，它离你的“运行系统”其实很远

这篇名字特别容易把人骗过去。

它确实有：

$$
belief\rightarrow emotion
$$

$$
belief+emotion\rightarrow intention
$$

$$
belief+emotion+intention\rightarrow action
$$

而且跨五个 scenario 建 mental-state trajectory。([ACL Anthology](https://aclanthology.org/2025.acl-long.1171.pdf))

但这些 trajectory 是：

1. GPT-4-Turbo 根据设计原则**先生成出来**；
2. 生成 state transition cue；
3. 人工评 coherence / rationality / authenticity；
4. 再根据这个预先规定好的 trajectory 生成 dialogue；
5. 最后把它变成选择题 benchmark。([ACL Anthology](https://aclanthology.org/2025.acl-long.1171.pdf))

它所谓的 dynamic evaluation 是问：

- state 有没有变化；
- 为什么变化；
- 五个 scenario 里怎么变化。

ground truth 就来自前面预制的 trajectory。([ACL Anthology](https://aclanthology.org/2025.acl-long.1171.pdf))

所以 DYNToM：

> **研究的是 LLM 能不能理解别人已经写好的心理状态演化，而不是一个人物状态更新机制本身是否正确。**

没有 executable world。
没有 `W→O`。
没有 action 真正反馈进 world。
没有干预之后重新运行状态动力学。
没有行为概率校准。

所以它应该从“危险的系统先例”降级成：

> **很重要的 evaluation / dataset 邻居。**

---

### Dynamic Persona Coherence：这个才真的直接撞你的“状态怎么更新”

这篇的定义就是：

$$
A_t=Transition(A_{t-1},E_t,I)
$$

其中：

- $I$：稳定 identity；
- $A_t$：动态心理状态；
- $E_t$：当前事件；
- $R_t$：行为响应。([ACL Anthology](https://aclanthology.org/2026.acl-long.1336.pdf))

而且他们真的显式维护了几个不同尺度/性质的状态，用 GPT-4o 给每个 event 算 state delta：

$$
\Delta S,\Delta M_m,\Delta M_s
$$

然后：

$$
S_t=\operatorname{clip}(S_{t-1}+\Delta S)
$$

长期累积。([ACL Anthology](https://aclanthology.org/2026.acl-long.1336.pdf))

所以你前几天说：

> 情绪快、压力慢、trust 建立慢但背叛骤降……

如果最终只是搞一个：

```text
fast state
medium state
slow state
+ event delta
```

那确实已经非常危险。

但是 DPC 的 `E_t` 本质还是**对话中的 event stream**。

它没有：

$$
\text{objective world}
\rightarrow
\text{observation}
$$

这一步。

更没有世界对象/affordance/action consequences。

因此它真正压的是：

> **explicit cumulative subjective-state dynamics**

而不是完整 `W/O/S/A`。

---

### PersonaArena：现在看，它其实是最值得你警惕的“现代整体闭环”

PersonaArena 真的已经有：

```text
Environment Agent
        ↓
character observes environment
        ↓
episodic memory
Self-Belief + Env-Belief
        ↓
action
        ↓
Environment Agent
        ↓
character state update + environment update
```

论文明确写 protagonist 每轮观察当前 environment、检索 episodic memory、更新 Self-Belief 和 Env-Belief。([ACL Anthology](https://aclanthology.org/2026.findings-acl.471.pdf))

然后 Environment Agent：

- 看 action / utterance；
- 判断对其他角色的 impact；
- 决定谁响应；
- 更新 memory / position / emotion；
- **直接更新 character internal state**；
- 再更新 global environment。([ACL Anthology](https://aclanthology.org/2026.findings-acl.471.pdf))

所以表面图：

$$
E\rightarrow S\rightarrow A\rightarrow E'
$$

确实跟你很像。

但它有一个特别大的边界差异：

**Environment Agent 是 LLM narrative controller。**

它既在判断：

> “这个行为对别人造成什么心理影响”

又在改：

> physical/psychological states

又在改：

> environment。

于是你最坚持的：

```text
世界事实
≠
人物看到什么
≠
人物如何解释
≠
人物主观状态
```

在 PersonaArena 里实际上被 Environment Agent 糊在一起了不少。

它所谓 global environment 也主要是动态社会场景的文本状态，不是 AI Town / Generative Agents 那种明确由 game engine 执行 invariant / movement / object update 的 runtime。

它最后也不是测：

$$
P(A|S,O)
$$

而是多个 LLM judge 对整条 trajectory 打 Behavioral Coherence、Adaptability 等分数。([ACL Anthology](https://aclanthology.org/2026.findings-acl.471.pdf))

所以它确实证明：

> “弄一个 Environment Agent + 动态角色 + 闭环交互 + 一致性评分”

**绝对不能当创新。**

但它并没有做掉你的：

> 严格世界事实 / observation / interpretation 分离后，状态是否具有行为预测充分性以及干预响应是否正确。

---

### BDI / interactive narrative 也得重新放对位置

这里尤其不能再说“BDI 已经做过了”就结束，因为 **BDI 是一整类 formalism，不是一篇方法**。

它最基本的区分本来就是：

- belief：人物认为世界是什么样，可以与真实世界不同；
- desire：想让什么 world state 成立；
- intention：实际承诺去实现什么；
- plan/action：具体怎么做。

例如 IRIS 这种 narrative BDI 系统会给每个人物各自的 beliefs/desires/intentions/plans，故事中的 action effect 会更新角色 beliefs；如果新 belief 让原计划失效，还会 revision intention。([AAAI](https://cdn.aaai.org/ojs/12461/12461-52-15989-1-2-20201228.pdf))

所以：

> belief ≠ actual world

绝不是你的新东西。

> belief 变化 → intention / plan 改变 → character action

当然也不是。

但 narrative planner 通常关心的是：

> **如何生成一个有角色动机、又满足作者剧情目标的故事。**

这和你想问：

> **哪个动态 subjective state 是对未来行为有预测力的？**

不是一个 evaluation target。

它虽然**字面上能从 PsychSim 原文找到依据**，但作为 related-work mapping 非常容易误导。

我会改成：

> **PsychSim 已建立 ground-truth factored state、主体对该状态及他人 mental model 的主观 belief、基于 belief/preferences 的决策以及 action-driven state transition，并允许观察到的行为反过来触发候选 mental-model revision。它因此直接覆盖本项目“客观真值与主观认知可分、Forward 决策与有限 Inverse 推断”的形式骨架；但其 `world` 主要是决策论中的状态/转移模型，不等同于独立对象化、带 affordance 与运行时因果约束的可执行环境。**

这个版本我现在敢认。

而且读完这一圈后，我对你整个方向的判断也变了一个很重要的地方：

```text

        ↓

        ↓

```

所以**“把它们拼起来”本身仍然不是科研创新**；但真正该查的已经非常具体了：

> 在一个严格执行 `W ≠ O ≠ interpretation ≠ S` 的受控环境里，**哪一种历史压缩/主观状态表示，能够比 raw history 或普通 memory 更好地预测未来行为，并且在改变历史或可见信息时产生可校准、方向正确的行为分布变化？**

# chatgpt response

你现在的问题其实比前面那些“大框架”清楚得多。**你真正想研究的不是 world model，也不是 ToM，更不是单纯的动态 persona。**

你想做的是一个 **动态角色行为模型**，它既能拿来“验角色”，又能拿来“驱动角色”。

可以直接写成：

$$
(W_t,\;P_i,\;S_t^i,\;H_{\le t})\rightarrow
P(A_{t+1}^i)
$$

其中：

- $W_t$：当前客观世界，谁在哪、门开没开、手里有什么、现在几点、谁刚说了什么；
- $P_i$：相对稳定的人格/性格背景；
- $S_t^i$：当前动态状态，尤其是情绪、关系、短期目标、压力、期待之类；
- $H_{\le t}$：此前经历；
- $A_{t+1}$：**下一阶段可能发生的角色行为，不要求是“大剧情动作”**，关门、坐下、没回话、绕开某个人、顺手拿杯水、语气变冷都可以。

你之前文件里其实已经非常接近这个意思了：一致性不是问某个动作“像不像角色”，而是实际动作是否落在当时合理的条件行为分布里。

---

## 你最核心的东西其实是“预测式角色一致性”

比如游戏已经有完整剧情：

```text
第 1 阶段
世界 + 角色背景
       ↓
你的系统预测
P(关门)=0.55
P(直接走)=0.25
P(回头说一句)=0.15
P(其他)=0.05

游戏实际：
角色把门轻轻关上
```

这个动作就得到一个较高的一致性分数。

继续往下：

```text
第 2 阶段
上一阶段真实发生的事情
+ 新世界状态
+ 更新后的角色状态
       ↓
再次预测下一行为
       ↓
和游戏真实下一阶段比较
```

整个游戏就变成：

$$
\{A_1^*,A_2^*,...,A_T^*\}
$$

和模型预测的：

$$
\{P(A_1),P(A_2),...,P(A_T)\}
$$

逐步比较。

这和现在很常见的：

> “给 LLM 一段剧情，让它打 1～5 分，看人物 OOC 没有”

完全是两种评价思想。

你是在问：

> **如果我真的理解了这个人物，那么在每一个具体局面，我应该能提前预测他接下来更可能做什么。**

这就是 predictive validity。

你的文件里 Forward 那部分其实已经写到了：

$$
(S_t,W_t)\rightarrow P(A_{t+1})
$$

并且明确提出可以用真实叙事做 replay / teacher forcing。

### 而真正关键的是：不只预测“大决策”

这点我之前也确实没有抓得足够重。

你想让角色“活起来”，大量信息其实来自**微小行为**。

一个性格内向、此刻心情低落的人：

- 进屋后顺手关门；
- 坐角落；
- 不主动打开音乐；
- 别人进来以后只是抬头；
- 手机亮了但没立即看；
- 离开的时候没有主动告别。

这些单独哪个都不是剧情节点。

但是很多这样的：

$$
a_t^{micro}
$$

累积起来才构成我们对“这个角色活着”的感觉。

所以你的 action space 不应该理解成传统规划里的：

```text
Attack
Help
Escape
Betray
```

完全可以同时存在：

```text
宏观行动
接受邀请
拒绝邀请
主动帮忙

互动行为
主动搭话
避开某人
回复消息
沉默

微行为
关门
坐哪里
是否看手机
走快/走慢
是否停顿
拿不拿某个物品
```

当然研究第一版不能无限开放，得从有限 affordance 里选。

比如当前世界：

```text
door = open
character = inside_room
phone = on_table
B = in_corridor
```

世界层告诉人物：

```text
合法动作：
- close_door
- leave_door_open
- pick_phone
- sit
- follow_B
- speak_to_B
...
```

然后角色模型决定：

$$
P(A\mid P,S,O)
$$

这就非常接近你真正想要的东西。

## 而“性格 + 情绪”这里，你的直觉也可以变得非常清晰

我不建议写成：

$$
Personality\rightarrow Action
$$

因为这样人物会像性格标签机器人。

你真正想表达的大概是：

$$
P_i
\rightarrow
\text{长期倾向 / 状态动力学}
$$

然后：

$$
S_t
\rightarrow
\text{此刻行动倾向}
$$

也就是：

### 性格是背景 / prior

例如一个人：

```text
低外向
高谨慎
习惯维持私人空间
不喜欢正面冲突
```

这决定他的长期行为分布长什么样，也影响状态怎样变化。

但是他不是：

> “内向，所以永远不主动讲话。”

### 情绪和当前状态负责“这一刻”

同一个人：

```text
平静
→ 可能顺手关门，自己坐着

兴奋
→ 可能忘记关门，直接进去跟朋友讲话

烦躁
→ 可能重重关门

警惕
```

- 不会胡编不存在的动作；
- 可以真的接游戏；
- 能拿到完整概率分布；
- 能评价小行为；
- 不需要 LLM judge 猜生成文本是不是等价。

这比 BehaviorChain 的自然语言行为生成**干净很多**。

但我目前不能说这是没人做过——这个需要专门查 **affordance-conditioned character action prediction / game NPC action modeling**。

也就是：

```text

↓

↓

↓

```

```text
        ↓
action
```

反而是一种 baseline。

# 所以现在终于可以谈“你的方法可能创新在哪里”

不是：

> 下一行为预测。

不是：

> 动态 persona。

也不是：

> AI NPC。

而是在**中间真正怎么计算**。

我目前看到四个非常具体、而且与你原始想法高度一致的候选方法问题：

1. **Personality-conditioned state dynamics**

   不只是把人格写进 Prompt。

   而是真正研究：

   $$
   S_{t+1}=F(S_t,O_t,Outcome_t,P,\Delta t)
   $$

   即：

   > **同一个事件，对不同性格的人应该留下不同的状态变化。**

   然后这个状态还会自然恢复、累积或突变。

2. **State-conditioned micro-action policy**

   世界先给有限的、真实可执行动作：

   $$
   \mathcal A_t
   $$

   角色模型再输出：

   $$
   P(A|\mathcal A_t,P,S_t,O_t)
   $$

   于是“关门、坐哪里、是否回应”这种微行为才能真正成为角色表现，而不是 LLM 自由写小说。

3. **Behavior-grounded state correction**

   这其实是你那个“反过来”的想法真正有趣的版本。

   假如系统认为：

   ```text
   A 对 B 已经非常厌恶
   ```

   因而预测：

   ```text
   help_B = 0.05
   ```

   结果游戏真实剧情里：

   > A 毫不犹豫帮了 B。

   那不是简单给这一题打叉就结束。

   **这条真实行为应该反过来告诉系统：你对 A 当前状态的估计可能错了。**

   即：

   $$
   S_t^{old}
   \xrightarrow[\text{observed }A_t^*]{}
   S_t^{revised}
   $$

   然后用修正后的状态继续预测后面。

   这才真正形成：

   ```text
   经历
   ↓
   估计人物状态
   ↓
   预测行为
   ↓
   看到真实行为
   ↓
   修正人物状态
   ↓
   再预测
   ```

   **这是一个真正的在线角色建模问题。**

4. **State 必须被行为证明，而不是自己说得好听**

   假如一个方法维护：

   ```text
   trust=0.42
   stress=0.71
   attachment=0.55
   ```

   看起来特别科学。

   但删掉这三个变量以后，下一行为预测完全不变。

   那这些就是假的“心理解释”。

   你的系统可以专门要求：

   > **状态改变必须对实际动作分布产生可测影响。**

   甚至进一步干预：

   ```text
   只改 anger
   ↓
   哪些动作概率应该变化？

   只改 trust_B
   ↓
   哪些与 B 有关的行为应该变化？

   只改 personality
   ↓
   状态更新轨迹和行为策略各自怎样变化？
   ```

这四个已经不是“大概念”了，而是四种可以写代码、跑实验、互相比较的**具体机制**。

## 现在真正的研究对象

你想做的可以叫 **动态角色行为模型 / Character Dynamics Model**。

它不是一句：

$$
History\rightarrow Action
$$

而是一条具体的计算链：

$$
\boxed{
W_t
\rightarrow O_t
\rightarrow S_t
\rightarrow P(A_{t+1})
\rightarrow W_{t+1}
}
$$

其中还存在一个相对稳定的角色背景 $P$，也就是性格、习惯、价值倾向等。

更完整地说：

$$
S_{t+1}=F(S_t,O_t,A_t,\mathrm{Outcome}_t,P,\Delta t)
$$

以及：

$$
P(A_{t+1}\mid P,S_{t+1},O_{t+1},\mathcal A_{t+1})
$$

这里的 $\mathcal A_t$ 是**世界当前真正允许角色执行的动作**。

这一步很重要，因为你从来没有限定 action 必须是“背叛、救人、接受任务”这种剧情大动作。你的真实兴趣反而大量在：

> 关不关门、坐哪、有没有接话、要不要看手机、有没有回头、会不会避开某个人、语气和动作方式……

这些小动作才是角色在游戏里“活起来”的主要部分。

而你最近又进一步明确了一层：

> **性格是背景，当前情绪和状态更直接驱动当下的小行为。**

所以性格 $P$ 不是一段放在 Prompt 顶部的角色介绍，而应该至少参与两个地方：

$$
P \rightarrow \text{状态怎么被事件改变}
$$

以及

$$
(P,S_t)\rightarrow \text{同一状态最终怎样表现成行为}
$$

例如同样被激怒，冲突回避的人可能沉默、关门、离开，外向冲动的人可能追出去对质。甚至同一个刺激本身，也可能因为性格不同造成不同的状态变化。

这已经从“动态 persona”进一步变成了**人物动力学**。

## Replay 和 NPC 生成现在也终于放对了位置

你一直想要的两个用途没有被删掉，只是我们现在知道它们属于**同一个 Character Model 的两种使用方式**。

第一种是已经写好的游戏、小说或者剧本：

```text
真实历史
→ 更新角色状态
→ 在这一时刻预测各种行为
→ 下一阶段真实行为揭晓
→ 检验模型
```

也就是你原来定义的 Forward / replay。

例如模型预测：

```text
关门       0.40
坐下       0.24
拿手机     0.15
追出去     0.04
……
```

然后游戏真实剧情里人物关门。

这不是你的“创新本身”，而是一个非常有价值的**试验仪器**：

> 如果你声称自己正确维护了“这个角色现在是什么状态”，那这个状态应该帮助你预测他后面真的会做什么。

第二种则是开放游戏：

```text
当前世界
→ 当前角色状态
→ 行为分布
→ 真正选一个动作
→ 游戏引擎执行
→ 世界变化
→ 状态继续更新
```

也就是用同一个模型真正驱动 NPC。

所以“角色一致性检测”和“让角色活起来”并不是两个互不相干的项目。前者给你真实 ground truth，后者是部署。

你的材料之前其实已经有这个思想，只是现在我们终于知道**它是模型使用方式，不是研究贡献本身**。

# 现在真正可能形成研究方向的地方

目前最值得研究的已经不是再造一个“动态 NPC 架构”，而是这条计算链里的几个“怎么”。

第一块是 **状态如何形成和更新**：

$$
S_{t+1}=F(S_t,O_t,P,\mathrm{Outcome},\Delta t)
$$

例如：

- 同一个事件为什么对不同性格的人产生不同影响？
- 情绪怎么恢复？
- trust 为什么有时慢慢积累、一次背叛又可能骤降？
- 一个 LLM 自由更新状态会不会把轻微受挫不断放大？
- 时间自然流逝应该怎样改变状态？

你原来的材料里已经保留了 “state jump / 单调负向漂移 / 恢复缺失 / framing amplification” 这些 failure mode。

这意味着一种可能的研究路线不是先发明心理公式，而是：

> **先证明现有 LLM 状态更新哪里会坏，再设计针对性的 Character State Dynamics。**

第二块是 **状态如何变成具体行为**：

$$
P(A|\mathcal A_t,P,S_t,O_t)
$$

这里很贴你的游戏兴趣。

世界负责：

> “现在客观上能做什么？”

角色负责：

> “在这些动作里，这个人现在想做什么？”

这样“关门”这种微行为才能被正式纳入角色建模，而不是让 LLM 自由写一段剧情。

这里可能进一步形成一个你很有特色的方向：

> **人物当前状态如何调制大量 affordance-level micro-actions，从而产生持续的角色感。**

这比泛泛的“NPC 选择行动”具体得多。

第三块是你之前提出、现在终于解释清楚的 **反向修正**。

不是简单：

$$
Action\rightarrow State
$$

而是：

```text
根据历史估计 S_t
↓
根据 S_t 预测行为
↓
真实行为出现
↓
发现预测不符
↓
反过来修正对 S_t 的估计
↓
继续预测后面
```

比如系统认为：

> A 已经极其厌恶 B。

于是预测：

$$
P(help_B)=0.03
$$

结果 A 毫不犹豫帮助了 B。

这个真实行为不应该只是“预测错一题”。

它应该反过来说明：

> **我们对这个角色当前状态的理解有问题。**

这才是你之前所谓 Forward–Inverse 真正有意思的版本：**在线角色状态估计与修正**。你的材料里原本已经明确提出行为/反馈反推状态这一方向。

第四块则是一个很重要的方法论原则：

> **人物状态不能只是写得很好看的心理档案，它必须真的影响行为。**

例如模型维护：

```text
trust = 0.42
anger = 0.73
stress = 0.65
```

看起来很高级。

但如果删掉这些字段，行为完全不变，那么这些状态就是装饰。

所以你可以做：

```text
只改变 trust
→ 与这个人的互动行为是否系统性改变？

只改变 anger
→ 哪些微行为概率改变？

换不同 personality
→ 同一事件造成的 StateDelta 是否不同？
```

这就是你之前提出的干预式验证。

# 所以我们现在的“定位”可以更新成这样

最开始很容易把你定位成：

> 动态 persona / 心理 NPC / AI 小镇。

现在我觉得都不准确。

更合适的是：

> **Character Dynamics：研究一个角色的稳定背景与动态主观状态如何在受控世界和连续经历中演化，并进一步产生具体行为；同时利用真实行为轨迹反过来检验和修正角色状态模型。**

而其中真正的科研核心不是“我要建一个大游戏世界”。

世界更多是实验条件。

也不是“我要设计一套完整心理学”。

心理变量只是候选表征。

更不是“我要让 LLM 扮演人物”。

LLM 只是可能的实现工具。

真正研究的是：

$$
\boxed{
\text{过去怎样留在一个人身上}
\rightarrow
\text{这个人现在是什么状态}
\rightarrow
\text{为什么此刻会这样行动}
}
$$

以及反方向：

$$
\boxed{
\text{他真的这样行动了}
\rightarrow
\text{我们之前对这个人的理解是否应该修正}
}
$$

这已经和最初“做一个能让人物活起来的系统”的兴趣保持住了，同时比“大而全 NPC 框架”更像科研问题。

## 我觉得我们这一轮最大的三个推进

第一，**没有为了“收科研问题”而把你的长期愿景删掉。** 小说/游戏 replay、NPC 驱动、客观世界、多主体以后都还在，只是第一次实验不必全做。你原来的底稿那句话仍然非常准确：**“收束的是一次可否证实验，不是整个好奇心。”** 

第二，**终于把“验证方法”和“模型方法”分开了。**

“预测下一真实行为”是验证。

真正的方法是：

$$
O\rightarrow StateDelta\rightarrow S
\rightarrow ActionDistribution
$$

以及真实行为对状态的反向修正。

第三，也是最关键的一点：**查新方式变了。**

以后不是：

> “有没有论文做动态人物？”

这种问题肯定一搜一大片。

而应该逐项查：

> 事件怎么变成 StateDelta？  
> 性格怎么调节 state transition？  
> 状态怎么影响微行为？  
> 世界 affordance 怎么进入角色决策？  
> observation 和 belief 怎么隔离？  
> 行为怎样反向校正角色状态？  
> 状态变量是否经过行为层面的 intervention 验证？

只有这样，我们才是在找**你的具体机制还能在哪里创新**，而不是不断把你的想法压成一个大概念，再发现“大概念早有人做了”。

所以目前我会把这个项目的阶段定位成：**母题已经比较稳定，整体系统愿景也清楚；现在刚刚进入真正的方法空间探索期，还远没有到“选定具体算法”的阶段。** 下一步应该逐个拆上面这些“怎么”，对着最直接的前人方法找可以改、可以组合、或者确实没解决好的地方，而不是继续扩充大框架。
