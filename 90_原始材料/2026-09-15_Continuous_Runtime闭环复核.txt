### 先说做对了什么

最重要的是，之前那个：

```text
scheduler = 09:10
World      = 09:00
O timestamp 手写 "09:10"
```

已经被正面解决了。

现在新增了 `WorldRuntimeAdapter`，明确规定它是 **scheduler-native 唯一允许推进 W 时间的桥**；构造时就要求 `world.time == scheduler.now`，每次 boundary 前后也都检查二者一致。 

而 `World` 也新增：

```cpp
advance_runtime_by(int elapsed_minutes)
```

旧 `settle()` 保留给 Reference v0，所以没有为了新 runtime 去破坏旧实验。这个边界是对的。

而且 vertical smoke 已经不再自己：

```cpp
world.unread_messages = 1;
```

伪造消息了。

现在 scheduler 只提供 09:30 这个 boundary，真正的 `message-study-group` 是由 `World::advance_runtime_by()` 在世界时间推进时产生的。这已经开始接近：

```text
clock
→ W
→ WorldEvent
```

了。

另外，**数据流已经第一次被写成正式架构规则**。

`ARCHITECTURE_RULES` 第一条现在明确写了：

- 单一 authoritative simulation clock；
- `W/O/S/P/RunningAction` 是 persistent nodes；
- deltas/events 才是 flow；
- action 不能推进 runtime clock；
- hidden W event 不能开 character gate；
- fixture 不能自己手工同步 timestamp。

`AGENTS.md` 也写进去了，所以以后 Codex 至少不会再完全忘掉这个基本原则。

这一步非常重要。

# 但现在有一个新坑：动作“完成”了，却没有真正结算

这个是目前最大的 blocker。

上一版 `e10c984` 在 35min action completion 时还有：

```text
scheduler says completed
↓
world.settle(StudyFocused)
↓
WorldOutcome
↓
self feedback → O
↓
X → S
↓
π
```

虽然它重复推进时间，所以错。

现在为了避免 `world.settle()` 再推进 35min，Luna **直接把整个 settlement 拿掉了**。

最新 smoke 到 action completion 后实际是：

```cpp
completion_boundary = scheduler.advance_to_next_boundary();

world_runtime.advance_to_boundary(...);

advance_continuous_state(...);

Appraisal completion_x = appraise(observation, ...);

update_state(...);

decide(...);
```

没有：

```text
W study settlement
task effort +
study_sessions +
WorldOutcome
self-action feedback
```



所以现在发生了：

```text
09:20 StudyFocused starts
        ↓
09:55 scheduler:
      RunningAction = Completed
        ↓
但 W：
      没结算 StudyFocused
      没增加 task effort
      没产生 ActionOutcome
      没有 self-feedback
        ↓
却直接开始下一次 decision
```

这当然不行。

但这是**非常明确、很好修的坑**：

> 我们需要一个 scheduler-native 的 **completion settlement**，它只结算动作效果，绝不推进时间。

也就是从旧：

```text
World::settle(action)
=
validate
+ effects
+ task progress
+ counters
+ AdvanceSimulationTime
+ scheduled events
```

正式拆出：

```text
runtime validate/start
```

以及：

```text
runtime settle_completion(action)
=
effects
+ task progress
+ counters
+ typed WorldOutcome

NO TIME ADVANCE
NO INTERVAL EVENT SCAN
```

这才完成我们一直想拆的：

```text
时间是谁管？
→ scheduler

动作结果是谁管？
→ W
```
