1. 设计 Theory-S v1

从仓库已有心理学 / computational emotion / game AI 文献中选择一个最小、可解释、可实现的 Theory-S v1。必须明确：

每个 X/appraisal 维度来自哪篇已有文献、承担什么职责；

每个 S field 自己的 dynamics：输入、惯性/恢复/衰减、饱和、P 调制；
S 如何进入行为评分，而不是只被记录。

不要为了“心理学感”无限增加字段。优先控制在约 3–5 个真正行为相关的动态状态。允许例如 tension / engagement / fatigue / satisfaction 一类字段，但最终选择必须由现有文献和当前系统职责共同决定，不得凭空拍脑袋。

P 保持稳定参数，S 表示当前动态状态。P 与 S 可以共同影响 action score，但不要让 P 或 S 偷偷改变动作是否合法。

2. 实现 dataset-neutral 的 Scene/Object → Action candidate generation

当前 LIGHT 的 candidate_set_factual 只能继续作为 source observed candidates，不能当作我们自己的 A^O。

复用现有 SceneSnapshot / Object / affordance 结构，新增或完善一条明确的数据流：

dataset fields -> SceneSnapshot -> Objects / agents / possessions / observable facts -> affordances -> generated A^O

原则：

数据集有什么就使用什么；
数据集没有的事实保持 unknown，不脑补 world truth；
Action 必须由 object / agent affordance 与当前 O 中已知条件生成；
生成 A^O 时绝对不能读取当前真实 A*；
A* 只在 candidate generation 完成以后用于检查 support hit；
A* ∉ generated A^O 必须作为 support miss 保留，不能为了命中把 gold 塞回候选集；
source available_actions 可以作为后验诊断/比较，不参与生成我们自己的候选集合。

先用 LIGHT 里已有 setting / room objects / room agents / inventory / actor observation 做第一个 adapter smoke，但实现层保持 dataset-neutral，后续其他数据集有什么字段就输入什么。
