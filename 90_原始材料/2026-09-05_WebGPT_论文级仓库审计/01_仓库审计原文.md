### 你现在这个课题，我认为真正应该钉死的位置

不是：

> 我设计了一套 `W/O/X/S/P/D` 人物心理架构。

这个太容易被别人用“belief、world state、appraisal、BDI、persona state 都有人做过”打散，而且你自己也已经吃过这种亏。

更准确的是：

> **在部分可观测、可回放的角色环境中，把“历史发生了什么”“角色实际知道什么”“持续状态留下了什么”“最终行为分布怎么变”拆开，并用干预和 held-out 行为预测去检验一个持续状态到底有没有保留行为相关信息。**

也就是说，`W/O/X/S/P` 是**实验仪器**，不是论文标题里的贡献本体。

这个位置我现在反而比前几轮更看好，因为它非常符合你最初那个执念：你不是单纯想让角色“更像人”，你一直在追问的是——**一个角色为什么会这样变，以及这种变化是不是真的能解释/预测后面的行为。**

### 你现在最大的误区：把三个问题绑死了

目前仓库实际上把三件难度完全不同的事绑在了一起：

**受控因果性**：同样的当前场景，不同过去经历，状态是否留下不同后果，并进一步改变 `π(A)`？

**预测价值**：这个 `S` 是否比 raw history / strong summary 更能预测下一步？

**生态有效性**：它能不能预测真人、小说角色、真实玩家之类的外部人物行为？

第三个确实必须有独立 `A*`。所以你发现自己的模拟器不能自评，然后去找 BehaviorChain、SOTOPIA，结果 SOTOPIA 又塌成 `said / did nothing / left`，整个项目就像被卡死了。

但实际上：

**SOTOPIA 失败，只意味着“这个外部数据源不适合你的动作预测协议”。它根本没有否定前两个问题。**

所以我会把项目立即拆成两条证据线：

第一条是 **controlled intervention**。小房间继续用，不拿它声称“预测真人”，只验证信息边界、状态传递、历史干预、`S` 置换以后 `π(A)` 是否按预注册方向改变。这是机制正确性。

第二条才是 **external replay**。拿独立人类/外部行为轨迹做真正 NLL / ranking。这是预测有效性。

这样你就不会因为找不到完美数据集而半年都没有实验。

### 而且我刚刚给你找到一个你仓库里目前居然没有的、非常值得查的数据源：LIGHT

我搜了你当前仓库，`LIGHT / PersonaForge / ThinkPersona / AdaMARP` 都没有命中。这里面 **LIGHT 我建议立刻放到数据路线最高优先级，甚至优先于继续折腾 SOTOPIA。**

LIGHT 本身就是一个有世界、地点、对象、affordance、角色 persona 的文本游戏环境，而且原始数据是**真人 crowdworker 扮演角色产生的连续交互**：约 11,000 个 episode，角色在每轮可以说话、执行物理 action、做 emote。它还明确研究过：加入地点、对象、affordance、角色及过去行动这些 world grounding 后，能不能更好预测角色后续行为。([ParlAI][1])

更有意思的是后面的 LIGHT Quests 工作：有**human expert demonstrations**，把整体行为明确拆成 action commands 和 dialogue，而且直接做 held-out expert demonstration evaluation。附录报告了 1800/100/211 的 train/valid/test human demonstrations，并显式把 action/dialogue 分解。([ACL Anthology][2])

这对你有两重意义。

一方面，它是一个**比 SOTOPIA 更贴你数据需求的 A* 候选**：有真人角色行为、有世界、有 affordance、有 sequential interaction。

另一方面，它也是一个非常重要的近邻：所以你以后绝不能说“我们首次把 world grounding 用于行为预测”。LIGHT 很早就做了。你的问题应该变成：

> **LIGHT 已经证明当前 world/context grounding 有用；那经过持续更新的 character state，是否还能在 history/world grounding 之外提供额外的、可干预的预测信息？**

这一下问题反而变得很干净。

我甚至建议你下一项外部数据工作不要叫 T0c“SOTOPIA 继续抢救”，直接做：

**T0c — LIGHT action replay feasibility audit。**

只拿 30～50 个 episode，什么模型都不训练，先看能否恢复每个 turn 的角色可知环境、persona、历史、自身/他人行为、合法 action candidates 和真实下一 action。

### 我直接审代码以后，还有几个必须现在处理的硬伤

最明显的是你的**理论文档已经互相打架**了。

`完整机制说明_v0.md §3.1.1` 明确写：

> 人际关系存在 `W` 的图中。

但同一文件 `§3.8` 又明确说：

> `R_i[j]` 语义上属于角色侧，不能当作 W 的上帝视角心理真值。

这不是文字小问题，是 ontology 冲突。我的建议不是二选一，而是把“关系”拆掉：

**客观关系事实**放 W，例如同学、室友、上下级、发生过争吵、A 曾帮助 B。

**主观关系状态**放 `R_i[j]`，例如 A 对 B 的信任、亲近、戒备、怨恨。

**角色知道哪些客观关系事实**仍经过 `O_i`。

这样你之前想要的方向性 `A→B ≠ B→A` 也自然成立。

然后还有一个对正式实验非常致命的问题：现在 `observation.cpp` 的 `A^O` 是先调用：

`world.available_actions()`

然后再根据角色看到哪些 Object 过滤。

也就是说，**W 已经提前帮角色把“真正非法”的动作删掉了。**

这正是你自己的 Q04 一直担心的隐藏前置条件泄漏。真正的 `A^O` 应该由：

> 角色知道的 Object + 它认为存在的 affordance + 它相信成立的 precondition

生成。

然后交给 W：

> 接受 / 拒绝。

否则角色永远不会尝试“它以为能做、实际上做不了”的动作，`W ≠ O` 最重要的一块就被偷偷破坏了。

还有一个挺典型的实现—文档漂移：TODO 的 `T33b` 还写着要把两个新 Study 动作加入 `advances_committed_task`，但我直接看现在的 `decision.cpp`，**它已经加好了**。也就是说，你现在文档治理已经复杂到开始反过来制造噪声了。

以及 `Appraisal` 现在实际上还是：

`boredom_delta / fatigue_delta / task_pressure_delta / ...`

所以当前代码里的 X 并不是你理论里说的“事件对角色意味着什么”，它其实已经非常接近 `ΔS` 了。这个你文档里自己承认了，所以不算 bug，但意味着：**现在别拿 reference demo 宣称 X→S 已经实现。**

### 如果这是我的项目，我从明天开始只做这 5 件事

1. **冻结 v0。** 第一篇/第一个实验只留 `W → O → X → S → π(A)`；`P` 固定，`D` 当派生量。Inverse、多角色、二阶 ToM、P 漂移先全部退出“阻塞首实验”的位置。不是删除，而是 backlog。X 只选 1～2 个有意义维度，别一次上心理学大全。

2. **先修实验有效性，不继续扩功能。** 把 `A^O` 从 `world.available_actions()` 解耦；解决 W 与 `R_i[j]` 的关系所有权冲突；顺手清掉已经完成的 T33b。`task.effort` 现在还被标成 `direct_room_visual` 精确复制 W，我也建议重新定义成角色自知/估计进度，而不是上帝给的精确浮点数。

3. **跑第一个 E0 干预实验。** 做几十组 paired traces：终局 W 相同、当前 O 尽量相同，只改变之前历史；或者 W 相同只改变 observation mask。记录 `ΔO → ΔX → ΔS → Δπ`。再做一次 permutation-S：把 S 换成另一条轨迹的 S。如果 `π` 基本不变，你这套状态链就当场暴露没用；如果明显变，这是机制接通证据，但暂时不叫“真实行为预测”。

4. **并行只做一个数据审计：LIGHT。** 不训练，不重构系统，只检查它能不能提供你要的 independent `A*`。如果能，再建立 `current O`、raw history、strong summary、naive-S、theory-S、permuted-S 的真正 replay。Primary metric 用**同一样本上的 paired ΔNLL 对强 baseline**；按 `|A^O|` 分层报告 raw NLL。你现在的 `NLL / ln|A^O|` 可以继续做诊断，但我不会让它当主指标。

5. **暂停“82→100 篇论文”这种增长。** 只补与你当前实验直接相撞的几篇。尤其 LIGHT；然后抽一天机制级看 2026 的 PersonaForge、PersonaArena、ThinkPersona、AdaMARP。PersonaForge 已经在做 psychology-grounded dual-process 和长期 drift，PersonaArena 做动态社会模拟，ThinkPersona 做历史/persona graph，AdaMARP 做动态 scene/multi-agent orchestration；它们不意味着“你被做完了”，但说明你的 82 篇并不等于 2026 邻域已经封口。([ACL Anthology][3])
