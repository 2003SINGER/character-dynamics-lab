# 数据流回答的阅读判断（2026-09-01）

## 可保留的候选骨架

这份回答提出把角色模拟理解为一条可记录、可替换、可回放的数据流：

```text
Objective Event
→ Perception / Information Mask
→ Observation
→ Interpretation / Appraisal
→ State Delta
→ Subject State
→ Decision Context
→ Action Distribution
→ Action
→ Consequence / next Objective Event
```

其中最值得继续保留的不是“使用数据流”这一表述，而是三条可测试的边界：

1. **客观事实、角色观察、解释/信念不应混为同一种状态。** 未被角色感知的世界事实不能直接进入其主观更新；解释也不能被回写成世界事实。
2. **更新输出可先表达为 `StateDelta`，再由受限更新器应用到状态。** 这为幅度限制、惯性、衰减、边界和错误追溯提供了明确接口；这些机制是否采用、如何定义仍未决定。
3. **事件与状态变化应可追溯。** 这可支持历史回放、反事实移除某事件和错误定位，但 provenance 的粒度及其是否提高行为预测尚未验证。

## 暂不接受为项目结论的部分

- “数据流架构”本身不是可主张的研究创新；至多是支持对照、消融和复现的工程/实验骨架。
- `appraisal`、心理状态变量、LLM 与规则的分工、三种更新器对比及其评价指标都还是候选设计，不能据此声称存在心理机制、方法优势或论文空白。
- 从该骨架接入游戏运行时是可行的产品想象，不是当前工程承诺。

## 恢复后的最小判断

若用户明确启动该项目，可先以一个小世界的固定事件轨迹测试两件事：信息遮罩是否阻断了不应获得的事实；同一事件在不同既有状态下是否只产生允许范围内、可解释的状态增量。只有这两点可操作，再决定是否把“预测下一行为优于静态 persona”写进第一张问题卡。
