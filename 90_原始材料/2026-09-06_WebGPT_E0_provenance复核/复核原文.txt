# 三、我认为实验前最值得做的重构只有 4 刀

不是大重构。

更不是：

```text
抽象基类
factory
plugin manager
dependency injection framework
动态加载
visitor
```

这些现在全都不要。

## 第一刀，也是最重要的一刀：拆“决策”和“执行”

现在：

```cpp
advance_one_decision(...)
```

一次性干了：

```text
refresh O
→ X
→ update S
→ decide π
→ sample A
→ W settle
→ feedback
→ commitment
```

自主 NPC 当然方便。

但 Replay 实验不行。

因为 Replay 要做的是：

```text
看到 t 时刻信息
↓
输出 π(A)
↓
保存预测
↓
这时候才揭晓真实 A*
↓
评分
↓
用真实后续推进
```

所以现在最值得做的代码重构是：

```cpp
DecisionSnapshot prepare_decision(...);
SettlementResult settle_action(...);
```

大概：

```text
prepare_decision
    O refresh
    ↓
    X
    ↓
    S update
    ↓
    D / π
    ↓
    RETURN
```

然后两条模式：

```text
Autonomous:
snapshot
→ sample_action(snapshot.pi)
→ settle_action()
```

```text
Replay:
snapshot
→ score(A*)
→ teacher-force / ingest A*
→ advance
```

### 这不是 clean-code 重构。

这是：

> **把研究协议直接编码进软件边界。**

我认为这是现在整个代码库最值钱的一次重构。

# 五、第三刀：`ObservationFact` 现在太 stringly-typed

这是第二个真正值得担心的代码问题。

现在大量：

```cpp
"task.coursework.status"
"wallet.balance"
"room.light"
"object.computer.usable"
```

value 也是：

```cpp
"active"
"completed"
"20"
"true"
```

甚至有：

```cpp
std::stoi(wallet->value)
```

这种东西。

我们之前已经因为：

```text
object.computer.usable
```

字符串解析出过一次 stale bug 了。

以后实验更多以后会出现：

```text
task.coursework.status
task.courseworks.status
task.coursework.state
```

这种非常难查的错误。

### 但我也不建议现在造一个庞大 variant ECS。

最小改法就够：

```cpp
namespace FactKey {
constexpr auto WalletBalance = "wallet.balance";
constexpr auto RoomLight = "room.light";
...
}
```

加 typed accessor：

```cpp
known_int(...)
known_bool(...)
known_enum(...)
```

比如：

```cpp
auto wallet = known_int(o, FactKey::WalletBalance);
```

而不是：

```cpp
std::stoi(find_fact(...)->value)
```

这是**实验可靠性重构**，值得做。

# 十四、我建议从现在开始改我们的 WebGPT → Luna 工作流


以后每个真正实验开始之前，你先自己回答五句话：

> 我要跟 history、summary 和乱掉的 S 比。

> 还要防止模型只是记住用户/商品或者 session 前后泄漏。

这已经是实验设计的骨架了。
