parser：

def parse_event(raw_line):

    payload, raw_timestamp = split_last_semicolon(raw_line)

    event_class, rest = split_first_colon(payload)

    event_type = longest_known_prefix(
        rest,
        EVENT_TYPES[event_class]
    )

    value = rest[len(event_type):]

    return {
        "raw": raw_line,
        "event_class": event_class,
        "event_type": event_type,
        "value": value or None,
        "raw_timestamp": raw_timestamp,
        "source_order": event_index
    }

例如：

adapter 先做：

assert required_roles_exist()

找不到就报错，不静默猜：

"maybe this is participant_id"
5.1 AGAIN 的核心资产不是 A*

主要资产：

time-varying arousal proxy

所以先输出：

participant
game/session
time
telemetry
raw arousal

而不是强行：

next action benchmark
5.2 时间对齐必须 causal

这是最重要的一条。

假设：

telemetry event at t
arousal samples at t0,t1,t2...

prediction-time proxy 只能使用：

latest arousal sample where arousal_time <= t

或者：

past_window = arousal[t-W : t]

绝对不要：

linear_interpolate(
    arousal_before_t,
    arousal_after_t
)

然后拿这个值做 prediction-time state。

因为 after_t 是未来。

如果为了画图做 interpolation：

noncausal_visualization_only = true

不能进入机制实验。

第一版：

step = {

另外生成专门 dynamics sequence：

      "t": ...,

以后主要拿它判断：

7. 每个 dataset 的研究职责暂时固定

不要把它们弄成一个东西：

→ long human action sequences
→ history / next-action

→ persona + environment + physical action + candidates
→ O/action/world boundary

FarmQuest
→ structured behavioral telemetry

PowerWash

→ persistence / progress / interruption / state dynamics

禁止：

survey → P
arousal → S
mood → S

→ source-preserving field

以及少数非常明确的：

9. 推荐实际实现顺序

现在按这个顺序做：

1. FarmQuest
