# P5 后续故事过程：同一便条的归档

状态：**DEVELOPMENT / PARTIAL / READY_FOR_INDEPENDENT_REVIEW**（2026-10-12；有界增量，系统未 CLOSED）。这是原 Mature-Methods Integration v1 的原生能力增量，不另立系统阶段；原 S1–S4 和 S2 权限编辑拒绝原样保留。运行场景、故障/恢复、负例及限制只在[唯一 RESULTS](../../../../02_实验/Mature_Methods_Integration_v1/RESULTS.md)维护；本 README 记录设计契约和模块边界。

## 本次具体对象

作者给出结果要求：原生 A→B 便条得到真实回应后，同一物理便条必须在绝对第 24 分钟前进入注册档案地点。作者无需填写完整移动/交还/归档动作路径。

游戏内容明确增加后续物品保管任务：B 可以自己归档，也可实际交还 A 再由 A 归档；角色是否接收这种任务由本实例的有限内容规则决定。浪漫便条接受/拒绝不是同意合作的通用语义。该内容规则、注册能力和局部任务接线属于新增游戏内容/知识工程，不是算法发现的因果法则。

便条不能预造：它由旧原生社交流程创建并交付。作者输入先引用未绑定便条，原生封存的创建/交付凭证才绑定具体 note ID；后续版本不得换成同名新物品。

## 分工与必须成立的证据

| 所属层 | 本次职责 | 不是它的权力 |
|---|---|---|
| 作者请求 / 固定初始 grant | 结果或过程要求、未来版本、绝对期限及任务控制范围 | 运行中改权限/补预算、撤销过去 |
| 原 GTPyhop 方法搜索 | `file_by_B` 与 `return_then_file_by_A` 各自检查前提并分解；由原搜索算法选择/回溯 | 先收 P5 已选答案再换名；写入 B 接受或任务已完成 |
| 角色内容与局部任务 | 接收/拒绝新任务，继续合法进行中的旧任务；从本地信息提出原生操作 | 读高层全知视图、假定别人已同意 |
| Evennia 与现有 P5 结算 | 同一时钟、真实 move/get/drop/give、精确实体前后状态与回执 | 用 planner primitive 的预测当效果 |
| TypedIR / 真实反馈 | 从注册的响应、交还、归档事件判定；保留未受影响历史和任务，反馈到未来方法 | 仅凭 method 名、日志文字或旧配送 SAT 判新目标完成 |

控制器在分钟封存后只能投递下一轮未来请求。接受、拒绝和物理结算在后续原生回调、下一次封存之前发生；不得向已封存分钟补写历史事件。

## 有界验收

1. 在同一真实封存状态下，两种方法可以同时合法；GTPyhop 的独立 task methods 返回替代分解，而不是一个 task 返回两段串联任务或外部预选方法 ID。
2. 接受与拒绝可形成不同的实际后续动作/持有链；新请求能被角色真实拒绝，导致另一合法方法被采用。物品移动必须有真实 command/前后状态凭证。
3. 未来作者目标编辑实际影响尚未执行的安排；旧提案版本不能继续派发，过去、绝对期限、进行中的合法物理动作和未受影响目标保留。
4. 结果约束、过程指定、授权直接编排、锁定片段的来源/进入条件分别记录；锁定核心不被自动改写。未支持控制方式明确拒绝，不能全部改成开路机会。
5. 无权限、资源不可用或期限不满足不能伪造归档；预测、任务准入、实际归档分别判定。
6. 同游戏内容、动作权限、反馈及预算下运行认真实现的事件驱动对照，允许它同样成功；不以原 P5 缺少新能力制造弱基线。
7. 保存有限原生轨迹、失败与配置、源身份、独立 DB 读回，并分别记新增游戏规则/方法/适配/调试与运行成本。复用既有实验目录和发布工具，不覆盖旧结果或复制新证据平台。

这是一项系统能力/开发诊断，不证明组合优于单组件、原创规划方法、作者总劳动降低或玩家生命感提升。LLM、关系/记忆模型、DODM、新通用调度器不属于本次实施。通过后停在开发交付待独立审阅，不自动扩系统，也不自行 CLOSED。
