# LIGHT source/O/recorded-candidate lineage audit (v1)

Date: 2026-10-06. Scope: read-only audit of the current LIGHT processed-data adapter and actor-local prediction surface. This is a source/measurement audit, not a model or psychological-validity review. Raw pickle was read locally for field/index equality checks only; it was not modified. No training or tests were run.

## Findings

| Question | Evidence-backed finding | Boundary / unresolved |
|---|---|---|
| Who produced the interaction? | Urbanek et al. describe LIGHT as crowdsourced human-human fantasy-game dialogues (10,777 dialogues); the official project page describes crowdworkers interacting as characters. The local processed record is consistent with a human dialogue dataset. | This establishes dataset-level provenance, not who entered each particular action string, whether it was typed or menu-selected, or the interface/version used for `light-dialog-processed-small7.pkl`. The 2019 main paper does not document that exact UI interaction path. |
| Free text or finite action menu? | The paper defines a constrained physical action vocabulary and game legality/argument constraints (§3, pp. 675–676). Its model section also uses candidate-action sets (§4, p. 676 onward). | Neither fact proves the historic worker UI: an action may be a textual command under a finite grammar without having been selected from a displayed menu. Exact collection UI/collector lineage remains **UNVERIFIED**. The current/modern LIGHT UI and later ParlAI task/model code are not evidence for the 2019 collector. |
| What is `source_O`? | `export_replay.py:9–27` copies the same-index raw `context` into `source_O`; the local actor-history view consumes that field. Direct raw-pickle join (SHA-256 `7c83cf49818586db9999ea67a4a6ad087afbd91c26ed629a9f00e21d0b84058f`) reconstructed each physical raw turn by filtering nonempty actions first: all 13,463 actor-local rows joined, and all 13,463 `source_O == raw.context[t]`. The observed view is an environmental snapshot beginning “You are in …”; it is not the paper’s full multimodal/dialogue model context. | `source_agents` and persona-like source fields are retained in episode metadata but omitted from the flattened actor-local model input; the latter uses current O plus earlier same-actor physical O/action pairs. The model history omits speech, emotes, other-actor actions/speech, and persona, so it is not the complete LIGHT observation/dialogue history `H^obs`. A maximum physical-action depth does not repair that omission. |
| Is the current action/candidate pairing faithful to the processed source? | The same exact join found `source_action_A_star == raw.action[t]` and `candidate_set_factual == raw.available_actions[t]` for all 13,463 rows. Same-turn `speech[t]` is nonempty in 13,456/13,463 rows, yet is not an input feature in the actor-local view. The direct adapter stores speech/emote separately in `source_step_context` (`export_replay.py:21–27`). | These are record-copy checks, not evidence that the candidate list is the legal world set `A^W`, the character-believed set `A^O`, or the list actually displayed to a historical worker. Same-turn speech availability identifies an omitted, co-recorded channel; it is not by itself proof of label leakage or that speech belongs in O. |
| Was candidate support present before the recorded action? | The raw schema stores same-index `available_actions` and `action`; the adapter copies both from that turn. The target label is ordinarily supported by the copied list (the actor-local cohort has 13,462 exact string memberships and 13,463 case-folded memberships; one is case-only). | This is a persisted alignment, not timestamp/order evidence about when candidates were generated or shown. Do not call `available_actions` the human’s menu or `A^O` without exact collector provenance and semantic validation. Preserve the distinction: observed candidate support ≠ reconstructed action availability. |
| Does the history row preserve raw turn identity? | `run_actor_local_history_gate_v0.py` filters to physical rows, then writes `target_step_index=i` and `previous_same_actor_t=prev[1]` from the filtered `rec.steps` sequence. | These values are physical-step indices, not the original raw turn `t`, despite the `_t` field name. The flattened history JSONL has lost the raw-turn position. Mapping it back requires the source episode plus the same nonempty-action filtering; direct indexing raw arrays by `target_step_index` is wrong. |

## Data lineage and scope

The current adapter is a direct field mapper, not a reconstruction of the official ParlAI teacher-input pipeline:

1. `02_实验/T0c_LIGHT/export_replay.py:7–22` iterates raw `action` turns, skips blank actions, and reads same-raw-index `character`, `context`, and `available_actions`; it separately preserves same-turn speech/emote and environment fields.
2. `02_实验/T0c_LIGHT/export_replay.py:23–75` records `context` as `source_O`, raw `action` as `source_action_A_star`, and raw candidate strings as `candidate_set_factual`; its own provenance text says no semantic inference, and candidate semantics remain unresolved.
3. `02_实验/T0c_LIGHT/run_actor_local_history_gate_v0.py` filters actor-attributed physical steps and builds only same-actor prior physical O/action pairs. It writes filtered physical indices, not raw-turn indices.
4. `02_实验/PredictionBaselineV1/README.md` correctly scopes its learner to current source O, prior same-actor physical O/action pairs, and recorded candidate support, and explicitly says this support is not `A^O`.

The official 2019 paper’s model context includes dialogue and grounding features (personas, setting/objects, self/partner actions; see §§4–5.4, especially pp. 676 and 680–681). That published model path is materially richer than this local O-only action record. The currently archived ParlAI `main` builder is useful only as a downstream model/preprocessing reference; it is neither pinned to the original processed-small7 collector nor proof of its worker interface. Later `quests` processing code is a different pipeline and is not used to fill this gap.

## Admission implication

This cohort can support a narrowly described development prediction task over recorded action strings conditional on an environmental context snapshot, actor-local prior physical O/A, and recorded candidate support. It cannot yet support claims about predicting a human’s action from the full LIGHT-observed context, a historically displayed menu, character-believed availability `A^O`, psychological state, or persistent sufficient state. Source provenance and candidate semantics remain admission blockers for formal Paper-0 use. This finding does not block the separate, explicitly scoped development learner; it limits what that learner’s data and metrics mean.
